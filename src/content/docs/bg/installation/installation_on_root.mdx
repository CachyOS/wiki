## Преди да започнете

:::note
Ако след натискане на **Launch Installer** виждате само GRUB и Limine като опции за boot мениджър, значи системата е заредена в Legacy/BIOS режим.
:::

:::note[Не е позволено да инсталирате множество десктоп среди по време на инсталационния процес.]
:::

:::caution[Secure Boot и CSM трябва да бъдат деактивирани в BIOS/UEFI настройките, когато инсталирате в UEFI режим.]
За да настроите Secure Boot след инсталацията, вижте раздела [Secure Boot](/configuration/secure_boot_setup).

`Legacy USB Support` трябва да бъде настроен на `Auto`.
:::

:::caution
Опциите `Install alongside` и `Replace partition` не са 100% надеждни и могат да доведат до провал на инсталацията.

**Силно се препоръчва** ръчното дялово разделяне (`Manual partitioning`) при инсталиране на CachyOS.
:::

:::tip
Силно се препоръчва да рестартирате в ISO образа след неуспешен опит за инсталация.

В противен случай могат да възникнат повторни грешки по време на инсталационния процес.

Това се случва, защото инсталаторът не демонтира правилно дяловете при неуспешна инсталация.
:::

## Методи за инсталация

### Ръчно дялово разделяне

:::note[Преди да продължите с дяловото разделяне за UEFI инсталация.]
    ```sh title='Изпълнете тази команда в терминала'
    efibootmgr -v
    ```
Ако резултатът е `EFI variables are not supported on this system.`, значи системата е заредена в Legacy/BIOS режим и трябва да се уверите, че UEFI режимът е конфигуриран в BIOS/UEFI настройките. Вижте раздела [Изисквания](/installation/installation_on_root/#before-you-begin).
:::

## Двойно зареждане на Windows и CachyOS

:::note[Това ръководство предполага, че Windows вече е инсталиран на системата и сте решили да инсталирате CachyOS заедно с него, използвайки същото устройство.]
:::

:::caution
Двойното зареждане на Windows и Linux не е 100% надеждно. Актуализациите на Windows могат да нарушат bootloader-а, като презапишат EFI дяла.
В някои случаи проблеми може никога да не възникнат, но за други потребители това може да бъде повтарящ се проблем.

Един от начините да се избегне този проблем е да инсталирате всяка операционна система на отделно устройство.
:::

:::caution
EFI дял може да се наложи да бъде преоразмерен, в зависимост от препоръчителния минимален размер за целевия boot мениджър. Вижте [Ръчно дялово разделяне](/installation/installation_on_root#manual-partitioning).

FAT файловите системи не могат да бъдат преоразмерявани на място. За правилното "преоразмеряване" на FAT EFI дяла трябва да архивирате съществуващата EFI файлова система, да използвате инструмент като `gparted`, за да преоразмерите съществуващия дял и да форматирате новия дял, след което да копирате предишната структура на файловата система обратно в EFI дяла.
:::

### Предварителни изисквания

- Windows Fast Startup и Hibernation трябва да бъдат деактивирани.
  - Отворете Windows Powershell като администратор и изпълнете следната команда:
      ```ps
      powercfg /H off
      ```
    Рестартирайте системата, за да се приложат промените.
- Windows BitLocker трябва да бъде деактивиран.
  - Проверка дали BitLocker е активиран:
    ```ps title='Отворете Command Prompt като администратор и изпълнете следната команда'
    manage-bde -status
    ```
  Ако **Encryption Method** показва `None`, тогава BitLocker е деактивиран.
- Secure Boot трябва да бъде деактивиран.
- Свободен дял ≥30 GB.
  - Ръководство как да свиете дял на Windows:
    - Натиснете `Win + R`, въведете `diskmgmt.msc` и натиснете Enter, за да отворите Disk Management.
    - Идентифицирайте основния дял на Windows (обикновено C:) и щракнете с десния бутон върху него.
    - Кликнете `Shrink Volume...`, задайте поне **30720 MB** (30 GiB) и кликнете `Shrink`.
- Bootable USB устройство с CachyOS.
  - Вижте раздела [Създаване на bootable USB устройство с CachyOS](/installation/installation_prepare#creating-a-bootable-cachyos-usb-drive).

<Tabs>
    <TabItem label='systemd-boot'>
        **Трябва да копираме Windows EFI двоичните файлове към Linux EFI дяла, за да може boot мениджърът да ги разпознае.**

        <Steps>
        1. Открийте **Windows EFI дяла** с `lsblk`.

            ```sh title='Изпълнете тази команда в терминала'
            lsblk -o NAME,FSTYPE,SIZE,MOUNTPOINT
            ```
            ```sh title='Примерен изход'
                        NAME        FSTYPE   SIZE MOUNTPOINT
            zram0               15.3G [SWAP]
            nvme0n1            476.9G
            ├─nvme0n1p1 vfat     100M
            ├─nvme0n1p2           16M
            ├─nvme0n1p3 ntfs   234.4G
            ├─nvme0n1p4 ntfs     830M
            ├─nvme0n1p5 vfat       2G /boot
            └─nvme0n1p6 btrfs  239.6G /var/tmp
            ```
            EFI дяловете почти винаги са форматирани като `FAT32/vfat`. Тъй като `nvme0n1p1` няма Linux точка на монтиране, можем да предположим, че този дял е Windows EFI дял.

        2. Временно монтирайте Windows EFI дяла.

            ```sh
            sudo mkdir /mnt/WinBoot
            sudo mount /dev/nvme0n1p1 /mnt/WinBoot # Заменете `nvme0n1p1` с името на Windows EFI дяла.
            ```

        3. Копирайте EFI двоичните файлове от **Windows EFI дяла** към **Linux EFI дяла**.

            ```sh
            sudo cp -r /mnt/WinBoot/EFI/Microsoft/ /boot/EFI
            ```

        4. Демонтирайте предварително монтирания дял. Windows трябва да се появи в менюто за зареждане при следващото стартиране.

            ```sh
            sudo umount /mnt/WinBoot
            sudo rm -r /mnt/WinBoot
            ```

        </Steps>
    </TabItem>

    <TabItem label='GRUB'>
        **GRUB използва os-prober за автоматично откриване на Windows EFI дяла и добавянето му в менюто за зареждане.**

        <Steps>
        1. Инсталирайте **os-prober**.

            ```sh
            sudo pacman -S os-prober
            ```

        2. Активирайте **os-prober** в конфигурационния файл на GRUB.

            ```sh title='Натиснете CTRL+S за запазване и CTRL+Q за изход от Micro'
            sudo micro /etc/default/grub
            # /etc/default/grub
            # Probing for other operating systems is disabled for security reasons. Read
            # documentation on GRUB_DISABLE_OS_PROBER, if still want to enable this
            # functionality install os-prober and uncomment to detect and include other
            # operating systems.
            GRUB_DISABLE_OS_PROBER=false

            ```

        3. Актуализирайте grub.cfg, сега използвайки **os-prober**.
            ```sh
            sudo grub-mkconfig -o /boot/grub/grub.cfg
            ```

            **Windows вече трябва да е добавен към boot менюто.**

        </Steps>
    </TabItem>
