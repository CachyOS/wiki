## Оптимизации на производителността за AMD

### Драйвер AMD P-State
---------------------------

`amd-pstate` е драйвер за мащабиране на производителността на процесорите AMD, който въвежда нов механизъм за управление на честотата на процесора в Linux ядрото за съвременните серии APU и CPU на AMD. Новият механизъм се базира на Collaborative Processor Performance Control (CPPC), който осигурява по-прецизно управление на честотата в сравнение с остарелите хардуерни ACPI P-States.

Настоящите платформи с AMD CPU/APU използват драйвера ACPI P-states за управление на честотата и тактовите цикли на процесора с превключване само между 3 P-състояния (P-states). CPPC заменя контролите на ACPI P-states и предоставя гъвкав интерфейс с ниска латентност, чрез който Linux ядрото директно подава насоки за производителността към хардуера.

По-долу са описани 3-те режима на работа на драйвера `amd_pstate` и параметрите на ядрото (cmdline), чрез които можете да ги използвате при стартиране:

- AMD P-State (неавтономен режим): `amd_pstate=passive`
- AMD P-State Guided (насочван автономен режим): `amd_pstate=guided`
- AMD P-State EPP (автономен режим): `amd_pstate=active`

:::note
Драйверът AMD P-State EPP се използва по подразбиране, когато не е зададена изрична конфигурация.
:::

Можете също така да превключвате между режимите на работа по време на работа на системата, за да тествате отделните опции:

- **Автономен режим**: платформата взема предвид само стойностите, зададени за минимална производителност, максимална производителност и предпочитание за енергийна ефективност (Energy Performance Preference).
   ```sh
   echo active | sudo tee /sys/devices/system/cpu/amd_pstate/status
   ```

- **Насочван автономен режим**: платформата задава работното ниво на производителност според текущото натоварване и в рамките на ограниченията, определени от ОС чрез регистрите за минимална и максимална производителност.
   ```sh
   echo guided | sudo tee /sys/devices/system/cpu/amd_pstate/status
   ```

- **Неавтономен режим**: платформата получава желаното ниво на производителност директно от ОС чрез регистъра за желана производителност (Desired Performance Register).
   ```sh
   echo passive | sudo tee /sys/devices/system/cpu/amd_pstate/status
   ```

### Конфигуриране на AMD P-State EPP

За да използвате P-State EPP, са налични два регулатора (governor) за мащабиране на честотата на процесора: `powersave` и `performance`. Препоръчително е да използвате регулатора `powersave` и да зададете предпочитание.

*   Задаване на регулатор `powersave`: `sudo cpupower frequency-set -g powersave`
*   Задаване на регулатор `performance`: `sudo cpupower frequency-set -g performance`

За да зададете предпочитание, изпълнете следната команда с желаната от вас стойност:

```sh
echo power | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/energy_performance_preference
```

Налични предпочитания: `performance`, `power`, `balance_power`, `balance_performance`

<LinkButton icon="external" href="https://lore.kernel.org/lkml/20221219064042.661122-1-perry.yuan@amd.com/">Официални бенчмаркове за всяко предпочитание</LinkButton>

### Оптимизатор за AMD 3D V-Cache

AMD публикува пач за оптимизиране на планирането на кеша при процесори с два CCD и 3D V-Cache, като 7950X3D и 7900X3D.
В BIOS, под опцията CPPC, трябва да изберете стойност „Driver“. Това ще позволи да презаписвате използвания режим чрез sysfs.

Налични са два режима:

1. Frequency (Честота)
2. Cache (Кеш)

Когато е зададено `cache`, драйверът ще се опитва да разпределя задачите първо към CCD с по-големия кеш, което е особено полезно при игри.
Опцията `frequency` ще се опитва да насочва задачите към втория CCD, който работи на по-висока честота в сравнение с CCD с 3D кеша.

Frequency (по подразбиране):
```sh
echo frequency | sudo tee /sys/bus/platform/drivers/amd_x3d_vcache/AMDI0101:00/amd_x3d_mode
```

Cache:
```sh
echo cache | sudo tee /sys/bus/platform/drivers/amd_x3d_vcache/AMDI0101:00/amd_x3d_mode
```

След като смените режима, статистиката за предпочитаните ядра на AMD трябва да показва различно подреждане (ranking). Можете да я проверите с:
```sh
grep -v /sys/devices/system/cpu/cpu*/cpufreq/amd_pstate_prefcore_ranking
```

### AMD P-State Core Performance Boost

AMD Core Performance Boost, известен още като AMD Turbo Core, е технология на AMD за динамично мащабиране на честотата, която позволява на процесора динамично да регулира и управлява работната си честота при определени модели процесори. Това осигурява по-висока производителност при нужда, като същевременно поддържа по-ниска консумация на енергия и по-добри температурни параметри при нормална работа.

За да управлявате AMD CPB в CachyOS, можете да използвате следните команди:

```sh
❯ echo 0 | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/boost # Деактивиране на boost за всички ядра
❯ lscpu -ae # Това показва, че AMD CPB е деактивиран глобално
CPU NODE SOCKET CORE L1d:L1i:L2:L3 ONLINE    MAXMHZ   MINMHZ       MHZ
  0    0      0    0 0:0:0:0          yes 3301.0000 400.0000 1212.8250
  1    0      0    0 0:0:0:0          yes 3301.0000 400.0000 1394.2180
  2    0      0    1 1:1:1:0          yes 3301.0000 400.0000 1204.4600

❯ echo 1 | sudo tee /sys/devices/system/cpu/cpu0/cpufreq/boost # Активира boost за cpu0
❯ lscpu -ae
CPU NODE SOCKET CORE L1d:L1i:L2:L3 ONLINE    MAXMHZ   MINMHZ       MHZ
  0    0      0    0 0:0:0:0          yes 4564.0000 400.0000 1393.2380
  1    0      0    0 0:0:0:0          yes 3301.0000 400.0000  400.0000
  2    0      0    1 1:1:1:0          yes 3301.0000 400.0000 2157.8469
```

CachyOS предоставя и версия на `power-profiles-daemon` с обратно приложен (backported) комит, който активира поддръжката на AMD CPB. При използване на профила `powersave` AMD CPB ще бъде деактивиран, а при `balanced` или `performance` ще бъде активиран.

## Подобрения на производителността

### [Входно-изходен планировчик ADIOS](https://github.com/firelzrd/adios)

Създаден от [firelzrd](https://github.com/firelzrd)

:::note
CachyOS включва стабилния клон на ADIOS в ядрото.

Текуща версия в **linux-cachyos**: `3.2.0`

Текуща версия в **linux-cachyos-rc**: `3.2.0`
:::

Кратко въведение от README:

- *ADIOS (Adaptive Deadline I/O Scheduler) е входно-изходен (I/O) планировчик на ниво блоков слой за Linux ядрото, проектиран за съвременни многоопашкови блокови устройства (blk-mq). Целта му е да осигури ниска латентност за I/O операциите, като комбинира принципите на планиране по краен срок (deadline scheduling) с адаптивен механизъм за контрол на латентността, базиран на обучение.*
  - *Вдъхновен е от и надгражда концепции от планировчиците mq-deadline и Kyber. Основната му функция е способността да предвижда латентността при завършване на I/O операциите въз основа на предходната производителност и характеристиките на заявката (тип операция, размер) и да използва тази прогноза за динамично регулиране на крайните срокове на заявките и групирането им (batching).*

Накратко: ADIOS работи, като изучава профила на латентност на вашето устройство за съхранение и използва тези данни за динамично определяне на крайните срокове за I/O заявките. Той приоритизира заявките в четири нива — от критични системни операции (Ниво 0) до фонови задачи (Ниво 3) — за да гарантира плавно потребителско изживяване. Макар да е фокусиран върху отзивчивостта, поведението му може да се настройва фино чрез sysfs параметри за баланс между латентност и пропускателна способност.

За демонстрация на живо можете да гледате това [видео](https://www.youtube.com/watch?v=L9WDcEeHgy4)

#### Как да активирате ADIOS

<Tabs>
    <TabItem label='Временно (влиза в сила веднага)'>
        Този метод задава планировчика за текущата сесия. Промяната ще бъде загубена след рестартиране.
        ```sh
        sync && echo adios | sudo tee /sys/block/<yourdrive>/queue/scheduler
            # Заменете <yourdrive> с реалния идентификатор на диска (напр. sda, sdb, nvme0n1)
        ```
    </TabItem>
    <TabItem label='Постоянно след рестартиране'>
        <Steps>
            1. Отворете или създайте нов файл с udev правила в предпочитания от вас текстов редактор (напр. nano, micro, vim)
                ```sh title='Пример'
                sudo nano /etc/udev/rules.d/60-ioschedulers.rules
                ```
            2. Добавете следните правила във файла. Тези правила автоматично прилагат конкретен I/O планировчик в зависимост от типа на устройството (HDD, SSD или NVMe).
                ```text
                # HDD
                ACTION=="add|change", KERNEL=="sd[a-z]*", ATTR{queue/rotational}=="1", \
                    ATTR{queue/scheduler}="bfq"

                # SSD
                ACTION=="add|change", KERNEL=="sd[a-z]*|mmcblk[0-9]*", ATTR{queue/rotational}=="0", \
                    ATTR{queue/scheduler}="adios"

                # NVMe SSD
                ACTION=="add|change", KERNEL=="nvme[0-9]*", ATTR{queue/rotational}=="0", \
                    ATTR{queue/scheduler}="adios"
                ```
              3.  Запазете файла и затворете редактора.
              4.  Презаредете `udev` правилата, за да приложите промените веднага без рестартиране.
                  ```sh
                  sudo udevadm control --reload-rules
                  sudo udevadm trigger
                  ```
        </Steps>
    </TabItem>
</Tabs>

Често задавани въпроси (FAQ):

- Щом подобрява отзивчивостта, защо не е активиран по подразбиране?
  - ADIOS все още е в активна разработка и подлежи на непрекъснато тестване. Макар да предлага значителни предимства за отзивчивостта на работния плот, все още не се счита за достатъчно стабилен, за да бъде по подразбиране за всички натоварвания и типове хардуер. В някои гранични случаи грешки могат да доведат до проблеми като замръзване на системата. Поради тази причина той е допълнителна (опционална) функция за потребители, които желаят да тестват и да се възползват от най-новите му подобрения.

### NVIDIA Smooth Motion (серия RTX 40xx и 50xx)

:::note[Съвместимост с игри]
Игри, които работят на DX11, DX12 и Vulkan. Вижте често задаваните въпроси за заобиколно решение при OpenGL.

Както DXVK, така и VKD3D работят безпроблемно.

**Поддържат се само 64-битови приложения. Smooth Motion няма да работи с 32-битови приложения (напр. стари DX11 игри).**

:::

Директен цитат от документацията на NVIDIA:

*NVIDIA Smooth Motion е нов AI модел на ниво драйвер, който осигурява по-плавен геймплей чрез генериране на допълнителен кадър между два рендирани кадъра. За игри без DLSS Frame Generation, NVIDIA Smooth Motion е нова опция за подобряване на изживяването при видеокарти от серия GeForce RTX 40 и по-нови.*

- Как да активирате NVIDIA Smooth Motion за дадена игра:
  - Добавете следната променлива на средата:
    ```text
    NVPRESENT_ENABLE_SMOOTH_MOTION=1
    ```

Често задавани въпроси (FAQ):

- Защо да използвам Smooth Motion вместо DLSS Frame Generation?
  - Когато дадена игра не поддържа DLSS Frame Generation, Smooth Motion служи като алтернатива благодарение на своя AI модел в драйвера.
- Има ли някакви недостатъци при използването на Smooth Motion?
  - Да, активирането на Smooth Motion може да въведе леко забавяне при вход (input lag) поради процеса на генериране на допълнителния кадър.
  - Възможно е да причинява проблеми с наслагвания (overlays) от трети страни. За да избегнете това, добавете следната променлива на средата:
    ```text
    NVPRESENT_QUEUE_FAMILY=1
    ```
    :::note[При използване на тази променлива може да се наблюдава влияние върху производителността.]
    :::
- Защо MangoHud не отчита увеличената кадрова честота?
  - Към момента MangoHud не отчита допълнителните кадри, генерирани от Smooth Motion, което води до подвеждащо отчитане на кадрите в секунда.
    - Използването на вградения FPS брояч на монитора ще покаже правилната кадрова честота.
- Какво е качеството на изображението в сравнение с DLSS Frame Generation?
  - Качеството на изображението не е толкова добро и може да се появят артефакти, особено при сцени с бързо движение.
- Съвместим ли е с външни инструменти за ограничаване на кадрите (напр. MangoHud)?
  - Не. Вграденият в играта ограничител на кадри би трябвало да работи нормално.
- Може ли Smooth Motion да се комбинира с DLSS Frame Generation?
  - Не. В даден момент може да бъде активен само един метод за генериране на кадри.
- Може ли Smooth Motion да се използва с OpenGL приложения?
  - Не директно, тъй като е реализиран като Vulkan слой, но е възможно чрез използване на [Zink](https://docs.mesa3d.org/drivers/zink.html) за превод на OpenGL извикванията към Vulkan:
    ```text
    NVPRESENT_ENABLE_SMOOTH_MOTION=1 zink-run <command>
    ```
    :::note
    Използването на Zink вероятно ще окаже влияние върху производителността и може да доведе до графични артефакти в някои игри.

    Потребителите с две видеокарти трябва да зададат `DRI_PRIME=1`, за да използват дискретната видеокарта на Nvidia, вместо по-обичайните методи за избор на видеокарта.
    :::

## Оптимизации за пестене на енергия

### thermald

`thermald` е демон за термично управление за системи с Intel. Той следи температурните сензори и прилага действия за охлаждане, като ограничения на мощността на процесора или промени в състоянията на производителност (performance-state), преди фърмуерът да се наложи да прибегне до по-агресивен throttling.

Основно е полезен за лаптопи с Intel, хибридни устройства (convertibles), таблети, портативни конзоли (handhelds) и компактни компютри (SFF), които предоставят термични контроли на Intel чрез `/sys/class/thermal`. Поддържаните системи обикновено използват температурни сензори за процесори Intel, Intel P-state, Intel power clamp, RAPL, `INT340X` или ACPI DPTF / адаптивни термични таблици. Процесорите на AMD не се поддържат от `thermald`.

Инсталирайте и го активирайте чрез:

```sh
sudo pacman -S thermald
sudo systemctl enable --now thermald.service
```

Проверете дали се е стартирал правилно:

```sh
systemctl status thermald.service
journalctl -u thermald.service -b
```

### Активиране на RCU Lazy

RCU Lazy помага за намаляване на консумацията на енергия при неактивни или слабо натоварени системи. Това може да бъде полезно за лаптопи и портативни устройства.
Подобрението е между 5 и 10% по отношение на пестенето на енергия. Важно е обаче да се отбележи, че тази функция за пестене на енергия може да доведе до леко понижаване на производителността в зависимост от сценария.
При ядрото `linux-cachyos-deckify` тази опция е активирана по подразбиране, тъй като пестенето на енергия е ключово и необходимо за тези устройства.

За да активирате RCU Lazy, добавете следния параметър към списъка с параметри на ядрото ([cmdline](/bg/configuration/boot_manager_configuration/)):
```text
rcutree.enable_rcu_lazy=1
```

## Отстраняване на проблеми с NVIDIA

### NVIDIA GSP фърмуер

Фърмуерът NVIDIA GSP може **„в някои случаи“** да доведе до понижена производителност. Въпреки че драйверът на NVIDIA 555.58.02 до голяма степен отстрани този проблем, той може да продължи да се проявява на определени системи.
Ако изпитвате насичания в KDE или слаба производителност в определени случаи, можете да деактивирате GSP фърмуера със следния конфигурационен файл:
`/etc/modprobe.d/nvidia-gsp.conf`

```text
options nvidia NVreg_EnableGpuFirmware=0
```

След като създадете файла, изпълнете следната команда:
```sh
sudo mkinitcpio -P
```

:::note
Отворените модули на ядрото на NVIDIA ([open kernel modules](https://github.com/NVIDIA/open-gpu-kernel-modules)) са базирани на GSP фърмуера. Поради това GSP не може да бъде деактивиран и тази modprobe опция ще бъде игнорирана при използването им. Използвайте `linux-cachyos-nvidia` или `nvidia-dkms`.
:::

Като цяло е препоръчително да тествате GSP фърмуера след всяка нова инсталация на драйвер на NVIDIA, тъй като той често въвежда полезни функции. Освен това NVIDIA вече провежда основните си QA тестове именно с GSP фърмуера.

## Подобрения на звука и софтуера

### Подобряване на звука от високоговорителите на лаптопа

Високоговорителите на лаптопите често възпроизвеждат плосък и слаб звук поради компактния си размер и ограничените хардуерни възможности. [EasyEffects](https://wiki.archlinux.org/title/PipeWire#EasyEffects) може значително да подобри качеството на звука от вградените високоговорители на вашия лаптоп чрез прилагане на различни аудио ефекти и персонализирани конфигурации.

За да започнете, трябва да инсталирате EasyEffects и необходимите зависимости:

```bash
# Инсталиране на EasyEffects
sudo pacman -S easyeffects
# Инсталиране на допълнителни плъгини за повече ефекти
sudo pacman -S lsp-plugins-lv2
sudo pacman -S zam-plugins
sudo pacman -S calf
sudo pacman -S mda.lv2
```

#### Конфигурация

Следвайте тези стъпки, за да конфигурирате EasyEffects:

1. Стартирайте EasyEffects от менюто с приложения или като въведете `easyeffects` в терминала.
2. Отидете в раздела **Output**, за да управлявате ефектите, прилагани към звука на вашите високоговорители.
3. Преминете към раздела **Effects**, за да добавяте, променяте или настройвате аудио ефекти.

<ImageComponent imgsrc={import('~/assets/images/easyeffects.png')} />

##### Използване на профили от общността (Community Presets)

За бърза и ефективна настройка започнете с **профили (presets), създадени от общността**, съобразени с различни аудио сценарии:

1. Изтеглете профили от хранилището [EasyEffects Community Presets](https://github.com/wwmm/easyeffects/wiki/Community-presets).
2. В EasyEffects натиснете бутона **Presets** и изберете **„Import preset from local storage“**.
3. Намерете и изберете изтегления файл с профила.
4. След като бъде импортиран, профилът ще се появи в списъка ви — натиснете **„Load“**, за да го приложите към вашия аудио изход.

<ImageComponent imgsrc={import('~/assets/images/easyeffects-presets.png')} />

##### Създаване на собствен профил

За по-персонализирано аудио изживяване създайте собствен профил, съобразен с високоговорителите на вашия лаптоп:

1. Натиснете бутона **„+“** в менюто Presets, за да създадете нов профил (напр. наименувайте го **„Laptop Speakers“**).
2. Изберете **„Load“**, за да активирате новия профил.
3. Добавете и конфигурирайте ефекти в раздела **Output** > **Effects**, като експериментирате с опции като еквалайзери, усилватели на басите (bass enhancers) или разширители на стерео картината (stereo wideners).

##### Използване на ефекта Convolver (лаптопи с Dolby Atmos)

Ефектът **Convolver** може драстично да подобри звука, като прилага импулсни отговори (impulse responses), които симулират висококачествени аудио среди. Това обаче изисква прецизна настройка:

1. Добавете ефекта **Convolver** към веригата от ефекти в раздела **Effects**.
2. Заредете файл с импулсен отговор (във формат `.wav`), специфичен за вашия модел лаптоп, ако има такъв. Можете да потърсите такива файлове онлайн в ресурси като:
   - https://wiki.archlinux.org/title/Lenovo_ThinkPad_T14_(AMD)_Gen_4#Speakers
   - https://github.com/m4tx/thinkpad-p14s-g4-linux/#sound
   - https://github.com/shuhaowu/linux-thinkpad-speaker-improvements/
3. **Предотвратяване на изкривявания (clipping)**: Ефектът Convolver може значително да увеличи силата на звука. Добавете ефект **Limiter** след Convolver във вашата верига от ефекти, за да контролирате пиковете и да избегнете изкривявания.

<ImageComponent imgsrc={import('~/assets/images/easyeffects-convolver.png')} />

#### Съвети за оптимални резултати

- **Експериментирайте** с различни профили, за да намерите най-доброто съчетание за конкретния модел лаптоп и вашите лични звукови предпочитания.
- **Правете постепенни корекции** на отделните ефекти, за да предотвратите изкривявания или неестествено звучене.
- **Сравнявайте чрез включване и изключване**: Често превключвайте EasyEffects между **включено/изключено**, за да оцените подобренията спрямо звука по подразбиране.
- Потърсете **специфични за устройството профили или Convolver импулсни отговори** за популярни модели лаптопи като **Framework Laptop 13** или **ThinkPad T14**, за да постигнете оптимални резултати.
- **Автоматизирайте стартирането**: Настройте EasyEffects да се стартира автоматично при пускане на системата чрез настройките на приложението, за да сте сигурни, че вашият профил винаги се прилага.
- **Автоматично зареждане на профили за множество устройства**: Използвайте раздела **PipeWire** > **Presets Autoloading**, за да свържете конкретни профили с различни изходни устройства (напр. високоговорители срещу слушалки) за плавно превключване. <ImageComponent imgsrc={import('~/assets/images/easyeffects-autoloading.png')} />

## Конфигурация на Swap

### Преминаване от ZRam към Zswap

По подразбиране CachyOS използва ZRam за управление на swap паметта. Ако обаче предпочитате да използвате Zswap вместо това, можете лесно да превключите, като следвате тези стъпки:

:::note
Това ръководство предполага, че използвате конфигурацията по подразбиране на CachyOS с активиран ZRam и без създаден swap дял или swap файл по време на инсталацията.
:::

<Steps>
    1. Деактивирайте ZRam, като добавите параметър на ядрото. [Редактирайте конфигурацията на вашия мениджър за зареждане](/bg/configuration/boot_manager_configuration) и добавете следния ред:
        ```text
        systemd.zram=0
        ```
    2. Активирайте Zswap, като добавите следния параметър на ядрото:
        ```text
        zswap.enabled=1 zswap.shrinker_enabled=1 zswap.compressor=lz4 zswap.max_pool_percent=30
        ```
    3. Създайте празен файл за презаписване (override), за да деактивирате [udev правилото на CachyOS](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/lib/udev/rules.d/30-zram.rules), което изключва Zswap:
        ```bash
        sudo touch /etc/udev/rules.d/30-zram.rules
        ```
    4. Създайте swap файл за Zswap.
        <details>
            <summary>Ако използвате Btrfs:</summary>
                <Steps>
                    1. Създайте Btrfs подтом (subvolume) за swap файла:
                        ```bash
                        sudo btrfs subvolume create /swap
                        ```
                    2. Създайте swap файл с желания от вас размер (напр. 8GB), като промените параметъра `--size`:
                        ```bash "--size"
                        sudo btrfs filesystem mkswapfile --size 4g --uuid clear /swap/swapfile
                        ```
                    3. Активирайте swap файла:
                        ```bash
                        sudo swapon /swap/swapfile
                        ```
                    4. Добавете swap файла към `/etc/fstab`, за да се запазва след рестартиране:
                        ```bash
                        echo "/swap/swapfile none swap defaults 0 0" | sudo tee -a /etc/fstab
                        ```
                </Steps>
        </details>
        <details>
            <summary>Ако не използвате Btrfs:</summary>
            <Steps>
                1. Създайте swap файл с желания от вас размер (напр. 8GB), като промените параметъра `count=`:
                    ```bash "count=8"
                    sudo dd if=/dev/zero of=/swapfile bs=1G count=8
                    ```
                2. Задайте правилните права за достъп до swap файла:
                    ```bash
                    sudo chmod 0600 /swapfile
                    ```
                3. Форматирайте swap файла:
                    ```bash
                    sudo mkswap /swapfile
                    ```
                4. Добавете swap файла към `/etc/fstab`, за да се запазва след рестартиране:
                    ```bash
                    echo "/swapfile none swap defaults 0 0" | sudo tee -a /etc/fstab
                    ```
                5. Активирайте swap файла:
                    ```bash
                    sudo swapon /swapfile
                    ```
            </Steps>
        </details>
    5. Добавете модула за компресия `lz4` към конфигурационния файл `mkinitcpio.conf`:
        1. Отворете файла с текстов редактор:
            ```bash
            sudo nano /etc/mkinitcpio.conf
            ```
        2. Намерете масива `MODULES` и добавете `lz4` към него. Трябва да изглежда приблизително така:
            ```text
            MODULES=(... lz4)
            ```
        3. Запазете файла, като натиснете `Ctrl + O` и `Enter` за потвърждение, след което излезте от редактора с `Ctrl + X`.
    6. Пресъздайте вашия initramfs, за да приложите промените. Командата зависи от вашия мениджър за зареждане:
        <details>
            <summary>systemd-boot</summary>
            ```bash
            sudo sdboot-manage gen
            ```
        </details>
        <details>
            <summary>GRUB</summary>
            ```bash
            sudo grub-mkconfig -o /boot/grub/grub.cfg
            ```
        </details>
        <details>
            <summary>Limine</summary>
            ```bash
            sudo limine-mkinitcpio
            ```
        </details>
    7. Рестартирайте системата си, за да приложите всички промени.
</Steps>
