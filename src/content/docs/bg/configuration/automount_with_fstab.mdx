Това ръководство описва основите за използване както на systemd mount файлове, така и на файла fstab, намиращ се в /etc/, за монтиране на статични дискове по време на зареждане. В него накратко се обяснява как да намерите UUID на дял или диск, какво правят някои от опциите, както и се предоставят допълнителни източници за четене, в случай че дадената информация не ви е достатъчна.

## Предварителни изисквания

- Root или sudo достъп

:::note[NTFS под Linux]
Файловата система NTFS може да бъде нестабилна под Linux, независимо дали се използва драйверът ntfs, ntfs3 или ntfs-3g. Използвайте я на свой собствен риск. За по-добра стабилност и производителност обмислете използването на нативни за Linux файлови системи като ext4, xfs или btrfs.
:::

## По-безопасен и лесен за начинаещи метод: Монтиране на дискове чрез systemd mount файлове

Предимството на монтирането чрез systemd е, че дори да сгрешите нещо във вашия mount файл, системата ви все пак ще се зареди. За разлика от това, грешка във fstab може да направи системата ви неспособна да стартира.

### 1. Извеждане на UUID на вашите дялове

```sh title="Отворете терминал и изпълнете следната команда"
lsblk -f
```

```sh title="Примерен изход"
NAME          FSTYPE FSVER LABEL UUID                                 FSAVAIL   FSUSE% MOUNTPOINTS
zram0                                                                              [SWAP]
nvme0n1
├─nvme0n1p1   vfat   FAT32       E04D-9F05
├─nvme0n1p2
├─nvme0n1p3   ntfs               08A24E90A24E81E4                      715.4G   50%
├─nvme0n1p4   vfat   FAT32       E09C-D4DA                             628.1M   39% /boot
├─nvme0n1p5   ext4   1.0         187a9f06-9411-48d9-b941-f03c2e605812  203.6G   47% /
└─nvme0n1p6   ntfs
nvme1n1
└─nvme1n1p1   ext4               4e55896f-3f1f-4bc5-aa8a-fec099689cd9  931.5G   0%

```

В този пример искаме да монтираме допълнителен диск, току-що форматиран като ext4. Знаем, че е 1TB диск и че на него все още няма записано нищо. Следователно можем да определим, че дялът за монтиране е `nvme1n1p1`, който има UUID `4e55896f-3f1f-4bc5-aa8a-fec099689cd9`.

### 2. Идентифициране на вашия дял

Често на този етап `lsblk -f` ще ви даде цялата информация, от която се нуждаете, за да монтирате диска си чрез systemd. Ако все още не сте сигурни кой е правилният дял, можете да изпълните следната команда:

```sh
sudo fdisk -l
```

```sh title="Примерен изход"
Device          Start       End         Sectors     Size    Type
/dev/nvme0n1p1  2048        206847      204800      100M    EFI System
/dev/nvme0n1p2  206848      239615      32768       16M     Microsoft reserved
/dev/nvme0n1p3  239616      2997384182  2997144567  1.4T    Microsoft basic data
/dev/nvme0n1p4  2997385216  2999482367  2097152     1G      EFI System
/dev/nvme0n1p5  2999482368  3905454079  905971712   432G    Linux root (x86-64)
/dev/nvme0n1p6  3905454080  3907026943  1572864     768M    Windows recovery environment
/dev/nvme1n1p1  2048        1953523711  1953521664  931.5G  Linux filesystem

```

В този пример вече знаем нашия UUID. Въпреки това `fdisk -l` може да внесе повече яснота, като покаже точния размер на дяла (931.5G), както и неговия тип (Linux filesystem).

Това прави съвсем сигурно, че дялът, който търсим, е `nvme1n1p1` с UUID `4e55896f-3f1f-4bc5-aa8a-fec099689cd9`, както беше описано по-рано. Знаехме го и преди, но сега сме напълно сигурни.

След като сте сигурни, че сте намерили правилния дял, копирайте неговия UUID. Копирането от терминалния емулатор обикновено се прави с `ctrl+shift+C`.

### 3. Създаване на systemd mount файла
Да кажем, че искаме да използваме този диск предимно за игри — добро място за монтирането му е във вашата потребителска домашна директория. Може да е навсякъде, но за простота ще използваме `/home/user` (заменете `user` с вашето Linux потребителско име). Това има значение, тъй като пътят на монтиране определя името на systemd mount файла. Понеже този диск е предназначен за игри, ще го монтираме в папката `games` в домашната директория на потребителя: `/home/user/games`.

За systemd mount файл това се превежда като `home-$USER-games.mount` (наклонените черти `/` се заменят с тирета `-`), като systemd mount файловете се поставят в `/etc/systemd/system`.

:::tip
Ако искате да използвате интервал, тире, CJK символ или символ с ударение/диакритика в името на папката за монтиране, името на файла трябва да бъде форматирано по различен начин. Да кажем, че искате да използвате пътя `/home/grzegorz/brzęczyszczykiewicz` — изпълнете следната команда, за да получите името, което трябва да използвате за вашия файл:
```bash
systemd-escape -p --suffix=mount "/home/grzegorz/brzęczyszczykiewicz"
```
Тъй като трябва да екранирате всяка обратна наклонена черта `\`, ще създадете mount файла като `/etc/systemd/system/home-grzegorz-brz\\xc4\\x99czyszczykiewicz.mount`
:::

Използвайте текстов редактор по ваш избор; в този пример ще използваме `micro`.

```sh
micro /etc/systemd/system/home-$USER-games.mount
```
:::note
Ако монтирате в потребителската си домашна директория, можете да оставите `$USER` в горното име на файла — вашето потребителско име ще заеме мястото му автоматично.
:::

Поставете този шаблон в празния файл:
```ini
[Unit]
Description=

[Mount]
What=
Where=
Type=
Options=

[Install]
WantedBy=multi-user.target
```
По-долу са описани всяко от полетата във файла:

  </TabItem>
  <TabItem label= 'Where'>

Следвайки примера, попълненият mount файл трябва да изглежда така:
```ini
[Unit]
Description=Mount games drive (/home/user/games)

[Mount]
What=UUID=4e55896f-3f1f-4bc5-aa8a-fec099689cd9
Where=/home/user/games
Type=ext4
Options=defaults,exec,rw,noatime

[Install]
WantedBy=multi-user.target
```

### 4. Завършване
За да монтирате диска, за който току-що създадохте запис, изпълнете следното:

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now home-$USER-games.mount
```

Трябва да видите избраната от вас папка за точка на монтиране и можете да проверите състоянието на монтирането с `systemctl status home-$USER-games.mount`:

### Накратко (tl;dr)

- Намерете **UUID** на вашия дял

```sh
lsblk -f
```

- Създайте mount файла

```sh
micro /etc/systemd/system/mnt-foo.mount
```

Като замените `mnt-foo` с пълния път, където искате да монтирате, заменяйки `/` с `-`.

- Попълнете mount файла

```sh
[Unit]
Description=Mount drive

[Mount]
What=UUID=<partition UUID>
Where=/mnt/foo
Type=somefs
Options=defaults

[Install]
WantedBy=multi-user.target
```

Като замените `<partition UUID>`, `/mnt/foo` и `somefs` с вашия UUID, директория и файлова система (напр. ext4), както и зададете други опции след `defaults`, които може да са ви нужни, например `_netdev` за NAS или `nofail` за диск, който не е критичен за системата.

- Презаредете демона

```sh
sudo systemctl daemon-reload
```

- Монтирайте диска и го настройте да се монтира при зареждане

```sh
sudo systemctl enable --now mnt-foo.mount
```

## Метод за напреднали: Добавяне на записи в /etc/fstab

:::danger
Файлът fstab се чете по време на зареждане и ако в него има грешка, това може да попречи на системата ви да стартира. Задължително проверете внимателно записа си за печатни грешки, преди да рестартирате. Ако все пак допуснете грешка, обикновено можете да я поправите, като заредите в live среда и направите [chroot във вашата инсталация](/bg/features/cachy_chroot), за да редактирате файла.
:::

### 1. Извеждане на UUID на вашите дялове

```sh title="Отворете терминал и изпълнете следната команда"
lsblk -f
```

```sh title="Примерен изход"

├─nvme0n1p2
├─nvme0n1p3 ntfs               08A24E90A24E81E4                      715.4G    50%
├─nvme0n1p4 vfat   FAT32       E09C-D4DA                             628.1M    39% /boot
├─nvme0n1p5 ext4   1.0         187a9f06-9411-48d9-b941-f03c2e605812  203.6G    47% /
```

В нашия пример знаем, че искаме да монтираме дял на Windows, който е ntfs. Също така знаем, че приблизително половината от пространството му е свободно. Следователно можем да определим, че дялът, който искаме да монтираме, е `nvme0n1p3`, а неговият UUID е `08A24E90A24E81E4` с файлова система `ntfs` в този пример.

### 2. Идентифициране на вашия дял

Често на този етап `lsblk -f` ще ви даде цялата информация, от която се нуждаете, за да монтирате диска си чрез `/etc/fstab`. Ако все още не сте сигурни кой е правилният дял, можете да изпълните следната команда:

```sh
sudo fdisk -l
```

```sh title="Примерен изход"

/dev/nvme0n1p1       2048     206847     204800  100M EFI System
/dev/nvme0n1p2     206848     239615      32768   16M Microsoft reserved
/dev/nvme0n1p3     239616 2997384182 2997144567  1.4T Microsoft basic data
/dev/nvme0n1p4 2997385216 2999482367    2097152    1G EFI System
/dev/nvme0n1p5 2999482368 3905454079  905971712  432G Linux root (x86-64)

```

В този пример вече знаем нашия UUID. Въпреки това `fdisk -l` може да внесе повече яснота, като покаже точния размер на дяла (1.4T), както и неговия тип (Microsoft basic data).

Това прави съвсем сигурно, че дялът, който търсим, е `nvme0n1p3` с UUID `08A24E90A24E81E4`, както беше описано по-рано. Знаехме го и преди, но сега сме напълно сигурни.

След като сте сигурни, че сте намерили правилния дял, копирайте неговия UUID. Копирането от терминалния емулатор обикновено се прави с `ctrl+shift+C`.

### 3. Добавяне на запис в /etc/fstab

Сега, след като разполагаме с UUID на нашия дял, е време да отворим файла fstab.

Използвайте текстов редактор по ваш избор. В този пример ще използваме `nano`. За да редактирате файла fstab, той трябва да бъде отворен като root:

```sh
sudo nano /etc/fstab
```

Използвайки клавишите със стрелки, отидете до края на файла fstab, след което създайте новия ни запис на празен нов ред:

```sh
UUID=08A24E90A24E81E4 /media/windows ntfs3 defaults,nofail,uid=1000,gid=1000,rw,user,exec,umask=000 0 0
```

:::note
`/media/windows` трябва да съществува във вашата файлова система. Използвайте `mkdir`, за да създадете директорията, ако не съществува.
:::

Разбивката на този запис е следната:

- `UUID=08A24E90A24E81E4` е файловата система, която искаме да монтираме, идентифицирана чрез своя UUID. Има и други методи за идентифициране на файлова система, въпреки че UUID обикновено е най-безопасният. Допълнителни методи са изброени [тук](https://wiki.archlinux.org/title/Fstab#Identifying_file_systems).

- `/media/windows` е точката на монтиране на нашия диск. [Стандартът за йерархия на файловата система в Linux (FHS)](https://refspecs.linuxfoundation.org/FHS_3.0/fhs/index.html) посочва, че `/media/` е правилното място за монтиране на сменяеми носители. `windows` указва директорията, в която искаме да монтираме нашия диск. Всеки диск, който искаме да монтираме, ще се нуждае от собствена директория.

- `ntfs3` е типът файлова система, която ще се използва. В нашия пример изрично използваме драйвера на ядрото ntfs3. Други примери биха били `ext4`, `xfs` или подобни. Това изрично указване на типа файлова система може да бъде заменено с `auto`, за да позволи на командата `mount` да направи най-доброто предположение.

- `defaults,nofail,uid=1000,gid=1000,rw,user,exec,umask=000`: Това са опциите за монтиране:

  - `defaults`: стандартен набор от опции, включващ `rw, suid, dev, exec, auto, nouser и async.`

  - `nofail`: позволява процесът на зареждане да продължи, дори ако това монтиране се провали.

  - `uid=1000` и `gid=1000`: задава собствеността на потребителя и групата на монтираните файлове на потребителя и групата с ID 1000.

  - `rw`: монтира файловата система в режим за четене и запис (read-write).

  - `user`: позволява на потребител без root права да монтира файловата система.

  - `exec`: позволява изпълнението на двоични файлове на монтираната файлова система.

  - `umask=000`: задава маската за права на файловете, така че да позволява права за четене, запис и изпълнение за всички.

  - `първата 0`: `dump` обикновено е остаряла опция при съвременните системи. Оставянето ѝ на 0 няма да навреди с нищо. Можете да прочетете повече за нея [тук](https://linux.die.net/man/8/dump).

  - `втората 0`: задава реда за проверка на файловата система при зареждане. За root дял това трябва да бъде 1, освен ако вашата root файлова система не е btrfs — в такъв случай трябва да бъде настроена на 0. Всички останали файлови системи във вашия fstab трябва да бъдат или 0 (деактивирано), или 2. Повече информация ще намерите [тук](https://man.archlinux.org/man/fsck.8).

За по-подробно разглеждане на всяка опция посетете страниците на ръководството за [fstab](https://man7.org/linux/man-pages/man5/fstab.5.html) и [mount](https://man7.org/linux/man-pages/man8/mount.8.html)

#### Допълнителна информация

Между другото, всички опции след указването на типа файлова система са незадължителни, ако не ги променяте от стойностите по подразбиране.

Така

`UUID=<partition UUID> /media/foo somefs`

и

`UUID=<partition UUID> /media/foo somefs defaults 0 0`

са еквивалентни. `somefs`, следвано от нищо, по подразбиране означава `somefs defaults 0 0`

```sh
sudo systemctl daemon-reload
```

```sh
sudo mount -a
```

```sh
UUID=<partition UUID> /media/foo somefs defaults 0 0
```

Като замените `<partition UUID>`, `foo` и `somefs` с вашия UUID, директория и файлова система (напр. ext4), както и зададете други опции след `defaults`, които може да са ви нужни, например `_netdev` за NAS или `nofail` за диск, който не е критичен за системата.

- Презаредете демона

```sh
sudo systemctl daemon-reload
```

- Монтирайте вашия диск

```sh
sudo mount -a
```

Дискът вече е монтиран и занапред ще се монтира автоматично при всяко зареждане на системата.
