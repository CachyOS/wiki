    Инсталиране/деинсталиране на пакети от AUR, официалните хранилища, AppImage, Flatpak и локални пакети, преглед на подробности за пакетите, управление на пакетни групи и др.

    - Поддържа повече пакетни формати (AUR, AppImage, Flatpak и др.).
    - Функции за сигурност като проверка на PKGBUILD файлове — вижте [Проверки за сигурност](https://www.seafoam-labs.org/shelly-alpm/docs/security/) за повече информация.

<TabItem label="Чрез Octopi (GUI)">

Octopi е графичен пакетен мениджър за базирани на Arch дистрибуции, който предоставя удобен начин за управление на пакети и актуализации.
За да актуализирате системата си с Octopi, следвайте тези стъпки:

<Steps>

1. Стартирайте **Octopi** от менюто с приложения.
2. В главния прозорец щракнете върху бутона **Проверка за обновления** (горе вляво), а след това до него — **Обновяване на системата**.
3. Octopi ще провери за налични актуализации и ще ви попита дали да ги инсталира в самия Octopi или в терминал.
4. За да продължите с актуализацията, щракнете върху бутона **Прилагане**.
5. Octopi ще изтегли и инсталира актуализациите.
6. Препоръчително е да рестартирате компютъра си след голяма актуализация **(особено ако ядрото е било обновено)**.

</Steps>

</TabItem>

<TabItem label="Чрез Pacman">

<Steps>

1. Отворете терминален емулатор (или натиснете `ctrl + alt + t` — `mod + return` при мениджър на прозорци, напр. Qtile).
2. Изпълнете следната команда, за да актуализирате системата:

   ```sh
   sudo pacman -Syu
   ```
3. Препоръчително е да рестартирате компютъра си след голяма актуализация **(особено ако ядрото е било обновено)**.

</Steps>

</TabItem>

<TabItem label="Офлайн актуализация на системата">

*CachyOS поддържа офлайн актуализации на системата чрез скрипта [`pacman-offline`](https://github.com/eworm-de/pacman-offline). Това позволява на системата ви да изтегля актуализациите на пакетите и да ги прилага при следващото рестартиране (да, подобно на Windows).*

:::note
Инструментът `pacman-offline` се интегрира с функцията за офлайн актуализации на systemd. Той автоматично обработва актуализациите на ядрото и зареждането на модули.

Файлът `/etc/pacman.d/offline.conf` е от решаващо значение за управлението на това кои пакети се актуализират при обикновени и при офлайн актуализации. Уверете се, че е конфигуриран правилно за желаното от вас ядро или добавете пакетите, които искате да се актуализират само при изпълнение на pacman-offline и да бъдат пропускани при обикновена актуализация (напр. `pacman -Syu`).

**Ако активирате таймера за автоматично актуализиране, вече няма да е необходимо да актуализирате системата си ръчно.**
:::

<Steps>

1. **Инсталирайте пакета pacman-offline**

   ```bash
   sudo pacman -S pacman-offline
   ```

2. **Настройте Pacman да чете от отделния списък за игнорирани пакети**

   :::note[Добавете реда след секцията [options]. Вижте примера по-долу за справка.]
   :::

   ```bash title='Добавете следния ред във файла /etc/pacman.conf'
   Include = /etc/pacman.d/offline.conf
   ```
   *Пример*
   ```bash
   # /etc/pacman.conf
   # REPOSITORIES
   #   - can be defined here or included from another file
   #   - pacman will search repositories in the order defined here
   #   - local/custom mirrors can be added here or in separate files
   #   - repositories listed first will take precedence when packages
   #     have identical names, regardless of version number
   #   - URLs will have $repo replaced by the name of the current repo
   #   - URLs will have $arch replaced by the name of the architecture
   #
   # Repository entries are of the format:
   #       [repo-name]
   #       Server = ServerName
   #       Include = IncludePath
   #
   # The header [repo-name] is crucial - it must be present and
   # uncommented to enable the repo.
   #
   # GENERAL OPTIONS
   [options]
   # other options like 'Color', 'CheckSpace', etc. can be here
   Include = /etc/pacman.d/offline.conf
   ```
3. **Добавяне на ядрата на CachyOS, за да може pacman да ги игнорира при обикновени актуализации**

   Инструментът `pacman-offline` използва този файл, за да определи кои пакети да игнорира по време на стандартните актуализации с pacman.

   Пример: когато изпълнявате `sudo pacman -Syu`

   *Заменете съдържанието на файла `/etc/pacman.d/offline.conf` със следното:*

   ```text
   # Arch Linux kernels
   IgnorePkg = linux linux-headers linux-docs
   IgnorePkg = linux-lts linux-lts-headers linux-lts-docs
   IgnorePkg = linux-zen linux-zen-headers linux-zen-docs
   IgnorePkg = linux-hardened linux-hardened-headers linux-hardened-docs

   # CachyOS kernels
   IgnorePkg = linux-cachyos linux-cachyos-headers linux-cachyos-nvidia-open linux-cachyos-zfs
   IgnorePkg = linux-cachyos-bmq linux-cachyos-bmq-headers linux-cachyos-bmq-nvidia-open linux-cachyos-bmq-zfs
   IgnorePkg = linux-cachyos-bore linux-cachyos-bore-headers linux-cachyos-bore-nvidia-open linux-cachyos-bore-zfs
   IgnorePkg = linux-cachyos-deckify linux-cachyos-deckify-headers linux-cachyos-deckify-nvidia-open linux-cachyos-deckify-zfs
   IgnorePkg = linux-cachyos-eevdf linux-cachyos-eevdf-headers linux-cachyos-eevdf-nvidia-open linux-cachyos-eevdf-zfs
   IgnorePkg = linux-cachyos-gcc linux-cachyos-gcc-headers linux-cachyos-gcc-nvidia-open linux-cachyos-gcc-zfs
   IgnorePkg = linux-cachyos-hardened linux-cachyos-hardened-headers linux-cachyos-hardened-nvidia-open linux-cachyos-nvidia-hardened-zfs
   IgnorePkg = linux-cachyos-lts linux-cachyos-lts-headers linux-cachyos-lts-nvidia-open linux-cachyos-lts-zfs
   IgnorePkg = linux-cachyos-rc linux-cachyos-rc-headers linux-cachyos-rc-nvidia-open linux-cachyos-rc-nvidia-open linux-cachyos-rc-zfs
   IgnorePkg = linux-cachyos-rt-bore linux-cachyos-rt-bore-headers linux-cachyos-rt-bore-nvidia-open
   IgnorePkg = linux-cachyos-server linux-cachyos-server-headers linux-cachyos-server-nvidia-open linux-cachyos-server-zfs
   ```

   *Сега всички тези пакети ще бъдат игнорирани при обикновените актуализации, но ще се проверяват по време на подготовката за офлайн актуализация.*

3. **Стартирайте еднократно подготовката за офлайн актуализацията**

   ```bash title='Изпълнете следната команда'
   sudo systemctl start pacman-offline-prepare.service
   ```
   Тази команда ще стартира pacman-offline еднократно, за да синхронизира базите данни с пакети и да изтегли актуализациите, без да ги инсталира.

</Steps>

*Ако искате този процес да бъде автоматизиран, следвайте следните стъпки:*

<Steps>

1. **Активирайте таймера за подготовка**

   Активирането на `pacman-offline-prepare.timer` ще позволи на systemd да стартира този скрипт за ежедневно изтегляне на актуализации няколко минути след всяко стартиране на системата.

   ```bash
   sudo systemctl enable pacman-offline-prepare.timer
   ```

2. **Рестартирайте системата си:**

   Актуализациите ще бъдат инсталирани при следващото рестартиране на системата.

3. **(По избор) Автоматични рестартирания на системата:**

    Активирайте `pacman-offline-reboot.timer`, за да рестартирате автоматично системата си по подразбиране в **3:00 ч. през нощта** (според вашата часова зона), ако има чакащи актуализации. Имайте предвид, че часът не е винаги точно един и същ поради включената опция `RandomizedDelaySec`, която по подразбиране е зададена на 2 часа.

    ```bash
    sudo systemctl enable pacman-offline-reboot.timer
    ```

    :::tip
    Можете да редактирате файла `pacman-offline-reboot.timer`, за да промените часа за рестартиране при наличие на чакащи актуализации или да изключите случайното забавяне.
    :::

</Steps>

</TabItem>

<TabItem label="Cachy-Update">

Разклонение на [Arch-Update](https://github.com/Antiz96/arch-update)

Известяващ и прилагащ инструмент за актуализации за Arch Linux, който ви помага с важни задачи преди и след актуализация.
Включва динамичен и интерактивен аплет за системния трей за лесна интеграция с всяка графична среда или мениджър на прозорци.

<details>
    <summary>Как да активирате Cachy-Update</summary>
    Активирайте Cachy-Update в `CachyOS Hello > Apps/Tweaks > Cachy Update enabled`
</details>
<details>
    <summary>Как да деактивирате Cachy-Update</summary>
        Деактивирайте Cachy-Update в `CachyOS Hello > Apps/Tweaks > Cachy Update disabled`
            :::tip
            Ако искате да запазите Cachy-Update и само да изключите аплета в системния трей, отворете терминал и изпълнете следните команди:
            ```bash
            mkdir -p ~/.config/autostart
            echo -e "[Desktop Entry]\nHidden=true" > ~/.config/autostart/arch-update-tray.desktop
            ```
            Ако искате да запазите аплета в системния трей включен и просто да деактивирате автоматичната проверка за актуализации, изпълнете следната команда:
            ```bash
            systemctl --user disable --now arch-update.timer
            ```
            :::
</details>

- Функции:
  - Автоматична проверка и извеждане на списък с наличните актуализации.
  - Проверка за скорошни новини за Arch Linux (и предлагане на показването им при наличие).
  - Проверка за осиротели пакети (и предлагане на премахването им при наличие).
  - Проверка за стари и деинсталирани пакети в кеша (и предлагане на премахването им при наличие).
  - Проверка за чакаща актуализация на ядрото, изискваща рестарт (и предлагане за рестарт при наличие).
  - Проверка за услуги, изискващи рестартиране след актуализация (и предлагане за рестартирането им при наличие).
  - Поддръжка за `sudo`, `sudo-rs`, `doas` и `run0`.

**Интервал на проверка за актуализации:** `Веднъж две минути след стартиране и след това веднъж дневно със случайно забавяне до един час.`

- Как да промените интервала за проверка за актуализации:

```sh title='Изпълнете следната команда'
systemctl --user edit --full arch-update.timer
# Съвет: Можете да използвате и друг текстов редактор по ваш избор вместо `nano`
# напр. EDITOR=micro systemctl --user edit --full arch-update.timer
```

<details>
<summary>Съдържание на файла по подразбиране:</summary>
    ```systemd
    [Timer]
    OnStartupSec=2min # Проверка за актуализации две минути след стартиране
    RandomizedDelaySec=1h # Случайно забавяне до един час
    OnUnitActiveSec=1d # Проверка за актуализации веднъж дневно
    ```
</details>
Можете да промените стойността на `OnUnitActiveSec` на каквото желаете. Например, ако искате да проверява за актуализации на всеки 30 минути, променете я на `30m`, а за всеки 6 часа — на `6h`. Вижте този [документ](https://www.freedesktop.org/software/systemd/man/latest/systemd.time.html#Parsing%20Time%20Spans) за повече подробности как да задавате времеви интервали.

В случай че искате Cachy-Update да проверява за нови актуализации само веднъж при стартиране, можете просто да изтриете изцяло реда `OnUnitActiveSec`.

Благодарности на [Antiz](https://github.com/Antiz96) за поддръжката на оригиналния проект Arch-Update и за внедряването на Cachy-Update.

</TabItem>

### Настройка на защитната стена (ufw)
:::note
UFW е активиран по подразбиране след инсталацията.
:::
За да конфигурирате ufw, следвайте тези стъпки:

<Tabs>

<TabItem label="Активиране">

```bash
sudo ufw enable
```

</TabItem>

<TabItem label="Деактивиране">

```bash
sudo ufw disable
```

</TabItem>

<TabItem label="Разрешаване">

По подразбиране ufw блокира входящия и разрешава изходящия трафик; можете да добавяте конкретни правила към защитната стена, за да блокирате или разрешавате определени връзки.

```bash
# Пример 1 — разрешаване на ssh трафик:
sudo ufw allow ssh
# Пример 2 — отваряне на порт 12345 за TCP и UDP трафик:
sudo ufw allow 12345

# Текстът или номерът на порта може да се променя според нуждите, напр. 12345/udp за разрешаване само на UDP трафик или замяна на ssh с име на програма
```

</TabItem>

<TabItem label="Забраняване">

По подразбиране ufw блокира входящия и разрешава изходящия трафик; можете да добавяте конкретни правила към защитната стена, за да блокирате или разрешавате определени връзки.

```bash
# Пример 1 — забраняване на ssh трафик:
sudo ufw deny ssh
# Пример 2 — затваряне на порт 12345 за TCP и UDP трафик:
sudo ufw deny 12345

# Текстът или номерът на порта може да се променя според нуждите, напр. 12345/udp за забраняване само на UDP трафик или замяна на ssh с име на програма
```

</TabItem>

<TabItem label="Състояние">

```bash
sudo ufw status verbose
```
:::tip
Ако не искате да забравите защо сте отворили/затворили даден порт, добавете коментар към правилото.
```bash
# Пример 1 — отваряне на порт 12345 за TCP и UDP трафик с коментар:
sudo ufw allow 12345 comment 'Example'
# Пример 2 — затваряне на порт 6789 за TCP с коментар:
sudo ufw deny 6789/tcp comment 'Comments can have spaces'
```
:::
</TabItem>

</Tabs>

:::note
Бъдете внимателни при настройването на правила за защитната стена, тъй като неправилно конфигурираните правила могат да ви заключат извън собствената ви система.
:::

:::note
Можете да я конфигурирате и графично от секцията „Защитна стена“ („Firewall“) в настройките на KDE Plasma.
:::

:::note
Промените при разрешаване/забраняване влизат в сила след рестартиране на ufw. Деактивирайте и след това активирайте ufw отново за незабавен резултат.
:::

### Активиране на глобалното меню
При някои приложения, като например Visual Studio Code, глобалното меню може да не работи или да остава закачено към самото приложение вместо към панела.

```sh
# За да активирате поддръжката на глобално меню, изпълнете командата и рестартирайте приложението.
sudo pacman -S appmenu-gtk-module libdbusmenu-glib
```

## Допълнителни настройки

### Промяна на обвивката (shell) по подразбиране

В момента CachyOS използва [fish](https://fishshell.com/) като обвивка (shell) по подразбиране за потребителя. Въпреки това можете да я промените на всяка друга по ваш избор.

<Tabs>
   <TabItem label='bash'>

      Това е обвивката по подразбиране в почти всяка Linux дистрибуция. Тя все още се използва и като входна обвивка за потребителя root. bash разполага с основно автоматично довършване и лесно управление на историята. Различава се от zsh и fish по това, че не разполага с богатата екосистема от плъгини и персонализации, които предлагат fish и zsh.


      ```sh title='Промяна на обвивката по подразбиране на bash'
      chsh -s /usr/bin/bash
      ```

   </TabItem>

   <TabItem label='zsh'>

      Предоставяме [конфигурация за zsh](https://github.com/CachyOS/cachyos-zsh-config) с често използвани плъгини и настройки.
      Тя цели функционалност 1:1 с нашата [конфигурация за fish](https://github.com/CachyOS/cachyos-fish-config).
      Това е и обвивката по подразбиране в macOS.

      ```sh title='Промяна на обвивката по подразбиране на zsh'
      chsh -s /usr/bin/zsh
      ```

   </TabItem>
</Tabs>

### Актуализиране/използване на [tldr](https://github.com/tldr-pages/tldr)

:::note
CachyOS използва [tealdeer](https://github.com/tealdeer-rs/tealdeer), което е по-бърза реализация на оригиналния tldr, написана на Rust.
:::

Този инструмент е изключително полезен за хората, които не искат да четат много или да губят време в преглеждане на дълги страници с помощна информация (`man`).

<Steps>

1. ```sh title="Отворете терминал и изпълнете следната команда"
   tldr --update
   ```

   tldr java

### Управление на AppImage приложения

AppImage са преносими приложения, които работят в повечето Linux дистрибуции, без да изискват инсталация или root права.

:::note[Всички AppImage файлове изискват права за изпълнение, за да се стартират.]
Можете да зададете права за изпълнение чрез следната команда:
```sh
chmod +x /path/to/your/appimage
```
Или щракнете с десния бутон върху AppImage файла, отидете в `Properties` > `Permissions` и поставете отметка на `Allow executing file as program` („Разреши изпълнението на файла като програма“).
:::

:::note[Преди да стартирате AppImage файлове, уверете се, че на системата ви е инсталиран FUSE (Filesystem in Userspace).]
```sh
sudo pacman -S fuse2
```
:::

За да управлявате AppImage файлове, можете да използвате [gearlever](https://github.com/mijorus/gearlever), който предлага лесен начин за интегриране на AppImage приложения във вашата система.

`gearlever` е графичен инструмент, който опростява управлението на AppImage файловете на системата ви. Той се интегрира с вашата графична среда, правейки стартирането и управлението им лесно.

За да инсталирате gearlever, следвайте тези стъпки:

<Steps>
    1. Инсталирайте flatpak, ако все още не сте го направили:
        ```sh
        sudo pacman -S flatpak
        ```
    2. Рестартирайте системата си.
    3. Инсталирайте gearlever чрез flatpak:
        ```sh
        flatpak install flathub it.mijorus.gearlever
        ```
    4. След инсталацията излезте от сесията си и влезте отново, за да видите gearlever в менюто с приложения.
</Steps>

### Настройка на достъпа до споделени ресурси на Samba

Samba е свободна софтуерна реализация на мрежовия протокол SMB. За да се свържете с вашия Samba сървър, за потребителите на CachyOS е предоставена удобна конфигурация, но тя изисква промяна в настройките на вашия Samba сървър.

#### Инсталиране и използване на файла smb.conf на CachyOS

За да използвате удобния файл `smb.conf`, първо инсталирайте конкретния пакет, който го предоставя. След това заменете съществуващия `smb.conf` на вашия сървър с този файл и преконфигурирайте споделените си дялове/директории.

:::note[Това ръководство предполага, че вече имате работещ Samba сървър.]
:::

<Steps>
    1. Направете резервно копие на оригиналния файл `smb.conf`, който обикновено се намира в `/etc/samba/smb.conf` при Linux системите.
    2. Инсталирайте пакета с настройки за Samba на CachyOS на клиентската машина:
        ```sh
        sudo pacman -S cachyos-samba-settings
        ```
    3. Копирайте файла `smb.conf` от клиентската машина на Samba сървъра.
    4. Отворете и редактирайте файла, за да добавите споделените си директории, принтери и др.
    5. Рестартирайте услугата Samba на вашия сървър:
        ```sh
        sudo systemctl restart --now samba
        ```
    6. На клиентската машина достъпете споделените ресурси чрез файловия мениджър (напр. `smb://<your_server_ip>/<share_name>`).

        Ако всичко е настроено правилно, ще бъдете подканени да въведете данни за вход. Не забравяйте да изберете опцията за запазване на данните за вход, ако желаете.
</Steps>

### Поддръжка на AppArmor с профили AppArmor.d

Цитат от Уикипедия:

*AppArmor („Application Armor“) е модул за сигурност на Linux ядрото, който позволява на системния администратор да ограничава възможностите на програмите чрез индивидуални профили. Профилите могат да разрешават възможности като достъп до мрежата, директен достъп до сокети и права за четене, запис или изпълнение на файлове по определени пътища.*

Това е само въведение как да инсталирате базова конфигурация на AppArmor. Ако не сте запознати с AppArmor, моля, не продължавайте, без да разбирате последиците.

За по-подробна информация относно AppArmor.d и как да създавате свои собствени профили, вижте [документацията на AppArmor.d](https://github.com/roddhjav/apparmor.d?tab=readme-ov-file#configuration).

:::caution[Действайте внимателно. Неправилно конфигуриран AppArmor може да доведе до проблеми.]
:::

<Steps>

1. Добавете следните параметри на ядрото към вашия мениджър за зареждане; вижте [Конфигурация на мениджъра за зареждане](/bg/configuration/boot_manager_configuration) за справка:

   ```text
   lsm=landlock,lockdown,yama,integrity,apparmor,bpf
   ```

2. Инсталирайте пакетите apparmor и apparmor.d **(набор от над 1500 профила)**:
   ```bash
   sudo pacman -S apparmor apparmor.d
   ```

3. Активирайте и стартирайте услугата AppArmor:

   ```bash
   systemctl enable --now apparmor.service
   ```

4. Активирайте кеширането за профилите на AppArmor:

   ```shell
   # /etc/apparmor/parser.conf
   ## Добавете следните редове:
   write-cache
   Optimize=compress-fast
   cache-loc /etc/apparmor/earlypolicy/
   ```
   Запазете файла и рестартирайте.
</Steps>

### Активиране на TRIM на криптирани (LUKS) устройства

CachyOS активира `fstrim.timer` по подразбиране, за да извършва периодично TRIM на SSD и NVMe дисковете, което помага за поддържане на скоростта на запис и дълготрайността на диска. Въпреки това слоят за криптиране на блокови устройства в Linux (`dm-crypt`/LUKS) блокира командите discard (TRIM) по подразбиране. В резултат на това периодичният TRIM се изпълнява безшумно, без да обработва криптираните дялове, освен ако пропускането на discard (discard passthrough) не бъде изрично активирано.

:::caution[Съображения за сигурност и поверителност]
Активирането на TRIM върху криптирано устройство позволява на контролера на SSD да разбере кои сектори са празни и кои съдържат данни. Въпреки че данните ви остават напълно криптирани, нападател с физически достъп до носителя би могъл да прецени приблизително заетото пространство, структурата на файловата система или моделите на разположение на данните.

Ако това изтичане на метаданни е приемливо за вашия модел на сигурност, можете спокойно да активирате discard passthrough за по-добра производителност и здраве на SSD диска.
:::

#### Активиране на Discard Passthrough (LUKS2)

<Steps>
1. Определете активното име на вашето LUKS съпоставяне (mapper name):

   ```bash
   lsblk
   ```

   Потърсете записа от тип `crypt` под съответния дисков дял (напр. `luks-1e647929-62c0-4922-8944-f941ed4155fd`).

2. Активирайте постоянното пропускане на discard за активното LUKS съпоставяне:

   ```bash
   sudo cryptsetup --allow-discards --persistent refresh <mapper_name>
   ```

   :::note
   Заменете `<mapper_name>` с действителното име на съпоставянето, намерено в стъпка 1 (например `sudo cryptsetup --allow-discards --persistent refresh luks-1e647929-62c0-4922-8944-f941ed4155fd`).
   :::

3. Рестартирайте системата си, за да приложите промените.

4. Проверете дали discard passthrough е активен:

   ```bash
   lsblk -D
   sudo fstrim -v /
   ```

   `lsblk -D` вече трябва да показва ненулеви стойности под `DISC-GRAN` и `DISC-MAX` за вашия криптиран том, а `fstrim` ще изведе количеството освободено пространство, вместо да пропусне устройството.
</Steps>
