## Installation

### Pourquoi KDE Plasma est-il la seule option disponible dans l'environnement live ?

KDE Plasma peut être considéré comme notre environnement de bureau « phare », c'est pourquoi il bénéficie de la plus grande partie de notre maintenance. Les autres ISO CachyOS
étaient maintenues de manière peu rigoureuse, donc pour éviter tout problème indésirable et tout désagrément pour l'utilisateur, nous avons décidé de les abandonner afin de
concentrer nos efforts sur la meilleure expérience utilisateur possible.

Nous recommandons d'installer CachyOS dans une machine virtuelle pour tester différents environnements de bureau et gestionnaires de fenêtres, car l'ISO live n'est utilisée que
pour l'installation et la récupération d'une installation défectueuse via [cachy-chroot](https://github.com/CachyOS/cachy-chroot).

### Quand j'appuie sur « Lancer l'installateur », rien ne semble se passer… ?

:::caution
Assurez-vous d'avoir une connexion internet active, sinon rien ne se passera après avoir cliqué sur ce bouton.
:::

Même si l'on pourrait croire que rien ne s'est passé, un script est déclenché en arrière-plan après avoir appuyé sur le bouton. Ce script prépare l'installation et vise à éviter d'éventuels problèmes, comme un trousseau de clés obsolète.

Voici une version courte de ce que [le script](https://github.com/CachyOS/CachyOS-Live-ISO/blob/master/archiso/airootfs/usr/local/bin/calamares-online.sh) fait en arrière-plan :

<Steps>

1.  Supprime le fichier de trousseau existant dans `/etc/pacman.d/gnupg`.
2.  Commence l'installation et la mise à jour des paquets de trousseaux `Arch Linux & CachyOS`.
3.  Initialise et remplit le trousseau de pacman.
4.  Active la synchronisation de l'heure réseau pour s'assurer que l'horloge système est précise en exécutant `timedatectl set-ntp true`.
5.  Détermine et vérifie si le type de système est **UEFI ou BIOS/MBR**.
6.  Si le système en cours d'exécution est **UEFI** > invite l'utilisateur à sélectionner un chargeur de démarrage, sinon ne le fait pas.

</Steps>

**C'est pourquoi le chargement de l'installateur prend généralement un peu de temps.**

## Gestion des logiciels

### Gestionnaires de paquets graphiques

:::caution[Avertissement concernant les gestionnaires de paquets graphiques]
Bien que les gestionnaires de paquets graphiques soient pratiques, certains sont connus pour causer de graves problèmes sur les systèmes en publication continue comme CachyOS et devraient être évités pour la gestion des paquets système.

-   **Pamac :** est connu pour mal gérer certaines tâches de gestion de paquets, comme la corruption des trousseaux de clés des paquets système. Cela peut entraîner des erreurs de signature PGP qui vous empêchent de mettre à jour votre système.

-   **Discover (KDE) & GNOME Software :** Ces boutiques d'applications utilisent le backend PackageKit. Bien qu'elles soient généralement sûres pour gérer les Flatpaks, les utiliser pour installer ou mettre à jour les **paquets système** est risqué. Les gestionnaires basés sur PackageKit peuvent également être instables ou sujets aux plantages, ce qui pourrait laisser votre système dans un état défectueux après une transaction échouée.

Pour une stabilité et une fiabilité maximales, nous **recommandons vivement** de gérer les paquets système via la ligne de commande avec **pacman**.

Si vous préférez une interface graphique, des interfaces comme **[Octopi](</fr/configuration/post_install_setup/#mise-à-jour-du-système>)** ou le **CachyOS Package Installer** sont considérées comme des alternatives sûres, car elles sont des surcouches plus directes des fonctionnalités de `pacman`.
:::

### File is corrupted (invalid or corrupted package (PGP signature)) (Le fichier est corrompu (paquet invalide ou corrompu (signature PGP)))

```text
# Exemple :
:: File /var/cache/pacman/pkg/python-charset-normalizer-3.4.0-1-any.pkg.tar.zst
is corrupted (invalid or corrupted package (PGP signature)).
```

```sh title='Exécutez les commandes suivantes'
sudo rm -rf /etc/pacman.d/gnupg/
sudo pacman-key --init
sudo pacman-key --populate

sudo pacman-key --recv-keys F3B607488DB35A47 --keyserver keyserver.ubuntu.com
sudo pacman-key --lsign-key F3B607488DB35A47

sudo rm -R /var/lib/pacman/sync
```

### Problèmes de miroirs

#### Téléchargements de paquets lents ou erreurs de connexion

```text
# Exemples d'erreurs :
error: failed retrieving file '...' from ... : Connection timed out
error: failed retrieving file '...' from ... : Couldn't resolve host name
error: failed retrieving file '...' from ... : The requested URL returned error: 526
```

Ces erreurs indiquent généralement des problèmes avec vos miroirs actuels - ils peuvent être lents, inaccessibles ou rencontrer des problèmes temporaires.

```sh title='Exécutez la commande suivante pour obtenir des miroirs plus rapides et plus fiables :'
sudo cachyos-rate-mirrors
# Ensuite, vous pouvez mettre à jour votre système avec :
sudo pacman -Syu
```

:::tip
La commande `cachyos-rate-mirrors` teste les miroirs CachyOS disponibles en fonction de leur vitesse et de leur état de synchronisation, puis met à jour votre fichier de liste de miroirs (`/etc/pacman.d/cachyos-mirrorlist`) avec les plus performants.

Pensez à l'exécuter périodiquement, surtout si vous remarquez des ralentissements lors des mises à jour du système.
:::

### Que signifie -bin à la fin du nom d'un paquet ? Par exemple librewolf-bin

Cela signifie que vous téléchargez/installez un paquet précompilé, vous n'avez donc pas besoin de le compiler ou de le construire vous-même.
Dans nos dépôts, nous stockons certains paquets bin qui sont essentiellement des miroirs que vous pouvez télécharger depuis l'AUR.

### error: could not remove /var/cache/pacman/pkg/download (erreur : impossible de supprimer /var/cache/pacman/pkg/download)

:::tip
Vous pouvez également nettoyer le cache de pacman en utilisant CachyOS Hello dans **Apps/Tweaks** > **Clear package cache**
:::

#### Exemple :

<br />
<ImageComponent imgsrc={import('~/assets/images/pacman-cache-error.png')} />

*Cela apparaît généralement lorsqu'il reste des paquets orphelins dans `/var/cache/pacman/pkg` que pacman ne peut pas supprimer.*

```sh title='Exécutez la commande suivante pour corriger le problème'
# Supprime tous les paquets orphelins stockés dans le cache pkg.
sudo rm -r /var/cache/pacman/pkg/*
```

### ERROR: module not found: 'nvidia', 'nvidia_modeset', 'nvidia_uvm', 'nvidia_drm' (ERREUR : module non trouvé)

```sh title='Exemple'
== >ERROR: module not found: 'nvidia'
== >ERROR: module not found: 'nvidia_modeset'
== >ERROR: module not found: 'nvidia_uvm'
== >ERROR: module not found: 'nvidia_drm'
```

**Deux raisons pour cette erreur :**

**1) Comme le chargement anticipé des modules est toujours activé dans cachy-chroot, mkinitcpio s'attend systématiquement à la présence des modules NVIDIA ; cette erreur survient lorsque ces modules sont absents.**

**2) Il se peut qu'il vous manque les modules NVIDIA pour d'autres noyaux installés sur votre système.**

```sh title='Installez le paquet suivant pour corriger cette erreur'
sudo pacman -S nvidia
```
