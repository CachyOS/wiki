Pour fournir une distribution optimisée pour la performance, CachyOS recompile les paquets Arch Linux spécifiquement pour les architectures `x86-64-v3`, `x86-64-v4` et `Zen4+`.

- **x86-64-v3 :** amélioration des performances de 5 % à 20 % par rapport à x86-64.
- **x86-64-v4 :** offre des gains de performance substantiels grâce au support AVX512, selon la charge de travail.
- **Zen 4/5 :** en plus du jeu d’instructions x86-64-v4, les instructions suivantes sont ajoutées :

```text
abm, adx, aes, avx512bf16, avx512bitalg, avx512ifma, avx512vbmi, avx512vbmi2, avx512vnni,
avx512vpopctndq, clflushopt, clwb, clzero, fsgsbase, gfni, mwaitx, pclmul, pku, prfchw,
rpdid, rdrnd, rdseed, sha, sse4a, vaes, vockmulqdq, wbnoinvd, savec, xsaveopt, xsaves
```

Pour en savoir plus sur ces architectures, [consultez cet article Wikipedia](https://fr.wikipedia.org/wiki/X86-64#Niveaux_de_microarchitecture).

## Paquets Personnalisés

Notre dépôt [CachyOS-PKGBUILDs](https://github.com/CachyOS/CachyOS-PKGBUILDS) contient des paquets recevant des mises à jour, correctifs et correctifs rétroportés en continu.  
Pour améliorer les performances, nous implémentons sélectivement PGO, LTO et BOLT selon les besoins.

## Migration de x86-64-v3 vers x86-64-v4 ou znver4

Si vous utilisez actuellement les dépôts x86-64-v3 et que votre nouveau CPU supporte x86-64-v4 (ou AMD Zen 4/5), vous pouvez migrer en suivant ces étapes :

### Vérification de la compatibilité CPU

:::caution
Les CPU Intel de 12ᵉ génération (Alder Lake) et plus récents peuvent indiquer un support `x86-64-v4`, mais en pratique ils **ne peuvent pas exécuter les instructions AVX-512**.

Pourquoi ?
- **Conflit d’architecture hybride** : les “P-cores” supportent AVX-512, mais pas les “E-cores”. Exécuter AVX-512 avec des E-cores actifs provoquerait des instabilités.
- **Solution Intel** : Pour éviter ce décalage, Intel a désactivé AVX-512 de deux manières :
  - **Mises à jour microcode/BIOS** (premiers Alder Lake) : AVX-512 pouvait être réactivé en évitant ou en annulant les mises à jour microcode.
  - **Fusible matériel** (chips 2022+) : AVX-512 est désactivé définitivement à l’usine.

Comme `x86-64-v4` requiert AVX-512, ces CPU doivent être traités comme **x86-64-v3 uniquement**.
:::

- Vérification du support `x86-64-v4` :
  ```sh title='Exécutez la commande suivante :'
  /lib/ld-linux-x86-64.so.2 --help | grep supported
  ```
- ✅ x86-64-v4 (supported, searched) → CPU supporte v4

- ❌ Pas de ligne x86-64-v4 → CPU ne supporte pas v4

Exemple (CPU supporte v4) :
  ```sh
  $ /lib/ld-linux-x86-64.so.2 --help | grep supported
    x86-64-v2 (supported, searched)
    x86-64-v3 (supported, searched)
    x86-64-v4 (supported, searched)
  ```

- Pour les CPU AMD Zen 4/5, vérifiez si votre CPU indique znver4 ou znver5 :
  ```sh
  gcc -march=native -Q --help=target 2>&1 | grep -Po "^\s+-march=\s+\K(\w+)\$"
  ```
  Si la sortie est znver4 ou znver5, vous pouvez continuer la migration.

:::note
x86-64-v4 et znver4 utilisent la même mirrorlist `/etc/pacman.d/cachyos-v4-mirrorlist`.
:::

:::note[Si vous devez revenir à un dépôt ou annuler le changement, ce guide vous sera utile.]
Exemple : de znver4 à v4.
:::

### Étapes de Migration

<Steps>
1. Modifiez `/etc/pacman.conf` et remplacez vos dépôts `x86-64-v3` par l’un des suivants selon le support CPU :
    <Tabs>
        <TabItem label="x86-64-v4">
            ```ini title='/etc/pacman.conf'
            [cachyos-v4]
            Include = /etc/pacman.d/cachyos-v4-mirrorlist

            [cachyos-core-v4]
            Include = /etc/pacman.d/cachyos-v4-mirrorlist

            [cachyos-extra-v4]
            Include = /etc/pacman.d/cachyos-v4-mirrorlist
            ```
        </TabItem>

        <TabItem label="znver4 (AMD Zen 4/5 only)">
          ```ini title='/etc/pacman.conf'
          [cachyos-znver4]
          Include = /etc/pacman.d/cachyos-v4-mirrorlist

          [cachyos-core-znver4]
          Include = /etc/pacman.d/cachyos-v4-mirrorlist

          [cachyos-extra-znver4]
          Include = /etc/pacman.d/cachyos-v4-mirrorlist
        ```
        </TabItem>
        Keep `[cachyos]`, `[core]`, `[extra]`, and `[multilib]` unchanged.
        </Tabs>
2. Videz le cache des paquets et synchronisez les bases de données :

   ```sh
   sudo pacman -Scc   # Confirm with 'y' twice
   sudo pacman -Sy
   ```

3. Réinstallez tous les paquets pour passer à la nouvelle architecture :

   ```sh
   pacman -Qqn | sudo pacman -S -
   ```

4. Redémarrez votre système.
</Steps>

## Ajouter Nos Dépôts à une Installation Arch Linux Existante

:::caution
Installer le Pacman de CachyOS installera une version forkée de pacman avec des fonctionnalités ajoutées par CachyOS, comme "INSTALLED_FROM" et une vérification automatique de l’architecture. Pacman 6.1 a ajouté une fonctionnalité de validation qui pourrait générer des avertissements si vous utilisez le pacman d’Arch Linux. Nous travaillons avec Arch Linux pour rétablir une compatibilité correcte.  
Si vous souhaitez éviter cela, **n’ajoutez pas le dépôt "cachyos"**, qui contient le pacman personnalisé. Tous les autres dépôts comme cachyos-v3, cachyos-v4, cachyos-extra/core-v3/4 sont sûrs à ajouter.
:::

:::tip
Avant de considérer l’ajout de nos dépôts, veuillez consulter la **[liste de compatibilité CPU](/installation/installation_prepare#x86_64-microarchitecture-level-support)**.
:::

<Tabs>

<TabItem label='Automatisé'>

Nous fournissons un script qui automatise l’ajout de nos dépôts sur vos installations basées sur Arch existantes.

```sh
curl https://mirror.cachyos.org/cachyos-repo.tar.xz -o cachyos-repo.tar.xz
tar xvf cachyos-repo.tar.xz && cd cachyos-repo
sudo ./cachyos-repo.sh
```

:::tip[Comment fonctionne le script]
Ce script détecte les jeux d’instructions supportés par votre CPU et installe la version de nos dépôts la plus optimisée pour celui-ci.  
Il sauvegarde également votre ancien `pacman.conf` pour pouvoir retirer les dépôts via le script.
:::

</TabItem>

<TabItem label='Manuel'>

<Steps>

1. Installez le trousseau de clés CachyOS :

   ```sh
   # Importer la clé du dépôt
   sudo pacman-key --recv-keys F3B607488DB35A47 --keyserver keyserver.ubuntu.com
   # Signer la clé du dépôt
   sudo pacman-key --lsign-key F3B607488DB35A47
   ```

2. Installez les paquets nécessaires :

   ```sh
   sudo pacman -U 'https://mirror.cachyos.org/repo/x86_64/cachyos/cachyos-keyring-20240331-1-any.pkg.tar.zst' \
   'https://mirror.cachyos.org/repo/x86_64/cachyos/cachyos-mirrorlist-22-1-any.pkg.tar.zst' \
   'https://mirror.cachyos.org/repo/x86_64/cachyos/cachyos-v3-mirrorlist-22-1-any.pkg.tar.zst' \
   'https://mirror.cachyos.org/repo/x86_64/cachyos/cachyos-v4-mirrorlist-22-1-any.pkg.tar.zst' \
   'https://mirror.cachyos.org/repo/x86_64/cachyos/pacman-7.0.0.r7.g1f38429-2-x86_64.pkg.tar.zst'
   ```

3. Ajoutez les dépôts CachyOS au fichier de configuration pacman :  

   :::note
   Ces dépôts doivent être placés **au-dessus des dépôts Arch Linux**.
   :::

   ```ini
   # /etc/pacman.conf
   # Si votre CPU ne supporte que x86-64, ajoutez seulement les dépôts [cachyos]
   [cachyos]
   Include = /etc/pacman.d/cachyos-mirrorlist

   # Si votre CPU supporte x86-64-v3, ajoutez [cachyos-v3], [cachyos-core-v3], [cachyos-extra-v3] et [cachyos]

   [cachyos-v3]
   Include = /etc/pacman.d/cachyos-v3-mirrorlist
   [cachyos-core-v3]
   Include = /etc/pacman.d/cachyos-v3-mirrorlist
   [cachyos-extra-v3]
   Include = /etc/pacman.d/cachyos-v3-mirrorlist
   [cachyos]
   Include = /etc/pacman.d/cachyos-mirrorlist

   # Si votre CPU supporte x86-64-v4, ajoutez [cachyos-v4], [cachyos-core-v4], [cachyos-extra-v4] et [cachyos]

   [cachyos-v4]
   Include = /etc/pacman.d/cachyos-v4-mirrorlist
   [cachyos-core-v4]
   Include = /etc/pacman.d/cachyos-v4-mirrorlist
   [cachyos-extra-v4]
   Include = /etc/pacman.d/cachyos-v4-mirrorlist
   [cachyos]
   Include = /etc/pacman.d/cachyos-mirrorlist

   # Si votre CPU est basé sur Zen 4 ou Zen 5, ajoutez [cachyos-znver4], [cachyos-core-znver4], [cachyos-extra-znver4] et [cachyos]

   [cachyos-znver4]
   Include = /etc/pacman.d/cachyos-v4-mirrorlist
   [cachyos-core-znver4]
   Include = /etc/pacman.d/cachyos-v4-mirrorlist
   [cachyos-extra-znver4]
   Include = /etc/pacman.d/cachyos-v4-mirrorlist
   [cachyos]
   Include = /etc/pacman.d/cachyos-mirrorlist
   ```

   :::tip
   Pour passer des dépôts `v4` aux dépôts `znver4` :

   Ajoutez les entrées correspondantes et exécutez :
   ```sh
   sudo pacman -Scc # Tapez Y deux fois
   sudo pacman -Sy
   pacman -Qqn | sudo pacman -S - # Remplace tous les paquets v4 par les paquets znver4
   # Redémarrez votre système
   ```
   :::
   
4. Enfin, mettez à jour votre système avec les paquets CachyOS :
   ```sh
   sudo pacman -Syu
   ```

</Steps>

</TabItem>

</Tabs>

### Désinstaller les Dépôts CachyOS

<Tabs>
<TabItem label='Automatisé'>

**Exécutez les commandes suivantes pour retirer les dépôts CachyOS de votre système :**
```sh
curl https://mirror.cachyos.org/cachyos-repo.tar.xz -o cachyos-repo.tar.xz
tar xvf cachyos-repo.tar.xz
cd cachyos-repo
sudo ./cachyos-repo.sh --remove
```

</TabItem>

<TabItem label='Manuel'>

<Steps>

1. Réinstallez le pacman original d’Arch Linux :
   ```sh
   sudo pacman -S core/pacman
   ```

2. Exécutez la commande suivante pour éviter les avertissements `%INSTALLED_DB%` :
   ```sh
   sudo find /var/lib/pacman/local/ -type f -name "desc" -exec sed -i '/^%INSTALLED_DB%$/,+2d' {} \;
   ```

3. Restaurez le fichier de configuration pacman depuis la sauvegarde :
   ```sh
   sudo mv /etc/pacman.conf.bak /etc/pacman.conf
   ```

4. Revenez aux paquets Arch Linux par défaut :
   ```sh
   pacman -Qqn | sudo pacman -S -
   sudo pacman -Syu
   ```

</Steps>

</TabItem>

## Tests et benchmarks

Michael de Phoronix a déjà évalué CachyOS à plusieurs reprises, montrant généralement des résultats de pointe dans les graphiques de benchmarks et sur la moyenne géométrique de tous les tests.  
Depuis le premier benchmark réalisé en 2022, CachyOS a beaucoup évolué et s’est considérablement amélioré en termes d’ergonomie et de performance.

Si vous souhaitez en savoir plus sur les gains de performance apportés par nos dépôts, consultez les liens ci-dessous :

* **14/03/2021 :** Une discussion RFC sur l’impact de x86-64-v3 lancée par **Mateusz Jończyk** de Arch Linux montrait quelques résultats initiaux.
  * [RFC : Use x86_64-v2 architecture](https://lists.archlinux.org/pipermail/arch-general/2021-March/048739.html)

* **09/12/2022 :** Premier benchmark réalisé par Michael.
  * [The Performance Of Arch Linux Powered CachyOS](https://www.phoronix.com/review/cachyos-linux-perf)

* **29/02/2024 :** Phoronix a effectué un autre benchmark comparant x86-64-v4, x86-64-v3 et x86-64 (générique). Pour des exemples comme PHP ou GCC, où nous personnalisons nos PKGBUILDs, une amélioration notable des performances est observée.
  * [Benchmarks Arch Linux CachyOS des dépôts x86-64-v3 & x86-64-v4](https://www.phoronix.com/review/cachyos-x86-64-v3-v4)

* **20/08/2024 :** Michael a publié un nouveau benchmark pour le AMD Ryzen 9950X incluant CachyOS et d’autres distributions Linux.
  * [Intel Continue de Montrer à AMD l’Importance des Optimisations Logiciels : +16% de Performance sur Ryzen 9 9950X](https://www.phoronix.com/review/linux-os-amd-ryzen9-9950x)

:::note
Liquid-DSP et RocksDB ont été compilés en utilisant le Phoronix Benchmark Suite, ignorant les flags de compilation spécifiés dans /etc/makepkg.conf, ce qui a donné des résultats de performance inattendus pour CachyOS.
:::
