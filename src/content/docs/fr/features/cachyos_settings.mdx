En plus de nos noyaux et dépôts optimisés, nous fournissons également des paramètres qui améliorent davantage l'expérience de bureau, ainsi que quelques
scripts d'aide pour des améliorations de la qualité de vie. Toutes ces configurations et scripts se trouvent dans le paquet `cachyos-settings`.

Consultez le [dépôt CachyOS Settings](https://github.com/CachyOS/CachyOS-Settings?tab=readme-ov-file#cachyos-settings) pour en savoir plus sur toutes les configurations et tous les scripts que nous fournissons.

## Scripts et outils

### DLSS Swapper

Peut s'avérer utile dans certains cas, en particulier pour la version de Proton fournie par Valve.

:::note
Proton-CachyOS fournit déjà une fonctionnalité de mise à niveau intégrée.
:::

:::caution
Ne combinez pas `PROTON_DLSS_UPGRADE=1` et `dlss-swapper` en même temps, car ils font tous les deux la même chose et peuvent provoquer des conflits.
:::

Ce script tente de mettre à jour les DLL et les préréglages DLSS vers la dernière version disponible, ce qui peut être utile pour certains jeux nécessitant une version spécifique de DLSS pour fonctionner correctement.

Comment ? En injectant des variables d'environnement dans le processus du jeu :

<details>
    <summary>Variables d'environnement de dlss-swapper</summary>
    ```sh
    export PROTON_ENABLE_NGX_UPDATER=1
    export DXVK_NVAPI_DRS_NGX_DLSS_RR_OVERRIDE=on
    export DXVK_NVAPI_DRS_NGX_DLSS_SR_OVERRIDE=on
    export DXVK_NVAPI_DRS_NGX_DLSS_FG_OVERRIDE=on
    export DXVK_NVAPI_DRS_NGX_DLSS_RR_OVERRIDE_RENDER_PRESET_SELECTION=render_preset_latest
    export DXVK_NVAPI_DRS_NGX_DLSS_SR_OVERRIDE_RENDER_PRESET_SELECTION=render_preset_latest
    ```
</details>
<details>
    <summary>Variables d'environnement de dlss-swapper-dll</summary>
    ```sh
    export DXVK_NVAPI_DRS_NGX_DLSS_RR_OVERRIDE=on
    export DXVK_NVAPI_DRS_NGX_DLSS_SR_OVERRIDE=on
    export DXVK_NVAPI_DRS_NGX_DLSS_FG_OVERRIDE=on
    export DXVK_NVAPI_DRS_NGX_DLSS_RR_OVERRIDE_RENDER_PRESET_SELECTION=render_preset_latest
    export DXVK_NVAPI_DRS_NGX_DLSS_SR_OVERRIDE_RENDER_PRESET_SELECTION=render_preset_latest
    ```
</details>

- Quelle est la différence entre `dlss-swapper` et `dlss-swapper-dll` ?
    - `dlss-swapper` met à jour les DLL et les préréglages DLSS vers les dernières versions disponibles fournies par NGX Updater, tandis que `dlss-swapper-dll` s'appuie sur les DLL déjà présentes dans le répertoire du jeu.


### [game-performance](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/bin/game-performance)

Petit script qui active le profil de performance via `powerprofilesctl` pour le processus cible (utilisable pour les jeux ou tout autre processus) et désactive l'économiseur d'écran pendant l'exécution du processus.

Questions fréquentes :

<details>
    <summary>Comment l'utiliser</summary>
    Supposons que vous souhaitiez utiliser `game-performance` pour un jeu Steam. Vous pouvez le faire en ajoutant la commande `game-performance` comme option de lancement pour le jeu dans Steam :
        <Steps>
            1. Ouvrez Steam et allez dans votre Bibliothèque.
            2. Faites un clic droit sur le jeu avec lequel vous souhaitez utiliser `game-performance` et sélectionnez « Propriétés ».
            3. Dans l'onglet « Général », trouvez la section « Options de lancement » et ajoutez la commande suivante :
                ```sh
                game-performance %command%
                ```
                :::tip[Guide sur la gestion des options de lancement dans Steam]
                Wiki CachyOS - [Comment configurer correctement plusieurs options de lancement](/fr/configuration/gaming#comment-configurer-correctement-plusieurs-options-de-lancement)
                :::
            4. Fermez la fenêtre des propriétés et lancez le jeu.
        </Steps>
        <details>
            <summary>Utilisation en dehors de Steam</summary>
            Puisque `game-performance` n'est qu'un script wrapper, vous pouvez l'utiliser pour lancer n'importe quel processus avec le profil de performance activé. Exécutez simplement la commande suivante dans le terminal :
            ```sh
            game-performance <command>
            ```
        </details>
</details>

<details>
    <summary>game-performance apporte-t-il un avantage sur un ancien processeur ?</summary>
    En général, non. Vous devriez l'éviter sur les anciens processeurs car cela peut faire plus de mal que de bien.

    À titre indicatif, l'utilisation de `game-performance` sur un processeur disposant de moins de 6 cœurs / 12 threads n'améliorera probablement pas les performances et pourrait même les réduire. Comme pour la plupart des options, vous devriez tester par vous-même si cela améliore ou non les performances sur votre système spécifique.
      - Pour les processeurs de bureau Intel, la limite approximative se situe à la 8e génération (Coffee Lake) pour les i7 et i9, et à la 10e génération (Comet Lake) pour les i5. Tous les processeurs Intel Ultra devraient convenir.
      - Pour les processeurs de bureau AMD, il s'agit de la série 1000 (Zen) pour les Ryzen 7 et Ryzen 9. Pour les Ryzen 5, c'est également la série 1000, mais uniquement à partir du Ryzen 5 1600. C'est le cas jusqu'à la série 5000 (Zen 3), à partir de laquelle tous les Ryzen 5 possèdent 6 cœurs et 12 threads.
      - Les processeurs de bureau Intel i3 et Ryzen 3 n'ont jamais plus de quatre cœurs.
      - Le nombre de cœurs des processeurs mobiles, de station de travail et de serveur varie énormément ; renseignez-vous sur votre matériel et testez différents paramètres, cela fait partie du plaisir de posséder un PC !
</details>

<details>
    <summary>Pourquoi n'est-il pas activé par défaut ?</summary>
    L'activation du profil de performance peut ne pas convenir à tous les utilisateurs et peut entraîner une augmentation de la consommation d'énergie et de la chaleur dégagée. En ne l'activant pas par défaut, nous donnons aux utilisateurs le choix de l'activer lorsqu'ils en ont besoin, sans l'imposer à tout le monde.
</details>

### [paste-cachyos](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/bin/paste-cachyos)

Un outil en ligne de commande simple qui vous permet de téléverser du texte vers notre [service pastebin](https://paste.cachyos.org). Il peut être utile pour partager des journaux et d'autres contenus texte lors du signalement de bogues ou de demandes d'aide.

:::note
Pour utiliser `paste-cachyos`, vous devez rediriger (`|`) le contenu que vous souhaitez téléverser vers la commande.

Exemple :
```sh
<command> | paste-cachyos
```
:::

Voici quelques exemples d'utilisation de `paste-cachyos` :

<details>
    <summary>Partager la sortie d'une mise à jour pacman</summary>
    ```sh
    sudo pacman -Syu | paste-cachyos
    ```
    [Exemple](https://paste.cachyos.org/p/079e1cc)
</details>

<details>
    <summary>Journal journalctl de systemd-resolved</summary>
    ```sh
    journalctl -u systemd-resolved.service | paste-cachyos
    ```
</details>

### [pci-latency](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/bin/pci-latency)

Un script simple destiné à réduire la latence et à améliorer les performances des cartes son PCI en modifiant le minuteur de latence PCI.

Disponible à la fois sous forme de binaire et de service systemd. Le service systemd appliquera automatiquement les modifications au démarrage, tandis que le binaire peut être utilisé pour appliquer les modifications à la demande.

<details>
    <summary>Utilisation ponctuelle pour la session actuelle</summary>
    ```sh
    sudo pci-latency
    ```
</details>
<details>
    <summary>Activation du service systemd</summary>
    ```sh
    systemctl enable pci-latency.service
    ```
</details>
<details>
    <summary>Désactivation du service systemd</summary>
    ```sh
    systemctl disable pci-latency.service
    ```
</details>

### [sbctl-batch-sign](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/bin/sbctl-batch-sign)

:::note
Non compatible avec Limine.
:::

`sbctl-batch-sign` est un script d'aide conçu pour faciliter aux utilisateurs la signature des fichiers nécessaires au support du démarrage sécurisé.

Le cas évident où ce script est très utile est lors d'un double amorçage (dual boot) avec Windows, car de nombreux fichiers de Windows doivent être signés dans l'EFI.

Bref résumé de l'exécution du script :

- Analyse les fichiers non signés à l'aide de `sbctl verify`
    - Si nécessaire, signe les fichiers détectés à l'aide de `sbctl sign`
- Évite les fichiers appartenant à Windows, GRUB ou ayant pour extension `.mui` et `.dll`

Consultez notre section [Configuration du démarrage sécurisé](/fr/configuration/secure_boot_setup#signature-de-limage-du-noyau-et-du-gestionnaire-de-démarrage) pour plus d'informations.

## Création de surcharges

Qu'est-ce qu'une surcharge (override) ?

Une surcharge est un fichier de configuration que vous créez pour modifier les paramètres par défaut fournis par `cachyos-settings`. Cela vous permet de personnaliser votre système sans modifier les fichiers d'origine, ce qui est utile pour préserver la compatibilité avec les futures mises à jour de `cachyos-settings`.

### sysctl

Nous fournissons de nombreux ajustements sysctl qui visent à améliorer les performances globales du bureau. Chaque entrée sysctl est bien documentée
dans le fichier [70-cachyos-settings.conf](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/lib/sysctl.d/70-cachyos-settings.conf).

Pour apporter des modifications à l'une de ces valeurs, copiez l'entrée originale et créez un nouveau fichier sous `/etc/sysctl.d/` avec la valeur modifiée.

<details>
    <summary>Exemple de surcharge sysctl</summary>
    <Steps>

    1. Jetez un œil à la valeur originale de `cachyos-settings`

        ```sh
        cat /usr/lib/sysctl.d/70-cachyos-settings.conf
        # Only experimental!
        # Let Realtime tasks run as long they need
        # sched: RT throttling activated
        kernel.sched_rt_runtime_us=-1
        ```
    2. Créez un nouveau fichier dans `/etc/sysctl.d` pour apporter des modifications aux paramètres sysctl

        ```sh title="Rétablissement de kernel.sched_rt_runtime_us= à sa valeur par défaut"
        sudo micro /etc/sysctl.d/99-kernel-sched-rt.conf # Si le fichier n'existe pas, cette commande le crée et vous permet de le modifier
        kernel.sched_rt_runtime_us=950000
        ```
    3. Enregistrez le fichier en appuyant sur `CTRL + S` et quittez l'éditeur en appuyant sur `CTRL + Q`.
    4. Après avoir modifié les paramètres sysctl, assurez-vous d'appliquer les changements :
        ```sh
        sudo sysctl --system
        ```
    </Steps>
</details>

### Règles udev

Il en va de même pour les règles udev. Vous pouvez créer vos propres surcharges en créant un nouveau fichier sous `/etc/udev/rules.d/` portant le même nom que le fichier d'origine.

:::tip[Utilisez la commande suivante pour trouver les fichiers d'origine]
```sh
pacman -Ql cachyos-settings | grep udev
```
:::

<details>
    <summary>Exemple de surcharge de règle udev</summary>
    1. Vérifiez la règle udev originale de CachyOS :
        ```sh
        cat /usr/lib/udev/rules.d/60-ioschedulers.rules
        ```
        <details>
            <summary>Sortie :</summary>
                ```sh
                # HDD
                ACTION=="add|change", KERNEL=="sd[a-z]*", ATTR{queue/rotational}=="1", \
                    ATTR{queue/scheduler}="bfq"

                # SSD
                ACTION=="add|change", KERNEL=="sd[a-z]*|mmcblk[0-9]*", ATTR{queue/rotational}=="0", \
                    ATTR{queue/scheduler}="mq-deadline"

                # NVMe SSD
                ACTION=="add|change", KERNEL=="nvme[0-9]*", ATTR{queue/rotational}=="0", \
                    ATTR{queue/scheduler}="none"
                ```
        </details>
        Imaginez maintenant que vous souhaitiez remplacer le planificateur d'E/S des SSD et des NVMe par `kyber` au lieu de `mq-deadline` et `none`, respectivement. Vous pouvez le faire en créant un fichier de surcharge.
    2. Créez un nouveau fichier dans `/etc/udev/rules.d` pour remplacer la règle d'origine :
        ```sh
        sudo micro /etc/udev/rules.d/60-ioschedulers.rules # Si le fichier n'existe pas, cette commande le crée et vous permet de le modifier
        # HDD
        ACTION=="add|change", KERNEL=="sd[a-z]*", ATTR{queue/rotational}=="1", \
            ATTR{queue/scheduler}="bfq"

        # SSD
        ACTION=="add|change", KERNEL=="sd[a-z]*|mmcblk[0-9]*", ATTR{queue/rotational}=="0", \
            ATTR{queue/scheduler}="kyber"

        # NVMe SSD
        ACTION=="add|change", KERNEL=="nvme[0-9]*", ATTR{queue/rotational}=="0", \
            ATTR{queue/scheduler}="kyber"
        ```
    3. Enregistrez le fichier en appuyant sur `CTRL + S` et quittez l'éditeur en appuyant sur `CTRL + Q`.
    4. Après avoir modifié les règles udev, assurez-vous de recharger les règles et de les déclencher :

        ```sh
        sudo udevadm control --reload-rules
        sudo udevadm trigger
        ```
</details>
