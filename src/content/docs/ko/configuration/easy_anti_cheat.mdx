[Easy Anti-Cheat Linux v2](https://onlineservices.epicgames.com/news/introducing-easy-anti-cheat-linux-v2)는
시스템이 어떻게 부팅되었는지 검증할 수 있을 때만 게임 실행을 허용합니다. 이때 다음 사항을 확인합니다.

- Secure Boot가 활성화되어 있고, 커널이 Epic이 신뢰하는 키로 서명되어 있는지 여부
- 시스템에 부팅의 모든 단계를 기록(측정 부팅, measured boot)하는 TPM 2.0이 있는지 여부
- 커널이 lockdown integrity 모드로 실행되며 서명된 모듈만 로드하는지 여부
- IOMMU가 활성화되어 있고, kexec이 비활성화되어 있으며, BPF LSM이 활성화되어 있는지 여부

CachyOS는 이러한 요구 사항을 충족하는 전용 커널 `linux-cachyos-eac`과 동일한 키로 서명된 systemd-boot를 제공합니다.
기존의 자체 Secure Boot 키는 그대로 유지됩니다. 유일하게 추가되는 것은 펌웨어가 CachyOS에서 서명한 파일을
신뢰할 수 있도록 Secure Boot 데이터베이스에 추가되는 **CachyOS EAC CA** 인증서뿐입니다.

EAC 커널은 별도의 부팅 항목으로 추가됩니다. 기존 일반 부팅 항목은 변경되지 않으므로,
EAC를 사용하는 게임을 플레이하고 싶을 때만 EAC 항목으로 부팅하면 됩니다.

EAC는 로드하는 모든 대상을 Secure Boot 데이터베이스로 검증하고 TPM에 측정(measure)하는 부트 매니저를 요구합니다.
systemd-boot는 이를 수행하지만 Limine은 수행하지 않습니다. rEFInd는 이를 수행하지만 사용자 자체 키로 서명되어 있어
EAC가 허용하지 않으며, GRUB도 마찬가지입니다. 따라서 Limine, rEFInd, GRUB 사용자는 기존 부트 매니저를
기본값으로 유지하고, 자체 펌웨어 부팅 항목을 가지며 EAC 부팅에만 사용되는 CachyOS 서명된 systemd-boot를
통해 EAC 커널을 시작합니다.

[`eac-setup` 스크립트](#eac-setup으로-설정)가 이러한 설정을 자동으로 수행해 줍니다.
[수동 설정](#수동-설정)에서는 동일한 과정을 직접 수행하는 단계를 설명합니다.

## 요구 사항

- UEFI 모드에서 **systemd-boot**, **Limine** 또는 **rEFInd**를 부트 매니저로 사용하여 설치된 CachyOS.
  rEFInd의 경우 CachyOS 설치 프로그램이 구성하는 방식대로 EFI 시스템 파티션이 `/boot`에 마운트되어 있어야 합니다.
  **GRUB**은 실험적으로 지원되며, [GRUB (실험적)](#grub-실험적)을 참고하세요.
- 최신 상태로 업데이트된 시스템(`sudo pacman -Syu`). `eac-setup`은 `cachyos-settings` 1.4.4 이상이 필요하며,
  `eac-status` 및 `sbctl-batch-sign`의 EAC 지원은 1.4.2 이상이 필요합니다.
- 펌웨어 설정에서 **TPM 2.0** 활성화. 펌웨어 TPM(AMD fTPM, Intel PTT)도 사용할 수 있습니다.
- 펌웨어 설정에서 **IOMMU** 활성화(AMD의 경우 AMD-Vi / "IOMMU", Intel의 경우 VT-d).
- NVIDIA GPU: Maxwell 이상(GTX 750, GTX 900 시리즈 및 이후 제품). EAC 커널은 NVIDIA 모듈을 패키지로 제공합니다.
  Turing 이상(GTX 16 / RTX 20 시리즈 및 이후 제품)에는 `linux-cachyos-eac-nvidia-open`을,
  Maxwell, Pascal 및 Volta에는 `linux-cachyos-eac-nvidia-580xx`를 사용합니다.

:::caution[DKMS 모듈 미지원]
EAC 커널은 커널 빌드 시점에 함께 서명된 모듈만 로드합니다. NVIDIA, ZFS 및 Realtek r8125 모듈은
`linux-cachyos-eac-*` 패키지로 제공되지만, DKMS로 빌드된 다른 모듈(예: `virtualbox-host-dkms`)은
EAC 부팅 항목에서 로드되지 않습니다. `linux-cachyos-eac-headers`는 설치하지 마세요.
:::

:::danger[BitLocker 및 TPM 디스크 잠금 해제]
이 설정은 Secure Boot 키를 변경하므로 TPM이 측정하는 값도 달라집니다. 이로 인해 Windows 듀얼 부팅의
BitLocker가 복구 키를 요구하거나, 직접 TPM에 바인딩한 LUKS 디스크가 암호(passphrase)를 요구할 수 있습니다.
시작하기 전에 해당 복구 키와 암호를 반드시 확보해 두세요. 그렇지 않으면 데이터에 접근하지 못할 수 있습니다.
:::

:::danger[Steam Deck]
Steam Deck에는 펌웨어 설정에 표준 Secure Boot 토글이 없으며 현재 지원되지 않습니다. 키를 등록하면 Secure Boot를
쉽게 비활성화할 방법 없이 부팅이 불가능한 상태가 될 수 있습니다. Steam Deck에서는 이 가이드를 따르지 마세요.
:::

## eac-setup으로 설정

`cachyos-settings`에 포함된 `eac-setup`은 systemd-boot, Limine, rEFInd 및 GRUB용 설정을 자동으로 수행합니다.
이미 완료된 작업을 확인하므로 설정을 복구하는 등의 목적으로 언제든지 다시 실행할 수 있습니다.
사용자가 직접 해야 하는 작업은 펌웨어 설정 변경뿐입니다.

<Steps>

1. **펌웨어를 Setup Mode로 전환**

    [Secure Boot 설정 가이드](/ko/configuration/secure_boot_setup) 등을 통해 이미 `sbctl`로 생성한 키로
    Secure Boot를 사용 중이라면 이 단계를 건너뛰세요. 이 경우 `eac-setup`은 Secure Boot를 활성화한 상태로
    유지하면서 CachyOS EAC CA만 Secure Boot 데이터베이스에 추가합니다.

    그렇지 않다면 [UEFI에서 Setup Mode 활성화](/ko/configuration/secure_boot_setup#uefi에서-setup-mode-활성화)를
    따르고, 지금은 Secure Boot를 **비활성화** 상태로 두세요.

    ```bash
    systemctl reboot --firmware-setup
    ```

2. **eac-setup 실행**

    ```bash
    sudo eac-setup
    ```

    스크립트는 Secure Boot 키를 등록하기 전에 확인을 요청하며, pacman은 패키지를 설치하기 전에 확인을 요청합니다.
    스크립트는 다음 단계를 수행합니다.

    - TPM, IOMMU 및 사용 중인 부트 매니저를 확인합니다.
    - CachyOS EAC CA를 등록합니다. Setup Mode에서는 먼저 자체 키를 생성한 뒤 Microsoft 키와 함께 등록합니다.
    - `linux-cachyos-eac`, `systemd-boot-cachyos-signed` 및 시스템에 맞는 `linux-cachyos-eac-*` 모듈 패키지
      (NVIDIA, ZFS, r8125)를 설치합니다.
    - Secure Boot가 활성화된 상태에서도 일반 부팅이 계속 작동하도록 자체 키로 일반 커널을 서명하고,
      Limine, rEFInd 또는 GRUB도 함께 서명합니다.
    - `sbctl`이 CachyOS 서명 파일을 건드리지 않도록 제외하고, `sbctl`이 다시 서명한 경우 원래 서명을 복원합니다.
    - 실행 중인 시스템의 커널 옵션과 EAC 옵션을 조합해 EAC 부팅 항목을 생성합니다. Limine, rEFInd 및 GRUB에서는
      자체 "CachyOS EAC" 펌웨어 부팅 항목과 함께 CachyOS 서명된 systemd-boot도 설치합니다.

    펌웨어가 Setup Mode가 아니고 키가 `sbctl`로 생성되지 않은 경우, 스크립트는 중지되고 펌웨어를
    Setup Mode로 전환하도록 안내합니다. 해당 작업을 진행한 뒤 다시 실행하세요.

    EAC 항목은 시스템이 현재 부팅될 때 사용한 커널 옵션을 사용합니다. 나중에 일반 부팅 항목의 커널 옵션을
    변경한 경우에는 재부팅한 뒤 `sudo eac-setup`을 다시 실행하세요.

3. **Secure Boot 활성화**

    마지막에 Secure Boot가 아직 비활성화되어 있다면 `eac-setup`이 이를 알려줍니다. 이미 활성화되어 있다면
    이 단계를 건너뛰세요.

    펌웨어 설정으로 재부팅하여 Secure Boot를 활성화하세요. 메인보드에 Secure Boot 스위치가 없는 경우
    [Secure Boot 설정 가이드](/ko/configuration/secure_boot_setup#커널-이미지와-부트-매니저-서명)의 ASUS 관련 안내를
    참고하세요.

    ```bash
    systemctl reboot --firmware-setup
    ```

4. **EAC로 부팅**

    ```bash
    sudo eac-setup boot
    ```

    이 명령어는 다음 한 번만 EAC 항목으로 재부팅합니다. 게임을 마친 뒤 다시 재부팅하면 일반 시스템으로 부팅됩니다.
    systemd-boot를 사용하는 경우에는 부트 메뉴에서 **CachyOS (EAC)**를 직접 선택할 수도 있습니다.

    :::caution
    Limine 및 GRUB 메뉴에도 `linux-cachyos-eac` 항목이 표시됩니다. Limine이나 GRUB을 통해 직접 부팅하면
    EAC 검사를 통과하지 **못합니다**. 항상 `sudo eac-setup boot`을 사용하세요.
    :::

    그런 다음 [설정 확인](#설정-확인)에 설명된 대로 결과를 확인하세요.

</Steps>

### GRUB (실험적)

GRUB 지원은 새로 추가된 기능으로 아직 테스트가 충분히 이루어지지 않았습니다. `cachyos-settings` 1.4.5 이상이 필요합니다.
문제가 발생하면 [CachyOS-Settings 이슈 트래커](https://github.com/CachyOS/CachyOS-Settings/issues)에 제보해 주세요.

GRUB은 `eac-setup`으로만 설정할 수 있으며 별도의 수동 가이드는 없습니다. 기본 단계는 위와 동일합니다.
추가로 스크립트는 다음 변경 사항을 적용합니다.

- `tpm` 모듈을 포함하고 shim lock 없이 GRUB을 다시 설치한 뒤 자체 키로 서명합니다. 이 작업이 없으면
  Secure Boot가 활성화된 상태에서 GRUB이 일반 커널을 시작하지 못합니다.
- systemd-boot는 루트 파일 시스템의 `/boot`에서 파일을 읽을 수 없으므로, EAC 커널과 initramfs를 EFI 시스템
  파티션으로 복사합니다. 이를 위해 약 40 MiB의 공간이 필요합니다. 스크립트는 EAC 커널이나 initramfs가
  변경될 때마다 복사본을 업데이트하는 mkinitcpio 훅이 포함된 `cachyos-eac-grub-hook`을 설치합니다.
- GRUB 메뉴를 다시 생성합니다. 메뉴의 UEFI 펌웨어 항목 아래에 `sudo eac-setup boot`과 동일한 동작을 하는
  **CachyOS EAC (EFI BootNext)** 항목이 추가됩니다.
- GRUB이 기본적으로 `linux-cachyos-eac`를 시작하게 되는 경우, `/etc/default/grub`의 `GRUB_TOP_LEVEL`을
  일반 커널로 설정합니다. 이 옵션이 아직 설정되어 있지 않으면 GRUB이 커널을 이름순으로 정렬하기 때문에 이런 현상이 발생합니다.

:::caution
`/etc/default/grub`에 `GRUB_SAVEDEFAULT=true`가 설정되어 있다면 **CachyOS EAC (EFI BootNext)** 항목을
선택하지 마세요. GRUB이 해당 선택을 기억하여 매 부팅마다 EAC를 시작하게 됩니다. 대신 `sudo eac-setup boot`을
사용하세요. 이미 이 문제가 발생한 경우 `sudo eac-setup`을 다시 실행하면 저장된 항목이 제거됩니다.
:::

GRUB에서는 아직 디스크 암호화가 지원되지 않습니다. CachyOS 설치 프로그램은 `/boot`를 암호화된 루트 파티션
안에 두고 디스크 키를 initramfs 안에 넣습니다. 암호화되지 않은 EFI 시스템 파티션에 initramfs 복사본을 두면
해당 키가 노출되므로, `/boot`가 암호화되어 있으면 `eac-setup`이 실행을 중단합니다.

## 수동 설정

이 섹션은 `eac-setup`이 수행하는 단계를 설명하며, 직접 설정하거나 스크립트가 무엇을 변경하는지 확인할 때
참고할 수 있습니다. 어느 시점에서든 스크립트로 전환할 수 있으며, 스크립트는 이미 완료된 부분부터 이어서 진행합니다.

:::note[bash에서 명령어 실행]
이 페이지의 명령어는 bash 기준으로 작성되었습니다. CachyOS의 기본 셸은 fish이므로 `Unsupported use of '='` 등의
오류를 내며 일부 명령어를 거부합니다. 먼저 터미널에서 `bash`를 실행한 뒤 명령어를 입력하세요.
:::

### 이미 Secure Boot를 사용 중인 경우

[Secure Boot 설정 가이드](/ko/configuration/secure_boot_setup) 등을 통해 이미 `sbctl`로 Secure Boot를 설정했다면
Setup Mode가 필요하지 않습니다. `sbctl`은 Secure Boot가 활성화된 상태를 유지하면서 CachyOS EAC CA를 Secure Boot
데이터베이스에 추가할 수 있습니다. 펌웨어가 신뢰하는 사용자 자체 KEK(Key Exchange Key)로 변경 사항에 서명하기 때문입니다.

<Steps>

1. **Secure Boot 설정 확인**

    ```bash
    sudo sbctl status
    ```

    출력에 `sbctl is installed`, `Setup Mode: Disabled`, `Secure Boot: Enabled`가 표시되어야 합니다.
    키가 `sbctl`로 생성되지 않았다면 대신 사용 중인 부트 매니저용 설정의 1단계부터 따르세요.

2. **CachyOS EAC CA 등록**

    ```bash
    sudo pacman -S cachyos-eac-signing-key
    sudo sbctl enroll-keys --append --partial db --custom --ignore-immutable
    ```

    `--append`는 이미 등록된 모든 인증서를 유지하고, `--partial db`는 Secure Boot 데이터베이스(`db`)만 변경하며,
    Linux가 기본적으로 이를 읽기 전용으로 표시하므로 `--ignore-immutable`을 지정해 `sbctl`이 쓸 수 있도록 합니다.

    :::caution[한 번만 실행하세요]
    `sbctl`은 어떤 인증서가 이미 등록되어 있는지 확인하지 않습니다. 실행할 때마다 사용자 자체 Database Key와
    함께 CachyOS EAC CA가 다시 추가되며, 펌웨어에는 이를 저장할 수 있는 공간이 제한되어 있습니다.
    :::

    인증서가 등록되었는지 확인합니다.

    ```bash
    sudo sbctl list-enrolled-keys
    ```

    `db` 섹션의 기존 항목 옆에 `CachyOS EAC CA`가 나열되어야 합니다. 사용자 자체 `Database Key`가
    두 번 표시될 수 있지만 이는 무해합니다.

    `sbctl`이 오류를 보고한다면 펌웨어가 변경을 거부한 것이며, 대개 등록된 KEK가 sbctl의 키 디렉터리에 있는
    키와 다르기 때문입니다. 이 경우 사용 중인 부트 매니저용 설정의 1단계부터 따르세요.

3. **부트 매니저별 설정 계속 진행**

    [부트 매니저별 설정](#부트-매니저별-설정)의 2단계부터 진행하세요. CA가 이미 등록되었고 부트 매니저도 서명되어
    있으므로 3단계는 건너뛰세요. 6단계에서는 Secure Boot가 이미 활성화되어 있으므로 EAC 항목으로 부팅만 하면 됩니다.

</Steps>

<TabItem label='Limine'>

Limine은 기본 부트 매니저로 유지됩니다. CachyOS 서명된 systemd-boot는 EFI 시스템 파티션의 자체 디렉터리에
별도의 펌웨어 부팅 항목과 함께 설치됩니다. 게임을 플레이할 때는 다음 부팅 시 한 번만 systemd-boot를 시작하도록
펌웨어에 지시합니다(`BootNext`). 그러면 systemd-boot가 EAC 커널을 직접 부팅합니다. 그다음 부팅부터는
시스템이 평소처럼 다시 Limine을 시작합니다.

<Steps>

1. **펌웨어를 Setup Mode로 전환**

    이미 `sbctl`로 Secure Boot를 사용 중이라면 대신 [이미 Secure Boot를 사용 중인 경우](#이미-secure-boot를-사용-중인-경우)를
    따른 뒤 2단계로 계속 진행하세요.

    [UEFI에서 Setup Mode 활성화](/ko/configuration/secure_boot_setup#uefi에서-setup-mode-활성화)를 따르고,
    지금은 Secure Boot를 **비활성화** 상태로 두세요.

    ```bash
    systemctl reboot --firmware-setup
    ```

2. **패키지 설치**

    Limine으로 전환하기 전에 [Secure Boot 설정 가이드](/ko/configuration/secure_boot_setup)를 따라 systemd-boot를
    사용한 적이 있다면, 먼저 자체 서명된 systemd-boot를 제거하세요. 그렇지 않으면 pacman이
    `systemd-boot-cachyos-signed` 설치를 거부하고 `sbctl`이 CachyOS 서명된 systemd-boot를 덮어씁니다.

    ```bash
    sudo sbctl remove-file /usr/lib/systemd/boot/efi/systemd-bootx64.efi
    sudo rm -f /usr/lib/systemd/boot/efi/systemd-bootx64.efi.signed
    ```

    그런 다음 패키지를 설치합니다.

    ```bash
    sudo pacman -S sbctl sbsigntools tpm2-tools efibootmgr cachyos-eac-signing-key linux-cachyos-eac systemd-boot-cachyos-signed
    ```

    NVIDIA GPU가 있는 시스템에서는 `linux-cachyos-eac-nvidia-open`(Turing 이상) 또는
    `linux-cachyos-eac-nvidia-580xx`(Maxwell, Pascal 및 Volta)도 함께 설치하세요. ZFS를 사용 중이라면
    `linux-cachyos-eac-zfs`도 설치하세요. Realtek 2.5 GbE 네트워크 카드용으로 `r8125-dkms`를 사용 중이라면
    `linux-cachyos-eac-r8125`도 설치하세요.

    :::danger
    `bootctl install`을 실행하지 **마세요**. 실행하면 systemd-boot가 기본 부트 매니저가 되고 EFI 시스템
    파티션의 폴백(fallback) 부트로더를 대체하게 됩니다.
    :::

    :::caution
    `/etc/default/limine`에서 `ENABLE_UKI=no`(기본값)를 유지하세요. UKI가 활성화되면 EAC 커널이 새 이미지로
    패킹된 뒤 `sbctl`이 사용자 자체 키로 서명하게 되며, 이는 EAC에서 허용되지 않습니다.
    :::

3. **Secure Boot 키 등록 및 Limine 서명**

    [이미 Secure Boot를 사용 중인 경우](#이미-secure-boot를-사용-중인-경우)에서 CA를 등록했다면 이 단계를 건너뛰세요.

    `cachyos-eac-signing-key`는 CachyOS EAC CA 인증서를 sbctl의 사용자 지정 인증서 디렉터리에 배치합니다.
    자체 키를 Microsoft 키, 펌웨어 내장 키 및 CachyOS EAC CA와 함께 등록합니다.

    :::caution[ASUS 및 Gigabyte 메인보드]
    해당 보드에서는 아래 마지막 명령어를 `--firmware-builtin` 없이 `sudo sbctl enroll-keys --microsoft --custom`으로
    실행하세요. 일부 보드에서는 해당 플래그가 중복 키 항목을 생성하여 Secure Boot를 활성화하면
    **Secure Boot Violation**과 함께 부팅이 중단됩니다. 이미 이 문제가 발생한 경우 펌웨어 설정에서 모든
    Secure Boot 키를 삭제해 Setup Mode로 다시 진입한 뒤([UEFI에서 Setup Mode 활성화](/ko/configuration/secure_boot_setup#uefi에서-setup-mode-활성화) 참고),
    CachyOS로 부팅하여 `sudo sbctl enroll-keys --microsoft --custom`을 실행하세요. Secure Boot 가이드의 명령어는
    CachyOS EAC CA가 빠져 있으므로 사용하지 마세요.
    :::

    ```bash
    sudo sbctl create-keys
    sudo sbctl enroll-keys --microsoft --firmware-builtin --custom
    ```

    `sbctl`이 `could not enroll built-in firmware keys` 오류로 중단되면 펌웨어에 내장 키가 없으며 아직 아무것도
    등록되지 않은 상태입니다. 마지막 명령어를 `--firmware-builtin` 없이 다시 실행하세요.

    인증서가 등록되었는지 확인합니다.

    ```bash
    sudo sbctl list-enrolled-keys
    ```

    `db` 섹션에 `CachyOS EAC CA`가 표시되어야 합니다.

    Secure Boot가 활성화된 상태에서 일반 부팅이 계속 작동하려면 Limine 자체도 사용자 자체 키로 서명해야 합니다.
    [커널 이미지와 부트 매니저 서명](/ko/configuration/secure_boot_setup#커널-이미지와-부트-매니저-서명)의
    Limine 탭을 따르세요.

    :::caution
    EAC 커널이나 CachyOS 서명된 systemd-boot를 `sbctl`로 절대 서명하지 마세요. `sbctl verify`에서 서명되지
    않은 것으로 표시되더라도 `sbctl-batch-sign`이나 `sbctl sign`을 사용하지 마세요. 이 파일들은 CachyOS가 서명한 것입니다.
    :::

4. **systemd-boot를 별도의 펌웨어 부팅 항목으로 추가**

    `sbctl`은 커널이나 EFI 바이너리가 업데이트될 때마다 데이터베이스에 있는 모든 파일을 다시 서명합니다.
    이전에 `sbctl sign -s` 등을 실행해 CachyOS 서명 파일이 데이터베이스에 들어 있지 않은지 확인하세요.

    ```bash
    sudo sbctl list-files
    ```

    목록에 `cachyos-eac`가 포함된 경로나 `/usr/lib/systemd/boot/efi/systemd-bootx64.efi`가 있다면
    `sudo sbctl remove-file <path>`로 제거하세요. 그런 다음 패키지를 재설치하여 CachyOS 서명을 복원합니다.

    ```bash
    sudo pacman -S linux-cachyos-eac systemd-boot-cachyos-signed
    ```

    서명된 systemd-boot를 EFI 시스템 파티션의 전용 디렉터리로 복사합니다.

    ```bash
    ESP="$(bootctl --print-esp-path)"
    sudo install -Dm644 /usr/lib/systemd/boot/efi/systemd-bootx64.efi.signed "$ESP/EFI/cachyos-eac/systemd-bootx64.efi"
    ```

    `EFI/cachyos-eac`가 존재하는 한 `systemd-boot-cachyos-signed`가 이 복사본을 자동으로 업데이트합니다.

    그런 다음 펌웨어 부팅 항목을 생성합니다. `--create-only`는 부팅 순서를 변경하지 않고 항목만 추가하므로
    Limine이 기본값으로 유지됩니다.

    ```bash
    ESP_DEV="$(findmnt -no SOURCE "$ESP")"
    ESP_DISK="/dev/$(lsblk -no PKNAME "$ESP_DEV")"
    ESP_PART="$(cat "/sys/class/block/$(basename "$ESP_DEV")/partition")"
    sudo efibootmgr --create-only --disk "$ESP_DISK" --part "$ESP_PART" \
      --label "CachyOS EAC" --loader '\EFI\cachyos-eac\systemd-bootx64.efi'
    ```

    새 항목이 목록에 있는지와 `BootOrder`가 여전히 Limine으로 시작하는지 확인합니다.

    ```bash
    efibootmgr
    ```

5. **EAC 부팅 항목 생성**

    systemd-boot는 EFI 시스템 파티션에서 구성을 읽습니다. Limine 훅은 machine ID 이름의 디렉터리에 EAC 커널과
    initramfs를 최신 상태로 유지합니다. 두 파일이 모두 존재하는지 확인합니다.

    ```bash
    ESP="$(bootctl --print-esp-path)"
    KERNEL="/$(cat /etc/machine-id)/linux-cachyos-eac/vmlinuz"
    INITRD="/$(cat /etc/machine-id)/linux-cachyos-eac/initramfs"
    sudo ls -l "$ESP$KERNEL" "$ESP$INITRD"
    ```

    그런 다음 실행 중인 시스템의 커널 명령줄과 EAC 옵션을 합쳐 커널 명령줄을 구성합니다.

    ```bash
    EAC_REQ="lockdown=integrity lsm=landlock,lockdown,yama,integrity,bpf iommu.passthrough=0 intel_iommu=on module.sig_enforce=1 sysctl.kernel.kexec_load_disabled=1"
    EAC_OPTS="$(sed -E 's/(^| )(BOOT_IMAGE|initrd)=[^ ]*//g' /proc/cmdline) $EAC_REQ"
    echo "$EAC_OPTS"
    ```

    출력에는 `root=` 옵션이 포함되어야 하며 끝부분은 EAC 옵션이어야 합니다. 이제 항목을 작성하고 기본값으로 설정하여
    systemd-boot가 메뉴를 표시하지 않고 바로 시작하도록 합니다. 이 작업은 기존 `loader/loader.conf`를 대체하지만,
    여기서는 systemd-boot가 EAC 항목만 시작하므로 괜찮습니다.

    ```bash
    printf 'title   CachyOS (EAC)\nlinux   %s\ninitrd  %s\noptions %s\n' "$KERNEL" "$INITRD" "$EAC_OPTS" \
      | sudo install -Dm644 /dev/stdin "$ESP/loader/entries/cachyos-eac.conf"
    printf 'default cachyos-eac.conf\ntimeout 0\n' | sudo install -Dm644 /dev/stdin "$ESP/loader/loader.conf"
    ```

    그래도 systemd-boot 메뉴를 보고 싶다면 시작할 때 <kbd>Space</kbd>를 길게 누르세요.

    :::caution
    Limine 메뉴에도 `linux-cachyos-eac` 항목이 표시됩니다. Limine을 통해 부팅하면 EAC 검사를 통과하지 **못합니다**.
    항상 "CachyOS EAC" 펌웨어 항목을 사용하세요.
    :::

    {/* TODO: hide the linux-cachyos-eac entry in Limine (limine-entry-tool has no per-kernel exclude yet) */}

6. **Secure Boot 활성화 및 EAC로 부팅**

    이미 Secure Boot가 활성화되어 있다면 EAC로 부팅하는 단계로 바로 넘어가세요.

    펌웨어 설정으로 재부팅하여 Secure Boot를 활성화하세요. 메인보드에 Secure Boot 스위치가 없는 경우
    [Secure Boot 설정 가이드](/ko/configuration/secure_boot_setup#커널-이미지와-부트-매니저-서명)의 ASUS 관련 안내를
    참고하세요.

    ```bash
    systemctl reboot --firmware-setup
    ```

    EAC로 부팅하려면 "CachyOS EAC" 항목을 `BootNext`로 설정하고 재부팅하세요. `sudo eac-setup boot`도
    동일한 작업을 수행합니다.

    ```bash
    EAC_BOOTNUM="$(efibootmgr | sed -n 's/^Boot\([0-9A-F]\{4\}\)\* CachyOS EAC.*/\1/p')"
    sudo efibootmgr --bootnext "$EAC_BOOTNUM" && systemctl reboot
    ```

    `BootNext`는 다음 한 번의 부팅에만 적용됩니다. 게임을 마친 뒤 다시 재부팅하면 Limine이 시작됩니다.

</Steps>

1. **펌웨어를 Setup Mode로 전환**

    이미 `sbctl`로 Secure Boot를 사용 중이라면 대신 [이미 Secure Boot를 사용 중인 경우](#이미-secure-boot를-사용-중인-경우)를

2. **패키지 설치**

    이전에 [Secure Boot 설정 가이드](/ko/configuration/secure_boot_setup)를 따른 적이 있다면, 먼저 그 과정에서
    생성된 자체 서명 systemd-boot를 제거하세요. `systemd-boot-cachyos-signed`가 이를 대체하므로 해당 파일이
    존재하면 pacman이 패키지 설치를 거부합니다. `sbctl`은 이를 서명되지 않은 파일 경로로 목록에 저장해 두며,


    그런 다음 패키지를 설치합니다.

    ```bash
    sudo pacman -S sbctl sbsigntools tpm2-tools cachyos-eac-signing-key linux-cachyos-eac systemd-boot-cachyos-signed
    sudo bootctl install
    ```

    NVIDIA GPU가 있는 시스템에서는 `linux-cachyos-eac-nvidia-open`(Turing 이상) 또는
    `linux-cachyos-eac-nvidia-580xx`(Maxwell, Pascal 및 Volta)도 함께 설치하세요. ZFS를 사용 중이라면

    `linux-cachyos-eac-r8125`도 설치하세요.

    `bootctl install`은 CachyOS 서명된 systemd-boot를 EFI 시스템 파티션에 설치합니다. 이후 systemd-boot
    업데이트 역시 CachyOS가 서명하여 제공하므로 사용자가 직접 서명할 필요가 없습니다.

3. **Secure Boot 키 등록**

    [이미 Secure Boot를 사용 중인 경우](#이미-secure-boot를-사용-중인-경우)에서 CA를 등록했다면 이 단계를 건너뛰세요.

    `cachyos-eac-signing-key`는 CachyOS EAC CA 인증서를 sbctl의 사용자 지정 인증서 디렉터리에 배치합니다.
    `sbctl`은 아직 자체 키가 없다면 키를 생성한 뒤 Microsoft 키, 펌웨어 내장 키 및 CachyOS EAC CA와 함께 등록합니다.

    :::caution[ASUS 및 Gigabyte 메인보드]
    해당 보드에서는 아래 마지막 명령어를 `--firmware-builtin` 없이 `sudo sbctl enroll-keys --microsoft --custom`으로
    실행하세요. 일부 보드에서는 해당 플래그가 중복 키 항목을 생성하여 Secure Boot를 활성화하면
    **Secure Boot Violation**과 함께 부팅이 중단됩니다. 이미 이 문제가 발생한 경우 펌웨어 설정에서 모든
    Secure Boot 키를 삭제해 Setup Mode로 다시 진입한 뒤([UEFI에서 Setup Mode 활성화](/ko/configuration/secure_boot_setup#uefi에서-setup-mode-활성화) 참고),
    CachyOS로 부팅하여 `sudo sbctl enroll-keys --microsoft --custom`을 실행하세요. Secure Boot 가이드의 명령어는
    CachyOS EAC CA가 빠져 있으므로 사용하지 마세요.
    :::

    ```bash
    sudo sbctl create-keys
    sudo sbctl enroll-keys --microsoft --firmware-builtin --custom
    ```

    `sbctl`이 `could not enroll built-in firmware keys` 오류로 중단되면 펌웨어에 내장 키가 없으며 아직 아무것도
    등록되지 않은 상태입니다. 마지막 명령어를 `--firmware-builtin` 없이 다시 실행하세요.

    인증서가 등록되었는지 확인합니다.

    ```bash
    sudo sbctl list-enrolled-keys
    ```

    `db` 섹션에 `CachyOS EAC CA`가 표시되어야 합니다.

    그런 다음 일반 커널에 서명하세요. 그렇지 않으면 Secure Boot가 활성화되었을 때 부팅되지 않습니다.
    아래 명령어는 이미 CachyOS가 서명한 EAC 커널을 건너뜁니다.

    ```bash
    sudo find /boot -maxdepth 1 -name 'vmlinuz-*' ! -name vmlinuz-linux-cachyos-eac -exec sbctl sign -s {} \;
    sudo sbctl list-files
    ```

    출력에 각 일반 커널이 서명된 상태로 표시되어야 합니다.

4. **sbctl이 CachyOS 서명 파일을 건드리지 않도록 설정**

    EAC 커널과 systemd-boot는 이미 CachyOS가 서명했습니다. `sbctl`이 사용자 자체 키로 이를 다시 서명하면
    EAC가 더 이상 이를 인식하지 못합니다. `cachyos-eac-signing-key`가 sbctl의 initramfs 훅에서 EAC 커널을
    서명하지 않도록 막아주지만, `sbctl-batch-sign`이나 `sbctl sign -s`를 실행한 후처럼 `sbctl` 데이터베이스에
    등록된 파일은 계속 다시 서명될 수 있습니다.

    ```bash
    sudo sbctl list-files
    ```

    `vmlinuz-linux-cachyos-eac`, `systemd-bootx64.efi` 또는 `BOOTX64.EFI`가 목록에 있다면 제거하고 패키지를
    재설치하여 CachyOS 서명을 복원하세요.

    ```bash
    sudo sbctl remove-file /boot/vmlinuz-linux-cachyos-eac
    sudo sbctl remove-file /boot/EFI/systemd/systemd-bootx64.efi
    sudo sbctl remove-file /boot/EFI/BOOT/BOOTX64.EFI
    sudo sbctl remove-file /usr/lib/systemd/boot/efi/systemd-bootx64.efi
    sudo pacman -S linux-cachyos-eac systemd-boot-cachyos-signed
    sudo bootctl install
    ```

    목록에 없는 파일에 대해서는 `sbctl`이 `doesn't exist in database`를 출력하며, 이는 정상입니다.

    서명을 확인합니다. 각 파일에는 `CachyOS EAC CA`에서 발급한 서명이 정확히 **하나**만 표시되고, 이어서
    `Signature verification OK`가 출력되어야 합니다.

    ```bash
    for f in /boot/vmlinuz-linux-cachyos-eac /boot/EFI/systemd/systemd-bootx64.efi; do
      sudo sbverify --list "$f"
      sudo sbverify --cert /usr/share/cachyos-eac/cachyos-eac-ca.crt "$f"
    done
    ```

    `sbctl verify`는 사용자 자체 키로 만든 서명만 계산하므로 이 파일들을 계속 서명되지 않은 것으로 표시합니다.
    서명하지 마세요. `sbctl-batch-sign`은 이 파일들을 건너뜁니다.

5. **EAC 부팅 항목 생성**

    EAC는 커널 명령줄에 필수 옵션이 있는지 확인하므로 EAC 커널에는 전용 부팅 항목이 필요합니다.
    `sdboot-manage`가 자동으로 생성하는 항목("Linux CachyOS Eac")에는 이러한 옵션이 빠져 있으며
    업데이트 시 덮어쓰여지므로, 현재 실행 중인 시스템의 명령줄을 기반으로 별도 항목을 생성하세요.

    {/* TODO: replace with automatic entry generation (sdboot-manage or package hook) */}

    ```bash
    EAC_REQ="lockdown=integrity lsm=landlock,lockdown,yama,integrity,bpf iommu.passthrough=0 intel_iommu=on module.sig_enforce=1 sysctl.kernel.kexec_load_disabled=1"
    EAC_OPTS="$(sed -E 's/(^| )(BOOT_IMAGE|initrd)=[^ ]*//g' /proc/cmdline) $EAC_REQ"
    echo "$EAC_OPTS"
    ```

    출력에는 `root=` 옵션이 포함되어야 하며 끝부분은 EAC 옵션이어야 합니다. 그런 다음 항목을 작성합니다.

    ```bash
    printf 'title   CachyOS (EAC)\nlinux   /vmlinuz-linux-cachyos-eac\ninitrd  /initramfs-linux-cachyos-eac.img\noptions %s\n' "$EAC_OPTS" \
      | sudo install -Dm644 /dev/stdin /boot/loader/entries/cachyos-eac.conf
    ```

    :::caution
    이 항목에서 EAC 옵션을 하나도 제거하지 마세요. 옵션이 빠지면 EAC가 게임 시작을 거부합니다.
    :::

6. **Secure Boot 활성화 및 EAC 항목으로 부팅**

    이미 Secure Boot가 활성화되어 있다면 EAC 항목으로 부팅하는 단계로 바로 넘어가세요.

    펌웨어 설정으로 재부팅하여 Secure Boot를 활성화하세요. 메인보드에 Secure Boot 스위치가 없는 경우
    [Secure Boot 설정 가이드](/ko/configuration/secure_boot_setup#커널-이미지와-부트-매니저-서명)의 ASUS 관련 안내를
    참고하세요.

    ```bash
    systemctl reboot --firmware-setup
    ```

    EAC 항목으로 부팅하려면 systemd-boot 메뉴에서 **CachyOS (EAC)**를 선택하거나 다음 명령어를 실행하세요.

    ```bash
    systemctl reboot --boot-loader-entry=cachyos-eac.conf
    ```

<TabItem label='rEFInd'>

rEFInd는 기본 부트 매니저로 유지됩니다. Limine과 마찬가지로 CachyOS 서명된 systemd-boot가 EFI 시스템 파티션의
자체 디렉터리에 별도의 펌웨어 부팅 항목과 함께 설치됩니다. 게임을 플레이할 때는 다음 부팅 시 한 번만 systemd-boot를
시작하도록 펌웨어에 지시합니다(`BootNext`). 그러면 systemd-boot가 EAC 커널을 직접 부팅합니다. 그다음 부팅부터는
시스템이 평소처럼 다시 rEFInd를 시작합니다.

이 단계를 수행하려면 CachyOS 설치 프로그램이 rEFInd를 구성하는 방식대로 EFI 시스템 파티션이 `/boot`에 마운트되어
있어야 합니다. 다음 명령어로 확인하세요.

```bash
bootctl --print-esp-path
```

출력은 `/boot`여야 합니다. 이전 설치에서 볼 수 있는 `/boot/efi` 위치의 EFI 시스템 파티션 등 다른 레이아웃은
지원되지 않습니다.

<Steps>

1. **펌웨어를 Setup Mode로 전환**

    이미 `sbctl`로 Secure Boot를 사용 중이라면 대신 [이미 Secure Boot를 사용 중인 경우](#이미-secure-boot를-사용-중인-경우)를
    따른 뒤 2단계로 계속 진행하세요.

    [UEFI에서 Setup Mode 활성화](/ko/configuration/secure_boot_setup#uefi에서-setup-mode-활성화)를 따르고,
    지금은 Secure Boot를 **비활성화** 상태로 두세요.

    ```bash
    systemctl reboot --firmware-setup
    ```

2. **패키지 설치**

    rEFInd로 전환하기 전에 [Secure Boot 설정 가이드](/ko/configuration/secure_boot_setup)를 따라 systemd-boot를
    사용한 적이 있다면, 먼저 자체 서명된 systemd-boot를 제거하세요. 그렇지 않으면 pacman이
    `systemd-boot-cachyos-signed` 설치를 거부하고 `sbctl`이 CachyOS 서명된 systemd-boot를 덮어씁니다.

    ```bash
    sudo sbctl remove-file /usr/lib/systemd/boot/efi/systemd-bootx64.efi
    sudo rm -f /usr/lib/systemd/boot/efi/systemd-bootx64.efi.signed
    ```

    그런 다음 패키지를 설치합니다.

    ```bash
    sudo pacman -S sbctl sbsigntools tpm2-tools efibootmgr cachyos-eac-signing-key linux-cachyos-eac systemd-boot-cachyos-signed
    ```

    NVIDIA GPU가 있는 시스템에서는 `linux-cachyos-eac-nvidia-open`(Turing 이상) 또는
    `linux-cachyos-eac-nvidia-580xx`(Maxwell, Pascal 및 Volta)도 함께 설치하세요. ZFS를 사용 중이라면
    `linux-cachyos-eac-zfs`도 설치하세요. Realtek 2.5 GbE 네트워크 카드용으로 `r8125-dkms`를 사용 중이라면
    `linux-cachyos-eac-r8125`도 설치하세요.

    :::danger
    `bootctl install`을 실행하지 **마세요**. 실행하면 systemd-boot가 기본 부트 매니저가 되고 EFI 시스템
    파티션의 폴백(fallback) 부트로더를 대체하게 됩니다.
    :::

3. **Secure Boot 키 등록 및 rEFInd 서명**

    [이미 Secure Boot를 사용 중인 경우](#이미-secure-boot를-사용-중인-경우)에서 CA를 등록했다면 이 단계를 건너뛰세요.

    `cachyos-eac-signing-key`는 CachyOS EAC CA 인증서를 sbctl의 사용자 지정 인증서 디렉터리에 배치합니다.
    자체 키를 Microsoft 키, 펌웨어 내장 키 및 CachyOS EAC CA와 함께 등록합니다.

    :::caution[ASUS 및 Gigabyte 메인보드]
    해당 보드에서는 아래 마지막 명령어를 `--firmware-builtin` 없이 `sudo sbctl enroll-keys --microsoft --custom`으로
    실행하세요. 일부 보드에서는 해당 플래그가 중복 키 항목을 생성하여 Secure Boot를 활성화하면
    **Secure Boot Violation**과 함께 부팅이 중단됩니다. 이미 이 문제가 발생한 경우 펌웨어 설정에서 모든
    Secure Boot 키를 삭제해 Setup Mode로 다시 진입한 뒤([UEFI에서 Setup Mode 활성화](/ko/configuration/secure_boot_setup#uefi에서-setup-mode-활성화) 참고),
    CachyOS로 부팅하여 `sudo sbctl enroll-keys --microsoft --custom`을 실행하세요. Secure Boot 가이드의 명령어는
    CachyOS EAC CA가 빠져 있으므로 사용하지 마세요.
    :::

    ```bash
    sudo sbctl create-keys
    sudo sbctl enroll-keys --microsoft --firmware-builtin --custom
    ```

    `sbctl`이 `could not enroll built-in firmware keys` 오류로 중단되면 펌웨어에 내장 키가 없으며 아직 아무것도
    등록되지 않은 상태입니다. 마지막 명령어를 `--firmware-builtin` 없이 다시 실행하세요.

    인증서가 등록되었는지 확인합니다.

    ```bash
    sudo sbctl list-enrolled-keys
    ```

    `db` 섹션에 `CachyOS EAC CA`가 표시되어야 합니다.

    Secure Boot가 활성화된 상태에서 일반 부팅이 계속 작동하려면 rEFInd와 일반 커널도 여전히 사용자 자체 키로
    서명해야 합니다. `find` 명령어는 이미 CachyOS가 서명한 EAC 커널을 건너뜁니다.

    ```bash
    sudo sbctl sign -s /boot/EFI/refind/refind_x64.efi
    sudo find /boot -maxdepth 1 -name 'vmlinuz-*' ! -name vmlinuz-linux-cachyos-eac -exec sbctl sign -s {} \;
    sudo sbctl list-files
    ```

    출력에 rEFInd와 각 일반 커널이 서명된 상태로 표시되어야 합니다. 커널 업데이트 후에는 `sbctl`이 이를 다시
    서명합니다. pacman은 EFI 시스템 파티션의 rEFInd를 업데이트하지 않습니다. 직접 `refind-install`을 실행한
    경우에는 이후 `sudo sbctl sign-all`을 실행하세요.

    :::caution
    EAC 커널이나 CachyOS 서명된 systemd-boot를 `sbctl`로 절대 서명하지 마세요. `sbctl verify`에서 서명되지
    않은 것으로 표시되더라도 `sbctl-batch-sign`이나 `sbctl sign`을 사용하지 마세요. 이 파일들은 CachyOS가 서명한 것입니다.
    :::

4. **systemd-boot를 별도의 펌웨어 부팅 항목으로 추가**

    `sbctl`은 커널이나 EFI 바이너리가 업데이트될 때마다 데이터베이스에 있는 모든 파일을 다시 서명합니다.
    이전에 `sbctl sign -s` 등을 실행해 CachyOS 서명 파일이 데이터베이스에 들어 있지 않은지 확인하세요.

    ```bash
    sudo sbctl list-files
    ```

    목록에 `cachyos-eac`가 포함된 경로나 `/usr/lib/systemd/boot/efi/systemd-bootx64.efi`가 있다면
    `sudo sbctl remove-file <path>`로 제거하세요. 그런 다음 패키지를 재설치하여 CachyOS 서명을 복원합니다.

    ```bash
    sudo pacman -S linux-cachyos-eac systemd-boot-cachyos-signed
    ```

    서명된 systemd-boot를 EFI 시스템 파티션의 전용 디렉터리로 복사합니다.

    ```bash
    ESP="$(bootctl --print-esp-path)"
    sudo install -Dm644 /usr/lib/systemd/boot/efi/systemd-bootx64.efi.signed "$ESP/EFI/cachyos-eac/systemd-bootx64.efi"
    ```

    `EFI/cachyos-eac`가 존재하는 한 `systemd-boot-cachyos-signed`가 이 복사본을 자동으로 업데이트합니다.

    그런 다음 펌웨어 부팅 항목을 생성합니다. `--create-only`는 부팅 순서를 변경하지 않고 항목만 추가하므로
    rEFInd가 기본값으로 유지됩니다.

    ```bash
    ESP_DEV="$(findmnt -no SOURCE "$ESP")"
    ESP_DISK="/dev/$(lsblk -no PKNAME "$ESP_DEV")"
    ESP_PART="$(cat "/sys/class/block/$(basename "$ESP_DEV")/partition")"
    sudo efibootmgr --create-only --disk "$ESP_DISK" --part "$ESP_PART" \
      --label "CachyOS EAC" --loader '\EFI\cachyos-eac\systemd-bootx64.efi'
    ```

    새 항목이 목록에 있는지와 `BootOrder`가 여전히 rEFInd로 시작하는지 확인합니다.

    ```bash
    efibootmgr
    ```

5. **EAC 부팅 항목 생성**

    systemd-boot는 EAC 커널과 initramfs가 이미 들어 있는 EFI 시스템 파티션에서 구성을 읽습니다.
    실행 중인 시스템의 커널 명령줄과 EAC 옵션을 합쳐 커널 명령줄을 구성하세요.

    ```bash
    EAC_REQ="lockdown=integrity lsm=landlock,lockdown,yama,integrity,bpf iommu.passthrough=0 intel_iommu=on module.sig_enforce=1 sysctl.kernel.kexec_load_disabled=1"
    EAC_OPTS="$(sed -E 's/(^| )(BOOT_IMAGE|initrd)=[^ ]*//g' /proc/cmdline) $EAC_REQ"
    echo "$EAC_OPTS"
    ```

    출력에는 `root=` 옵션이 포함되어야 하며 끝부분은 EAC 옵션이어야 합니다. 이제 항목을 작성하고 기본값으로 설정하여
    systemd-boot가 메뉴를 표시하지 않고 바로 시작하도록 합니다.

    ```bash
    ESP="$(bootctl --print-esp-path)"
    printf 'title   CachyOS (EAC)\nlinux   /vmlinuz-linux-cachyos-eac\ninitrd  /initramfs-linux-cachyos-eac.img\noptions %s\n' "$EAC_OPTS" \
      | sudo install -Dm644 /dev/stdin "$ESP/loader/entries/cachyos-eac.conf"
    printf 'default cachyos-eac.conf\ntimeout 0\n' | sudo install -Dm644 /dev/stdin "$ESP/loader/loader.conf"
    ```

    그래도 systemd-boot 메뉴를 보고 싶다면 시작할 때 <kbd>Space</kbd>를 길게 누르세요.

    rEFInd는 자체적으로 EAC 커널과 systemd-boot를 찾아 메뉴에 추가합니다. rEFInd는 사용자 자체 키로 서명되어
    있으므로 rEFInd 메뉴에서 시작한 항목은 EAC 검사를 통과하지 **못합니다**. 두 항목을 모두 숨기세요.

    ```bash
    printf '\n# Easy Anti-Cheat: boot these only through the "CachyOS EAC" firmware entry\ndont_scan_files +,vmlinuz-linux-cachyos-eac\ndont_scan_dirs +,EFI/cachyos-eac\n' \
      | sudo tee -a "$ESP/EFI/refind/refind.conf" >/dev/null
    ```

    `+`는 rEFInd가 이미 건너뛰고 있는 파일과 디렉터리를 그대로 유지합니다. 다음 부팅부터는 rEFInd 메뉴에
    일반 커널만 표시됩니다.

6. **Secure Boot 활성화 및 EAC로 부팅**

    이미 Secure Boot가 활성화되어 있다면 EAC로 부팅하는 단계로 바로 넘어가세요.

    펌웨어 설정으로 재부팅하여 Secure Boot를 활성화하세요. 메인보드에 Secure Boot 스위치가 없는 경우
    [Secure Boot 설정 가이드](/ko/configuration/secure_boot_setup#커널-이미지와-부트-매니저-서명)의 ASUS 관련 안내를
    참고하세요.

    ```bash
    systemctl reboot --firmware-setup
    ```

    EAC로 부팅하려면 "CachyOS EAC" 항목을 `BootNext`로 설정하고 재부팅하세요. `sudo eac-setup boot`도
    동일한 작업을 수행합니다.

    ```bash
    EAC_BOOTNUM="$(efibootmgr | sed -n 's/^Boot\([0-9A-F]\{4\}\)\* CachyOS EAC.*/\1/p')"
    sudo efibootmgr --bootnext "$EAC_BOOTNUM" && systemctl reboot
    ```

    `BootNext`는 다음 한 번의 부팅에만 적용됩니다. 게임을 마친 뒤 다시 재부팅하면 rEFInd가 시작됩니다.

## 설정 확인

EAC 항목으로 부팅한 뒤 `cachyos-settings`에 포함된 `eac-status`를 실행하세요.

```bash
sudo eac-status
```

이 도구는 Secure Boot 및 Setup Mode, TPM, 등록된 CachyOS EAC CA, EAC 커널 및 systemd-boot의 서명,
커널 명령줄, lockdown, 모듈 서명, kexec, IOMMU, 그리고 펌웨어가 부팅을 검증할 때 사용한 인증서(TPM 이벤트 로그 기준)를
확인합니다. 모든 항목이 `[ OK ]`로 표시되어야 하며, 마지막 줄에 `All checks passed`가 출력되어야 합니다.
일반 부팅 항목에서 실행하면 펌웨어와 부팅 파일만 확인하며, 준비가 된 경우 `The boot files are ready`로 끝납니다.

이 검사는 사용자 시스템 상태만 확인합니다. 실제로 게임이 실행되는지는 Easy Anti-Cheat와 해당 게임에 달려 있습니다.

TPM 이벤트 로그에 Microsoft 인증서가 있는 것은 정상(GPU 펌웨어에 사용됨)이며 보고되지 않습니다.
사용자 자체 "Database Key" 같은 다른 인증서가 있다면 `[WARN] Boot was also verified by`로 보고됩니다.

## 문제 해결

### `eac-status`가 두 개의 서명 또는 자체 키를 보고하는 경우

`has 2 signatures` 또는 `Boot was also verified by Database Key`가 표시된다면 `sbctl`이 사용자 자체 키로
EAC 커널 또는 systemd-boot를 다시 서명했음을 의미합니다. 1-2 이전 버전의 `cachyos-eac-signing-key`는
initramfs가 다시 빌드될 때마다 sbctl의 initramfs 훅이 이를 수행하도록 허용했으므로 먼저 시스템을 업데이트하세요.

```bash
sudo pacman -Syu
```

그런 다음 `sudo eac-setup`을 다시 실행하세요. sbctl 데이터베이스에서 해당 파일을 제거하고 CachyOS 서명을 복원합니다.
수동으로 복원하려면 아래 단계를 따르세요.

systemd-boot를 사용 중이라면 [부트 매니저별 설정](#부트-매니저별-설정)의 systemd-boot 탭에서 4단계를 반복하여
sbctl 데이터베이스에서 파일을 제거하고 패키지를 재설치하세요.

Limine이나 rEFInd를 사용 중이라면 해당 단계를 따르지 **마세요**. 그 단계의 `bootctl install`이 systemd-boot를
기본 부트 매니저로 만들고 EFI 시스템 파티션의 폴백 부트로더를 대체하게 됩니다. 대신 sbctl 데이터베이스를 확인하세요.

```bash
sudo sbctl list-files
```

목록에 `cachyos-eac`가 포함된 경로나 `/usr/lib/systemd/boot/efi/systemd-bootx64.efi`(Secure Boot 가이드의
systemd-boot 단계에서 남은 파일)가 있다면 `sudo sbctl remove-file <path>`로 제거하세요. 그런 다음 패키지를
재설치하고 서명된 systemd-boot를 다시 복사하세요.

```bash
sudo pacman -S linux-cachyos-eac systemd-boot-cachyos-signed
ESP="$(bootctl --print-esp-path)"
sudo install -Dm644 /usr/lib/systemd/boot/efi/systemd-bootx64.efi.signed "$ESP/EFI/cachyos-eac/systemd-bootx64.efi"
```

### `eac-status`가 CachyOS EAC CA로 부팅이 검증되지 않았다고 보고하는 경우

`Boot was not verified by CachyOS EAC CA`가 커널 명령줄 검사 실패와 함께 표시된다면 잘못된 항목으로 부팅한 것입니다.
[게임에서 지원되지 않는 시스템이라고 표시되는 경우](#게임에서-지원되지-않는-시스템이라고-표시되는-경우)를 참고하세요.

이 항목만 유일하게 실패했다면 펌웨어가 부팅 파일을 검증할 때 어떤 인증서를 사용했는지 기록하지 않은 것입니다.
MSI 보드에서 가장 흔한 원인은 기본 Secure Boot 정책입니다. 즉, Secure Boot가 활성화되어 있어도 펌웨어가
모든 부팅 파일을 검증 없이 시작하는 경우입니다.

펌웨어 설정의 Secure Boot 페이지를 여세요. 보드에 따라 **Settings > Advanced > Windows OS Configuration > Secure Boot**
또는 **Settings > Security > Secure Boot** 아래에 있습니다. 옵션 이름은 펌웨어 버전에 따라 다릅니다.

| 옵션 | 값 |
| ---------------------- | ------------------------------------------------------------ |
| Image Execution Policy | **Fixed Media** 및 **Removable Media**에 대해 **Deny Execute** |
| Secure Boot Preset | **Maximum Security** |
| Target OS | **Windows UEFI OS** |

:::caution
**Secure Boot Mode**를 **Standard**로 전환하거나 공장 키를 복원하지 마세요. 두 작업 모두 CachyOS EAC CA와
사용자 자체 키를 삭제합니다.
:::

변경 사항을 저장하고 EAC 항목으로 부팅한 뒤 `sudo eac-status`를 다시 실행하세요. 이제 CachyOS EAC CA가 등록되지
않았다고 보고하면 펌웨어가 키를 초기화한 것이므로 `sudo eac-setup`을 다시 실행하세요.

### 게임에서 지원되지 않는 시스템이라고 표시되는 경우

EAC 항목에서 `sudo eac-status`를 실행하고 `[FAIL]`로 표시된 모든 항목을 해결하세요. 가장 흔한 원인은 잘못된 항목으로
부팅한 경우이며, 이 경우 `eac-status`가 커널 명령줄에서 EAC 옵션이 누락되었다고 보고합니다. `sudo eac-setup boot`으로
재부팅하세요. systemd-boot에서는 자동 생성된 "Linux CachyOS Eac" 항목이 아니라 **CachyOS (EAC)**를 선택할 수도
있습니다. Limine, rEFInd 또는 GRUB에서는 부트 매니저 메뉴에서 EAC 커널을 직접 시작하지 마세요.

### EAC 항목 대신 Limine 또는 rEFInd가 시작되는 경우

재부팅 전에 `BootNext`가 설정되었는지 확인하세요.

```bash
efibootmgr | grep -E 'BootNext|CachyOS EAC'
```

"CachyOS EAC" 항목이 없다면 펌웨어가 이를 삭제한 것이며, 일부 보드에서는 펌웨어 업데이트나 초기화 후 이런 일이
발생합니다. `sudo eac-setup`을 실행해 다시 생성하거나, [부트 매니저별 설정](#부트-매니저별-설정)의 Limine 또는
rEFInd 탭에서 4단계를 반복하세요. 펌웨어의 일회성 부팅 메뉴에서 "CachyOS EAC"를 직접 선택할 수도 있습니다.

### EAC 항목에서 모듈이 로드되지 않는 경우

DKMS로 빌드된 모듈은 커널 키로 서명되지 않았으므로 로드할 수 없습니다. EAC 커널용으로 제공되는 모듈
(`linux-cachyos-eac-nvidia-open`, `linux-cachyos-eac-nvidia-580xx`, `linux-cachyos-eac-zfs` 또는
`linux-cachyos-eac-r8125`)을 사용하거나, DKMS 모듈이 필요한 작업에는 일반 커널로 부팅하세요.
