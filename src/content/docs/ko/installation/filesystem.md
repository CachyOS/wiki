CachyOS는 사용자가 자신의 필요에 가장 잘 맞는 것을 선택할 수 있도록 5가지 파일 시스템을 제공합니다. 아래에서는 각 파일 시스템의 장점, 단점, 권장 사항을 살펴봅니다. 각 파일 시스템에 필요한 요구 사항/유틸리티는 CachyOS에 사전 설치되어 제공됩니다.

:::note
BTRFS는 CachyOS의 기본 및 권장 파일 시스템입니다. 잘 모르겠다면 이 파일 시스템을 선택하세요.
:::

## XFS

XFS는 Silicon Graphics, Inc.에서 만들고 개발한 저널링 파일 시스템입니다. 1993년에 만들어졌고, 2001년에 Linux로 포팅되었으며, 현재는 대부분의 Linux 배포판에서 널리 지원됩니다.

### 장점

- XFS는 원래 속도와 극도의 확장성을 염두에 두고 설계되었습니다.
- 신뢰성이 높으며, XFS는 데이터 손상을 방지하기 위해 여러 기술을 사용합니다.
- 익스텐트 기반 구조와 지연 할당 전략 덕분에 단편화에 강합니다.

### 단점

- 축소할 수 없습니다.

### 사용자 공간 유틸리티

XFS 파일 시스템을 관리하기 위한 사용자 공간 도구가 포함된 패키지는 `xfsprogs`입니다.

### 권장 사항

XFS는 고급 기능이 필요하지 않고 빠르고 안정적인 파일 시스템만 원하는 사용자에게 권장되는 파일 시스템입니다.

## BTRFS

BTRFS는 2007년에 만들어지고 2013년에 Linux 커널에서 안정화된 최신 copy-on-write(COW) 파일 시스템입니다. 널리 지원되며, 주로 고급 기능 모음으로 잘 알려져 있습니다.

### 장점

- 투명 압축. BTRFS는 사용자의 개입 없이 파일을 투명하게 압축하여 상당한 공간 절약을 가능하게 합니다. **CachyOS는 기본적으로 ZSTD 압축을 level 3으로 설정해 제공합니다.**
- 스냅샷 기능. BTRFS는 COW 특성을 활용하여 실제 공간을 매우 적게 차지하는 서브볼륨 스냅샷을 만들 수 있습니다.
- 파일 시스템을 더 세밀하게 제어할 수 있는 서브볼륨 기능.
- 확장하거나 축소할 수 있습니다.
- 개발 속도가 매우 빠릅니다.

### 단점

- 때때로 조각 모음 또는 밸런싱이 필요합니다.
- 앞서 언급한 단편화 때문에 회전식 드라이브에서는 성능이 더 나쁩니다.

### 사용자 공간 유틸리티

Btrfs 사용자 공간 유틸리티 패키지는 `btrfs-progs`입니다.

### 서브볼륨 레이아웃

CachyOS는 쉬운 스냅샷 기능을 위해 기본 서브볼륨 레이아웃을 제공합니다.

- Subvol @ = /
- Subvol @home = /home
- Subvol @root = /root
- Subvol @srv = /srv
- Subvol @cache = /var/cache
- Subvol @tmp = /var/tmp
- Subvol @log = /var/log

### 권장 사항

BTRFS는 스냅샷/백업 기능과 투명 압축을 원하는 사용자에게 권장됩니다.

## EXT4

EXT4(네 번째 확장 파일 시스템)는 가장 일반적으로 사용되는 Linux 파일 시스템입니다. EXT4는 2008년에 Linux 커널에서 안정화되었습니다.

### 장점

- 일부 상황에서는 XFS만큼 빠르거나 더 빠를 수 있습니다.
- 매우 흔하게 사용되므로 많은 자료에 쉽게 접근할 수 있습니다.
- 신뢰성이 높습니다. EXT4는 매우 안정적이라는 검증된 기록을 가지고 있습니다.
- 확장하거나 축소할 수 있습니다.
  - 축소는 오프라인 상태에서만 지원되며, 파일 시스템이 마운트 해제되어 있어야 합니다.

### 단점

- 다른 파일 시스템이 제공하는 많은 고급 기능이 부족합니다.

### 사용자 공간 유틸리티

ext4를 관리하는 패키지는 `e2fsprogs`입니다.

### 권장 사항

EXT4는 가장 단순하고 가장 일반적으로 사용되는 파일 시스템을 원하는 사용자에게 권장됩니다.

## ZFS

ZFS는 2005년에 Sun Microsystems가 처음 개발한 고급 파일 시스템입니다. ZFS에는 많은 기능이 있지만 CDDL 라이선스를 사용하므로 Linux 커널 안에 포함될 수 없고, 별도의 모듈 설치가 필요합니다.

:::caution
ZFS와 함께 Real-time 커널을 사용하지 마세요. 라이선스 문제로 인해 호환되지 않습니다.
:::

### 장점

- 풀링된 스토리지(zpool)
- COW를 사용하는 스냅샷
- 압축
- Raid-Z 지원
- ARC 캐시는 자주 접근하는 파일에 대해 매우 빠른 읽기 시간을 제공합니다.

### 단점

- zpool과 ARC 같은 기능 때문에 사용하고 이해하기가 매우 복잡합니다.
- ARC가 효과적이려면 많은 RAM이 필요합니다.
- Linux 커널에 포함되어 있지 않으므로 서드파티 커널 모듈(OpenZFS)에 의존합니다.
- Real-time preemption과 호환되지 않습니다.

### 필요한 도구

'ZFS-Module' CachyOS는 각 커널 버전용 사전 컴파일된 zfs 모듈을 제공합니다.
사용자 공간 유틸리티에는 `zfs-utils`가 필요합니다.

### 권장 사항

ZFS는 풀링된 스토리지나 ARC 캐시 같은 고급 기능을 사용하려는 고급 사용자만 사용해야 합니다.

## F2FS

F2FS(Flash-Friendly File System)는 Samsung이 Linux 커널용으로 처음 만들고 개발한 플래시 파일 시스템입니다. F2FS는 현대 저장 장치에서 사용되는 NAND 플래시에 특화되도록 만들어졌습니다.

### 장점

- 플래시 친화성을 염두에 두고 설계되었습니다.
- 디스크 쓰기를 줄이기 위해 투명 압축을 사용합니다(공간 절약분은 현재 사용자가 활용할 수 없습니다).
- 더 나은 wear leveling을 제공하여 NAND 플래시의 수명을 더욱 연장합니다.

### 단점

- 축소할 수 없습니다.
- 압축으로 절약된 공간은 현재 사용자가 활용할 수 없습니다. 이 기능은 향후 추가될 수 있습니다.
- fsck(파일 시스템 검사)가 상대적으로 약합니다.
- 파일 시스템을 만든 커널 버전보다 오래된 커널로 다운그레이드하면 문제가 발생할 수 있습니다.
- MBR/BIOS 시스템에서 GRUB와 함께 사용할 때 우회 방법이 필요합니다.

### 사용자 공간 유틸리티

f2fs의 주요 유틸리티는 `f2fs-tools`입니다.

### 권장 사항

- F2FS는 NAND 플래시 장치의 수명을 최대화하고 싶은 사용자에게 권장됩니다.
- MBR/BIOS 시스템의 F2FS 사용자에게는 Limine이 권장 부트로더입니다. GRUB처럼 우회 방법이 필요하지 않기 때문입니다.

## TL:DR

기본 파일 시스템인 **BTRFS**를 사용하세요. 안정적인 것으로 간주되며 여러 유용한 기능(스냅샷, 압축 등)을 갖추고 있기 때문입니다. 단순하고 빠른 파일 시스템을 원한다면 **XFS** 또는 **EXT4**를
사용하세요.
