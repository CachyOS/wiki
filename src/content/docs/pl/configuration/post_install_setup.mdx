<TabItem label="Używając Octopi (GUI)">

Octopi to graficzny menedżer pakietów dla dystrybucji opartych na Arch, który zapewnia wygodny sposób zarządzania pakietami i aktualizacjami.
Aby zaktualizować system za pomocą Octopi, wykonaj następujące kroki:

<Steps>

1. Uruchom **Octopi** z menu aplikacji.
2. W głównym oknie kliknij przycisk **Sprawdź aktualizacje** (w lewym górnym rogu), a następnie obok niego **Aktualizacja systemu**.
3. Octopi sprawdzi teraz dostępne aktualizacje i poprosi o zainstalowanie ich w samym Octopi lub w terminalu.
4. Aby kontynuować aktualizację, kliknij przycisk **Zastosuj**.
5. Octopi pobierze i zainstaluje aktualizacje.
6. Zaleca się ponowne uruchomienie komputera po dużej aktualizacji **(szczególnie jeśli zaktualizowano jądro)**.

</Steps>

</TabItem>

<TabItem label="Używając Pacmana">

<Steps>

1. Otwórz emulator terminala (lub naciśnij `ctrl + alt + t` - `mod + return` w menedżerze okien, np. Qtile).
2. Uruchom następujące polecenie, aby zaktualizować system:

   ```sh
   sudo pacman -Syu
   ```
3. Zaleca się ponowne uruchomienie komputera po dużej aktualizacji **(szczególnie jeśli zaktualizowano jądro)**.

</Steps>

</TabItem>

<TabItem label="Aktualizacja Systemu Offline">

*CachyOS wspiera aktualizacje systemu offline za pomocą skryptu [`pacman-offline`](https://github.com/eworm-de/pacman-offline). Pozwala to systemowi na pobieranie aktualizacji pakietów i ich zastosowanie przy następnym restarcie. (Tak, jak w systemie Windows)*

:::note
Narzędzie `pacman-offline` integruje się z funkcją aktualizacji offline systemd. Automatycznie obsługuje aktualizacje jądra i ładowanie modułów.

Plik `/etc/pacman.d/offline.conf` jest kluczowy do zarządzania, które pakiety są aktualizowane podczas regularnych i offline'owych aktualizacji. Upewnij się, że jest on poprawnie skonfigurowany dla wybranego jądra lub dodaj pakiety, które chcesz, aby były aktualizowane tylko podczas wykonywania pacman-offline i ignorowane podczas regularnej aktualizacji. Przykład: `pacman -Syu`.

**Jeśli włączysz timer automatycznych aktualizacji, nie musisz już ręcznie aktualizować systemu.**
:::

<Steps>

1. **Zainstaluj pakiet pacman-offline**

   ```bash
   sudo pacman -S pacman-offline
   ```

2. **Poinformowanie Pacmana o konieczności czytania z oddzielnej listy ignorowanych pakietów.**

   :::note[Dodaj linię po sekcji [options]. Sprawdź poniższy przykład jako odniesienie.]
   :::

   ```bash title='Dodaj następującą linię do pliku /etc/pacman.conf'
   Include = /etc/pacman.d/offline.conf
   ```
   *Przykład*
   ```bash
   # /etc/pacman.conf
   # REPOZYTORIA
   #   - mogą być zdefiniowane tutaj lub dołączone z innego pliku
   #   - pacman będzie przeszukiwał repozytoria w kolejności zdefiniowanej tutaj
   #   - lokalne/niestandardowe mirrory mogą być dodane tutaj lub w oddzielnych plikach
   #   - repozytoria wymienione jako pierwsze będą miały pierwszeństwo, gdy pakiety
   #     mają identyczne nazwy, niezależnie od numeru wersji
   #   - w adresach URL $repo zostanie zastąpione nazwą bieżącego repozytorium
   #   - w adresach URL $arch zostanie zastąpione nazwą architektury
   #
   # Wpisy repozytoriów mają format:
   #       [nazwa-repo]
   #       Server = NazwaSerwera
   #       Include = SciezkaDoPliku
   #
   # Nagłówek [nazwa-repo] jest kluczowy - musi być obecny i
   # niezakomentowany, aby włączyć repozytorium.
   #
   # OPCJE OGÓLNE
   [options]
   # inne opcje, takie jak 'Color', 'CheckSpace', itp. mogą być tutaj
   Include = /etc/pacman.d/offline.conf
   ```
3. **Dodanie jąder CachyOS, aby pacman ignorował je podczas regularnych aktualizacji**

   Narzędzie `pacman-offline` używa tego pliku do określenia, które pakiety ignorować podczas tradycyjnych aktualizacji pacmana.

   Przykład: kiedy uruchamiasz `sudo pacman -Syu`

   *Zastąp zawartość pliku `/etc/pacman.d/offline.conf` następującym tekstem:*

   ```text
   # Jądra Arch Linux
   IgnorePkg = linux linux-headers linux-docs
   IgnorePkg = linux-lts linux-lts-headers linux-lts-docs
   IgnorePkg = linux-zen linux-zen-headers linux-zen-docs
   IgnorePkg = linux-hardened linux-hardened-headers linux-hardened-docs

   # Jądra CachyOS
   IgnorePkg = linux-cachyos linux-cachyos-headers linux-cachyos-nvidia-open linux-cachyos-zfs
   IgnorePkg = linux-cachyos-bmq linux-cachyos-bmq-headers linux-cachyos-bmq-nvidia-open linux-cachyos-bmq-zfs
   IgnorePkg = linux-cachyos-bore linux-cachyos-bore-headers linux-cachyos-bore-nvidia-open linux-cachyos-bore-zfs
   IgnorePkg = linux-cachyos-deckify linux-cachyos-deckify-headers linux-cachyos-deckify-nvidia-open linux-cachyos-deckify-zfs
   IgnorePkg = linux-cachyos-eevdf linux-cachyos-eevdf-headers linux-cachyos-eevdf-nvidia-open linux-cachyos-eevdf-zfs
   IgnorePkg = linux-cachyos-gcc linux-cachyos-gcc-headers linux-cachyos-gcc-nvidia-open linux-cachyos-gcc-zfs
   IgnorePkg = linux-cachyos-hardened linux-cachyos-hardened-headers linux-cachyos-hardened-nvidia-open linux-cachyos-nvidia-hardened-zfs
   IgnorePkg = linux-cachyos-lts linux-cachyos-lts-headers linux-cachyos-lts-nvidia-open linux-cachyos-lts-zfs
   IgnorePkg = linux-cachyos-rc linux-cachyos-rc-headers linux-cachyos-rc-nvidia-open linux-cachyos-rc-nvidia-open linux-cachyos-rc-zfs
   IgnorePkg = linux-cachyos-rt-bore linux-cachyos-rt-bore-headers linux-cachyos-rt-bore-nvidia-open
   IgnorePkg = linux-cachyos-server linux-cachyos-server-headers linux-cachyos-server-nvidia-open linux-cachyos-server-zfs
   ```

   *Teraz wszystkie te pakiety będą ignorowane podczas regularnych aktualizacji, ale sprawdzane podczas przygotowania do aktualizacji offline.*

3. **Rozpocznij przygotowanie do aktualizacji offline tylko raz**

   ```bash title='Uruchom następujące polecenie'
   sudo systemctl start pacman-offline-prepare.service
   ```
   To polecenie spowoduje jednorazowe wykonanie pacman-offline, zsynchronizowanie baz danych pakietów i pobranie aktualizacji, ale bez ich instalacji.

</Steps>

*Jeśli chcesz, aby ten skrypt działał automatycznie, wykonaj następujące kroki:*

<Steps>

1. **Włącz timer przygotowania**

   Włączenie `pacman-offline-prepare.timer` pozwoli systemd na codzienne uruchamianie tego skryptu w celu pobierania aktualizacji kilka minut po każdym uruchomieniu systemu.

   ```bash
   sudo systemctl enable pacman-offline-prepare.timer
   ```

2. **Uruchom ponownie system:**

   Aktualizacje zostaną zainstalowane podczas następnego ponownego uruchomienia systemu.

3. **(Opcjonalnie) Automatyczne ponowne uruchamianie systemu:**

    Włącz `pacman-offline-reboot.timer`, aby system automatycznie uruchamiał się ponownie domyślnie o **3 w nocy** (Twoja strefa czasowa), jeśli są oczekujące aktualizacje. Pamiętaj, że nie zawsze odbywa się to o tej samej porze ze względu na `RandomizedDelaySec`, który domyślnie jest ustawiony na 2 godziny.

    ```bash
    sudo systemctl enable pacman-offline-reboot.timer
    ```

    :::tip
    Możesz edytować plik `pacman-offline-reboot.timer`, aby zmienić godzinę, o której system ma się ponownie uruchomić, jeśli są oczekujące aktualizacje, lub wyłączyć losowy harmonogram.
    :::

</Steps>

</TabItem>

<TabItem label="Cachy-Update">

Fork [Arch-Update](https://github.com/Antiz96/arch-update)

Powiadamiający o aktualizacjach i aplikujący je dla Arch Linux, który pomaga w ważnych zadaniach przed i po aktualizacji.
Zawiera dynamiczny i klikalny aplet w zasobniku systemowym dla łatwej integracji z dowolnym środowiskiem graficznym / menedżerem okien.

<details>
    <summary>Jak włączyć Cachy-Update</summary>
    Włącz Cachy-Update w `CachyOS Hello > Apps/Tweaks > Cachy Update enabled`
</details>
<details>
    <summary>Jak wyłączyć Cachy-Update</summary>
        Wyłącz Cachy-Update w `CachyOS Hello > Apps/Tweaks > Cachy Update disabled`
            :::tip
            Jeśli chcesz zachować Cachy-Update i wyłączyć jedynie aplet w zasobniku systemowym, otwórz terminal i uruchom następujące polecenia:
            ```bash
            mkdir -p ~/.config/autostart
            echo -e "[Desktop Entry]\nHidden=true" > ~/.config/autostart/arch-update-tray.desktop
            ```
            Jeśli chcesz zachować aplet w zasobniku systemowym i po prostu wyłączyć automatyczne sprawdzanie aktualizacji, uruchom następujące polecenie:
            ```bash
            systemctl --user disable --now arch-update.timer
            ```
            :::
</details>

- Funkcje:
  - Automatyczne sprawdzanie i listowanie dostępnych aktualizacji.
  - Sprawdzanie najnowszych wiadomości z Arch Linux (i oferowanie ich wyświetlenia, jeśli są).
  - Sprawdzanie osieroconych pakietów (i oferowanie ich usunięcia, jeśli są).
  - Sprawdzanie starych i odinstalowanych pakietów w pamięci podręcznej (i oferowanie ich usunięcia, jeśli są).
  - Sprawdzanie oczekującej aktualizacji jądra wymagającej ponownego uruchomienia (i oferowanie tego, jeśli jest).
  - Sprawdzanie usług wymagających ponownego uruchomienia po aktualizacji (i oferowanie tego, jeśli są).
  - Wsparcie dla `sudo`, `sudo-rs`, `doas` i `run0`.

**Interwał sprawdzania aktualizacji:** `Raz dwie minuty po uruchomieniu, a następnie raz dziennie z godzinnym losowym opóźnieniem.`

- Jak zmienić interwał sprawdzania aktualizacji:

```sh title='Uruchom następujące polecenie'
systemctl --user edit --full arch-update.timer
# Wskazówka: Możesz również użyć dowolnego edytora tekstu zamiast `nano`
# np. EDITOR=micro systemctl --user edit --full arch-update.timer
```

<details>
<summary>Domyślna zawartość pliku:</summary>
    ```systemd
    [Timer]
    OnStartupSec=2min # Sprawdź aktualizacje dwie minuty po uruchomieniu
    RandomizedDelaySec=1h # Godzinne losowe opóźnienie
    OnUnitActiveSec=1d # Sprawdzaj aktualizacje raz dziennie
    ```
</details>
Zasadniczo możesz zmienić wartość `OnUnitActiveSec` na dowolną. Na przykład, jeśli chcesz sprawdzać aktualizacje co 30 minut, zmień ją na `30m`. lub co 6 godzin, zmień ją na `6h`. Sprawdź ten [dokument](https://www.freedesktop.org/software/systemd/man/latest/systemd.time.html#Parsing%20Time%20Spans) aby uzyskać więcej informacji na temat ustawiania interwału czasowego.

W przypadku, gdy chcesz, aby Cachy-Update sprawdzał nowe aktualizacje tylko raz przy starcie systemu, możesz po prostu całkowicie usunąć linię `OnUnitActiveSec`.

Podziękowania dla [Antiz](https://github.com/Antiz96) za utrzymywanie projektu nadrzędnego Arch-Update i za implementację Cachy-Update

### Konfiguracja Zapory Sieciowej (ufw)
:::note
UFW jest domyślnie włączone po instalacji.
:::
Aby skonfigurować ufw, wykonaj następujące kroki:

<Tabs>

<TabItem label="Włącz">

```bash
sudo ufw enable
```

</TabItem>

<TabItem label="Wyłącz">

```bash
sudo ufw disable
```

</TabItem>

<TabItem label="Zezwól">

Domyślnie ufw ignoruje ruch przychodzący i zezwala na ruch wychodzący; możesz dodać konkretne reguły do zapory sieciowej, aby blokować lub zezwalać na określone połączenia.

```bash
# Przykład 1, zezwól na ruch ssh:
sudo ufw allow ssh
# Przykład 2, otwórz port 12345 dla ruchu TCP i UDP:
sudo ufw allow 12345

# Tekst lub numer portu można dostosować według potrzeb, np. 12345/udp, aby zezwolić tylko na ruch UDP, lub zastępując ssh nazwą programu
```

</TabItem>

<TabItem label="Odmów">

Domyślnie ufw ignoruje ruch przychodzący i zezwala na ruch wychodzący; możesz dodać konkretne reguły do zapory sieciowej, aby blokować lub zezwalać na określone połączenia.

```bash
# Przykład 1, zablokuj ruch ssh:
sudo ufw deny ssh
# Przykład 2, zamknij port 12345 dla ruchu TCP i UDP:
sudo ufw deny 12345

# Tekst lub numer portu można dostosować według potrzeb, np. 12345/udp, aby zablokować tylko ruch UDP, lub zastępując ssh nazwą programu
```

</TabItem>

<TabItem label="Status">

```bash
sudo ufw status verbose
```
:::tip
Jeśli nie chcesz zapomnieć, dlaczego otworzyłeś/zamknąłeś dany port, dodaj komentarz do reguły.
```bash
# Przykład 1, otwórz port 12345 dla ruchu TCP i UDP z komentarzem:
sudo ufw allow 12345 comment 'Example'
# Przykład 2, zamknij port 6789 dla TCP z komentarzem:
sudo ufw deny 6789/tcp comment 'Comments can have spaces'
```
:::
</TabItem>

</Tabs>

:::note
Zachowaj ostrożność podczas konfigurowania reguł zapory sieciowej, ponieważ nieprawidłowo skonfigurowane reguły mogą zablokować dostęp do Twojego systemu.
:::

:::note
Możesz także skonfigurować ją graficznie, korzystając z sekcji "Zapora sieciowa" w ustawieniach KDE Plasma.
:::

:::note
Zmiany w regułach zezwalania/odmowy wchodzą w życie po ponownym uruchomieniu ufw. Wyłącz, a następnie ponownie włącz ufw, aby uzyskać natychmiastowy efekt.
:::

## Opcjonalne konfiguracje

### Zmiana Domyślnej Powłoki

Obecnie CachyOS używa [fish](https://fishshell.com/) jako domyślnej powłoki logowania użytkownika. Jednak możesz zmienić
domyślną powłokę na dowolną inną.

<Tabs>
   <TabItem label='bash'>

      Jest to domyślna powłoka w prawie każdej dystrybucji Linuksa. Jest również nadal używana jako powłoka logowania użytkownika root. bash
      posiada podstawową funkcjonalność autouzupełniania i łatwe zarządzanie historią. Różni się od zsh i fish tym, że nie ma
      zaawansowanej personalizacji i ekosystemu wtyczek, które mają zarówno fish, jak i zsh.


      ```sh title='Zmiana domyślnej powłoki na bash'
      chsh -s /usr/bin/bash
      ```

   </TabItem>

   <TabItem label='zsh'>

      Dostarczamy [konfigurację zsh](https://github.com/CachyOS/cachyos-zsh-config) z często używanymi wtyczkami i konfiguracjami.
      Ma ona na celu zapewnienie funkcjonalności 1:1 z naszą [konfiguracją fish](https://github.com/CachyOS/cachyos-fish-config).
      Jest to również domyślna powłoka używana w MacOS.

      ```sh title='Zmiana domyślnej powłoki na zsh'
      chsh -s /usr/bin/zsh
      ```

   </TabItem>
</Tabs>

### Aktualizacja/używanie [tldr](https://github.com/tldr-pages/tldr)

:::note
CachyOS używa [tealdeer](https://github.com/tealdeer-rs/tealdeer), która jest szybszą implementacją oryginalnego tldr opartą na Rust.
:::

To narzędzie jest niezwykle przydatne dla tych, którzy nie chcą dużo czytać ani tracić czasu na czytanie strony pomocy/man.

<Steps>

1. ```sh title="Otwórz terminal i uruchom następujące polecenie"
   tldr --update
   ```
2. Przykład użycia tldr:
   ```sh
   tldr java
     Execute a `.jar` program:

      java -jar filename.jar

   # Jak widać, jest to naprawdę przydatne, a nowe narzędzia/strony są dodawane z czasem.
   ```

</Steps>

### Zarządzanie plikami AppImage

AppImage to przenośne aplikacje, które działają na większości dystrybucji Linuksa bez potrzeby instalacji ani uprawnień roota.

:::note[Wszystkie pliki AppImage wymagają uprawnień do wykonywania, aby mogły być uruchomione.]
Możesz ustawić uprawnienia do wykonywania za pomocą następującego polecenia:
```sh
chmod +x /ścieżka/do/twojego/appimage
```
Lub kliknij prawym przyciskiem myszy plik AppImage, przejdź do `Właściwości` > `Uprawnienia` i zaznacz pole `Zezwalaj na wykonywanie pliku jako programu`.
:::

:::note[Przed uruchomieniem plików AppImage upewnij się, że na Twoim systemie zainstalowany jest FUSE (Filesystem in Userspace).]
```sh
sudo pacman -S fuse2
```
:::

Do zarządzania plikami AppImage możesz użyć [gearlever](https://github.com/mijorus/gearlever), który zapewnia łatwy sposób integracji plików AppImage z systemem.

`gearlever` to graficzne narzędzie, które upraszcza zarządzanie plikami AppImage w systemie. Integruje się ze środowiskiem graficznym, ułatwiając uruchamianie i zarządzanie plikami AppImage.

Aby zainstalować gearlever, wykonaj następujące kroki:

<Steps>
    1. Zainstaluj flatpak, jeśli jeszcze go nie masz:
        ```sh
        sudo pacman -S flatpak
        ```
    2. Uruchom ponownie system.
    3. Zainstaluj gearlever za pomocą flatpaka:
        ```sh
        flatpak install flathub it.mijorus.gearlever
        ```
    4. Po instalacji wyloguj się i zaloguj ponownie, aby zobaczyć gearlever w menu aplikacji.
</Steps>

### Konfiguracja dostępu do udziałów Samba

Samba to darmowa re-implementacja protokołu sieciowego SMB. Aby połączyć się z serwerem samba, udostępniono użytkownikom CachyOS przydatną konfigurację, ale wymaga ona zmiany konfiguracji serwera samba.

#### Instalacja i używanie pliku smb.conf CachyOS

Aby użyć wygodnego pliku smb.conf, najpierw zainstaluj odpowiedni pakiet, który dostarcza wymagany plik smb.conf. Następnie zastąp istniejący plik smb.conf na serwerze tym plikiem i ponownie skonfiguruj udostępnione woluminy.

:::note[Ten przewodnik zakłada, że masz już działający serwer Samba]
:::

<Steps>
    1. Utwórz kopię zapasową oryginalnego pliku `smb.conf`, zwykle znajdującego się w `/etc/samba/smb.conf` w systemach Linux.
    2. Zainstaluj pakiet ustawień Samba CachyOS na maszynie klienta:
        ```sh
        sudo pacman -S cachyos-samba-settings
        ```
    3. Skopiuj plik `smb.conf` z maszyny klienta na serwer Samba.
    4. Otwórz i edytuj plik, aby dodać swoje udostępnione katalogi, drukarki itp.
    5. Zrestartuj usługę Samba na serwerze:
        ```sh
        sudo systemctl restart --now samba
        ```
    6. Na maszynie klienta uzyskaj dostęp do udostępnionych zasobów za pomocą menedżera plików (np. `smb://<adres_ip_serwera>/<nazwa_udziału>`).

        Jeśli skonfigurowano poprawnie, zostaniesz poproszony o dane logowania. Pamiętaj, aby wybrać opcję zapisania informacji logowania, jeśli chcesz.
</Steps>

### Wsparcie AppArmor przy użyciu profili AppArmor.d

Cytat z Wikipedii:

*AppArmor („Application Armor”) to moduł bezpieczeństwa jądra Linux, który pozwala administratorowi systemu ograniczać uprawnienia programów za pomocą profili przypisanych do poszczególnych programów. Profile mogą zezwalać na takie uprawnienia jak dostęp do sieci, dostęp do surowych gniazd (raw sockets) oraz uprawnienia do odczytu, zapisu lub wykonywania plików pod pasującymi ścieżkami.*

Jest to jedynie wprowadzenie do instalacji podstawowej konfiguracji AppArmor — jeśli nie znasz AppArmor, nie kontynuuj bez zrozumienia konsekwencji.

Więcej szczegółowych informacji o AppArmor.d oraz o tym, jak tworzyć własne profile, znajdziesz w [dokumentacji AppArmor.d](https://github.com/roddhjav/apparmor.d?tab=readme-ov-file#configuration).

:::caution[Postępuj ostrożnie. Źle skonfigurowana instalacja AppArmor może powodować problemy.]
:::

<Steps>

1. Dodaj następujące parametry jądra do swojego menedżera rozruchu, zobacz [Konfiguracja menedżera rozruchu](/pl/configuration/boot_manager_configuration) jako odniesienie

   ```text
   lsm=landlock,lockdown,yama,integrity,apparmor,bpf
   ```

2. Zainstaluj pakiety apparmor i apparmord **(Zestaw ponad +1500 profili)**
   ```bash
   sudo pacman -S apparmor apparmor.d
   ```

3. Włącz/Uruchom usługę AppArmor

   ```bash
   systemctl enable --now apparmor.service
   ```

4. Włącz buforowanie profili AppArmor

   ```shell
   # /etc/apparmor/parser.conf
   ## Dodaj następujące linie:
   write-cache
   Optimize=compress-fast
   cache-loc /etc/apparmor/earlypolicy/
   ```
   Zapisz plik i uruchom ponownie.
</Steps>

### Włączanie TRIM na szyfrowanych urządzeniach (LUKS)

CachyOS domyślnie włącza `fstrim.timer`, aby okresowo wykonywać operację TRIM na dyskach SSD i NVMe, co pomaga utrzymać wydajność zapisu i wydłużyć żywotność dysku. Jednak warstwa szyfrowania device-mapper w systemie Linux (`dm-crypt`/LUKS) domyślnie blokuje polecenia discard (TRIM). W rezultacie okresowy TRIM działa po cichu, pomijając zaszyfrowane partycje, chyba że przekazywanie poleceń discard zostanie jawnie włączone.

:::caution[Kwestie bezpieczeństwa i prywatności]
Włączenie TRIM na zaszyfrowanym urządzeniu pozwala kontrolerowi dysku SSD określić, które sektory są puste, a które zawierają dane. Choć Twoje dane pozostają w pełni zaszyfrowane, osoba atakująca z fizycznym dostępem do surowego nośnika mogłaby wywnioskować przybliżoną ilość zajętego miejsca, układ systemu plików lub wzorce danych.

Jeśli taki wyciek metadanych jest akceptowalny w Twoim modelu zagrożeń, możesz bezpiecznie włączyć przekazywanie discard, aby poprawić wydajność i kondycję dysku SSD.
:::

#### Włączanie przekazywania Discard (LUKS2)

<Steps>
1. Określ nazwę aktywnego mapowania LUKS:

   ```bash
   lsblk
   ```

   Poszukaj wpisu typu `crypt` pod swoją partycją dysku (np. `luks-1e647929-62c0-4922-8944-f941ed4155fd`).

2. Włącz trwałe przekazywanie discard dla aktywnego mapowania LUKS:

   ```bash
   sudo cryptsetup --allow-discards --persistent refresh <mapper_name>
   ```

   :::note
   Zastąp `<mapper_name>` swoją rzeczywistą nazwą mapowania znalezioną w kroku 1 (na przykład `sudo cryptsetup --allow-discards --persistent refresh luks-1e647929-62c0-4922-8944-f941ed4155fd`).
   :::

3. Uruchom ponownie system, aby zastosować zmiany.

4. Sprawdź, czy przekazywanie discard jest aktywne:

   ```bash
   lsblk -D
   sudo fstrim -v /
   ```

   Polecenie `lsblk -D` powinno teraz wyświetlać niezerowe wartości w kolumnach `DISC-GRAN` oraz `DISC-MAX` dla Twojego zaszyfrowanego woluminu, a `fstrim` wypisze ilość przyciętego miejsca zamiast pomijać urządzenie.
</Steps>
