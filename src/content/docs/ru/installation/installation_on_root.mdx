## Перед началом

:::note[Если после нажатия «Запустить установщик» в качестве опций менеджера загрузки предлагаются только GRUB и Limine, значит, система загружена в режиме Legacy/BIOS.]
:::

:::danger[Установка нескольких окружений рабочего стола в процессе установки не допускается.]
:::

:::caution[Secure Boot и CSM должны быть отключены в настройках BIOS/UEFI при установке в режиме UEFI.]
Чтобы настроить Secure Boot после установки, обратитесь к разделу [Настройка Secure Boot](/ru/configuration/secure_boot_setup).

`Legacy USB Support` должен быть установлен в `Auto`
:::

:::caution
Опции `Установить рядом` и `Заменить раздел` не на 100% надёжны и могут привести к сбою установки.

При установке CachyOS **предпочтительна** `Ручная разметка`.
:::

:::tip
Настоятельно рекомендуется перезагрузить ISO после неудачной попытки установки.

В противном случае в процессе установки могут возникать постоянные ошибки.

Это происходит потому, что установщик не может корректно отмонтировать разделы при неудачной установке.

:::

## Способы установки

### Ручная разметка

:::note[Прежде чем приступать к разметке диска для установки UEFI.]
    ```sh title='Выполните эту команду в терминале'
    efibootmgr -v
    ```
Если вывод: `EFI variables are not supported on this system.` (Переменные EFI не поддерживаются в этой системе), значит, система загружена в режиме Legacy/BIOS, и вам необходимо убедиться, что в настройках BIOS/UEFI сконфигурирован режим UEFI. Обратитесь к разделу **[Требования](/ru/installation/installation_on_root#_top).**
:::

<Steps>

</Steps>

## Двойная загрузка Windows и CachyOS

:::note[Это руководство предполагает, что Windows уже установлена на системе, и вы решили установить CachyOS рядом с ней на одном диске.]
:::

:::caution
Двойная загрузка Windows и Linux не является на 100% надёжной. Обновления Windows могут сломать загрузчик, перезаписав раздел EFI.
В некоторых случаях проблемы могут никогда не возникнуть, но для некоторых пользователей это может стать повторяющейся проблемой.

Один из способов избежать этой проблемы — установить каждую операционную систему на отдельные диски.
:::

:::caution
Раздел EFI может потребовать изменения размера в зависимости от рекомендуемого минимального размера для целевого менеджера загрузки. Обратитесь к **[Ручной разметке](/ru/installation/installation_on_root#ручная-разметка)**. Обратите внимание, что файловые системы FAT не могут быть изменены «на месте». Чтобы правильно «изменить размер» раздела FAT EFI, необходимо сделать резервную копию существующей файловой системы EFI, использовать инструмент, такой как `gparted`, для изменения размера существующего раздела и переформатирования нового раздела, а затем скопировать предыдущую структуру файловой системы обратно в раздел EFI.
:::

- Предварительные требования

- Отключите быстрый запуск и гибернацию Windows
  - Откройте Windows Powershell от имени администратора и выполните следующую команду:
      ```ps
      powercfg /H off
      ```
    Перезагрузите систему, чтобы убедиться, что изменения вступили в силу.
- Windows BitLocker должен быть отключен
  - Проверка, включен ли BitLocker:
    ```ps title='Откройте командную строку от имени администратора и выполните следующую команду'
    manage-bde -status
    ```
  Если в поле «Метод шифрования» указано `None`, значит, BitLocker отключен.
- Secure Boot должен быть отключен.
- Пустой раздел размером +30 ГБ
  - Руководство по сжатию раздела Windows:
    - Нажмите `Win + R`, введите `diskmgmt.msc` и нажмите Enter, чтобы открыть «Управление дисками».
    - Найдите основной раздел Windows (обычно C:) и щёлкните по нему правой кнопкой мыши.
    - Нажмите `Сжать том...`, укажите не менее **30720 МБ** (30 ГБ) и нажмите `Сжать`.
- Загрузочный USB с CachyOS
  - Обратитесь к разделу [Создание загрузочного USB-накопителя CachyOS](/ru/installation/installation_prepare#создание-загрузочного-usb-накопителя-cachyos).

<Tabs>
    <TabItem label='systemd-boot'>
        **Нам нужно скопировать бинарные файлы Windows EFI в раздел Linux EFI, чтобы менеджер загрузки мог их распознать.**

        <Steps>
        1. Найдите **раздел Windows EFI** с помощью `lsblk`

            ```sh title='Выполните эту команду в терминале'
            lsblk -o NAME,FSTYPE,SIZE,MOUNTPOINT
            ```
            ```sh title='Пример вывода'
                        NAME        FSTYPE   SIZE MOUNTPOINT
            zram0               15.3G [SWAP]
            nvme0n1            476.9G
            ├─nvme0n1p1 vfat     100M
            ├─nvme0n1p2           16M
            ├─nvme0n1p3 ntfs   234.4G
            ├─nvme0n1p4 ntfs     830M
            ├─nvme0n1p5 vfat       2G /boot
            └─nvme0n1p6 btrfs  239.6G /var/tmp
            ```
            Разделы EFI почти всегда отформатированы как `FAT32/vfat`. Поскольку `nvme0n1p1` не имеет точки монтирования в Linux, можно предположить, что этот раздел является разделом EFI Windows.

        2. Временно смонтируйте раздел EFI Windows

            ```sh
            sudo mkdir /mnt/WinBoot
            sudo mount /dev/nvme0n1p1 /mnt/WinBoot # Замените `nvme0n1p1` на имя раздела EFI Windows.
            ```

        3. Скопируйте бинарные файлы EFI из **раздела EFI Windows** в **раздел EFI Linux**:

            ```sh
            sudo cp -r /mnt/WinBoot/EFI/Microsoft/ /boot/EFI
            ```

        4. Отмонтируйте ранее смонтированный раздел, и Windows должна появиться в меню загрузки при следующем запуске.

            ```sh
            sudo umount /mnt/WinBoot
            sudo rm -r /mnt/WinBoot
            ```

        </Steps>
    </TabItem>

    <TabItem label='GRUB'>
        **GRUB использует os-prober для автоматического обнаружения раздела EFI Windows и добавления его в меню загрузки.**

        <Steps>
        1. Установите и запустите **os-prober**

            ```sh
            sudo pacman -S os-prober
            sudo os-prober
            ```

        2. Включите **os-prober** в файле конфигурации GRUB

            ```sh title='Нажмите CTRL+S для сохранения и CTRL+Q для выхода из Micro'
            sudo micro /etc/default/grub
            # /etc/default/grub
            # Probing for other operating systems is disabled for security reasons. Read
            # documentation on GRUB_DISABLE_OS_PROBER, if still want to enable this
            # functionality install os-prober and uncomment to detect and include other
            # operating systems.
            GRUB_DISABLE_OS_PROBER=false

            sudo grub-mkconfig -o /boot/grub/grub.cfg
            ```

            **Теперь Windows должна быть добавлена в меню загрузки.**

        </Steps>
    </TabItem>
</Tabs>
