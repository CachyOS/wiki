## Установка и Live-окружение

### Почему в live ISO CachyOS доступен только KDE Plasma?

Мы решили сосредоточить наши усилия по разработке и поддержке исключительно на окружении рабочего стола KDE Plasma. Это позволяет нам предоставлять более отточенный, стабильный и последовательный пользовательский опыт в нашем live ISO.

Live-окружение в первую очередь предназначено для установки CachyOS или использования cachy-chroot для восстановления системы. Для безопасного тестирования других окружений рабочего стола или оконных менеджеров мы настоятельно рекомендуем пробовать их в виртуальной машине (ВМ).

### Почему установщик долго запускается после нажатия "Запустить установщик"?

:::caution
Убедитесь, что у вас есть активное интернет-соединение, иначе после нажатия этой кнопки ничего не произойдет.
:::

Установщик не завис. Он выполняет необходимый фоновый скрипт для подготовки вашей системы к установке. Этот процесс гарантирует, что связки ключей и системное время обновлены, что помогает предотвратить распространенные проблемы при установке.

[Просмотрите скрипт на GitHub](https://github.com/CachyOS/CachyOS-Live-ISO/blob/master/archiso/airootfs/usr/local/bin/calamares-online.sh), чтобы лучше понять, что он делает.
<Steps>
  1. Удаляет старые файлы связок ключей.
  2. Устанавливает и обновляет последние пакеты связок ключей Arch Linux и CachyOS.
  3. Инициализирует и заполняет связку ключей pacman.
  4. Включает синхронизацию времени по сети.
  5. Проверяет тип загрузки вашей системы (UEFI или BIOS/MBR), чтобы предложить пользователю выбрать загрузчик в зависимости от типа.
</Steps>

Вот почему загрузка установщика может занять некоторое время.

### Почему моя установка застряла на 33%?

Это происходит, когда установщику не удается загрузить пакеты. Обычно это признак очень медленного или нестабильного интернет-соединения. Пожалуйста, проверьте ваше сетевое подключение и попробуйте снова.

## Управление пакетами и обновления

### Устранение неполадок Pacman

#### error: signature is invalid (ошибка: подпись недействительна)

Эта ошибка указывает на проблему с криптографической подписью пакета. Обычно она вызвана устаревшим зеркалом или поврежденной связкой ключей в вашей системе.

Хотя зеркала часто исправляются сами по себе через некоторое время, если проблема сохраняется, вам следует попробовать одно из следующих двух решений.

<Tabs>

<TabItem label='Первое решение: Оценить зеркала'>

```sh title='Оцените ваши зеркала'
sudo cachyos-rate-mirrors
```

</TabItem>

<TabItem label='Второе решение: Сбросить связки ключей'>

Если оценка зеркал не помогла, вероятно, связки ключей вашей системы повреждены.

- Откройте CachyOS Hello и перейдите в **Apps/Tweaks**.
- Нажмите кнопку Reset keyrings (Сбросить связки ключей).

</TabItem>

</Tabs>

#### error: 404 Not Found

Эта ошибка означает, что пакет, который вы пытаетесь установить, недоступен на вашем текущем зеркале. Обычно это происходит, когда ваша локальная база данных пакетов не синхронизирована с удаленными репозиториями.

**Решение:**

Выполните следующую команду, чтобы обновить базу данных пакетов и выполнить полное обновление системы. Это гарантирует, что ваша система будет знать о последних доступных пакетах.

```sh
sudo pacman -Syu
# Затем попробуйте снова установить нужный пакет.
```

#### error: could not remove

Эта ошибка возникает, когда кэш pacman содержит файлы, которыми система не может управлять автоматически. Это распространенная проблема, которую можно легко исправить.

- Решение 1: Используйте CachyOS Hello.
  - Самый простой способ исправить это — с помощью CachyOS Hello. Откройте его и перейдите в **Apps/Tweaks**, затем нажмите кнопку **Clear package cache** (Очистить кэш пакетов).

- Решение 2: Удалите кэш вручную.
  - Выполните следующую команду, чтобы удалить все осиротевшие пакеты из кэша.
  ```sh
  sudo rm -r /var/cache/pacman/pkg/*
  ```

#### error: File is corrupted (invalid or corrupted package (PGP signature))

```sh
# Пример:
:: File /var/cache/pacman/pkg/python-charset-normalizer-3.4.0-1-any.pkg.tar.zst
is corrupted (invalid or corrupted package (PGP signature)).
```

Эта ошибка обычно указывает на проблему со связками ключей pacman в вашей системе, которые проверяют подлинность пакетов. Следующие команды сбросят и повторно заполнят связки ключей, чтобы решить проблему.

```sh
sudo rm -rf /etc/pacman.d/gnupg/ # Принудительно удалить старые связки ключей
sudo pacman-key --init # Инициализировать связку ключей
sudo pacman-key --populate # Заполнить связку ключей

sudo pacman-key --recv-keys F3B607488DB35A47 --keyserver keyserver.ubuntu.com # Вручную импортировать ключ CachyOS
sudo pacman-key --lsign-key F3B607488DB35A47 # Вручную подписать ключ

sudo rm -R /var/lib/pacman/sync # Удалить синхронизированные базы данных, чтобы принудительно загрузить их заново
```

#### error: unable to lock database

Эта ошибка возникает, когда уже запущен другой процесс pacman, который блокирует базу данных для предотвращения повреждения. Если предыдущий процесс завершился аварийно или был прерван, файл блокировки `db.lck` мог не удалиться.

- Решение 1: Используйте CachyOS Hello
  - Самый простой способ исправить это — использовать функцию **Remove db lock** (Удалить блокировку БД) на вкладке **Apps/Tweaks** в CachyOS Hello

- Решение 2: Удалите файл блокировки вручную
  - Если вы предпочитаете не использовать CachyOS Hello, вы можете удалить файл блокировки вручную:

```sh
sudo rm /var/lib/pacman/db.lck
```

#### error: failed retrieving file ... Connection timed out

Вы можете видеть ошибки, подобные этим:

```text
# Примеры ошибок:
error: failed retrieving file '...' from ... : Connection timed out
error: failed retrieving file '...' from ... : Couldn't resolve host name
error: failed retrieving file '...' from ... : The requested URL returned error: 526
```

Эти ошибки почти всегда указывают на проблему с вашими текущими зеркалами. Они могут быть медленными, временно недоступными или недостижимыми из вашего местоположения.

- Решение: Лучший способ исправить это — обновить список зеркал на более быстрые и надежные.

```sh
sudo cachyos-rate-mirrors
# После этого вы можете обновить систему с помощью:
sudo pacman -Syu
```

:::tip
Команда `cachyos-rate-mirrors` тестирует доступные зеркала CachyOS по скорости и статусу синхронизации, а затем обновляет ваш файл списка зеркал (`/etc/pacman.d/cachyos-mirrorlist`) самыми производительными.

Рекомендуется периодически запускать ее, особенно если вы замечаете замедление во время обновлений системы.
:::

#### warning: local is newer than...

Это предупреждение появляется, когда версия пакета в вашей системе новее, чем версия, доступная в официальных репозиториях. Это может произойти, если зеркало устарело, если версия пакета в репозиториях была понижена или если пакет был установлен из другого источника.

- Решение: команда `pacman -Syuu` выполняет полное обновление системы и разрешает понижение версий, что устранит предупреждение, синхронизировав ваши локальные пакеты с версиями в репозитории.

```sh title='Чтобы убрать эти предупреждения, выполните следующую команду:'
sudo pacman -Syuu
```

#### error: failed to commit transaction (conflicting files)

Эта ошибка указывает на то, что pacman пытается установить или обновить пакет, который содержит файлы, уже присутствующие в вашей системе из другого источника. Это встроенная функция безопасности для предотвращения поломки системы.

- Решение: Вы можете решить эту проблему, удалив конфликтующие файлы вручную. Для получения дополнительной информации и решений, пожалуйста, обратитесь к [Arch Wiki](https://wiki.archlinux.org/title/Pacman#%22Failed_to_commit_transaction_(conflicting_files)%22_error).

```sh title='Пример'
error: failed to commit transaction (conflicting files)
nvidia-utils: /usr/lib/environment.d/10-gsk.conf exists in filesystem
Errors occurred, no packages were upgraded.
 -> error installing repo packages
```

Чтобы исправить этот конкретный пример, вам нужно удалить конфликтующий файл, а затем снова запустить команду обновления.

```sh
sudo rm /usr/lib/environment.d/10-gsk.conf
```

#### ERROR: module not found: 'nvidia', 'nvidia_modeset', ...

```sh title='Пример'
==> ERROR: module not found: 'nvidia'
==> ERROR: module not found: 'nvidia_modeset'
==> ERROR: module not found: 'nvidia_uvm'
==> ERROR: module not found: 'nvidia_drm'
```

**Две причины этой ошибки:**

1) Поскольку ранняя загрузка модулей всегда включена в chwd, mkinitcpio постоянно ожидает наличия модулей NVIDIA; эта ошибка возникает, когда эти модули отсутствуют.

2) У вас могут отсутствовать модули NVIDIA от других установленных ядер в вашей системе.

```sh title='Установите следующий пакет, чтобы исправить эту ошибку'
sudo pacman -S nvidia
```

### Общие вопросы

#### С какой периодичностью обновляются -git пакеты?

Обычно раз в понедельник, хотя могут быть исключения.

#### Почему в некоторых репозиториях есть два одинаковых пакета wine?

- `cachyos-v3/v4/wine` = Wine с набором патчей NTSync
- `cachyos-extra-v3/v4/znver4/wine` = Стандартный Wine, **пересобранный CachyOS**

Как только в Wine будет включен набор патчей NTSync, мы удалим пакет `cachyos-v3/v4/wine`. Пакет `cachyos-extra-v3/v4/znver4/wine` останется доступным.

#### Как отключить анимацию загрузки (Plymouth)

:::note[Это может решить проблему с черным экраном на некоторых системах, например, со старыми видеокартами NVIDIA]
:::

Чтобы отключить анимацию загрузки, вам нужно отредактировать конфигурацию вашего [загрузчика](/ru/configuration/boot_manager_configuration) и добавить следующие параметры ядра:

```sh
plymouth.enable=0 disablehooks=plymouth
```

:::note[systemd-boot, GRUB и Limine требуют перегенерации образов initramfs]
systemd-boot: `sudo sdboot-manage gen`

GRUB: `sudo grub-mkconfig -o /boot/grub/grub.cfg`

Limine: `sudo limine-mkinitcpio`
:::

## Безопасность и лучшие практики

### Практики безопасного использования AUR

AUR предлагает огромный выбор, но безопасность превыше всего. Вот краткое руководство по безопасному использованию AUR в вашей системе CachyOS.

* **1. Понимайте PKGBUILD:** Это скрипт сборки. Изучите его структуру, переменные (`source`, `pkgname`) и функции (`build()`, `package()`).
* **2. Проверяйте ссылки на исходники:** Всегда проверяйте, что URL-адреса в `source` ведут на официальные сайты проектов или доверенные репозитории. Избегайте подозрительных или личных ссылок.
* **3. Просматривайте шаги установки:** Изучите, куда устанавливаются файлы (функция `package()`) и есть ли какие-либо необычные команды или команды, затрагивающие чувствительные области системы. Также проверяйте `.install` скрипты.
* **4. Исследуйте мейнтейнера:** Просмотрите историю мейнтейнера на AUR на предмет прошлых проблем с безопасностью или подозрительной активности.
* **5. Проверяйте контрольные суммы и PGP:** Абсолютно необходимо! Убедитесь, что все контрольные суммы (SHA256, BLAKE2b и т. д.) совпадают с исходными. Используйте PGP-подписи (`validpgpkeys`) для проверки подлинности, когда это возможно.
* **6. Будьте осторожны с `-bin` пакетами:** Они используют предварительно скомпилированные бинарные файлы, что означает, что вы не можете проверить исходный код. Проявляйте максимальную бдительность в отношении их происхождения и целостности.
* **7. Читайте комментарии сообщества:** Проверяйте комментарии на странице AUR на наличие предупреждений, проблем или мнений от других пользователей.
* **8. Никогда не пропускайте проверку целостности:** Использование `--skipinteg` или подобных флагов обходит все проверки безопасности. Не делайте этого.
* **9. Контролируйте свой AUR-хелпер:** Понимайте, как работает ваш хелпер (yay, paru). Убедитесь, что он показывает вам PKGBUILD и его изменения, или собирайте вручную с помощью `makepkg`.
* **10. Оценивайте необходимость:** Перед установкой спросите себя, действительно ли вам нужен этот пакет из AUR, или существует альтернатива в официальных репозиториях.
* **11. Поддерживайте систему в актуальном состоянии:** Регулярно запускайте `sudo pacman -Syu`, чтобы все компоненты вашей системы, включая `pacman` и `makepkg`, имели последние исправления безопасности.

Будьте бдительны, чтобы ваша система на базе Arch оставалась в безопасности!

### Выбор графического менеджера пакетов

Хотя графические менеджеры пакетов предлагают удобство, некоторые из них известны тем, что вызывают серьезные проблемы в системах с плавающими релизами, таких как CachyOS, и их следует избегать для управления системными пакетами.

-   **Pamac:** известен тем, что некорректно обрабатывает некоторые задачи управления пакетами, такие как повреждение связок ключей системных пакетов. Это может привести к ошибкам PGP-подписей, которые помешают вам обновить систему.

-   **Discover (KDE) и GNOME Software Center:** Эти магазины приложений используют бэкенд PackageKit. Хотя они в целом безопасны для управления Flatpak-пакетами, использование их для установки или обновления **системных пакетов** рискованно. Менеджеры на основе PackageKit также могут быть нестабильными или подверженными сбоям, что может привести вашу систему в нерабочее состояние после неудачной транзакции.

Для максимальной стабильности и надежности мы **настоятельно рекомендуем** управлять системными пакетами через командную строку с помощью `pacman`

Если вы предпочитаете графический интерфейс, GUI-оболочки, такие как **[Octopi](</ru/configuration/post_install_setup/#обновление-системы>)** или **CachyOS Package Installer**, считаются безопасными альтернативами, поскольку они являются более прямыми обертками для функциональности pacman.
