Это руководство описывает основы использования файла fstab, расположенного в /etc/, для монтирования статических дисков во время загрузки. В нем кратко объясняется, как найти UUID раздела или диска, что делают некоторые опции, и даются ссылки для дальнейшего чтения, если предоставленной информации окажется недостаточно.

## Предварительные требования

- Доступ с правами root или через sudo

## Добавление записей в /etc/fstab

:::note[NTFS в Linux]
Файловая система NTFS может быть нестабильной в Linux, независимо от того, используется ли драйвер ntfs3 или ntfs-3g. Используйте её на свой страх и риск. Для лучшей стабильности и производительности рассмотрите нативные файловые системы Linux, такие как ext4, xfs или btrfs.
:::

### 1. Выведите список UUID ваших разделов

```sh title="Откройте терминал и выполните следующую команду"
lsblk -f
```

```text title="Пример вывода"
# NAME        FSTYPE FSVER LABEL UUID                                 FSAVAIL FSUSE% MOUNTPOINTS
# zram0                                                                              [SWAP]
# nvme0n1
# ├─nvme0n1p1 vfat   FAT32       E04D-9F05
# ├─nvme0n1p2
# ├─nvme0n1p3 ntfs               08A24E90A24E81E4                      715.4G    50%
# ├─nvme0n1p4 vfat   FAT32       E09C-D4DA                             628.1M    39% /boot
# ├─nvme0n1p5 ext4   1.0         187a9f06-9411-48d9-b941-f03c2e605812  203.6G    47% /
# └─nvme0n1p6 ntfs
```

В нашем примере мы знаем, что хотим смонтировать раздел Windows, который имеет файловую систему ntfs. Мы также знаем, что примерно половина его пространства свободна. Следовательно, мы можем определить, что раздел, который мы хотим смонтировать, это `nvme0n1p3`, его UUID — `08A24E90A24E81E4`, а файловая система в этом примере — `ntfs`.

### 2. Идентификация вашего раздела

Часто `lsblk -f` предоставляет всю необходимую информацию для монтирования диска через /etc/fstab. Если вы все еще не уверены, какой раздел является правильным, вы можете выполнить следующую команду:

```sh
sudo fdisk -l
```

```text title="Пример вывода"
# Device              Start        End    Sectors  Size Type
# /dev/nvme0n1p1       2048     206847     204800  100M EFI System
# /dev/nvme0n1p2     206848     239615      32768   16M Microsoft reserved
# /dev/nvme0n1p3     239616 2997384182 2997144567  1.4T Microsoft basic data
# /dev/nvme0n1p4 2997385216 2999482367    2097152    1G EFI System
# /dev/nvme0n1p5 2999482368 3905454079  905971712  432G Linux root (x86-64)
# /dev/nvme0n1p6 3905454080 3907026943    1572864  768M Windows recovery environment
```

В нашем примере мы уже знаем UUID. Однако, `fdisk -l` может сделать это немного понятнее, показав точный размер раздела (1.4T), а также его тип (Microsoft basic data).

Это должно сделать для нас совершенно очевидным, что нужный нам раздел — это `nvme0n1p3` с UUID `08A24E90A24E81E4`, как было описано ранее. Мы знали это и раньше, но теперь мы в этом абсолютно уверены.

Как только вы будете уверены, что нашли правильный раздел, скопируйте UUID. Копирование из эмулятора терминала обычно выполняется с помощью `ctrl+shift+C`.

### 3. Добавление записи в /etc/fstab

Теперь, когда мы получили UUID нашего раздела, пришло время открыть файл fstab.

Не стесняйтесь использовать текстовый редактор по вашему выбору. В этом примере мы будем использовать nano. Чтобы отредактировать файл fstab, его нужно открыть с правами root:

```sh
sudo nano /etc/fstab
```

Используя клавиши со стрелками, перейдите в конец файла fstab, затем создайте нашу новую запись на пустой новой строке:

```sh
UUID=08A24E90A24E81E4 /media/windows ntfs3 defaults,nofail,uid=1000,gid=1000,rw,user,exec,umask=000 0 0
```

Разберем эту запись:

- `UUID=08A24E90A24E81E4` — это файловая система, которую мы хотим смонтировать, идентифицированная по ее UUID. Существуют и другие методы идентификации вашей файловой системы, хотя UUID, как правило, является самым безопасным. Дополнительные методы перечислены [здесь](https://wiki.archlinux.org/title/Fstab#Identifying_file_systems).

- `/media/windows` — это точка монтирования нашего диска. [Стандарт иерархии файловой системы Linux](https://refspecs.linuxfoundation.org/FHS_3.0/fhs/index.html) гласит, что `/media/` является подходящим местом для монтирования съёмных носителей. `windows` указывает на каталог, в который мы хотим смонтировать наш диск. Каждому диску, который мы хотим смонтировать, потребуется свой собственный каталог.

- `ntfs3` — это тип используемой файловой системы. В нашем примере мы явно используем драйвер ядра ntfs3. Другими примерами могут быть `ext4`, `xfs` и тому подобное. Это явное объявление типа файловой системы можно заменить на `auto`, чтобы позволить команде mount самой определить тип.

- `defaults,nofail,uid=1000,gid=1000,rw,user,exec,umask=000`: Это опции монтирования:

  - `defaults`: стандартный набор опций, включающий `rw, suid, dev, exec, auto, nouser, и async.`

  - `nofail`: позволяет процессу загрузки продолжаться, даже если это монтирование не удалось.

  - `uid=1000` и `gid=1000`: устанавливает владельца и группу для смонтированных файлов на пользователя и группу с ID 1000.

  - `rw`: монтирует файловую систему для чтения и записи.

  - `user`: позволяет монтировать файловую систему пользователю без прав root.

  - `exec`: разрешает выполнение бинарных файлов на смонтированной файловой системе.

  - `umask=000`: устанавливает маску прав доступа к файлам, чтобы разрешить чтение, запись и выполнение для всех.

  - `первый 0` (dump) обычно устарел в современных системах. Оставление этого значения равным 0 ничему не повредит. Вы можете прочитать об этом подробнее [здесь](https://linux.die.net/man/8/dump).

  - `второй 0` устанавливает порядок проверки файловых систем при загрузке. Для корневого раздела это значение должно быть 1, если только ваша корневая файловая система не btrfs, для которой оно должно быть 0. Все остальные файловые системы в вашем fstab должны иметь значение либо 0 (отключено), либо 2. Больше информации [здесь](https://man.archlinux.org/man/fsck.8).

Для более подробного рассмотрения каждой опции посетите эти две страницы руководства: [fstab man page](https://man7.org/linux/man-pages/man5/fstab.5.html) и [mount man page](https://man7.org/linux/man-pages/man8/mount.8.html).

#### Дополнительная информация

К слову, все опции после объявления типа файловой системы являются необязательными, если вы не изменяете их по сравнению со значением по умолчанию.

Таким образом,

`UUID=<UUID раздела> /media/foo somefs`

и

`UUID=<UUID раздела> /media/foo somefs defaults 0 0`

эквивалентны. `somefs`, за которым ничего не следует, неявно означает `somefs defaults 0 0`.

### 4. Завершение

Если вы хотите смонтировать диск, для которого вы только что создали запись, вам нужно выполнить следующее:

```sh
sudo systemctl daemon-reload
```

а затем:

```sh
sudo mount -a
```

Ваш диск теперь должен появиться в `/media/windows` и будет появляться там при каждой перезагрузке.

```sh
ls /media/windows

# Games                     RetroArch-Win64

 ```

Если вы хотите создать символическую ссылку на ваш недавно смонтированный диск в домашнем каталоге, вы можете выполнить следующую команду:

 ```sh
 ln -s /media/windows ~/Windows
 ```

 Чтобы убедиться, что это сработало:

## tl;dr (кратко)

- Найдите **UUID** вашего раздела

```sh
lsblk -f
```

- Откройте `/etc/fstab`

```sh
sudo nano /etc/fstab
```

- Создайте запись в конце файла

```sh
UUID=<UUID раздела> /media/foo somefs defaults 0 0
```

Заменив `<UUID раздела>`, `foo` и `somefs` на ваш UUID, каталог и файловую систему, например, ext4, а также установив любые другие опции, которые вы хотите добавить после defaults, такие как `_netdev` для NAS или `nofail` для любого некритичного диска.

- Перезагрузите конфигурацию systemd

```sh
sudo systemctl daemon-reload
```

- Смонтируйте ваш диск

```sh
sudo mount -a
```

Этот диск теперь смонтирован и будет монтироваться при каждой загрузке в дальнейшем.
