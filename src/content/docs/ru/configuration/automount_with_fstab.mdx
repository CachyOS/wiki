Это руководство описывает основы использования как файлов монтирования systemd, так и файла fstab, расположенного в /etc/, для монтирования статических дисков во время загрузки. Здесь кратко объясняется, как найти UUID раздела или диска, что делают некоторые опции, а также приводятся ссылки для дальнейшего чтения, если предоставленной информации окажется недостаточно.

## Предварительные требования

-   Доступ с правами root или sudo

:::note[NTFS в Linux]
Файловая система NTFS может быть нестабильной в Linux при использовании драйверов ntfs, ntfs3 или ntfs-3g. Используйте её на свой страх и риск. Для лучшей стабильности и производительности рассмотрите использование нативных файловых систем Linux, таких как ext4, xfs или btrfs.
:::

## Более безопасный и понятный для новичков метод: монтирование дисков с помощью файлов монтирования systemd

Преимущество монтирования через systemd заключается в том, что даже если вы что-то сделаете неправильно в файле монтирования, ваша система всё равно загрузится. В то время как ошибка в fstab может сделать вашу систему невозможной для загрузки.

### 1. Вывод списка UUID ваших разделов

```sh title="Откройте терминал и выполните следующую команду"
lsblk -f
```

```sh title="Пример вывода"
NAME          FSTYPE FSVER LABEL UUID                                 FSAVAIL   FSUSE% MOUNTPOINTS
zram0                                                                              [SWAP]
nvme0n1
├─nvme0n1p1   vfat   FAT32       E04D-9F05
├─nvme0n1p2
├─nvme0n1p3   ntfs               08A24E90A24E81E4                      715.4G   50%
├─nvme0n1p4   vfat   FAT32       E09C-D4DA                             628.1M   39% /boot
├─nvme0n1p5   ext4   1.0         187a9f06-9411-48d9-b941-f03c2e605812  203.6G   47% /
└─nvme0n1p6   ntfs
nvme1n1
└─nvme1n1p1   ext4               4e55896f-3f1f-4bc5-aa8a-fec099689cd9  931.5G   0%

```

В этом примере мы хотим смонтировать дополнительный диск, который был только что отформатирован в ext4. Мы знаем, что это диск на 1 ТБ, и знаем, что на нём ещё ничего не хранится. Следовательно, мы можем определить, что раздел, который нужно смонтировать, — это `nvme1n1p1` с UUID `4e55896f-3f1f-4bc5-aa8a-fec099689cd9`.

### 2. Идентификация вашего раздела

Часто `lsblk -f` предоставляет всю информацию, необходимую для монтирования диска с помощью systemd на этом этапе. Если вы всё ещё не уверены, какой раздел является правильным, вы можете выполнить следующую команду:

```sh
sudo fdisk -l
```

```sh title="Пример вывода"
Device          Start       End         Sectors     Size    Type
/dev/nvme0n1p1  2048        206847      204800      100M    EFI System
/dev/nvme0n1p2  206848      239615      32768       16M     Microsoft reserved
/dev/nvme0n1p3  239616      2997384182  2997144567  1.4T    Microsoft basic data
/dev/nvme0n1p4  2997385216  2999482367  2097152     1G      EFI System
/dev/nvme0n1p5  2999482368  3905454079  905971712   432G    Linux root (x86-64)
/dev/nvme0n1p6  3905454080  3907026943  1572864     768M    Windows recovery environment
/dev/nvme1n1p1  2048        1953523711  1953521664  931.5G  Linux filesystem

```

В этом примере мы уже знаем наш UUID. Однако `fdisk -l` может сделать это немного понятнее, показав точный размер раздела (931.5G), а также его тип (Linux filesystem).

Это должно окончательно прояснить, что нужный нам раздел — `nvme1n1p1` с UUID `4e55896f-3f1f-4bc5-aa8a-fec099689cd9`, как было описано ранее. Мы и так это знали, но теперь просто уверены в этом на сто процентов.

Как только вы убедитесь, что нашли правильный раздел, скопируйте его UUID. Копирование из эмулятора терминала обычно выполняется с помощью `ctrl+shift+C`.

### 3. Создание файла монтирования systemd

Допустим, мы хотим использовать этот диск в основном для игр, хорошим местом для монтирования будет ваш домашний каталог пользователя. Это может быть где угодно, но для простоты мы остановимся на /home/user (замените user на ваше имя пользователя Linux). Это важно, потому что путь монтирования определяет имя файла монтирования systemd. Поскольку этот диск предназначен для игр, мы смонтируем его в папку games в домашнем каталоге пользователя, `/home/user/games`.

Для файла монтирования systemd это превращается в home-$USER-games.mount (прямые слеши `/` заменяются на дефисы `-`), а файлы монтирования systemd находятся в /etc/systemd/system.

:::tip
Если вы хотите использовать пробел, дефис, символ CJK или акцентированный символ в имени папки монтирования, его необходимо форматировать иначе. Допустим, вы хотите использовать путь папки `/home/grzegorz/brzęczyszczykiewicz`, выполните следующую команду, чтобы получить имя, которое вам нужно использовать с вашим файлом:
```bash
systemd-escape -p --suffix=mount "/home/grzegorz/brzęczyszczykiewicz"
```
Поскольку вам нужно экранировать любые `\`, вы создадите файл монтирования как `/etc/systemd/system/home-grzegorz-brz\\xc4\\x99czyszczykiewicz.mount`
:::

Вы можете использовать любой текстовый редактор по вашему выбору, в этом примере мы будем использовать `micro`.

```sh
micro /etc/systemd/system/home-$USER-games.mount
```
:::note
Если вы монтируете в свой домашний каталог пользователя, вы можете оставить вышеуказанный $USER в имени файла, ваше имя пользователя автоматически займёт его место.
:::

Вставьте этот шаблон в пустой файл:
```ini
[Unit]
Description=

[Mount]
What=
Where=
Type=
Options=

[Install]
WantedBy=multi-user.target
```
Ниже приведены описания для каждого поля в файле:

  </TabItem>

  </TabItem>

---

Следуя примеру, заполненный файл монтирования должен выглядеть так:
```ini
[Unit]
Description=Mount games drive (/home/user/games)

[Mount]
What=UUID=4e55896f-3f1f-4bc5-aa8a-fec099689cd9
Where=/home/user/games
Type=ext4
Options=defaults,exec,rw,noatime

[Install]
WantedBy=multi-user.target
```

### 4. Завершение

Чтобы смонтировать диск, для которого мы только что создали запись, выполните следующее:

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now home-$USER-games.mount
```

Вы должны увидеть папку, которую вы выбрали для точки монтирования, и можете проверить статус монтирования с помощью `systemctl status home-$USER-games.mount`:

### tl;dr

-   Найдите **UUID** вашего раздела

```sh
lsblk -f
```

-   Создайте файл монтирования

```sh
micro /etc/systemd/system/mnt-foo.mount
```

Замените `mnt-foo` на полный путь, куда вы хотите смонтировать, заменив `/` на `-`.

-   Заполните файл монтирования

```sh
[Unit]
Description=Mount drive

[Mount]
What=UUID=<partition UUID>
Where=/mnt/foo
Type=somefs
Options=defaults

[Install]
WantedBy=multi-user.target
```

Замените `<partition UUID>`, `/mnt/foo` и `somefs` на ваш UUID, каталог и файловую систему (например, ext4), а также установите любые другие опции, которые вы можете захотеть после defaults, такие как `_netdev` для NAS или `nofail` для любого некритичного диска.

-   Перезагрузите ваш daemon

```sh
sudo systemctl daemon-reload
```

-   Смонтируйте ваш диск и настройте его монтирование при загрузке

```sh
sudo systemctl enable --now mnt-foo.mount
```

## Продвинутый метод: добавление записей в /etc/fstab

:::danger
Файл fstab читается во время загрузки, и если в файле есть ошибка, это может привести к сбою загрузки вашей системы. Обязательно дважды проверьте вашу запись на наличие опечаток перед перезагрузкой. Если вы допустили ошибку, вы обычно можете исправить её, загрузившись в live-среду и [выполнив chroot в вашу установку](/ru/features/cachy_chroot), чтобы отредактировать файл.
:::

### 1. Вывод списка UUID ваших разделов

```sh title="Откройте терминал и выполните следующую команду"
lsblk -f
```

```sh title="Пример вывода"
NAME        FSTYPE FSVER LABEL UUID                                 FSAVAIL FSUSE% MOUNTPOINTS
zram0                                                                              [SWAP]
nvme0n1
├─nvme0n1p1 vfat   FAT32       E04D-9F05
├─nvme0n1p2
├─nvme0n1p3 ntfs               08A24E90A24E81E4                      715.4G    50%
├─nvme0n1p4 vfat   FAT32       E09C-D4DA                             628.1M    39% /boot
├─nvme0n1p5 ext4   1.0         187a9f06-9411-48d9-b941-f03c2e605812  203.6G    47% /
└─nvme0n1p6 ntfs
```

В нашем примере мы знаем, что хотим смонтировать раздел Windows, который имеет файловую систему ntfs. Мы также знаем, что примерно половина его пространства доступна. Следовательно, мы можем определить, что раздел, который мы хотим смонтировать, это `nvme0n1p3`, его UUID — `08A24E90A24E81E4`, а файловая система в данном примере — `ntfs`.

### 2. Идентификация вашего раздела

Часто `lsblk -f` предоставляет всю информацию, необходимую для монтирования диска через /etc/fstab на этом этапе. Если вы всё ещё не уверены, какой раздел является правильным, вы можете выполнить следующую команду:

```sh
sudo fdisk -l
```

```sh title="Пример вывода"
Device              Start        End    Sectors  Size Type
/dev/nvme0n1p1       2048     206847     204800  100M EFI System
/dev/nvme0n1p2     206848     239615      32768   16M Microsoft reserved
/dev/nvme0n1p3     239616 2997384182 2997144567  1.4T Microsoft basic data
/dev/nvme0n1p4 2997385216 2999482367    2097152    1G EFI System
/dev/nvme0n1p5 2999482368 3905454079  905971712  432G Linux root (x86-64)
/dev/nvme0n1p6 3905454080 3907026943    1572864  768M Windows recovery environment
```

В этом примере мы уже знаем наш UUID. Однако `fdisk -l` может сделать это немного понятнее, показав точный размер раздела (1.4T), а также его тип (Microsoft basic data).

Это должно окончательно прояснить, что нужный нам раздел — `nvme0n1p3` с UUID `08A24E90A24E81E4`, как было описано ранее. Мы и так это знали, но теперь просто уверены в этом на сто процентов.

Как только вы убедитесь, что нашли правильный раздел, скопируйте его UUID. Копирование из эмулятора терминала обычно выполняется с помощью `ctrl+shift+C`.

### 3. Добавление записи в /etc/fstab

Теперь, когда мы получили UUID нашего раздела, пришло время открыть файл fstab.

Вы можете использовать любой текстовый редактор по вашему выбору. В этом примере мы будем использовать nano. Чтобы отредактировать файл fstab, его нужно открыть с правами root:

```sh
sudo nano /etc/fstab
```

С помощью клавиш со стрелками перейдите в конец файла fstab, а затем создайте нашу новую запись на пустой строке:

```sh
UUID=08A24E90A24E81E4 /media/windows ntfs3 defaults,nofail,uid=1000,gid=1000,rw,user,exec,umask=000 0 0
```

:::note
Каталог `/media/windows` должен существовать в вашей файловой системе. Используйте `mkdir`, чтобы создать его, если он отсутствует.
:::

Разбор этой записи следующий:

-   `UUID=08A24E90A24E81E4` — это файловая система, которую мы хотим смонтировать, идентифицированная по её UUID. Существуют и другие методы идентификации файловой системы, хотя UUID, как правило, является самым безопасным. Дополнительные методы перечислены [здесь](https://wiki.archlinux.org/title/Fstab#Identifying_file_systems).

-   `/media/windows` — это точка монтирования нашего диска. [Стандарт иерархии файловой системы Linux](https://refspecs.linuxfoundation.org/FHS_3.0/fhs/index.html) гласит, что `/media/` — это подходящее место для монтирования съёмных дисков. `windows` указывает на каталог, в который мы хотим смонтировать наш диск. Каждому монтируемому диску потребуется свой собственный каталог.

-   `ntfs3` — это тип файловой системы, который будет использоваться. В нашем примере мы явно используем драйвер ядра ntfs3. Другими примерами могут быть `ext4`, `xfs` и тому подобное. Это явное объявление типа файловой системы можно заменить на `auto`, чтобы позволить команде mount сделать наилучшее предположение.

-   `defaults,nofail,uid=1000,gid=1000,rw,user,exec,umask=000`: Это опции монтирования:

    -   `defaults`: стандартный набор опций, включающий `rw, suid, dev, exec, auto, nouser, and async.`

    -   `nofail`: позволяет процессу загрузки продолжаться, даже если это монтирование не удалось.

    -   `uid=1000` и `gid=1000`: устанавливает владельца и группу смонтированных файлов на пользователя и группу с ID 1000.

    -   `rw`: монтирует файловую систему в режиме чтения-записи.

    -   `user`: позволяет монтировать файловую систему пользователю без прав root.

    -   `exec`: разрешает выполнение бинарных файлов на смонтированной файловой системе.

    -   `umask=000`: устанавливает маску прав доступа к файлам, разрешая чтение, запись и выполнение для всех.

    -   `первый 0` (dump) обычно является устаревшим в современных системах. Если оставить его равным 0, ничего страшного не произойдёт. Вы можете прочитать больше об этом [здесь](https://linux.die.net/man/8/dump).

    -   `второй 0` (pass) устанавливает порядок проверки файловых систем во время загрузки. Для корневого раздела это значение должно быть 1, если только ваша корневая файловая система не btrfs, для которой оно должно быть 0. Все остальные файловые системы в вашем fstab должны иметь значение либо 0 (отключено), либо 2. Больше информации [здесь](https://man.archlinux.org/man/fsck.8).

Для более подробного ознакомления с каждой опцией посетите эти две страницы руководства: [man-страница fstab](https://man7.org/linux/man-pages/man5/fstab.5.html) и [man-страница mount](https://man7.org/linux/man-pages/man8/mount.8.html).

#### Дополнительные сведения

К слову, все опции после объявления типа файловой системы являются необязательными, если вы не изменяете их значения по умолчанию.

Таким образом,

`UUID=<partition UUID> /media/foo somefs`

и

`UUID=<partition UUID> /media/foo somefs defaults 0 0`

эквивалентны. `somefs`, за которым ничего не следует, неявно означает `somefs defaults 0 0`.

```sh
sudo mount -a
```

Теперь этот диск смонтирован и будет монтироваться при каждой загрузке в дальнейшем.
