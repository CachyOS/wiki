## Настройки производительности AMD

### Драйвер AMD P-State
---------------------------

`amd-pstate` — это драйвер управления производительностью процессоров AMD, который вводит новый механизм контроля частоты CPU для современных серий APU и CPU от AMD в ядре Linux. Новый механизм основан на Collaborative Processor Performance Control (CPPC), который обеспечивает более тонкое управление частотой по сравнению с устаревшими аппаратными P-состояниями ACPI.

Текущие платформы CPU/APU от AMD используют драйвер ACPI P-states для управления частотой и тактовыми сигналами процессора, переключаясь всего между 3 P-состояниями. CPPC заменяет управление ACPI P-states и предоставляет гибкий интерфейс с низкой задержкой для ядра Linux, позволяющий напрямую передавать оборудованию подсказки о производительности.

Ниже представлены 3 режима работы драйвера `amd-pstate` и параметры командной строки ядра для их использования при загрузке:

- AMD P-State (неавтономный режим): `amd-pstate=passive`
- AMD P-State Guided (управляемый автономный режим): `amd-pstate=guided`
- AMD P-State EPP (автономный режим): `amd-pstate=active`

:::note
Драйвер AMD P-State EPP используется по умолчанию, если не задана явная конфигурация.
:::

Вы также можете переключаться между режимами работы во время выполнения, чтобы протестировать опции:

- **Автономный режим**: платформа учитывает только значения, установленные для минимальной производительности, максимальной производительности и предпочтения энергоэффективности.
   ```sh
   echo active | sudo tee /sys/devices/system/cpu/amd_pstate/status
   ```

- **Управляемый автономный режим**: платформа устанавливает рабочий уровень производительности в соответствии с текущей нагрузкой и в пределах, заданных ОС через регистры минимальной и максимальной производительности.
   ```sh
   echo guided | sudo tee /sys/devices/system/cpu/amd_pstate/status
   ```

- **Неавтономный режим**: платформа получает желаемый уровень производительности напрямую от ОС через регистр желаемой производительности.
   ```sh
   echo passive | sudo tee /sys/devices/system/cpu/amd_pstate/status
   ```

### Настройка AMD P-State EPP


Для использования P-State EPP доступны два регулятора масштабирования частоты CPU: `powersave` и `performance`. Рекомендуется использовать регулятор powersave и установить предпочтение.

*   Установить регулятор powersave: `sudo cpupower frequency-set -g powersave`
*   Установить регулятор performance: `sudo cpupower frequency-set -g performance`

Чтобы установить предпочтение, выполните следующую команду с желаемым значением:

```sh
echo power | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/energy_performance_preference
```

Доступные предпочтения: `performance`, `power`, `balance_power`, `balance_performance`

Тесты производительности для каждого предпочтения можно найти здесь:
[https://lore.kernel.org/lkml/20221219064042.661122-1-perry.yuan@amd.com/](https://lore.kernel.org/lkml/20221219064042.661122-1-perry.yuan@amd.com/)

### Оптимизатор AMD 3D V-Cache

AMD опубликовала патч для оптимизации планирования кэша на процессорах с двумя CCD и 3D-кэшем, таких как 7950X3D и 7900X3D.
Вам необходимо в BIOS в опции CPPC установить значение "Driver". Это позволит переопределять используемый режим через sysfs.

Есть два режима:
1. Frequency (Частота)
2. Cache (Кэш)

Если установлен режим `cache`, драйвер будет пытаться размещать задачи в первую очередь на CCD с большим объемом кэша, что в основном выгодно для игр.
Опция `frequency` будет пытаться размещать задачи на втором CCD, который имеет более высокую частоту, чем CCD с 3D-кэшем.

Частота (по умолчанию):
```sh
echo frequency | sudo tee /sys/bus/platform/drivers/amd_x3d_vcache/AMDI0101:00/amd_x3d_mode
```

Кэш:
```sh
echo cache | sudo tee /sys/bus/platform/drivers/amd_x3d_vcache/AMDI0101:00/amd_x3d_mode
```

После смены режимов, статистика предпочтительных ядер AMD должна показать другой рейтинг. Вы можете прочитать его с помощью:
```sh
grep -v /sys/devices/system/cpu/cpu*/cpufreq/amd_pstate_prefcore_ranking
```

### AMD P-State Core Performance Boost

AMD Core Performance Boost, также известный как AMD Turbo Core, — это технология динамического масштабирования частоты от AMD, которая позволяет
процессору динамически регулировать и контролировать свою рабочую частоту в некоторых версиях процессоров,
что обеспечивает повышенную производительность при необходимости, сохраняя при этом низкое энергопотребление и тепловыделение при обычной работе.

Начиная с `linux-cachyos` 6.9.6, ядро пропатчено с поддержкой CPB для драйверов p-state от AMD (включая `passive`, `active` и `guided`).
Пользователи могут изменять состояние boost для каждого ядра CPU через файл boost в sysfs `/sys/devices/system/cpu/cpuX/cpufreq/boost`
(X обозначает номер ядра, например, cpu0 — первое ядро, cpu1 — второе и т.д.).

```sh
❯ echo 0 | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/boost # Отключить boost для всех ядер
❯ lscpu -ae # Это показывает, что AMD CPB отключен глобально
CPU NODE SOCKET CORE L1d:L1i:L2:L3 ONLINE    MAXMHZ   MINMHZ       MHZ
  0    0      0    0 0:0:0:0          yes 3301.0000 400.0000 1212.8250
  1    0      0    0 0:0:0:0          yes 3301.0000 400.0000 1394.2180
  2    0      0    1 1:1:1:0          yes 3301.0000 400.0000 1204.4600

❯ echo 1 | sudo tee /sys/devices/system/cpu/cpu0/cpufreq/boost # Включает boost на cpu0
❯ lscpu -ae
CPU NODE SOCKET CORE L1d:L1i:L2:L3 ONLINE    MAXMHZ   MINMHZ       MHZ
  0    0      0    0 0:0:0:0          yes 4564.0000 400.0000 1393.2380
  1    0      0    0 0:0:0:0          yes 3301.0000 400.0000  400.0000
  2    0      0    1 1:1:1:0          yes 3301.0000 400.0000 2157.8469
```

CachyOS также предоставляет версию `power-profiles-daemon`, в которую бэкпортирован коммит, включающий
поддержку AMD CPB. AMD CPB будет отключен, если используется профиль `powersave`, и включен при профилях `balanced` или `performance`.

Для дополнительной информации смотрите:

## Улучшения производительности

### Отключение Split Lock Mitigate

В некоторых случаях смягчение последствий разделенной блокировки (split lock) может снижать производительность в некоторых приложениях и играх. Доступен патч для его отключения через sysctl.

*   Отключить смягчение разделенной блокировки: `sudo sysctl kernel.split_lock_mitigate=0`
*   Включить смягчение разделенной блокировки: `sudo sysctl kernel.split_lock_mitigate=1`

Чтобы сделать изменение постоянным, добавьте следующую строку в `/etc/sysctl.d/99-splitlock.conf`:

```text
kernel.split_lock_mitigate=0
```

Для дополнительной информации о разделенной блокировке смотрите:

- https://www.phoronix.com/news/Linux-Splitlock-Hurts-Gaming
- https://github.com/doitsujin/dxvk/issues/2938

### [Планировщик ввода-вывода ADIOS](https://github.com/firelzrd/adios)

Создан [firelzrd](https://github.com/firelzrd)

:::note
CachyOS включает стабильную ветку ADIOS в ядро.

Текущая стабильная версия: `3.0.1`
:::

Краткое введение из README:

- *ADIOS (Adaptive Deadline I/O Scheduler) — это планировщик ввода-вывода на уровне блочных устройств для ядра Linux, разработанный для современных многоочередных блочных устройств (blk-mq). Его цель — обеспечить низкую задержку для операций ввода-вывода, сочетая принципы планирования по крайнему сроку (deadline scheduling) с адаптивным механизмом контроля задержки на основе обучения.*
  - *Вдохновлен и основан на концепциях планировщиков ввода-вывода mq-deadline и Kyber. Его ключевая особенность — способность прогнозировать задержку завершения операций ввода-вывода на основе прошлой производительности и характеристик запроса (тип операции, размер) и использовать этот прогноз для динамической корректировки крайних сроков запросов и поведения пакетной обработки.*

Короче говоря: ADIOS работает, изучая профиль задержек вашего устройства хранения данных и используя эти знания для динамической установки крайних сроков для запросов ввода-вывода. Он распределяет запросы по четырем уровням приоритета, от критически важных системных операций (уровень 0) до фоновых задач (уровень 3), чтобы обеспечить плавность работы пользователя. Хотя он ориентирован на отзывчивость, его поведение можно тонко настроить через параметры sysfs для балансировки между задержкой и пропускной способностью.

Для живой демонстрации вы можете посмотреть это [видео](https://www.youtube.com/watch?v=L9WDcEeHgy4)

#### Как включить ADIOS

    <TabItem label='Временно (действует во время сессии)'>
        Этот метод устанавливает планировщик для текущей сессии. Изменение будет потеряно после перезагрузки.
        ```sh
        sync && echo adios | sudo tee /sys/block/<ваш_диск>/queue/scheduler
            # Замените <ваш_диск> на фактический идентификатор диска (например, sda, sdb, nvme0n1)
        ```
    </TabItem>
    <TabItem label='Постоянно (после перезагрузки)'>
        <Steps>
            1. Откройте или создайте новый файл правил udev в вашем любимом текстовом редакторе (например, nano, micro, vim)
                ```sh title='Пример'
                sudo nano /etc/udev/rules.d/60-ioschedulers.rules
                ```
            2. Добавьте в файл следующие правила. Эти правила автоматически применяют определенный планировщик ввода-вывода в зависимости от типа диска (HDD, SSD или NVMe).
                ```text
                # HDD
                ACTION=="add|change", KERNEL=="sd[a-z]*", ATTR{queue/rotational}=="1", \
                    ATTR{queue/scheduler}="bfq"

                # SSD
                ACTION=="add|change", KERNEL=="sd[a-z]*|mmcblk[0-9]*", ATTR{queue/rotational}=="0", \
                    ATTR{queue/scheduler}="adios"

                # NVMe SSD
                ACTION=="add|change", KERNEL=="nvme[0-9]*", ATTR{queue/rotational}=="0", \
                    ATTR{queue/scheduler}="adios"
                ```
              3.  Сохраните файл и закройте редактор.
              4.  Перезагрузите правила `udev`, чтобы применить изменения немедленно, без перезагрузки.
                  ```sh
                  sudo udevadm control --reload-rules
                  sudo udevadm trigger
                  ```
        </Steps>
    </TabItem>
</Tabs>

Часто задаваемые вопросы:

- Если он улучшает отзывчивость, почему он не включен по умолчанию?
  - ADIOS все еще находится в активной разработке и постоянном тестировании. Хотя он предлагает значительные преимущества для отзывчивости настольных систем, он еще не считается достаточно стабильным, чтобы быть стандартным для всех рабочих нагрузок и типов оборудования. В некоторых крайних случаях ошибки могут приводить к проблемам, таким как зависания системы. По этой причине это необязательная функция для пользователей, которые хотят протестировать и воспользоваться его последними улучшениями.

## Настройки энергосбережения

### Включить RCU Lazy

RCU Lazy помогает снизить энергопотребление в режиме простоя или при слабой нагрузке системы. Это может быть полезно для ноутбуков и портативных устройств.
Улучшение составляет от 5 до 10% в плане экономии энергии. Однако важно отметить, что эта функция энергосбережения может достигаться за счет незначительного снижения производительности в зависимости от сценария.
В ядре linux-cachyos-deckify эта опция будет включена по умолчанию, поскольку энергосбережение является ключевым и необходимым для этих устройств.

Чтобы включить RCU Lazy, добавьте следующий параметр в список параметров [командной строки](/ru/configuration/boot_manager_configuration/) вашего ядра:
```text
rcutree.enable_rcu_lazy=1
```

## Устранение проблем с NVIDIA

### Отключение бэкенда Wayland для SDDM

:::note
Начиная с cachyos-kde-settings 4.3, SDDM по умолчанию использует KWin в качестве своего композитора Wayland.
:::

Хотя это хороший шаг вперед, он может вызывать некоторые неудобства, такие как нарушение поддержки разгона с помощью nvidia-settings или проблемы совместимости со старыми GPU, которые плохо работают под Wayland.

Чтобы отменить это изменение, удалите пакет cachyos-kde-settings:
```sh
sudo pacman -R cachyos-kde-settings
```

### Прошивка NVIDIA GSP

Прошивка NVIDIA GSP **"в некоторых случаях"** может приводить к снижению производительности. Хотя драйвер NVIDIA 555.58.02 в значительной степени решил эту проблему, она может сохраняться на некоторых системах.
Если вы сталкиваетесь с подтормаживаниями в KDE или плохой производительностью в некоторых случаях, вы можете отключить прошивку GSP с помощью следующего файла конфигурации:
`/etc/modprobe.d/nvidia-gsp.conf`

```text
options nvidia NVreg_EnableGpuFirmware=0
```

После создания файла выполните следующую команду:
```sh
sudo mkinitcpio -P
```

:::note
[Открытые модули ядра](https://github.com/NVIDIA/open-gpu-kernel-modules) от NVIDIA основаны на прошивке GSP. Из-за этого GSP нельзя отключить, и эта опция modprobe будет проигнорирована при их использовании. Используйте `linux-cachyos-nvidia` или `nvidia-dkms`.
:::

Обычно рекомендуется тестировать прошивку GSP после каждой новой установки драйвера NVIDIA, поскольку она часто вводит полезные функции. Более того, NVIDIA в основном начала проводить QA-тестирование с использованием прошивки GSP.

## Улучшения звука и программного обеспечения

### Улучшение звука динамиков ноутбука

Динамики ноутбуков часто звучат плоско и невыразительно из-за их компактного размера и ограниченных аппаратных возможностей. [EasyEffects](https://wiki.archlinux.org/title/PipeWire#EasyEffects) может значительно улучшить качество звука встроенных динамиков вашего ноутбука, применяя различные звуковые эффекты и пользовательские конфигурации.

Для начала вам нужно установить EasyEffects и необходимые зависимости:

```bash
# Установить EasyEffects
sudo pacman -S easyeffects
# Установить дополнительные плагины для большего количества эффектов
sudo pacman -S lsp-plugins-lv2
sudo pacman -S zam-plugins
sudo pacman -S calf
sudo pacman -S mda.lv2
```

#### Конфигурация

Следуйте этим шагам для настройки EasyEffects:

1. Запустите EasyEffects из меню приложений или введя `easyeffects` в терминале.
2. Перейдите на вкладку **Вывод** для управления эффектами, применяемыми к звуку ваших динамиков.
3. Переключитесь на вкладку **Эффекты**, чтобы добавлять, изменять или настраивать звуковые эффекты.

##### Использование пресетов сообщества

Для быстрой и эффективной настройки начните с **пресетов, созданных сообществом**, которые подходят для различных аудиосценариев:

1. Загрузите пресеты из репозитория [EasyEffects Community Presets](https://github.com/wwmm/easyeffects/wiki/Community-presets).
2. В EasyEffects нажмите кнопку **Пресеты** и выберите **"Импортировать пресет из локального хранилища"**.
3. Найдите и выберите загруженный файл пресета.
4. После импорта пресет появится в вашем списке — нажмите **"Загрузить"**, чтобы применить его к вашему аудиовыходу.

<ImageComponent imgsrc={import('~/assets/images/easyeffects-presets.png')} />

##### Создание пользовательского профиля

Для более персонализированного звукового опыта создайте пользовательский профиль, адаптированный под динамики вашего ноутбука:

1. Нажмите кнопку **"+"** в меню Пресеты, чтобы создать новый пресет (например, назовите его **"Динамики ноутбука"**).
2. Выберите **"Загрузить"**, чтобы активировать новый пресет.
3. Добавьте и настройте эффекты на вкладке **Вывод** > **Эффекты**, экспериментируя с такими опциями, как эквалайзеры, усилители басов или расширители стереобазы.

##### Использование эффекта Convolver (ноутбуки с Dolby Atmos)

Эффект **Convolver** может кардинально улучшить звук, применяя импульсные отклики, которые симулируют высококачественные аудио-окружения. Однако он требует точной настройки:

1. Добавьте эффект **Convolver** в свою цепочку эффектов на вкладке **Эффекты**.
2. Загрузите файл импульсного отклика (в формате `.wav`), специфичный для вашей модели ноутбука, если таковой имеется. Вы можете найти эти файлы в интернете на таких ресурсах, как:
   - https://wiki.archlinux.org/title/Lenovo_ThinkPad_T14_(AMD)_Gen_4#Speakers
   - https://github.com/m4tx/thinkpad-p14s-g4-linux/#sound
   - https://github.com/shuhaowu/linux-thinkpad-speaker-improvements/
3. **Предотвращение клиппинга**: Эффект Convolver может значительно увеличить громкость. Добавьте эффект **Limiter** после Convolver в вашей цепочке эффектов, чтобы контролировать пики и избежать искажений.

#### Советы для оптимальных результатов

- **Экспериментируйте** с различными пресетами, чтобы найти наилучшее соответствие для вашей конкретной модели ноутбука и личных звуковых предпочтений.
- **Вносите постепенные изменения** в отдельные эффекты, чтобы предотвратить искажения или неестественный звук.
- **Сравнивайте с помощью переключателя**: Часто включайте и выключайте EasyEffects, чтобы оценить улучшения по сравнению со стандартным звуком.
- Ищите **пресеты или импульсные отклики Convolver для конкретных устройств**, таких как **Framework Laptop 13** или **ThinkPad T14**, чтобы добиться индивидуальных результатов.
- **Автоматизируйте запуск**: Настройте автоматический запуск EasyEffects при старте системы через настройки приложения, чтобы ваш пользовательский профиль всегда применялся.
- **Автозагрузка пресетов для нескольких устройств**: Используйте вкладку **PipeWire** > **Автозагрузка пресетов**, чтобы связать определенные пресеты с разными устройствами вывода (например, Динамики vs. Наушники) для плавного переключения. <ImageComponent imgsrc={import('~/assets/images/easyeffects-autoloading.png')} />

### OBS Studio

Мы предоставляем в нашем репозитории специальный пакет obs-studio-browser, который рекомендуется использовать вместо стандартного пакета `obs-studio`. Он содержит патчи для исправления некоторых распространенных проблем, таких как ошибки cuda и проблемы с виртуальной камерой.

```sh title='Откройте терминал и выполните следующую команду'
sudo pacman -S obs-studio-browser
# Если у вас ранее был установлен obs-studio, pacman спросит,

```
