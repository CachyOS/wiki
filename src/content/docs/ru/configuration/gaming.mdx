Добро пожаловать в руководство по играм в CachyOS. Мы проведём вас по основным аспектам настройки, чтобы вы получили отличный игровой опыт.

## Предварительные требования

:::caution
Прежде чем мы перейдём к самому интересному, необходимо убедиться, что драйверы вашей видеокарты установлены и работают корректно. Если ваша видеокарта работает неоптимально, вы можете столкнуться с проблемами при запуске игр.
:::

### Основные пакеты

Чтобы облегчить вам задачу, CachyOS сгруппировала все необходимые для игр пакеты в один мета-пакет, который включает все необходимые зависимости и библиотеки для игр в Linux, а также отдельный пакет для инструментов и лаунчеров/магазинов. Это делает процесс установки и настройки игр быстрее и проще для всех.

*Если вы обнаружите, что каких-то пакетов не хватает, не стесняйтесь сообщить об этом команде CachyOS.*

Следуйте шагам ниже, чтобы начать настройку игр.

## Proton-CachyOS

Proton-CachyOS основан на ветке `bleeding-edge` от Proton и применяет ряд модификаций поверх неё.
- **Патчи Wine-staging**
- **Полноэкранный FSR в Wine**
- **Включает видео- и аудиокодеки для игровых катсцен**
- **Поддержка umu-launcher, включая UMU-Protonfixes**
- **Добавляет ранние хотфиксы/обходные пути для игр**

:::note
Пакет `proton-cachyos` из репозиториев CachyOS скомпилирован с использованием нативных системных библиотек и не использует Steam Linux Runtime. Целевая архитектура зависит от репозитория. В настоящее время репозитории `x86_64_v3`, `x86_64_v4` и `znver4` используют одни и те же бинарные файлы `x86_64_v3`.
:::

:::caution[NTSync не включен по умолчанию. Вы можете включить его с помощью переменной окружения `PROTON_USE_NTSYNC=1`.]
:::

### Как правильно задать несколько параметров запуска

```bash title="Параметры запуска в Steam строятся по следующему шаблону:"
<переменные окружения> <обёртки> %command% <аргументы приложения>
```

- **`<переменные окружения>`:** Это опции в формате: `ПЕРЕМЕННАЯ=значение`
  ```bash title="Примеры:"
  PROTON_DXVK_D3D8=1
  # Или
  DXVK_HUD="fps,memory,version,api"
  ``` 

- **`<обёртки>`:** Приложения и скрипты, которые изменяют способ запуска реального приложения. Аргументы для обёртки обычно идут после её исполняемого файла.
  ```bash title="Примеры:"
  mangohud --dlsym
  # Или
  gamescope -W 1680 -H 1050 -w 1280 -h 720 -S fit -F fsr --mangoapp --
  ```

- **`%command%`:** Это само приложение. Эту часть нужно указывать именно так, и Steam заменит её на правильную команду при запуске приложения.

- **`<аргументы приложения>`:** Это различные аргументы для самого приложения, и они зависят от конкретного приложения.
  ```bash title="Пример:"
  %command% -dx11
  ```
  
**Пример полного параметра запуска, объединяющего все элементы:**

  ```bash 
  __GL_SHADER_DISK_CACHE_SKIP_CLEANUP=1 prime-run game-performance %command% -dx11
  ```

:::caution
Не добавляйте несколько `%command%`, используя их в качестве разделителей для нескольких параметров запуска.

Пример: `__GL_SHADER_DISK_CACHE_SKIP_CLEANUP=1 %command% game-performance %command% prime-run %command%`

В этом случае всё, что идёт после первого `%command%`, будет проигнорировано, так как будет рассматриваться как аргументы игры, поэтому в качестве параметра запуска будет распознан только `__GL_SHADER_DISK_CACHE_SKIP_CLEANUP=1`.
:::

#### Переменные окружения

<Tabs>
<TabItem label="Графика и апскейлинг">

- DLSS и функции NVIDIA
    - `PROTON_DLSS_UPGRADE=1`: Автоматически обновляет DLSS до последней версии
    - `PROTON_DLSS_INDICATOR=1`: Показывает индикатор статуса DLSS в игре
    - `PROTON_NVIDIA_LIBS=1`: Включает библиотеки NVIDIA (PhysX, CUDA) - не требуется для DLSS/трассировки лучей

<details>
<summary>Расширенные настройки NVIDIA</summary>

- `PROTON_NVIDIA_NVCUDA=1`: Включает только поддержку CUDA
- `PROTON_NVIDIA_NVENC=1`: Включает только кодирование NVENC
- `PROTON_NVIDIA_NVML=1`: Включает мониторинг NVML
- `PROTON_NVIDIA_NVOPTIX=1`: Включает трассировку лучей OptiX
- `PROTON_NVIDIA_LIBS_NO_32BIT=1`: Включать только в 64-битных играх (исправляет проблемы с производительностью на RTX 4000+)
</details>

- Апскейлинг AMD и Intel
    - `PROTON_FSR4_UPGRADE=1`: Автоматически обновляет FSR до последней версии от AMD
    - `PROTON_FSR4_RDNA3_UPGRADE=1`: Использует FSR4 DLL, оптимизированную для RDNA3
    - `PROTON_XESS_UPGRADE=1`: Автоматически обновляет XeSS до последней версии

</TabItem>

<TabItem label="Дисплей и HDR">

- Wayland и дисплей
    - `PROTON_ENABLE_WAYLAND=1`: Включает нативную поддержку Wayland
    - **Преимущества**: HDR без Gamescope, улучшенная задержка/плавность кадров
    - **Недостатки**: Ломает оверлей Steam, на данный момент экспериментальная функция
    - `PROTON_NO_WM_DECORATION=1`: Отключает декорации оконного менеджера
        - **Исправляет**: Проблемы с полноэкранным режимом без рамок, прокликивание мыши сквозь окна

- Поддержка HDR
    - `PROTON_ENABLE_HDR=1`: Включает поддержку вывода HDR
    - **Требования**: Gamescope с флагом `--hdr-enabled` ИЛИ `PROTON_ENABLE_WAYLAND=1`
    - **Настройка**: [Требуется дополнительная конфигурация](https://wiki.archlinux.org/title/HDR_monitor_support)

</TabItem>

<TabItem label="Производительность и кэширование">

- Производительность CPU и синхронизация
    - `PROTON_USE_NTSYNC=1`: Использует NTSync для лучшей производительности CPU
        - **Лучше всего для**: Игр, упирающихся в CPU, заменяет WINESync
        - **Примечание**: Экспериментальная функция, может вызывать проблемы в некоторых играх
        - **Проверка**: Используйте `lsof /dev/ntsync` (MangoHud сообщает неверно)

- Управление шейдерами и кэшем
    - `PROTON_LOCAL_SHADER_CACHE=1`: Включает кэш шейдеров для каждой игры, аналогично "Предварительному кэшированию шейдеров" в Steam. Это НЕ компилирует шейдеры заранее, а ТОЛЬКО изолирует кэш шейдеров каждой игры. Шейдеры по-прежнему будут компилироваться во время игрового процесса.
    - `PROTON_ENABLE_MEDIACONV=1`: Включает Proton Media Converter
        - **Примечание**: Только для целей тестирования

- AMD Anti-Lag
    - `ENABLE_LAYER_MESA_ANTI_LAG=1`: Включает AMD Anti-Lag для снижения задержки ввода
    :::danger
    proton-cachyos отключает эту функцию, так как она мешает обновлениям FSR4 и может вызывать подтормаживания или другие проблемы ([подробности](https://github.com/CachyOS/CachyOS-PKGBUILDS/pull/909)).
    :::

</TabItem>

<TabItem label="Ввод и совместимость">

- Контроллер и ввод
    - `PROTON_PREFER_SDL=1`: Обходной путь для проблем с определением контроллера
    - `PROTON_NO_STEAMINPUT=1`: Отключает поддержку Steam Input
        - **Исправляет**: Проблемы с контроллером/геймпадом в Wayland

</TabItem>
</Tabs>

## Wine-CachyOS

Это тот же `wine`, который лежит в основе `proton-cachyos`, но в виде отдельного пакета. Его можно использовать в Lutris, Heroic, Bottles и других программах.

- **Все модификации Wine, включённые в Proton-CachyOS**
- **Добавляет ранние хотфиксы/обходные пути для игр**

:::note
В репозиториях CachyOS **Wine-CachyOS** предлагается в двух разных пакетах. `wine-cachyos` устанавливает его как системный Wine по умолчанию и заменяет `wine` или `wine-staging`. `wine-cachyos-opt` устанавливает его в другое место, что позволяет нескольким версиям wine сосуществовать в системе.
:::

:::caution
Основное предназначение **Wine-CachyOS** — это **игры**. Хотя его можно использовать как системный Wine для настольных приложений, имейте в виду, что это может привести к неожиданному поведению и проблемам из-за модификаций, ориентированных на игры.

Если вы хотите использовать настольные приложения, мы предлагаем использовать `wine` или `wine-staging` в качестве системного Wine и установить `wine-cachyos-opt` для игр.
:::

**Дополнительные параметры конфигурации**

- `WINE_WMCLASS="<name>"`: Устанавливает `WM_CLASS` для всех окон wine, позволяя оконному менеджеру управлять окнами Wine через правила.
- `WINEUSERSANDBOX=1`: Отключает создание символических ссылок из папок пользователя Wine, таких как Documents/Pictures, в эквивалентные папки в каталоге `HOME` пользователя.
- `WINE_NO_WM_DECORATION=1`: Отключает декорации окон с помощью оконного менеджера Linux. Это может исправить проблемы с **полноэкранным режимом без рамок** и прокликиванием мыши сквозь окно.
- `WINE_PREFER_SDL_INPUT=1`: Включите, чтобы обойти проблемы с правильным определением контроллера.

### Как использовать wine-cachyos-opt

<Tabs>
    <TabItem label='Автономно'>
    Обычно запуска `/opt/wine-cachyos/bin/wine` вместо просто `wine` должно быть достаточно, чтобы приложение запустилось с использованием `wine-cachyos-opt`.

    Если требуется более строгая конфигурация, она может выглядеть так:
    ```shell
    export PATH="/opt/wine-cachyos/bin/:$PATH"
    export WINEDLLPATH="/opt/wine-cachyos/lib/wine:/opt/wine-cachyos/lib32/wine:$WINEDLLPATH"
    export LD_LIBRARY_PATH="/opt/wine-cachyos/lib/:/opt/wine-cachyos/lib32/:$LD_LIBRARY_PATH"
    ```

    Если вы хотите использовать `winetricks` с `wine-cachyos-opt`, вы можете вызвать его так:
    ```shell
    WINE=/opt/wine-cachyos/bin/wine WINEPRFIX=<your prefix> winetricks <verb>
    ```

### Какую версию Proton использовать в Steam?

:::note
Так как на **Reddit** возникла некоторая путаница, нативная версия `Proton-CachyOS` не будет прекращена в связи с тем, что `steam-native-runtime` был объявлен устаревшим.

Они не связаны и не имеют отношения друг к другу. В последнее время мы рекомендуем SLR, **который мы также устанавливаем по умолчанию**, чтобы уменьшить путаницу и проблемы для новичков в CachyOS и Linux в целом. Если вам нравится нативная версия и она у вас работает, продолжайте ее использовать.
:::

- `Proton 10.0` — это стабильный релиз от `Valve`. Используйте его, если известно, что игра, в которую вы хотите поиграть, работает хорошо.
- `Proton Experimental` — это самый свежий релиз от `Valve`. Используйте его, если игра, в которую вы хотите поиграть, относительно новая, плохо работает с текущей стабильной версией Proton или если люди рекомендуют его на [ProtonDB](https://www.protondb.com/).
- `proton-cachyos-slr` — это версия, которую мы создаем и поддерживаем. Ее использование настоятельно рекомендуется благодаря различным улучшениям, исправлениям и оптимизациям. Для игр, использующих античит, таких как **BattlEye** или **Easy Anti-Cheat**, или кастомные лаунчеры, предпочтительнее использовать `proton-cachyos-slr`.
- `proton-cachyos` — это та же версия, что и `proton-cachyos-slr`, но собранная без зависимости от Steam Linux Runtime. Используйте ее, только если вы понимаете значение этого различия, и переключайтесь на `proton-cachyos-slr` в случае возникновения проблем.
- `Proton-GE` — это кастомная сборка от [GloriousEggroll](https://github.com/GloriousEggroll/proton-ge-custom). Она включает различные исправления и может быть полезна в определенных ситуациях.
- `Proton 9.0.4 или ниже` — это стабильные релизы от `Valve`. Используйте их, если игра, в которую вы хотите поиграть, работает только на предыдущей версии Proton.

### Как правильно настроить несколько параметров запуска и переменных окружения в Lutris

- Параметры запуска, такие как `-dx11` или `-fullscreen`, следует добавлять в поле **Arguments** на вкладке **Game options**, разделяя их пробелом.
- Обёртки команд, например, `mangohud --dlsym` или `game-performance`, следует добавлять в поле **Command prefix** на вкладке **System options**, разделяя их пробелом.
- Переменные окружения, такие как `PROTON_ENABLE_HDR=1`, следует добавлять в таблицу **Environment variables** на вкладке **System options**, используя кнопку `+` для добавления новой записи.
:::note[Не включайте `=` в поле Key. Оно должно содержать только имя переменной.]

## Советы по производительности и прочее

### Чего не следует делать при играх в CachyOS

#### Совмещение gamemode и ananicy-cpp

:::note
`gamemode` и `game-performance` — это два разных инструмента. [gamemode](https://github.com/FeralInteractive/gamemode) — это инструмент, созданный Feral Interactive, в то время как `game-performance` — это кастомный скрипт, созданный CachyOS.
:::

Из-за того, что `gamemode` и `ananicy-cpp` оба пытаются одновременно изменить приоритет процесса (niceness), это может привести к конфликтам и непредсказуемому поведению. Рекомендуется использовать gamemode без ananicy-cpp.

Чтобы остановить ananicy-cpp, выполните следующую команду:

```bash
systemctl stop ananicy-cpp
```

### Переключение профиля питания по требованию

:::note
Это поведение немного отличается с `intel_pstate`. На Intel регулятор остается в режиме powersave, но значения EPP/EPB настраиваются для производительности.
:::

:::caution[game-performance может не дать никаких преимуществ на старых процессорах.]
:::

CachyOS включает скрипт-обертку [game-performance](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/bin/game-performance),
который использует `power-profiles-daemon` для временного переключения профиля питания на `performance`.
Этот профиль повышает уровни энергопотребления системы и устанавливает регулятор CPU на `performance`, а также переключает любой активный планировщик scx на его игровой профиль (если доступен).

При использовании для запуска игры система остается в **режиме производительности** до тех пор, пока игра не будет закрыта, после чего восстанавливается предыдущий профиль.

[GameMode от Feral](https://github.com/FeralInteractive/gamemode)
предлагает аналогичную функциональность.

### Увеличение максимального размера кэша шейдеров

Шейдеры игр компилируются автоматически во время игры, что может вызывать долгие загрузки и заикания при их первом появлении. Эти шейдеры сохраняются в вашей системе для повторного использования при необходимости.

Однако существует максимальный предел размера файла кэша шейдеров, из-за чего старые шейдеры забываются при превышении размера по умолчанию. Это может стать проблемой, так как у больших игр размер шейдеров может превышать 1 ГБ, что заставляет их перекомпилировать шейдеры при каждом запуске.

Чтобы избежать долгих загрузок и заиканий, мы можем увеличить глобальный размер кэша шейдеров:

<Tabs>

<TabItem label='GPU Nvidia'>

<Steps>
1. Откройте терминал.
2. Введите эту команду для редактирования файла окружения:
	```sh
	sudo nano /etc/environment
	```
3. Вставьте следующее в конец файла:
	```sh
	# Увеличить размер кэша шейдеров Nvidia до 12 ГБ
	__GL_SHADER_DISK_CACHE_SIZE=12000000000
	```
4. Сохраните файл, нажав `CTRL+X`, `Y`, а затем `Enter`.
5. Перезагрузите систему.
</Steps>

</TabItem>

<TabItem label='GPU AMD'>

<Steps>
1. Откройте терминал.
2. Введите эту команду для редактирования файла окружения:
	```sh
	sudo nano /etc/environment
	```
3. Вставьте следующее в конец файла:
	```sh
	# Принудительно использовать реализацию RADV Vulkan
	AMD_VULKAN_ICD=RADV

	# Увеличить размер кэша шейдеров AMD до 12 ГБ
	MESA_SHADER_CACHE_MAX_SIZE=12G
	```
4. Сохраните файл, нажав `CTRL+X`, `Y`, а затем `Enter`.
5. Перезагрузите систему.
</Steps>

</TabItem>

</Tabs>

После перезагрузки максимальный размер кэша шейдеров должен быть постоянно увеличен. Спасибо [psygreg's shader booster](https://github.com/psygreg/shader-booster/) за помощь в создании этого руководства.

### Падение производительности на NVIDIA в играх с DirectX12

Некоторые пользователи сообщают, что проблема связана с тем, как драйверы NVIDIA для Linux обрабатывают планирование задач GPU — в отличие от Windows, где обеспечивается правильное планирование. Официального заявления от NVIDIA пока нет. На данный момент известного обходного пути для этой проблемы не существует, и NVIDIA, предположительно, работает над исправлением, но неясно, когда оно будет выпущено.

**Это никак не связано с CachyOS.**

В некоторых играх падение производительности менее заметно, чем в других. Посмотрите это [сравнительное видео с бенчмарками](https://www.youtube.com/watch?v=SU2mFqCOh5A) для справки.

Следите за [темой на форуме NVIDIA](https://forums.developer.nvidia.com/t/directx12-performance-is-terrible-on-linux/303207/488) об этой проблеме, чтобы узнать больше.
