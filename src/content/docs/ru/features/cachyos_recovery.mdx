[CachyOS Recovery](https://github.com/CachyOS/cachyos-recovery) — это небольшая система восстановления, которая устанавливается рядом с вашими ядрами и запускается из меню загрузки. Если обновление или изменение конфигурации нарушит работу системы, вы можете использовать её без live-USB, чтобы:

- **загрузить снимок Btrfs** и проверить его работоспособность без внесения изменений в систему;
- **выполнить откат** к снимку на постоянной основе, включая соответствующие ядра и загрузочные файлы;
- **открыть установленную систему в контейнере**, чтобы исправить её вручную.

Среда восстановления занимает около 70 МБ. Она не зависит от состояния установленной системы, поэтому работает даже в том случае, если сама система больше не загружается.

:::caution
Снимки — это не резервная копия. Они хранятся на том же диске, что и ваша система, и не защищают от сбоев диска или случайного удаления файлов в `/home`. Регулярно делайте резервные копии важных данных.
:::

## Требования

Среда восстановления запускается в любой системе CachyOS с корневой файловой системой Btrfs, ext4, XFS или F2FS. Для операций со снимками дополнительно требуются:

- Корневая файловая система **Btrfs** с корнем на подтоме `@`, как это настраивает установщик CachyOS.
- **Снимки только для чтения** корневого подтома. Snapper создаёт их по умолчанию, а при наличии пакета `cachyos-snapper-support` CachyOS делает их автоматически до и после каждой транзакции `pacman`. В установках с systemd-boot этого пакета пока нет — см. [«No snapshots were found»](#no-snapshots-were-found). См. также [Снимки Btrfs](/ru/configuration/btrfs_snapshots).
- **mkinitcpio** в качестве генератора initramfs (используется в CachyOS по умолчанию).

В системах UEFI системный раздел EFI должен быть указан в `/etc/fstab` с типом `vfat` и смонтирован в `/boot`, `/efi` или `/boot/efi`.

Если системный раздел EFI смонтирован в `/boot`, откат также пересоздаёт ядра, образы initramfs и конфигурацию загрузчика для **Limine**, **systemd-boot** (с помощью `sdboot-manage`) и **GRUB**. **rEFInd** не требует обновления конфигурации. Если системный раздел EFI смонтирован в `/efi` или `/boot/efi`, а также в системах BIOS, где `/boot` является частью корневой файловой системы, ядра входят в состав снимка и восстанавливаются вместе с ним.

### Зашифрованные диски и раскладка клавиатуры

Диски, зашифрованные с помощью **LUKS**, поддерживаются. Если диск ещё не разблокирован, среда восстановления запросит парольную фразу LUKS при запуске. Держите парольную фразу под рукой, даже если обычно вы разблокируете диск через TPM2 или FIDO2.

Среда восстановления всегда использует **американскую раскладку клавиатуры (US)**, в том числе для ввода парольной фразы и входа в chroot. Если ваша парольная фраза или пароль содержат символы, которые на вашей клавиатуре расположены в других местах, вводите их так же, как на раскладке US.

## Установка

<Tabs syncKey="firmware">
  <TabItem label="UEFI">
    ```bash
    sudo pacman -S cachyos-recovery
    ```

    Во время установки хук pacman автоматически настраивает всё необходимое:

    - Копирует образ восстановления в `EFI/Linux/cachyos-recovery.efi` на вашем системном разделе EFI.
    - Записывает расположение вашей корневой файловой системы (и устройства LUKS, если оно используется) в небольшое дополнение рядом с образом — `EFI/Linux/cachyos-recovery.efi.extra.d/root.addon.efi`.
    - Подписывает оба файла с помощью `sbctl`, если Secure Boot настроен через `sbctl` (см. [Secure Boot](#secure-boot)).
    - Для **Limine** добавляет пункт **CachyOS Recovery** в меню загрузки.
    - Для **GRUB** записывает пункт **CachyOS Recovery** в `/etc/grub.d/50-cachyos-recovery` и пересоздаёт конфигурацию GRUB.
    - Добавляет пункт **CachyOS Recovery** в меню загрузки вашей прошивки (требуется `efibootmgr`). Пункт добавляется в конец порядка загрузки, поэтому ваш основной загрузчик остаётся по умолчанию.

    **systemd-boot** автоматически отображает образы из `EFI/Linux`, а **rEFInd** находит образ при сканировании системного раздела EFI. При использовании других загрузчиков запускайте среду восстановления из меню загрузки вашей прошивки.
  </TabItem>
  <TabItem label="BIOS">
    ```bash
    sudo pacman -S cachyos-recovery-legacy
    ```

    Во время установки хук pacman добавляет пункт **CachyOS Recovery** в меню загрузки **Limine** или **GRUB**. Для GRUB он копирует ядро и initramfs среды восстановления в `/boot/cachyos-recovery.vmlinuz` и `/boot/cachyos-recovery.initrd`, записывает пункт в `/etc/grub.d/50-cachyos-recovery` и пересоздаёт конфигурацию GRUB.

    Пакеты `cachyos-recovery` и `cachyos-recovery-legacy` не могут быть установлены одновременно. Не устанавливайте `cachyos-recovery` в системе с BIOS — он содержит только образ для UEFI.
  </TabItem>
</Tabs>

Хук запускается повторно при каждом обновлении пакета. Если вы изменили расположение вашей системы — например, после переноса на другой диск или настройки шифрования — переустановите пакет, чтобы среда восстановления снова смогла найти вашу корневую файловую систему: `sudo pacman -S cachyos-recovery` для UEFI или `sudo pacman -S cachyos-recovery-legacy` для BIOS.

Устанавливайте и переустанавливайте пакет из обычно загруженной системы. При загрузке из снимка он не сможет определить вашу корневую файловую систему.

### Secure Boot

Если вы настроили Secure Boot с помощью `sbctl`, как описано в руководстве [Настройка Secure Boot](/ru/configuration/secure_boot_setup), образ восстановления и его дополнение подписываются автоматически. Это происходит, если:

- `sbctl` установлен и уже создал свои ключи;
- Secure Boot включён, а прошивка не находится в режиме настройки (Setup Mode);
- ваши ключи зарегистрированы в прошивке.

Проверить подписи можно командой:

```bash
sudo sbctl verify | grep cachyos-recovery
```

Если файлы не подписаны — например, потому что вы включили Secure Boot уже после установки пакета — удалите образ восстановления и переустановите пакет. Одной переустановки недостаточно, поскольку хук не копирует и не подписывает образ повторно, если он уже находится на системном разделе EFI без изменений.

```bash
sudo rm /boot/EFI/Linux/cachyos-recovery.efi
sudo pacman -S cachyos-recovery
```

Скорректируйте путь, если ваш системный раздел EFI смонтирован в `/efi` или `/boot/efi`. После этого хук подпишет оба файла и, при использовании Limine, обновит пункт меню загрузки.

:::caution
При включённом Secure Boot прошивка откажется запускать неподписанный образ восстановления, и Limine покажет ошибку вместо меню восстановления. Если Limine настроен на запоминание последнего выбранного пункта, выберите в меню загрузки другой пункт, чтобы снова загрузить систему, а затем подпишите файлы.
:::

## Запуск среды восстановления

<Steps>
1. Перезагрузите компьютер.
2. Выберите **CachyOS Recovery** в меню загрузки. Если в вашем загрузчике нет такого пункта, откройте меню загрузки прошивки (обычно клавишей <kbd>F8</kbd>, <kbd>F11</kbd> или <kbd>F12</kbd> при запуске) и выберите **CachyOS Recovery** там.

   <ImageComponent imgsrc={import('~/assets/images/cachyos-recovery-limine-entry.png')} />
3. Если диск зашифрован, введите парольную фразу LUKS. У вас есть пять попыток.
4. Откроется меню среды восстановления.

   <ImageComponent imgsrc={import('~/assets/images/cachyos-recovery-main-menu.png')} />
</Steps>

Используйте клавиши со стрелками и <kbd>Enter</kbd> для выбора пункта, а <kbd>Esc</kbd> — для возврата назад. В списках можно начинать ввод с клавиатуры, чтобы фильтровать записи. Поле внизу экрана описывает выбранное действие.

Среда восстановления монтирует вашу систему в режиме только для чтения. На диске ничего не изменится, пока вы не запустите откат или не внесёте изменения в chroot.

| Действие | Что оно делает |
| --- | --- |
| **Boot Btrfs snapshot** | Загружает снимок с временной корневой файловой системой, доступной для записи. Рекомендуемый первый шаг. |
| **Rollback Btrfs snapshot** | Восстанавливает снимок на постоянной основе. |
| **Chroot into target system** | Запускает установленную систему в контейнере (для опытных пользователей). |
| **Reboot** | Перезагружает компьютер. |

Два пункта для работы со снимками отображаются только в том случае, если ваша корневая файловая система — Btrfs.

## Загрузка снимка

Загрузка снимка — самый безопасный способ найти рабочее состояние системы. Вы работаете со снимком как с обычной системой, и ничего не восстанавливается окончательно, пока вы не решите сохранить его.

<Steps>
1. Выберите **Boot Btrfs snapshot**.
2. Выберите снимок. В списке показаны идентификатор подтома Btrfs и время создания по UTC. Справа отображается путь к снимку, а для снимков Snapper — также описание и тип. Выберите снимок вашей корневой файловой системы. Его путь выглядит как `.snapshots/<номер>/snapshot`.

   <ImageComponent imgsrc={import('~/assets/images/cachyos-recovery-snapshot-list.png')} />
3. Выберите ядро для загрузки. В списке показаны только ядра, установленные в этом снимке.

   <ImageComponent imgsrc={import('~/assets/images/cachyos-recovery-kernel-picker.png')} />
4. Среда восстановления подготовит снимок и запустит его. Система загрузится как обычно. При использовании зашифрованного диска может потребоваться повторно ввести парольную фразу.
</Steps>

Пока вы загружены в снимок:

- Изменения в системе (всё, что находится на корневом подтоме) хранятся в оперативной памяти и теряются при перезагрузке.
- Остальные подтома и разделы, например `/home`, монтируются как обычно. **Изменения в них сохраняются.**
- Ваши собственные параметры ядра не применяются. Снимок загружается с параметрами, необходимыми для поиска вашей системы.

### Сохранение снимка

После входа в рабочее окружение появится уведомление с вопросом, хотите ли вы сохранить снимок.

<ImageComponent imgsrc={import('~/assets/images/cachyos-recovery-notifier.png')} />

- **Rollback snapshot** открывает терминал и запрашивает пароль. После подтверждения клавишей `y` снимок заменит вашу текущую систему (см. [Что делает откат](#что-делает-откат)). После завершения перезагрузите компьютер.
- **Stay in snapshot** закрывает уведомление. Ничего не восстанавливается, а установленная система остаётся без изменений.

Если уведомление не появляется (например, в оконном менеджере без службы уведомлений) или терминал не открывается, запустите откат из терминала:

```bash
sudo cachyos-recovery rollback
```

Эта команда доступна только тогда, когда вы загружены в снимок из среды восстановления.

:::tip
Если снимок не загружается — например, из-за того, что ваше оборудование некорректно обрабатывает перезапуск в ядро снимка — вместо этого используйте пункт **Rollback Btrfs snapshot** в меню среды восстановления.
:::

## Откат к снимку

Используйте этот способ, когда вы уже знаете, какой снимок работает, или когда загрузка снимка завершается неудачей.

<Steps>
1. Выберите **Rollback Btrfs snapshot**.
2. Выберите снимок для восстановления, как описано в разделе [Загрузка снимка](#загрузка-снимка).
3. Подтвердите действие, нажав `y` и <kbd>Enter</kbd>.
4. Дождитесь завершения отката. После этого среда восстановления спросит, нужно ли перезагрузиться.
5. Выберите **Yes, reboot**, чтобы запустить восстановленную систему.
</Steps>

:::danger[Текущее состояние системы будет удалено]
Откат заменяет текущий корневой подтом и удаляет его после успешного завершения. Отменить это действие можно только с помощью снимка, сделанного ранее. Ваш домашний каталог и другие подтома не затрагиваются, а существующие снимки сохраняются.
:::

### Что делает откат

<Steps>
1. Если ваш системный раздел EFI смонтирован в `/boot`, среда восстановления копирует ядра из снимка и генерирует соответствующие образы initramfs и конфигурацию загрузчика, используя инструменты внутри снимка. Эти файлы сначала подготавливаются во временном каталоге, поэтому системный раздел EFI пока не изменяется. Ядра, отсутствующие в снимке, удаляются из меню загрузки, а сами файлы подписываются, если Secure Boot настроен с помощью `sbctl`.
2. Создаётся новый корневой подтом из снимка, и он меняется местами с вашим текущим корнем.
3. Вложенные подтома, например `/.snapshots`, переносятся из старого корня в новый, чтобы ваши снимки оставались доступными.
4. Подготовленные загрузочные файлы копируются на системный раздел EFI.
5. Старый корневой подтом удаляется.
</Steps>

Если какой-либо шаг завершится с ошибкой до копирования загрузочных файлов, среда восстановления вернёт ваш старый корень и оставит системный раздел EFI без изменений.

Если системный раздел EFI смонтирован в `/efi` или `/boot/efi`, ядра входят в состав самого снимка, поэтому шаг 1 и шаг 4 пропускаются.

:::caution[Secure Boot и старые снимки]
Новые загрузочные файлы подписываются с помощью `sbctl`, установленного **внутри снимка**. Если вы откатитесь к снимку, который был сделан до настройки Secure Boot, ничего не будет подписано, и система не загрузится при включённом Secure Boot. Среда восстановления не предупреждает об этом. Ваши ключи `sbctl` в `/var/lib/sbctl` также удаляются вместе со старым корнем.

Сам образ восстановления остаётся подписанным. Если в более новом снимке всё ещё есть `sbctl` и его ключи, запустите **CachyOS Recovery** из меню загрузки прошивки и выполните откат к этому снимку. Откат снова подпишет загрузочные файлы.

В противном случае отключите Secure Boot в прошивке и загрузите систему. Установите `sbctl` и скопируйте `/var/lib/sbctl` обратно из более нового снимка в `/.snapshots`. Затем подпишите ядра и загрузчик, как описано в разделе [Подпись образа ядра и загрузчика](/ru/configuration/secure_boot_setup#подпись-образа-ядра-и-загрузчика), и снова включите Secure Boot. Если ни в одном из более новых снимков нет `/var/lib/sbctl`, пройдите руководство [Настройка Secure Boot](/ru/configuration/secure_boot_setup) с самого начала, чтобы создать и зарегистрировать новые ключи.
:::

:::note[Ядро Easy Anti-Cheat]
Откат не подписывает ядро `linux-cachyos-eac` вашим собственным ключом, поэтому оно сохраняет подпись CachyOS, необходимую для пункта загрузки [Easy Anti-Cheat](/ru/configuration/easy_anti_cheat). Если пункт Easy Anti-Cheat не загружается после отката, скопируйте подписанное CachyOS ядро обратно в `/boot`, переустановив `linux-cachyos-eac`, или в случае с Limine выполнив `sudo limine-mkinitcpio`.
:::

## Вход в систему через chroot

Пункт **Chroot into target system** запускает вашу установленную систему в контейнере с помощью `systemd-nspawn`. Появится приглашение входа вашей установленной системы, где вы сможете войти с вашим именем пользователя и паролем. В этом режиме корневая файловая система доступна для записи, поэтому внесённые изменения сохраняются.

Используйте этот режим для автономного ремонта корневой файловой системы — например, чтобы исправить повреждённый файл конфигурации в `/etc` или отключить службу, мешающую загрузке. В контейнере **нет доступа к сети**, и смонтирована только корневая файловая система. На Btrfs другие подтома, такие как `/home`, `/var/cache` и `/var/log`, а также другие разделы, включая системный раздел EFI, могут быть недоступны. Для ремонта, которому они необходимы — например, установки или переустановки пакетов — используйте [cachy-chroot](/ru/features/cachy_chroot) с live-ISO.

Чтобы выйти из контейнера и вернуться в меню среды восстановления, нажмите <kbd>Ctrl</kbd>+<kbd>]</kbd> три раза в течение одной секунды.

  </TabItem>
</Tabs>

## Устранение неполадок

### В меню загрузки отсутствует пункт CachyOS Recovery

Переустановите пакет (`cachyos-recovery` для UEFI, `cachyos-recovery-legacy` для BIOS) и изучите вывод шага **Installing system recovery image...**:

```bash
sudo pacman -S cachyos-recovery
```

Для создания пункта Limine требуется `limine-entry-tool`, а для пункта в меню прошивки — `efibootmgr`. При использовании systemd-boot образ должен находиться на том же системном разделе EFI, на который установлен systemd-boot.

### Среда восстановления не запускается при включённом Secure Boot

Образ восстановления или его дополнение не подписаны. Проверьте и подпишите их, как описано в разделе [Secure Boot](#secure-boot).

### «No snapshots were found»

Среда восстановления показывает только снимки, доступные только для чтения. Проверьте, создаёт ли Snapper снимки вашей корневой файловой системы:

```bash
sudo snapper list
```

Если команда сообщает, что конфигурация `root` не существует, Snapper не настроен. Это характерно для установок с **systemd-boot**, где установщик пока не настраивает Snapper. Установите пакет `cachyos-snapper-support`, который создаст конфигурацию Snapper для корневой файловой системы и установит `snap-pac` для автоматического создания снимков до и после каждой транзакции `pacman`:

```bash
sudo pacman -S cachyos-snapper-support
```

Среда восстановления сможет использовать все снимки, созданные с этого момента.

### Снимок не загружается или экран остаётся чёрным

Прямой запуск ядра снимка из среды восстановления работает не на каждом устройстве. Вместо этого используйте пункт **Rollback Btrfs snapshot** для восстановления снимка.

### «No ESP partition was found»

И установка пакета, и откат считывают расположение системного раздела EFI из `/etc/fstab` (во время отката — из `/etc/fstab` внутри снимка). Раздел должен быть указан там с типом `vfat` и точкой монтирования `/boot`, `/efi` или `/boot/efi`.

### Откат прерывается с ошибкой

Прочитайте текст ошибки над этим сообщением. Если среде восстановления не удалось подготовить загрузочные файлы, ничего не изменилось, и ваша старая система остаётся на месте.

Если в сообщении говорится, что снимок восстановлен, но содержимое `/boot` несогласованно, значит, снимок восстановлен, но скопировать загрузочные файлы не удалось. Загрузитесь с live-ISO, войдите в систему через [cachy-chroot](/ru/features/cachy_chroot) и пересоздайте загрузочные файлы:

- Для **Limine** выполните `limine-mkinitcpio`.
- Для других загрузчиков переустановите пакеты ядра, например `pacman -S linux-cachyos`. Это сработает, если установленная версия ядра всё ещё есть в кэше пакетов. Если pacman не может её скачать, вместо этого обновите всю систему командой `pacman -Syu`.
