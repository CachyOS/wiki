Установка ядра из репозитория
---------------------------------------

CachyOS Kernel Manager упрощает установку и управление ядрами из любого репозитория Arch Linux.

Для установки ядра запустите приложение `CachyOS Kernel Manager` и выберите желаемое ядро, отметив галочкой поле `[]` в списке всех доступных опций, затем просто нажмите `Execute` для начала установки ядра.

Для удаления ядра просто снимите галочку с поля `[]` рядом с установленным ядром, которое вы хотите удалить, и снова нажмите `Execute`.

<br />
<ImageComponent imgsrc={import('~/assets/images/cachyos-km1.png')} />

:::note
Кнопка `Execute` становится недоступной, когда вы выбираете уже установленное ядро.
:::

Конфигурирование и сборка пользовательского ядра CachyOS
---------------------------------

<br />
<ImageComponent imgsrc={import('~/assets/images/cachyos-km2.png')} />

:::note
CachyOS Kernel Manager специально разработан для сборки пользовательских ядер для **вариантов CachyOS** и не поддерживает сборку или конфигурирование стандартного ядра Arch Linux или любого другого варианта.
:::

*Для начала откройте Kernel Manager и нажмите на кнопку `Configure`, чтобы начать настройку различных параметров, таких как желаемый планировщик, частота тиков и многое другое. После внесения желаемых изменений нажмите на `Build kernel`, чтобы начать сборку вашего пользовательского ядра CachyOS.*

**Собранные пакеты ядра и кэш хранятся в** `~/.cache/cachyos-km/`

**Доступные опции конфигурации:**

* `Custom package name`: С помощью этой опции вы можете назвать ваше ядро как угодно. Например: `linux-custom-cachy`
* Планировщик (BORE, RC, RT, RT+BORE, EEVDF и BMQ)
* Включить конфигурацию CachyOS
* Тонкая настройка конфигурации через nconfig, menuconfig, xconfig или gconfig
* Включить/Отключить NUMA
* Включить/Отключить Modprobed-db
* Флаги KBUILD CFLAGS (-O3 или -O2)
* Использовать Performance governor по умолчанию
* Включить BBR3
* Выбор частоты тиков (100Hz, 250Hz, 300Hz, 500Hz, 600Hz, 750Hz, 1000Hz)
* Режим Tickless (idle, periodic, full)
* Вытеснение (Full, Voluntary или Server)
* Transparent Hugepages (Always или Madvise)
* Включить/Отключить DAMON
* Включить/Отключить автоматическое определение архитектуры CPU
* Применить оптимизацию ядра для конкретных архитектур CPU
* Включить LTO (Full, Thin, No)
* Собрать модуль ZFS
* Собрать закрытый модуль NVIDIA
* Собрать открытый модуль NVIDIA
* Включить vmlinux с отладочной информацией/символами
* Загрузить/Сохранить пресет конфигурации Kernel Manager: `(Только пресеты из самого менеджера)`
* Управление патчами ядра (поддержка удаленных и локальных)

*После успешной сборки ядра вам будет предложено ввести пароль sudo для его установки.*

## Управление фреймворком Sched-ext

Kernel Manager предоставляет графический пользовательский интерфейс (GUI) для управления и контроля планировщиков sched-ext. Доступ к GUI можно получить, нажав на кнопку `sched-ext scheduler config` в главном окне.

<br />
<ImageComponent imgsrc={import('~/assets/images/cachyos-km3.png')} />

Этот GUI позволяет вам:

- Переключаться между различными планировщиками sched-ext (scx).
- Включать или отключать службу планировщика.
- Проверять текущий запущенный планировщик.
- Устанавливать флаги и профили планировщика.

Для этого Kernel Manager использует `scx_loader` с конфигурацией, хранящейся в `/etc/scx_loader.toml`.

Для получения дополнительной информации о файле конфигурации `scx_loader` ознакомьтесь с [этой документацией](https://github.com/sched-ext/scx/blob/main/tools/scx_loader/configuration.md).

- Как работает `scx_loader`?
    - После выбора планировщика и профиля, scx_loader запустит планировщик с выбранным профилем и сохранит эту конфигурацию в файл `/etc/scx_loader.toml` для обеспечения постоянства между перезагрузками. Пример того, как будет выглядеть файл при выборе `scx_bpfland` с профилем `Gaming`:
        ```toml
        default_sched = "scx_bpfland"
        default_mode = "Gaming"

        [scheds.scx_bpfland]
        auto_mode = []
        gaming_mode = ["-m", "performance"]
        lowlatency_mode = ["-k", "-s", "5000", "-l", "5000"]
        powersave_mode = ["-m", "powersave"]
        ```

### Профили планировщика

- Для чего нужны "профили"?
  - Это пресеты для планировщика, которые изменяют флаги на основе проверенных комбинаций для повышения эффективности в конкретных случаях использования, таких как "Игры".

#### Bpfland

**Низкая задержка (Low Latency)**
* **Флаги командной строки:** `-s 5000 -S 500 -l 5000 -m performance`
* **Описание:** Предназначен для снижения задержки за счет пропускной способности. Подходит для приложений мягкого реального времени, таких как обработка звука и мультимедиа.

**Игры (Gaming)**
* **Флаги командной строки:** `-m performance`
* **Описание:** Оптимизирует стабильность производительности в играх на системах с гибридными ядрами. Приоритезирует P-ядра над E-ядрами на процессорах Intel и CCD на процессорах Ryzen X3D.

**Энергосбережение (Power Save)**
* **Флаги командной строки:** `-m powersave`
* **Описание:** Приоритезирует энергоэффективность. Отдает предпочтение менее производительным ядрам (например, E-ядрам на Intel).

**Сервер (Server)**
* **Флаги командной строки:** `-p`
* **Описание:** Приоритезирует задачи со строгой привязкой к ядру. Эта опция может увеличить пропускную способность за счет задержки и больше подходит для серверных нагрузок.

#### Flash

**Низкая задержка (Low Latency)**
* **Флаги командной строки:** `-m performance -w -C 0`
* **Описание:** Предназначен для снижения задержки за счет пропускной способности. Подходит для приложений мягкого реального времени, таких как обработка звука и мультимедиа.

**Игры (Gaming)**
* **Флаги командной строки:** `-m all`
* **Описание:** Оптимизирует для высокой производительности в играх.

**Энергосбережение (Power Save)**
* **Флаги командной строки:** `-m powersave -I 10000 -t 10000 -s 10000 -S 1000`
* **Описание:** Приоритезирует энергоэффективность. Отдает предпочтение менее производительным ядрам (например, E-ядрам на Intel) и вводит принудительный цикл простоя каждые 10 мс для увеличения энергосбережения.

**Сервер (Server)**
* **Флаги командной строки:** `-m all -s 20000 -S 1000 -I -1 -D -L`
* **Описание:** Настроен для серверных нагрузок. Жертвует отзывчивостью ради пропускной способности.

#### LAVD

**Игры и низкая задержка (Gaming & Low Latency)**
* **Флаги командной строки:** `--performance`
* **Описание:** Максимизирует производительность, используя все доступные ядра, с приоритетом на физические ядра.

**Энергосбережение (Power save)**
* **Флаги командной строки:** `--powersave`
* **Описание:** Минимизирует потребление энергии, сохраняя приемлемую производительность. Приоритезирует эффективные ядра и потоки над физическими ядрами.

#### P2DQ

**Игры (Gaming)**
* **Флаги командной строки:** `--task-slice true -f --sched-mode performance`
* **Описание:** Улучшает стабильность игровой производительности и увеличивает смещение в сторону планирования на более производительных ядрах.

**Низкая задержка (Low Latency)**
* **Флаги командной строки:** `-y -f --task-slice true`
* **Описание:** Снижает задержку, заставляя интерактивные задачи дольше оставаться на назначенном им CPU и повышая стабильность временного кванта.

**Энергосбережение (Power Save)**
* **Флаги командной строки:** `--sched-mode efficiency`
* **Описание:** Повышает энергоэффективность, отдавая приоритет энергоэффективным ядрам.

**Сервер (Server)**
* **Флаги командной строки:** `--keep-running`
* **Описание:** Улучшает производительность серверных нагрузок, позволяя задачам выполняться дольше своего кванта, если CPU простаивает.

#### Tickless

**Игры (Gaming)**
* **Флаги командной строки:** `-f 5000 -s 5000`
* **Описание:** Повышает игровую производительность за счет более частого обнаружения конкуренции за CPU и вызова переключений контекста с более коротким временным квантом.

**Энергосбережение (Power Save)**
* **Флаги командной строки:** `-f 50 -p`
* **Описание:** Повышает энергоэффективность, снижая частоту проверок на конкуренцию и агрессивно пытаясь удерживать задачи на одном и том же CPU.

**Низкая задержка (Low Latency)**
* **Флаги командной строки:** `-f 5000 -s 1000`
* **Описание:** Аналогичен игровому профилю, но с еще более уменьшенным квантом времени.

**Сервер (Server)**
* **Флаги командной строки:** `-f 100`
* **Описание:** Снижает частоту проверок планировщика на конкуренцию за CPU для улучшения пропускной способности за счет отзывчивости.

#### Cosmos

**Игры (Gaming)**
* **Флаги командной строки:** `-c 0 -p 0`
* **Описание:** Отключает отслеживание загрузки CPU и всегда принудительно использует планирование на основе дедлайнов для улучшения отзывчивости.

**Энергосбережение (Power Save)**
* **Флаги командной строки:** `-m powersave -d -p 5000`
* **Описание:** Приоритезирует энергоэффективность. Отдает предпочтение менее производительным ядрам (например, E-ядрам на Intel) и отключает отложенные пробуждения, снижая пропускную способность, но повышая энергоэффективность. Интервал опроса загрузки CPU увеличен до 5 мс.

**Низкая задержка (Low Latency)**
* **Флаги командной строки:** `-m performance -c 0 -p 0 -w`
* **Описание:** Предназначен для снижения задержки за счет пропускной способности. Подходит для приложений мягкого реального времени, таких как обработка звука и мультимедиа. Всегда принудительно использует планирование на основе дедлайнов и оптимизации синхронного пробуждения для улучшения предсказуемости производительности.

**Сервер (Server)**
* **Флаги командной строки:** `-a -s 20000`
* **Описание:** Включает привязку к адресному пространству для улучшения локальности и производительности в определенных кэш-чувствительных нагрузках. Интервал опроса увеличен до 20 мс.
