Instalar un kernel desde un repositorio
---------------------------------------

El CachyOS Kernel Manager simplifica la instalación y gestión de kernels desde cualquier repositorio de Arch Linux.

Para instalar un kernel. Inicia la aplicación `CachyOS Kernel Manager` y elige el kernel deseado marcando la casilla `[]` de la lista de todas las opciones disponibles, luego simplemente presiona `Execute` para iniciar la instalación del kernel.

Para desinstalar un kernel, simplemente desmarca la casilla `[]` junto al kernel instalado que deseas eliminar y presiona `Execute` de nuevo.

<br />
<ImageComponent imgsrc={import('~/assets/images/cachyos-km1.png')} />

:::note
El botón `Execute` se desactiva cuando eliges un kernel ya instalado.
:::

Configurar y compilar un kernel personalizado de CachyOS
---------------------------------

<br />
<ImageComponent imgsrc={import('~/assets/images/cachyos-km2.png')} />

:::note
El CachyOS Kernel Manager está diseñado específicamente para compilar kernels personalizados para las **variantes de CachyOS** y no es compatible con la compilación o configuración de un kernel estándar de Arch Linux o cualquier otra variante.
:::

*Para empezar. Abre el Kernel Manager y haz clic en el botón `Configure` para comenzar a ajustar varias configuraciones, como el planificador deseado, la frecuencia de interrupción (tick rate) y más. Una vez que hayas realizado los cambios deseados, haz clic en `Build kernel` para comenzar a compilar tu kernel personalizado de CachyOS.*

**Los paquetes del kernel compilado y la caché se almacenan en** `~/.cache/cachyos-km/`

**Opciones de configuración disponibles:**

* `Custom package name`: Con esta opción, puedes nombrar tu kernel como quieras. Por ejemplo: `linux-custom-cachy`
* Planificador (Scheduler) (BORE, RC, RT, RT+BORE, EEVDF y BMQ)
* Habilitar configuración de CachyOS
* Ajustar configuración mediante nconfig, menuconfig, xconfig o gconfig
* Habilitar/Deshabilitar NUMA
* Habilitar/Deshabilitar Modprobed-db
* KBUILD CFLAGS (-O3 o -O2)
* Gobernador de rendimiento (Performance governor) como predeterminado
* Habilitar BBR3
* Selección de frecuencia de interrupción (tick rate) (100Hz, 250Hz, 300Hz, 500Hz, 600Hz, 750Hz, 1000Hz)
* Modo sin interrupciones (Tickless mode) (idle, periodic, full)
* Prioridad de expropiación (Preemption) (Full, Voluntary o Server)
* Páginas enormes transparentes (Transparent Hugepages) (Always o Madvise)
* Habilitar/Deshabilitar DAMON
* Habilitar/Deshabilitar detección automática de la arquitectura de la CPU
* Aplicar optimización del kernel para arquitecturas de CPU específicas
* Habilitar LTO (Full, Thin, No)
* Compilar módulo ZFS
* Compilar módulo cerrado de NVIDIA
* Compilar módulo abierto de NVIDIA
* Incluir vmlinux con información/símbolos de depuración
* Cargar/Guardar preajuste de configuración del Kernel Manager: `(Solo preajustes del propio gestor)`
* Gestión de parches del kernel (soporte remoto y local)

*Una vez que el kernel se haya compilado con éxito, se te pedirá tu contraseña de sudo para instalar el kernel.*

## Gestión del framework Sched-ext

El Kernel Manager proporciona una interfaz gráfica de usuario (GUI) para gestionar y controlar los planificadores sched-ext. Accede a la GUI haciendo clic en el botón `sched-ext scheduler config` en la ventana principal.

<br />
<ImageComponent imgsrc={import('~/assets/images/cachyos-km3.png')} />

Esta GUI te permite:

- Cambiar entre diferentes planificadores sched-ext (scx).
- Habilitar o deshabilitar el servicio del planificador.
- Comprobar el planificador que se está ejecutando actualmente.
- Establecer indicadores (flags) y perfiles del planificador.

Para lograr esto, el Kernel Manager utiliza `scx_loader` con una configuración almacenada en `/etc/scx_loader.toml`.

Para más información sobre el archivo de configuración de `scx_loader`, consulta [esta documentación](https://github.com/sched-ext/scx/blob/main/rust/scx_loader/configuration.md).

- ¿Cómo funciona `scx_loader`?
    - Una vez que has seleccionado el planificador y el perfil, scx_loader iniciará el planificador con el perfil que ha sido seleccionado y guardará esta configuración en el archivo `/etc/scx_loader.toml` para lograr persistencia entre reinicios. Un ejemplo de cómo se verá el archivo al elegir `scx_bpfland` con el perfil `Gaming`:
        ```toml
        default_sched = "scx_bpfland"
        default_mode = "Gaming"

        [scheds.scx_bpfland]
        auto_mode = []
        gaming_mode = ["-m", "performance"]
        lowlatency_mode = ["-k", "-s", "5000", "-l", "5000"]
        powersave_mode = ["-m", "powersave"]
        ```

### Perfiles del planificador

- ¿Para qué sirven los "perfiles"?
  - Son preajustes para el planificador que modifican los indicadores (flags) basándose en combinaciones probadas para mejorar la eficacia en casos de uso específicos, como "Gaming".

#### Bpfland

**Baja Latencia (Low Latency)**
* **Indicadores de línea de comandos:** `-s 5000 -S 500 -l 5000 -m performance`
* **Descripción:** Diseñado para reducir la latencia a costa del rendimiento (throughput). Adecuado para aplicaciones de tiempo real no estrictas como procesamiento de audio y multimedia.

**Juegos (Gaming)**
* **Indicadores de línea de comandos:** `-m performance`
* **Descripción:** Optimiza la consistencia del rendimiento en juegos en sistemas con núcleos híbridos. Prioriza los P-cores sobre los E-cores en CPUs Intel y los CCDs en CPUs Ryzen X3D.

**Ahorro de Energía (Power Save)**
* **Indicadores de línea de comandos:** `-m powersave`
* **Descripción:** Prioriza la eficiencia energética. Favorece los núcleos menos potentes (ej. E-cores en Intel).

**Servidor (Server)**
* **Indicadores de línea de comandos:** `-p`
* **Descripción:** Prioriza tareas con afinidad estricta. Esta opción puede aumentar el rendimiento (throughput) a costa de la latencia y es más adecuada para cargas de trabajo de servidor.

#### Flash

**Baja Latencia (Low Latency)**
* **Indicadores de línea de comandos:** `-m performance -w -C 0`
* **Descripción:** Diseñado para reducir la latencia a costa del rendimiento (throughput). Adecuado para aplicaciones de tiempo real no estrictas como procesamiento de audio y multimedia.

**Juegos (Gaming)**
* **Indicadores de línea de comandos:** `-m all`
* **Descripción:** Optimiza para un alto rendimiento en juegos.

**Ahorro de Energía (Power Save)**
* **Indicadores de línea de comandos:** `-m powersave -I 10000 -t 10000 -s 10000 -S 1000`
* **Descripción:** Prioriza la eficiencia energética. Favorece los núcleos menos potentes (ej., E-cores en Intel) e introduce un ciclo de inactividad forzado cada 10 ms para aumentar el ahorro de energía.

**Servidor (Server)**
* **Indicadores de línea de comandos:** `-m all -s 20000 -S 1000 -I -1 -D -L`
* **Descripción:** Ajustado para cargas de trabajo de servidor. Sacrifica la capacidad de respuesta por el rendimiento (throughput).

#### LAVD

**Juegos y Baja Latencia (Gaming & Low Latency)**
* **Indicadores de línea de comandos:** `--performance`
* **Descripción:** Maximiza el rendimiento utilizando todos los núcleos disponibles, priorizando los núcleos físicos.

**Ahorro de energía (Power save)**
* **Indicadores de línea de comandos:** `--powersave`
* **Descripción:** Minimiza el consumo de energía manteniendo un rendimiento razonable. Prioriza los núcleos e hilos eficientes sobre los núcleos físicos.

#### P2DQ

**Juegos (Gaming)**
* **Indicadores de línea de comandos:** `--task-slice true -f --sched-mode performance`
* **Descripción:** Mejora la consistencia en el rendimiento de los juegos y aumenta la preferencia por planificar en núcleos de mayor rendimiento.

**Baja Latencia (Low Latency)**
* **Indicadores de línea de comandos:** `-y -f --task-slice true`
* **Descripción:** Reduce la latencia haciendo que las tareas interactivas se adhieran más a la CPU a la que fueron asignadas y aumentando la estabilidad en el tiempo de ejecución (slice time).

**Ahorro de Energía (Power Save)**
* **Indicadores de línea de comandos:** `--sched-mode efficiency`
* **Descripción:** Mejora la eficiencia energética al priorizar los núcleos de bajo consumo.

**Servidor (Server)**
* **Indicadores de línea de comandos:** `--keep-running`
* **Descripción:** Mejora las cargas de trabajo del servidor al permitir que las tareas se ejecuten más allá de su tiempo asignado (slice) si la CPU está inactiva.

#### Tickless

**Juegos (Gaming)**
* **Indicadores de línea de comandos:** `-f 5000 -s 5000`
* **Descripción:** Aumenta el rendimiento en juegos al incrementar la frecuencia con la que el planificador detecta la contención de la CPU y provoca cambios de contexto con un tiempo de ejecución (time slice) más corto.

**Ahorro de Energía (Power Save)**
* **Indicadores de línea de comandos:** `-f 50 -p`
* **Descripción:** Mejora la eficiencia energética al reducir las comprobaciones de contención e intentar agresivamente mantener las tareas en la misma CPU.

**Baja Latencia (Low Latency)**
* **Indicadores de línea de comandos:** `-f 5000 -s 1000`
* **Descripción:** Similar al perfil de juegos pero con un tiempo de ejecución (slice) aún más reducido.

**Servidor (Server)**
* **Indicadores de línea de comandos:** `-f 100`
* **Descripción:** Reduce la frecuencia con la que el planificador comprueba la contención de la CPU para mejorar el rendimiento (throughput) a costa de la capacidad de respuesta.

#### Cosmos

**Juegos (Gaming)**
* **Indicadores de línea de comandos:** `-c 0 -p 0`
* **Descripción:** Deshabilita el seguimiento de la carga de la CPU y siempre impone una planificación basada en plazos (deadline-based) para mejorar la capacidad de respuesta.

**Ahorro de Energía (Power Save)**
* **Indicadores de línea de comandos:** `-m powersave -d -p 5000`
* **Descripción:** Prioriza la eficiencia energética. Favorece los núcleos menos potentes (ej., E-cores en Intel) y deshabilita los despertares diferidos, reduciendo el rendimiento (throughput) mientras aumenta la eficiencia energética. El sondeo de carga de la CPU se aumenta a 5 ms.

**Baja Latencia (Low Latency)**
* **Indicadores de línea de comandos:** `-m performance -c 0 -p 0 -w`
* **Descripción:** Diseñado para reducir la latencia a costa del rendimiento (throughput). Adecuado para aplicaciones de tiempo real no estrictas como procesamiento de audio y multimedia. Siempre impone una planificación basada en plazos (deadline-based) y optimizaciones de despertar síncrono para mejorar la predictibilidad del rendimiento.

**Servidor (Server)**
* **Indicadores de línea de comandos:** `-a -s 20000`
* **Descripción:** Habilita la afinidad del espacio de direcciones para mejorar la localidad y el rendimiento en ciertas cargas de trabajo sensibles a la caché. El sondeo se aumenta a 20 ms.
