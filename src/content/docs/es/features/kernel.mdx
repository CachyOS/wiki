El kernel de CachyOS es un kernel personalizado que utiliza mejoras, configuraciones y parches originales.

## Características

### Optimizaciones de rendimiento

- **Compilación avanzada**: PKGBUILD altamente personalizable compatible con compiladores GCC y Clang
- **Optimización del tiempo de enlace (LTO)**: LTO fino habilitado por defecto para un mejor rendimiento
- **Optimización guiada por perfiles**: AutoFDO + generación de perfiles Propeller para una generación óptima de código ([Más información](https://cachyos.org/blog/2411-kernel-autofdo/))
- **Integridad del flujo de control del kernel (kCFI)**: Disponible al usar LLVM para mayor seguridad
- **Opciones de frecuencia del temporizador**: Configurable entre 300 Hz, 500 Hz, 600 Hz, 750 Hz y 1000 Hz (predeterminado: 1000 Hz)
- **Optimizaciones de arquitectura**: Compatibilidad con x86-64-v3, x86-64-v4 y AMD Zen4 Compilaciones
- **Optimizaciones del compilador**: Indicadores GCC avanzados, incluyendo `-fivopts` y `-fmodulo-sched`

### Mejoras de la CPU

- **Múltiples programadores**: Programadores BORE, EEVDF y BMQ para optimizar diferentes cargas de trabajo
- **Mejoras de AMD P-State**: Compatibilidad con Preferred Core y las últimas mejoras de amd-pstate de linux-next
- **Soporte en tiempo real**: Compilaciones de kernel RT disponibles con integración del programador BORE
- **CachyOS Sauce**: Configuración personalizada de `CONFIG_CACHY` con programador y ajustes del sistema
- **Optimizaciones de baja latencia**: Parches para mejorar la capacidad de respuesta y reducir el jitter

### Sistema de archivos y memoria

- **Compatibilidad con ZFS**: Compatibilidad integrada con el sistema de archivos ZFS con módulos precompilados
- **Integración con NVIDIA**:
  - Módulos de controlador NVIDIA propietarios con parches
  - Compatibilidad con controladores NVIDIA de código abierto
  - Módulos listos para usar en el repositorio
- **Mejoras del programador de E/S**:
  - Rendimiento mejorado de BFQ y mq-deadline
  - Compatibilidad con el programador de E/S alternativo [ADIOS](https://github.com/firelzrd/adios)
- **Gestión de memoria**:
  - Parche [le9uo](https://github.com/firelzrd/le9uo) para evitar la sobrecarga de páginas bajo presión de memoria
  - Ajustes de la gestión de memoria del núcleo Zen (compactación, optimización de marca de agua)

### Características adicionales

#### Compatibilidad con hardware
- **Hardware para juegos**: Parches para Steam Deck (audio, peculiaridades de hardware, HID) y compatibilidad con ROG Ally
- **Hardware de Apple**: Compatibilidad con MacBook T2 incluida por defecto
- **Hardware de ASUS**: Parches de compatibilidad ampliada con hardware de ASUS
- **Gráficos**: Compatibilidad con HDR habilitada, anulación de min_powercap de AMDGPU (`amdgpu_ignore_min_pcap`)

#### Mejoras del sistema
- **Multimedia**: Módulos v4l2loopback incluidos por defecto
- **Virtualización**: Compatibilidad con anulación de ACS para el paso a través de VFIO/GPU
- **Integración ascendente**: Parches seleccionados de Clear Linux y linux-next

#### Miscélaneo

El kernel de CachyOS también cuenta con otras características notables que, aunque sutiles, mejoran la experiencia del usuario:

- Incluye una variante de depuración del kernel que proporciona un binario del kernel sin depurar para fines de depuración. Este paquete es necesario para perfilar el kernel con AutoFDO. 
- [Binder](https://developer.android.com/reference/android/os/Binder), el módulo necesario para [Waydroid](https://waydro.id/) está habilitado por defecto en la configuración del kernel y ya está 
[configurado](https://github.com/CachyOS/linux-cachyos/blob/master/linux-cachyos/config#L10784).

## Variantes

CachyOS ofrece una amplia gama de opciones de kernel. Todos los kernels que ofrecemos incluyen el [conjunto de parches base de CachyOS](https://github.com/CachyOS/kernel-patches).

Para cada kernel, existe una [variante -lto correspondiente](#Convención de nomenclatura de paquetes) que se compila con [clang](https://clang.llvm.org/) en lugar de [GCC](https://gcc.gnu.org/).

- **linux-cachyos**
  - El kernel predeterminado. Este es el kernel recomendado si no está seguro de cuál usar.
  - Frecuencia de ticks de 1000 Hz para una mejor capacidad de respuesta.
  - Desarrollado con Clang y ThinLTO.
  - Perfilado con nuestro propio perfil [AutoFDO](https://cachyos.org/blog/2411-kernel-autofdo/) para un mejor rendimiento. [Script](https://github.com/CachyOS/cachyos-benchmarker/blob/master/kernel-autofdo.sh) utilizado para perfilar el kernel.
- **linux-cachyos-bore**
  - Utiliza el programador [BORE](https://github.com/firelzrd/bore-scheduler). - **linux-cachyos-bmq**
- **linux-cachyos-bmq**
  - Utiliza el planificador BMQ del [Proyect C](https://gitlab.com/alfredchen/projectc/) de Alfred Chen.
    - `No es compatible con sched-ext.`
- **linux-cachyos-deckify**
  - El kernel predeterminado para dispositivos portátiles. No se recomienda ni se admite el uso de ningún otro kernel en dispositivos portátiles.
  - Utiliza el planificador [BORE](https://github.com/firelzrd/bore-scheduler).
  - Parches específicos para dispositivos portátiles, además del conjunto de parches base, para mejorar la compatibilidad y la experiencia general en dispositivos portátiles.
- **linux-cachyos-eevdf**
  - Ajusta el planificador predeterminado del kernel para una mejor respuesta.
- **linux-cachyos-lts**
  - Basado en el último kernel con soporte a largo plazo. 
  - Utiliza el programador [BORE](https://github.com/firelzrd/bore-scheduler).
  - Mínimamente parcheado en comparación con otros kernels para garantizar estabilidad máxima.
- **linux-cachyos-hardened**
  - Utiliza el planificador [BORE](https://github.com/firelzrd/bore-scheduler).
  - Incluye el conjunto de parches [linux-hardened](https://github.com/anthraxx/linux-hardened).
  - Configuración del kernel basada en [linux-hardened config](https://gitlab.archlinux.org/archlinux/packaging/packages/linux-hardened/-/blob/main/config).
    - Contiene un endurecimiento muy agresivo que reduce significativamente el rendimiento y la experiencia del usuario.
    - `No es compatible con sched-ext.`
- **linux-cachyos-rc**
  - Basado en el kernel principal más reciente del [árbol de Linus](https://github.com/torvalds/linux/).
  - Utiliza el programador [BORE](https://github.com/firelzrd/bore-scheduler).
  - Kernel principal para introducir nuevas funciones en nuestro conjunto de parches.
- **linux-cachyos-server**
  - Optimizado para cargas de trabajo de servidor en comparación con el uso de escritorio.
    - Frecuencia de tick de 300 Hz.
    - Sin preempción.
    - EEVDF estándar.
- **linux-cachyos-rt-bore**
  - Preempción en tiempo real.
  - Utiliza el programador [BORE](https://github.com/firelzrd/bore-scheduler).

:::note
A menos que se especifique lo contrario, se puede asumir que todas las demás variantes del kernel tienen la misma configuración que el kernel predeterminado. 
:::

Abre un issue en [linux-cachyos GitHub](https://github.com/CachyOS/linux-cachyos) para obtener sugerencias y mejoras que se puedan añadir al kernel predeterminado.

### Convención de nomenclatura de paquetes

```sh
linux-cachyos # Paquete base del kernel predeterminado. Compilado con Clang y ThinLTO.
linux-cachyos-hardened # Paquete base del kernel reforzado. Compilado con GCC
linux-cachyos-hardened-lto # equivalente compilado en clang para linux-cachyos-hardened
linux-cachyos-hardened-{,lto-}headers
linux-cachyos-hardened-{,lto-}nvidia
linux-cachyos-hardened-{,lto-}nvidia-open
linux-cachyos-hardened-{,lto-}zfs
linux-cachyos-hardened-{,lto-}dbg
```

## Módulos de kernel precompilados

Para dar cabida a una mayor base de usuarios, CachyOS incluye algunos módulos de kernel conocidos y muy utilizados. Esto significa que los usuarios ya no tendrán que recompilarlos tras cada actualización o instalación del kernel, sino que 
solo tendrán que instalarlos desde el repositorio, ya que están precompilados. Esto deja obsoleto cualquier paquete `-dkms` que un usuario pueda tener y que proporcione el mismo módulo que la versión precompilada.

### ZFS

[ZFS](https://openzfs.org/wiki/Main_Page) es uno de los muchos sistemas de archivos compatibles con CachyOS. Al tener licencia [CDDL](https://opensource.org/license/cddl-1-0), es incompatible con la licencia del kernel de Linux y, por lo
tanto, no se puede fusionar en árbol. El módulo incluido incluye las últimas funciones y correcciones originales para garantizar la compatibilidad con el kernel más reciente.

### NVIDIA

CachyOS incluye versiones precompiladas de los módulos del kernel de código cerrado y de [código abierto](https://github.com/NVIDIA/open-gpu-kernel-modules/). Debido a que el desarrollo del módulo del kernel de NVIDIA está fuera del árbol 
de desarrollo y, por lo tanto, no sigue la cadencia de lanzamiento del kernel, la configuración predeterminada a veces puede ser incompatible con el kernel más reciente. Como solución alternativa, CachyOS parchea los módulos con parches 
creados por la comunidad o compartidos directamente por NVIDIA.

## Preguntas frecuentes

### ¿Por qué no se utiliza AutoFDO para todas las demás variantes del kernel?

Porque es costoso de compilar, ya que básicamente requiere compilar el kernel dos veces, lo que implica más tiempo y recursos dedicados a la compilación. El proceso de compilar un kernel con AutoFDO implica los siguientes pasos:

1) Compilar el kernel con AutoFDO y las capacidades de depuración habilitadas.
2) Crear un perfil, lo que implica ejecutar cargas de trabajo para recopilar datos de perfilado para las posibles optimizaciones.
3) Recompilar el kernel con el perfil AutoFDO.

Por lo tanto, solo está presente en la variante [linux-cachyos](/features/kernel#variants) por ahora. Para más información sobre AutoFDO, haga clic [aquí].(https://cachyos.org/blog/2411-kernel-autofdo/)

### ¿El kernel en tiempo real mejora el rendimiento de los juegos?

No. El kernel en tiempo real permite preemptar mucho más código en comparación con un kernel normal totalmente preemptible. Esto significa que muchas más tareas (incluidos los procesos de juegos) se preemptan con frecuencia y dejen de usar 
recursos del sistema de forma forzada, lo que resulta en un peor rendimiento.
