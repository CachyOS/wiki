## Antes de empezar

:::note
Si solo obtienes GRUB y Limine como opciones de gestor de arranque después de presionar **Launch Installer**, entonces el sistema se ha iniciado en modo Legacy/BIOS.
:::

:::note[No se permite instalar múltiples entornos de escritorio durante el proceso de instalación.]
:::

:::caution[Secure Boot y CSM deben estar desactivados en la configuración de la BIOS/UEFI al instalar en modo UEFI.]
Para configurar Secure Boot después de la instalación, consulta la sección [Secure Boot](/es/configuration/secure_boot_setup).

`Legacy USB Support` debe estar configurado en `Auto`.
:::

:::caution
Las opciones `Install alongside` (Instalar junto a) y `Replace partition` (Reemplazar partición) no son 100% fiables y pueden hacer que la instalación falle.

Se **prefiere encarecidamente** el `Manual partitioning` (Particionado manual) al instalar CachyOS.
:::

:::tip
Se recomienda encarecidamente reiniciar en la ISO después de un intento de instalación fallido.

De lo contrario, pueden ocurrir errores continuos durante el proceso de instalación.

Esto sucede porque el instalador no desmonta correctamente las particiones en una instalación fallida.

:::

## Métodos de Instalación

### Particionado Manual

:::note[Antes de proceder con el particionado del disco para una instalación UEFI.]
    ```sh title='Ejecuta este comando en la terminal'
    efibootmgr -v
    ```
Si la salida es `EFI variables are not supported on this system.`, entonces el sistema se ha iniciado en modo Legacy/BIOS, y necesitas asegurarte de que el modo UEFI esté configurado en los ajustes de la BIOS/UEFI. Consulta la sección [Requisitos](/es/installation/installation_on_root/#antes-de-empezar).
:::

## Arranque Dual de Windows y CachyOS

:::note[Esta guía asume que Windows ya está instalado en el sistema y has decidido instalar CachyOS junto a él, compartiendo la misma unidad.]
:::

:::caution
El arranque dual de Windows y Linux no es 100% fiable. Las actualizaciones de Windows pueden romper el gestor de arranque al sobrescribir la partición EFI.
En algunos casos, puede que nunca ocurran problemas, pero para algunos usuarios puede ser un problema recurrente.

Una forma de evitar este problema es instalar cada sistema operativo en una unidad separada.
:::

:::caution
Es posible que sea necesario redimensionar la partición EFI, dependiendo del tamaño mínimo recomendado para el gestor de arranque de destino. Consulta [Particionado Manual](/es/installation/installation_on_root#particionado-manual).

Los sistemas de archivos FAT no se pueden redimensionar en el lugar. Para "redimensionar" correctamente la partición EFI FAT, se debe hacer una copia de seguridad del sistema de archivos EFI existente, usar una herramienta como `gparted` para redimensionar la partición existente y reformatear la nueva partición, y luego copiar la estructura del sistema de archivos anterior de nuevo en la partición EFI.
:::

### Prerrequisitos

- El Inicio Rápido y la Hibernación de Windows deben estar desactivados.
  - Abre Windows Powershell como administrador y ejecuta el siguiente comando:
      ```ps
      powercfg /H off
      ```
    Reinicia el sistema para asegurarte de que los cambios surtan efecto.
- BitLocker de Windows debe estar desactivado.
  - Comprobando si BitLocker está activado:
    ```ps title='Abre un Símbolo del sistema como administrador y ejecuta el siguiente comando'
    manage-bde -status
    ```
  Si **Método de cifrado** muestra `Ninguno`, entonces BitLocker está desactivado.
- Secure Boot debe estar desactivado.
- Una partición vacía de ≥30 GB.
  - Guía sobre cómo reducir una partición de Windows:
    - Presiona `Win + R`, escribe `diskmgmt.msc` y presiona Enter para abrir la Administración de discos.
    - Identifica tu partición principal de Windows (generalmente C:) y haz clic derecho sobre ella.
    - Haz clic en `Reducir volumen...`, especifica al menos **30720 MB** (30 GiB) y haz clic en `Reducir`.
- Un USB de arranque con CachyOS.
  - Consulta la sección [Crear una unidad USB de arranque de CachyOS](/es/installation/installation_prepare#creación-de-una-unidad-usb-de-arranque-de-cachyos).

<Tabs>
    <TabItem label='systemd-boot'>
        **Necesitamos copiar los binarios EFI de Windows a la partición EFI de Linux para que el gestor de arranque pueda reconocerlos.**

        <Steps>
        1. Localiza la **partición EFI de Windows** con `lsblk`.

            ```sh title='Ejecuta este comando en la terminal'
            lsblk -o NAME,FSTYPE,SIZE,MOUNTPOINT
            ```
            ```sh title='Ejemplo de salida'
                        NAME        FSTYPE   SIZE MOUNTPOINT
            zram0               15.3G [SWAP]
            nvme0n1            476.9G
            ├─nvme0n1p1 vfat     100M
            ├─nvme0n1p2           16M
            ├─nvme0n1p3 ntfs   234.4G
            ├─nvme0n1p4 ntfs     830M
            ├─nvme0n1p5 vfat       2G /boot
            └─nvme0n1p6 btrfs  239.6G /var/tmp
            ```
            Las particiones EFI casi siempre están formateadas como `FAT32/vfat`. Dado que `nvme0n1p1` no tiene un punto de montaje de Linux, podemos asumir que esta partición es la partición EFI de Windows.

        2. Monta temporalmente la partición EFI de Windows.

            ```sh
            sudo mkdir /mnt/WinBoot
            sudo mount /dev/nvme0n1p1 /mnt/WinBoot # Reemplaza `nvme0n1p1` con el nombre de la partición EFI de Windows.
            ```

        3. Copia los binarios EFI de la **partición EFI de Windows** a la **partición EFI de Linux**.

            ```sh
            sudo cp -r /mnt/WinBoot/EFI/Microsoft/ /boot/EFI
            ```

        4. Desmonta la partición montada previamente. Windows debería aparecer en el menú de arranque en el próximo inicio.

            ```sh
            sudo umount /mnt/WinBoot
            sudo rm -r /mnt/WinBoot
            ```

        </Steps>
    </TabItem>

    <TabItem label='GRUB'>
        **GRUB usa os-prober para detectar automáticamente la partición EFI de Windows y añadirla al menú de arranque.**

        <Steps>
        1. Instala **os-prober**.

            ```sh
            sudo pacman -S os-prober
            ```

        2. Habilita **os-prober** en el archivo de configuración de GRUB.

            ```sh title='Presiona CTRL+S para guardar y CTRL+Q para salir de Micro'
            sudo micro /etc/default/grub
            # /etc/default/grub
            # Probing for other operating systems is disabled for security reasons. Read
            # documentation on GRUB_DISABLE_OS_PROBER, if still want to enable this
            # functionality install os-prober and uncomment to detect and include other
            # operating systems.
            GRUB_DISABLE_OS_PROBER=false

            ```

        3. Actualiza grub.cfg, ahora usando **os-prober**.
            ```sh
            sudo grub-mkconfig -o /boot/grub/grub.cfg
            ```

            **Windows debería ahora estar añadido al menú de arranque.**

        </Steps>
    </TabItem>
</Tabs>
