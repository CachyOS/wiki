Bienvenido a la guía para jugar en CachyOS. Te guiaremos a través de los aspectos esenciales sobre cómo configurar todo y tener una gran experiencia.

## Prerrequisitos

:::caution
Antes de sumergirnos en lo divertido, es esencial asegurarse de que los controladores de tu tarjeta gráfica estén instalados y funcionando correctamente. Si tu tarjeta gráfica no está rindiendo de manera óptima, podrías encontrar problemas al jugar.
:::

### Paquetes Esenciales

Para facilitarte las cosas, CachyOS ha agrupado todos los paquetes necesarios para jugar en un único metapaquete que incluye todas las dependencias y bibliotecas necesarias para jugar en Linux, y un paquete separado para las herramientas y lanzadores/tiendas. Esto hace que el proceso de instalación y configuración para jugar sea más rápido y menos enrevesado para todos.

*Si encuentras que falta algún paquete, no dudes en comunicárselo al equipo de CachyOS.*

Sigue los pasos a continuación para comenzar con la configuración de juegos.

## Proton-CachyOS

Proton-CachyOS se basa en la rama `bleeding-edge` de Proton y le aplica varias modificaciones.
- **Parches de Wine-staging**
- **FSR de pantalla completa de Wine**
- **Incluye códecs de video y audio para las cinemáticas de los juegos**
- **Soporte para umu-launcher incluyendo UMU-Protonfixes**
- **Añade correcciones/soluciones tempranas para juegos**

:::note
El paquete `proton-cachyos` de los repositorios de CachyOS se compila contra las bibliotecas nativas del sistema, no utiliza el Steam Linux Runtime. La arquitectura de destino depende del repositorio. Actualmente los repositorios `x86_64_v3`, `x86_64_v4` y `znver4` usan los mismos binarios `x86_64_v3`.
:::

:::caution[NTSync no está activado por defecto. Puedes activarlo usando la variable de entorno `PROTON_USE_NTSYNC=1`.]
:::

### Cómo configurar correctamente múltiples opciones de lanzamiento

```bash title="Las opciones de lanzamiento en Steam se construyen usando el siguiente patrón:"
<variables de entorno> <envoltorios> %command% <argumentos de la aplicación>
```

- **`<variables de entorno>`:** Son opciones en la forma de: `VARIABLE=valor`
  ```bash title="Ejemplos:"
  PROTON_DXVK_D3D8=1
  # O
  DXVK_HUD="fps,memory,version,api"
  ``` 

- **`<envoltorios>`:** Aplicaciones y scripts que modifican cómo se ejecuta la aplicación real. Los argumentos para el envoltorio suelen ir después del ejecutable del envoltorio.
  ```bash title="Ejemplos:"
  mangohud --dlsym
  # O
  gamescope -W 1680 -H 1050 -w 1280 -h 720 -S fit -F fsr --mangoapp --
  ```

- **`%command%`:** Esta es la aplicación real. Debe especificarse exactamente así y Steam lo reemplazará con el comando adecuado cuando se ejecute la aplicación.

- **`<argumentos de la aplicación>`:** Son diversos argumentos para la aplicación real, y dependen de la aplicación.
  ```bash title="Ejemplo:"
  %command% -dx11
  ```
  
**Ejemplo de una opción de lanzamiento completa combinando todos los elementos:**

  ```bash 
  __GL_SHADER_DISK_CACHE_SKIP_CLEANUP=1 prime-run game-performance %command% -dx11
  ```

:::caution
No agregues múltiples `%command%` usándolos como separadores para múltiples opciones de lanzamiento.

Ejemplo: `__GL_SHADER_DISK_CACHE_SKIP_CLEANUP=1 %command% game-performance %command% prime-run %command%`

En este caso, todo lo que sigue al primer `%command%` será ignorado porque se trata como argumentos del juego, por lo tanto, solo `__GL_SHADER_DISK_CACHE_SKIP_CLEANUP=1` es reconocido como una opción de lanzamiento.
:::

#### Variables de Entorno

<Tabs>
<TabItem label="Gráficos y Escalado">

- DLSS y Características de NVIDIA
    - `PROTON_DLSS_UPGRADE=1`: Actualiza automáticamente DLSS a la última versión
    - `PROTON_DLSS_INDICATOR=1`: Muestra el indicador de estado de DLSS en el juego
    - `PROTON_NVIDIA_LIBS=1`: Activa las bibliotecas de NVIDIA (PhysX, CUDA) - no es necesario para DLSS/ray tracing

<details>
<summary>Controles Avanzados de NVIDIA</summary>

- `PROTON_NVIDIA_NVCUDA=1`: Activa solo el soporte de CUDA
- `PROTON_NVIDIA_NVENC=1`: Activa solo la codificación NVENC
- `PROTON_NVIDIA_NVML=1`: Activa la monitorización NVML
- `PROTON_NVIDIA_NVOPTIX=1`: Activa el trazado de rayos OptiX
- `PROTON_NVIDIA_LIBS_NO_32BIT=1`: Activar solo en juegos de 64 bits (soluciona problemas de rendimiento en RTX 4000+)
</details>

- Escalado de AMD e Intel
    - `PROTON_FSR4_UPGRADE=1`: Actualiza automáticamente FSR a la última versión de AMD
    - `PROTON_FSR4_RDNA3_UPGRADE=1`: Usa la DLL de FSR4 optimizada para RDNA3
    - `PROTON_XESS_UPGRADE=1`: Actualiza automáticamente XeSS a la última versión

</TabItem>

<TabItem label="Pantalla y HDR">

- Wayland y Pantalla
    - `PROTON_ENABLE_WAYLAND=1`: Activa el soporte nativo de Wayland
    - **Beneficios**: HDR sin Gamescope, latencia/ritmo de fotogramas mejorado
    - **Inconvenientes**: Rompe el Overlay de Steam, actualmente experimental
    - `PROTON_NO_WM_DECORATION=1`: Desactiva las decoraciones del gestor de ventanas
        - **Soluciona**: Problemas con el modo de pantalla completa sin bordes, clics del ratón que atraviesan las ventanas

- Soporte HDR
    - `PROTON_ENABLE_HDR=1`: Activa el soporte de salida HDR
    - **Requisitos**: Gamescope con `--hdr-enabled` O `PROTON_ENABLE_WAYLAND=1`
    - **Configuración**: [Se necesita configuración adicional](https://wiki.archlinux.org/title/HDR_monitor_support)

</TabItem>

<TabItem label="Rendimiento y Caché">

- Rendimiento de CPU y Sincronización
    - `PROTON_USE_NTSYNC=1`: Usa NTSync para un mejor rendimiento de la CPU
        - **Ideal para**: Juegos limitados por la CPU, reemplaza a WINESync
        - **Nota**: Experimental, puede causar problemas en algunos juegos
        - **Verificación**: Usa `lsof /dev/ntsync` (MangoHud lo reporta incorrectamente)

- Gestión de Shaders y Caché
    - `PROTON_LOCAL_SHADER_CACHE=1`: Activa la caché de shaders por juego, similar al "Pre-cacheo de Shaders" de Steam. Esto NO compila los shaders por adelantado, SOLO aísla la caché de shaders de cada juego. Los shaders se seguirán compilando durante el juego.
    - `PROTON_ENABLE_MEDIACONV=1`: Activa el Proton Media Converter
        - **Nota**: Solo para fines de prueba

- AMD Anti-Lag
    - `ENABLE_LAYER_MESA_ANTI_LAG=1`: Activa AMD Anti-Lag para reducir la latencia de entrada
    :::danger
    proton-cachyos desactiva esto porque impide las actualizaciones de FSR4 y puede provocar tartamudeo u otros problemas ([detalles](https://github.com/CachyOS/CachyOS-PKGBUILDS/pull/909)).
    :::

</TabItem>

<TabItem label="Entrada y Compatibilidad">

- Mando y Entrada
    - `PROTON_PREFER_SDL=1`: Solución para problemas de detección de mandos
    - `PROTON_NO_STEAMINPUT=1`: Desactiva el soporte de Steam Input
        - **Soluciona**: Problemas con mandos/gamepads en Wayland

</TabItem>
</Tabs>

## Wine-CachyOS

Este es el mismo `wine` que se encuentra en el núcleo de `proton-cachyos`, pero como un paquete independiente. Puede usarse en Lutris, Heroic, Bottles y otros.

- **Todas las modificaciones de Wine incluidas con Proton-CachyOS**
- **Añade correcciones/soluciones tempranas para juegos**

:::note
En los repositorios de CachyOS, **Wine-CachyOS** se ofrece en dos paquetes diferentes. `wine-cachyos` lo instala como el Wine predeterminado del sistema y reemplaza a `wine` o `wine-staging`. `wine-cachyos-opt` lo instala en una ubicación diferente, lo que permite que coexistan múltiples versiones de wine en el sistema.
:::

:::caution
El uso principal de **Wine-CachyOS** es para **juegos**. Aunque se puede usar como un Wine de sistema con aplicaciones de escritorio, ten en cuenta que podría provocar comportamientos inesperados y problemas debido a las modificaciones centradas en los juegos.

Si quieres usar aplicaciones de escritorio, te sugerimos usar `wine` o `wine-staging` como el Wine de tu sistema e instalar `wine-cachyos-opt` para los juegos.
:::

**Opciones de configuración adicionales**

- `WINE_WMCLASS="<nombre>"`: Establece la `WM_CLASS` de todas las ventanas de wine, permitiendo que el gestor de ventanas controle las ventanas de Wine a través de reglas.
- `WINEUSERSANDBOX=1`: Desactiva la creación de enlaces simbólicos desde las carpetas de usuario de Wine como Documentos/Imágenes, a las carpetas equivalentes en el directorio `HOME` del usuario.
- `WINE_NO_WM_DECORATION=1`: Desactiva las decoraciones de ventana usando el gestor de ventanas de Linux. Puede solucionar problemas con la **pantalla completa sin bordes** y el clic del ratón que atraviesa la ventana.
- `WINE_PREFER_SDL_INPUT=1`: Actívalo para solucionar problemas con la detección correcta de mandos.

### Cómo usar wine-cachyos-opt

<Tabs>
    <TabItem label='Independiente'>

    ```shell
    export PATH="/opt/wine-cachyos/bin/:$PATH"
    export WINEDLLPATH="/opt/wine-cachyos/lib/wine:/opt/wine-cachyos/lib32/wine:$WINEDLLPATH"
    export LD_LIBRARY_PATH="/opt/wine-cachyos/lib/:/opt/wine-cachyos/lib32/:$LD_LIBRARY_PATH"
    ```


## Preguntas frecuentes y consejos de Steam

:::note
Los usuarios de portátiles con GPU NVIDIA dedicadas deben consultar la [guía de portátiles con doble GPU](/es/configuration/dual_gpu/)
:::

:::tip
CachyOS proporciona varias versiones de Proton que compilamos y mantenemos para obtener mejoras adicionales de rendimiento:
- `proton-cachyos` `(incluido en el paquete cachyos-gaming-meta)` es el que desarrollamos con cambios añadidos para mejorar la calidad de vida + parches seleccionados + optimizaciones de compilación `(x86-64-v3 y x86-64-v4)`
:::

:::tip
Para comprobar si tu juego es compatible o cómo funciona con Linux, visita **[ProtonDB](https://www.protondb.com/)** o **[Are We Anti-Cheat Yet?](https://areweanticheatyet.com/).**
:::

### ¿Qué versión de Proton se debe usar en Steam?

:::note
Dado que hay cierta confusión en **Reddit**, la versión nativa de `Proton-CachyOS` no se va a discontinuar como resultado de que `steam-native-runtime` haya sido discontinuado.

No están relacionados y son irrelevantes entre sí. Últimamente nuestra sugerencia ha sido el SLR, **que también instalamos por defecto**, para reducir la confusión y los problemas para los recién llegados a CachyOS y Linux en general. Si te gusta la versión nativa y te funciona, sigue usándola.
:::

- `Proton 10.0` es la versión estable de `Valve`. Úsala si se sabe que el juego que quieres jugar funciona bien.
- `Proton Experimental` es la versión más avanzada de `Valve`. Úsala si el juego que quieres jugar es relativamente nuevo, no funciona bien con la versión estable actual de Proton, o si la gente lo recomienda en [ProtonDB](https://www.protondb.com/).
- `proton-cachyos-slr` es el que nosotros compilamos y mantenemos. Su uso es muy recomendable, con varias características de calidad de vida, correcciones y optimizaciones. Para juegos que usan anticheat, como **BattlEye** o **Easy Anti-Cheat** o lanzadores personalizados, prefiere `proton-cachyos-slr`.
- `proton-cachyos` es la misma versión que `proton-cachyos-slr` pero compilada sin depender del Steam Linux Runtime. Úsala solo si entiendes el significado de esta diferencia y vuelve a `proton-cachyos-slr` si surgen problemas.
- `Proton-GE` es una compilación personalizada hecha por [GloriousEggroll](https://github.com/GloriousEggroll/proton-ge-custom). Incluye varias correcciones y puede ser útil tenerla en ciertas situaciones.
- `Proton 9.0.4 o inferior` son las versiones estables de `Valve`. Úsalas si el juego que quieres jugar solo funciona con una versión anterior de Proton.

### Corregir el tartamudeo (stuttering) causado por la función de grabación de juegos de Steam

:::caution
Añadir esta variable de entorno hace que la **superposición de Steam** deje de funcionar.
:::

```sh title='Añade la siguiente opción de lanzamiento a tu juego'
LD_PRELOAD="" %command%
```

### Capturar y compartir registros de Proton

:::note
Cuando compartas registros con CachyOS, por favor súbelos a **[paste-cachyos](https://paste.cachyos.org/)** en lugar de publicarlos directamente.

Simplemente puedes arrastrar y soltar el archivo de registro en el sitio web y luego compartir el enlace generado.
:::

Para habilitar el registro de Proton para un juego:

<Steps>
    1. Haz clic derecho en tu juego en Steam y selecciona **Propiedades**.
    2. En **Parámetros de lanzamiento**, añade la variable de entorno `PROTON_LOG`:
        ```sh
        PROTON_LOG=1 %command%
        ```
        Esto creará un archivo de registro en tu directorio personal, llamado `steam-<AppID>.log` (por ejemplo, Counter Strike 2 usa el AppID **730**, por lo que el archivo sería `steam-730.log`).
</Steps>

<details>
<summary>Directorio de registro personalizado</summary>

Para establecer un directorio de registro personalizado, usa `PROTON_LOG_DIR`:

```bash title='Ejemplo'
PROTON_LOG=1 PROTON_LOG_DIR=/home/cachyos/steam-logs %command%
```
</details>

### Pre-caché de shaders con Proton-CachyOS, -GE y -EM

:::note
Se recomienda desactivar la función de `Pre-caché de shaders de Steam` cuando se utiliza Proton-CachyOS, Proton-GE o Proton-EM. Ya contienen todos los códecs necesarios para reproducir vídeos dentro de los juegos, y hoy en día una combinación de GPU-CPU relativamente moderna debería ser más que capaz de lidiar con la compilación de shaders en el juego.

Pero si tienes tiempo de sobra, entonces puedes ignorar este consejo y dejar que Steam precompile algunos shaders para tu juego.

`Ten en cuenta que no todo se guarda en caché durante este proceso.`
:::

### Cómo configurar correctamente múltiples opciones de lanzamiento y variables de entorno en Lutris

- Las opciones de lanzamiento como `-dx11` o `-fullscreen` deben añadirse en el campo **Argumentos** bajo la pestaña **Opciones del juego** usando un espacio como separador.
- Los envoltorios de comandos, por ejemplo `mangohud --dlsym` o `game-performance`, deben añadirse en el campo **Prefijo de comando** bajo la pestaña **Opciones del sistema** usando un espacio como separador.
- Las variables de entorno como `PROTON_ENABLE_HDR=1` deben añadirse en la tabla **Variables de entorno** bajo la pestaña **Opciones del sistema** usando el botón `+` para añadir una nueva entrada.
:::note[No incluyas `=` en el campo Clave. Solo debe contener el nombre de la variable.]
:::

## Consejos de rendimiento y varios

### Qué no hacer al jugar en CachyOS

#### Combinar gamemode y ananicy-cpp

Debido a que tanto `gamemode` como `ananicy-cpp` intentan modificar la prioridad (niceness) de un proceso al mismo tiempo, puede generar conflictos y comportamientos inesperados. Se recomienda usar gamemode sin ananicy-cpp.

Para detener ananicy-cpp, ejecuta el siguiente comando:

```bash
systemctl stop ananicy-cpp
```

### Cambio de perfil de energía bajo demanda

:::note
Este comportamiento difiere ligeramente con `intel_pstate`. En Intel, el gobernador se mantiene en powersave, pero los valores EPP/EPB se ajustan para el rendimiento.
:::

:::caution[game-performance puede no ofrecer ningún beneficio en CPUs antiguas.]
:::

CachyOS incluye un script envoltorio [game-performance](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/bin/game-performance)
que utiliza `power-profiles-daemon` para cambiar temporalmente el perfil de energía a `performance`.
El perfil eleva los niveles de energía del sistema y establece el gobernador de la CPU a `performance`, y también cambia cualquier planificador scx activo a su perfil de juego (si está disponible).

Cuando se usa para lanzar un juego, el sistema permanece en **modo de rendimiento** hasta que el juego se cierra, momento en el que se restaura el perfil anterior.

El [GameMode de Feral](https://github.com/FeralInteractive/gamemode)
ofrece una funcionalidad similar.

### Aumentar el tamaño máximo de la caché de shaders

Los shaders de los juegos se compilan automáticamente mientras juegas, lo que puede causar largos tiempos de carga y tartamudeo la primera vez que los encuentras. Estos shaders se almacenan en tu sistema para ser reutilizados cuando sea necesario.

Sin embargo, hay un límite máximo para el tamaño del archivo de la caché de shaders, lo que hace que los shaders antiguos se olviden cuando se excede el tamaño predeterminado. Esto puede ser un problema, ya que los juegos grandes pueden tener shaders de más de 1GB de tamaño, lo que hace que recompilen shaders en cada lanzamiento.

Para evitar largos tiempos de carga y tartamudeo, podemos aumentar el tamaño global de la caché de shaders:

<Tabs>

<TabItem label='GPU Nvidia'>

<Steps>
1. Abre la terminal.
2. Introduce este comando para editar el archivo de entorno:
	```sh
	sudo nano /etc/environment
	```
3. Pega lo siguiente al final del archivo:
	```sh
	# Aumentar el tamaño de la caché de shaders de Nvidia a 12GB
	__GL_SHADER_DISK_CACHE_SIZE=12000000000
	```
4. Guarda el archivo presionando `CTRL+X`, `Y`, y luego `Enter`.
5. Reinicia tu sistema.
</Steps>

</TabItem>

<TabItem label='GPU AMD'>

<Steps>
1. Abre la terminal.
2. Introduce este comando para editar el archivo de entorno:
	```sh
	sudo nano /etc/environment
	```
3. Pega lo siguiente al final del archivo:
	```sh
	# Fuerza la implementación de Vulkan RADV
	AMD_VULKAN_ICD=RADV

	# Aumentar el tamaño de la caché de shaders de AMD a 12GB
	MESA_SHADER_CACHE_MAX_SIZE=12G
	```
4. Guarda el archivo presionando `CTRL+X`, `Y`, y luego `Enter`.
5. Reinicia tu sistema.
</Steps>

</TabItem>

</Tabs>

Después de reiniciar, el tamaño máximo de la caché de shaders debería haberse aumentado permanentemente. Gracias a [psygreg's shader booster](https://github.com/psygreg/shader-booster/) por ayudar con esta guía.

### Caída de rendimiento en NVIDIA en juegos con DirectX12

Algunos usuarios informan que el problema está relacionado con cómo los controladores de NVIDIA para Linux manejan la programación de la GPU; a diferencia de Windows, donde se aplica una programación adecuada. Todavía no hay una declaración oficial de NVIDIA. Actualmente no se conoce ninguna solución para este problema y supuestamente NVIDIA está trabajando en una solución, pero no está claro cuándo se lanzará.

**No tiene nada que ver con CachyOS.**

En algunos títulos, la caída de rendimiento es menos notable que en otros. Echa un vistazo a este [vídeo de comparación de benchmarks](https://www.youtube.com/watch?v=SU2mFqCOh5A) como referencia.

Sigue el [hilo de NVIDIA](https://forums.developer.nvidia.com/t/directx12-performance-is-terrible-on-linux/303207/488) sobre este problema para saber más al respecto.
