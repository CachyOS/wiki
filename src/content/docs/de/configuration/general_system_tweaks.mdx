## AMD-Leistungsanpassungen

### AMD P-State-Treiber
---------------------------

`amd-pstate` ist der AMD-CPU-Leistungsskalierungstreiber, der einen neuen Mechanismus zur Steuerung der CPU-Frequenz auf modernen AMD APU- und CPU-Serien im Linux-Kernel einführt. Der neue Mechanismus basiert auf Collaborative Processor Performance Control (CPPC), das eine feiner granulierte Frequenzverwaltung ermöglicht als die herkömmlichen ACPI-Hardware-P-States.

Aktuelle AMD-CPU/APU-Plattformen verwenden den ACPI-P-States-Treiber zur Verwaltung der CPU-Frequenz und -Taktraten mit nur 3 P-States. CPPC ersetzt die ACPI-P-States-Steuerung und ermöglicht eine flexible, latenzarme Schnittstelle für den Linux-Kernel, um Leistungshinweise direkt an die Hardware zu kommunizieren.

Nachfolgend sind 3 Betriebsmodi des `amd-pstate`-Treibers und die entsprechenden Kernel-Kommandozeilenoptionen aufgeführt, um sie beim Booten zu verwenden:

- AMD P-State (nicht-autonomer Modus): `amd-pstate=passive`
- AMD P-State Guided (geführter autonomer Modus): `amd-pstate=guided`
- AMD P-State EPP (autonomer Modus): `amd-pstate=active`

:::note
Der AMD P-State EPP-Treiber wird standardmäßig verwendet, wenn keine explizite Konfiguration vorgenommen wird.
:::

Du kannst auch zur Laufzeit zwischen den Betriebsmodi wechseln, um die Optionen zu testen:

- **Autonomer Modus**: Die Plattform berücksichtigt nur die für minimale Leistung, maximale Leistung und Energie-Leistungs-Präferenz eingestellten Werte.
   ```sh
   echo active | sudo tee /sys/devices/system/cpu/amd_pstate/status
   ```

- **Geführter autonomer Modus**: Die Plattform stellt die Betriebsleistungsstufe entsprechend der aktuellen Arbeitslast und innerhalb der vom Betriebssystem über minimale und maximale Leistungsregister gesetzten Grenzen ein.
   ```sh
   echo guided | sudo tee /sys/devices/system/cpu/amd_pstate/status
   ```

- **Nicht-autonomer Modus**: Die Plattform erhält die gewünschte Leistungsstufe direkt vom Betriebssystem über das Desired-Performance-Register.
   ```sh
   echo passive | sudo tee /sys/devices/system/cpu/amd_pstate/status
   ```

### AMD P-State EPP konfigurieren


Um P-State EPP zu verwenden, stehen zwei CPU-Frequenzskalierungs-Governors zur Verfügung: `powersave` und `performance`. Es wird empfohlen, den `powersave`-Governor zu verwenden und eine Präferenz festzulegen.

*   `powersave`-Governor setzen: `sudo cpupower frequency-set -g powersave`
*   `performance`-Governor setzen: `sudo cpupower frequency-set -g performance`

Um eine Präferenz festzulegen, führ den folgenden Befehl mit der gewünschten Präferenz aus:

```sh
echo power | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/energy_performance_preference
```

Verfügbare Präferenzen: `performance`, `power`, `balance_power`, `balance_performance`

Benchmarks für jede Präferenz findest du hier:
[https://lore.kernel.org/lkml/20221219064042.661122-1-perry.yuan@amd.com/](https://lore.kernel.org/lkml/20221219064042.661122-1-perry.yuan@amd.com/)

### AMD 3D V-Cache Optimierer

AMD hat einen Patch zur Optimierung des Cache-Schedulings auf Dual-CCD-3D-CPUs wie 7950X3D und 7900X3D veröffentlicht.
Du musst im BIOS unter der CPPC-Option die Option „Driver“ einstellen. Dies ermöglicht es, den verwendeten Modus über sysfs zu überschreiben.

Es gibt zwei Modi:
1. Frequency
2. Cache

Wenn `cache` eingestellt ist, versucht der Treiber, die Aufgaben zuerst auf den CCD mit dem größeren Cache zu legen, was hauptsächlich bei Spielen vorteilhaft ist.
Die `frequency`-Option versucht, die Aufgaben auf den zweiten CCD zu legen, der eine höhere Frequenz als der 3D-Cache-CCD hat.

Frequenz (Standard):
```sh
echo frequency | sudo tee /sys/bus/platform/drivers/amd_x3d_vcache/AMDI0101:00/amd_x3d_mode
```

Cache:
```sh
echo cache | sudo tee /sys/bus/platform/drivers/amd_x3d_vcache/AMDI0101:00/amd_x3d_mode
```

Nachdem du die Modi geändert hast, sollten die „amd preferred core stats“ eine andere Rangfolge anzeigen. Du kannst diese mit folgendem Befehl auslesen:
```sh
grep -v /sys/devices/system/cpu/cpu*/cpufreq/amd_pstate_prefcore_ranking
```

### AMD P-State Core Performance Boost

AMD Core Performance Boost, auch bekannt als AMD Turbo Core, ist eine dynamische Frequenzskalierungstechnologie von AMD, die es dem
Prozessor ermöglicht, die Betriebsfrequenz in bestimmten Prozessorversionen dynamisch anzupassen und zu steuern,
was bei Bedarf eine erhöhte Leistung ermöglicht, während im Normalbetrieb niedrigere Leistungs- und Wärmeparameter beibehalten werden.

Seit `linux-cachyos` 6.9.6 ist der Kernel mit CPB-Unterstützung für AMDs P-State-Treiber gepatcht (einschließlich `passive`, `active` und `guided`).
Benutzer können den Boost-Status jedes CPU-Kerns über die sysfs-Boost-Datei `/sys/devices/system/cpu/cpuX/cpufreq/boost` ändern
(X bezieht sich auf die Kernnummer, z.B. cpu0 ist der erste Kern, cpu1 der zweite, usw.).

```sh
❯ echo 0 | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/boost # Boost für alle Kerne deaktivieren
❯ lscpu -ae # Dies zeigt, dass AMD CPB global deaktiviert ist
CPU NODE SOCKET CORE L1d:L1i:L2:L3 ONLINE    MAXMHZ   MINMHZ       MHZ
  0    0      0    0 0:0:0:0          yes 3301.0000 400.0000 1212.8250
  1    0      0    0 0:0:0:0          yes 3301.0000 400.0000 1394.2180
  2    0      0    1 1:1:1:0          yes 3301.0000 400.0000 1204.4600

❯ echo 1 | sudo tee /sys/devices/system/cpu/cpu0/cpufreq/boost # Aktiviert Boost auf cpu0
❯ lscpu -ae
CPU NODE SOCKET CORE L1d:L1i:L2:L3 ONLINE    MAXMHZ   MINMHZ       MHZ
  0    0      0    0 0:0:0:0          yes 4564.0000 400.0000 1393.2380
  1    0      0    0 0:0:0:0          yes 3301.0000 400.0000  400.0000
  2    0      0    1 1:1:1:0          yes 3301.0000 400.0000 2157.8469
```

CachyOS bietet auch eine Version von `power-profiles-daemon`, die einen Commit zurückportiert, der
Unterstützung für AMD CPB ermöglicht. AMD CPB wird deaktiviert, wenn das `powersave`-Profil verwendet wird, und aktiviert, wenn `balanced` oder `performance` verwendet wird.

## Leistungsverbesserungen

### Split Lock Mitigate deaktivieren

In einigen Fällen kann die Split-Lock-Mitigation die Leistung in einigen Anwendungen und Spielen verlangsamen. Es ist ein Patch verfügbar, um sie über sysctl zu deaktivieren.

*   Split-Lock-Mitigation deaktivieren: `sudo sysctl kernel.split_lock_mitigate=0`
*   Split-Lock-Mitigation aktivieren: `sudo sysctl kernel.split_lock_mitigate=1`

Um die Änderung dauerhaft zu machen, füge die folgende Zeile zu `/etc/sysctl.d/99-splitlock.conf` hinzu:

```text
kernel.split_lock_mitigate=0
```

Weitere Informationen zu Split-Lock findest du unter:

- https://www.phoronix.com/news/Linux-Splitlock-Hurts-Gaming
- https://github.com/doitsujin/dxvk/issues/2938

### [ADIOS I/O-Scheduler](https://github.com/firelzrd/adios)

Erstellt von [firelzrd](https://github.com/firelzrd)

:::note
CachyOS enthält den stabilen Zweig von ADIOS im Kernel.

Aktuelle stabile Version: `3.0.1`
:::

Kurze Einführung aus der README-Datei:

- *ADIOS (Adaptive Deadline I/O Scheduler) ist ein Block-Layer-I/O-Scheduler für den Linux-Kernel, der für moderne Multi-Queue-Blockgeräte (blk-mq) entwickelt wurde. Er zielt darauf ab, niedrige Latenzen für I/O-Operationen zu bieten, indem er Deadline-Scheduling-Prinzipien mit einem lernbasierten, adaptiven Latenzkontrollmechanismus kombiniert.*
  - *Inspiriert von und aufbauend auf Konzepten der mq-deadline- und Kyber-I/O-Scheduler. Sein Hauptmerkmal ist die Fähigkeit, die I/O-Abschlusslatenz basierend auf der bisherigen Leistung und den Anforderungsmerkmalen (Operationstyp, Größe) vorherzusagen und diese Vorhersage zu nutzen, um die Anforderungsdeadlines und das Batching-Verhalten dynamisch anzupassen.*

Kurz gesagt: ADIOS lernt das Latenzprofil deines Speichergeräts und nutzt dieses Wissen, um dynamisch Deadlines für I/O-Anfragen festzulegen. Es priorisiert Anfragen in vier Stufen, von kritischen Systemoperationen (Stufe 0) bis zu Hintergrundaufgaben (Stufe 3), um ein reibungsloses Benutzererlebnis zu gewährleisten. Während der Fokus auf der Reaktionsfähigkeit liegt, kann sein Verhalten über sysfs-Einstellungen feinabgestimmt werden, um Latenz und Durchsatz auszugleichen.

Für eine Live-Demo kannst du dir dieses [Video](https://www.youtube.com/watch?v=L9WDcEeHgy4) ansehen.

#### Wie man ADIOS aktiviert

        Diese Methode setzt den Scheduler für die aktuelle Sitzung. Die Änderung geht beim Neustart verloren.
        ```sh
        sync && echo adios | sudo tee /sys/block/<DeinLaufwerk>/queue/scheduler
            # Ersetze <DeinLaufwerk> durch die tatsächliche Laufwerkskennung (z.B. sda, sdb, nvme0n1)
        ```
    </TabItem>
    <TabItem label='Dauerhaft nach Neustart'>
        <Steps>
            1. Öffne oder erstelle eine neue udev-Regeldatei in deinem bevorzugten Texteditor (z.B. nano, micro, vim)
                ```sh title='Beispiel'
                sudo nano /etc/udev/rules.d/60-ioschedulers.rules
                ```
            2. Füge die folgenden Regeln zur Datei hinzu. Diese Regeln wenden automatisch einen bestimmten I/O-Scheduler basierend auf dem Laufwerkstyp (HDD, SSD oder NVMe) an.
                ```text
                # HDD
                ACTION=="add|change", KERNEL=="sd[a-z]*", ATTR{queue/rotational}=="1", \
                    ATTR{queue/scheduler}="bfq"

                # SSD
                ACTION=="add|change", KERNEL=="sd[a-z]*|mmcblk[0-9]*", ATTR{queue/rotational}=="0", \
                    ATTR{queue/scheduler}="adios"

                # NVMe SSD
                ACTION=="add|change", KERNEL=="nvme[0-9]*", ATTR{queue/rotational}=="0", \
                    ATTR{queue/scheduler}="adios"
                ```
              3.  Speichere die Datei und schließe den Editor.
              4.  Lade die `udev`-Regeln neu, um die Änderungen sofort ohne Neustart anzuwenden.
                  ```sh
                  sudo udevadm control --reload-rules
                  sudo udevadm trigger
                  ```
        </Steps>
    </TabItem>
</Tabs>

FAQ:

- Wenn es die Reaktionsfähigkeit verbessert, warum ist es nicht standardmäßig aktiviert?
  - ADIOS befindet sich noch in aktiver Entwicklung und wird kontinuierlich getestet. Obwohl es erhebliche Vorteile für die Reaktionsfähigkeit von Desktops bietet, wird es noch nicht als stabil genug angesehen, um für alle Workloads und Hardwaretypen als Standard zu dienen. In einigen Grenzfällen könnten Fehler zu Problemen wie System-Lockups führen. Aus diesem Grund ist es eine optionale Funktion für Benutzer, die seine neuesten Verbesserungen testen und davon profitieren möchten.

## Energiespar-Anpassungen

### RCU Lazy aktivieren

RCU Lazy hilft, den Stromverbrauch bei Systemen im Leerlauf oder bei geringer Last zu reduzieren. Dies kann für Laptops und Handheld-Geräte nützlich sein.
Die Verbesserung liegt bei 5-10% in Bezug auf die Energieeinsparungen. Es ist jedoch wichtig zu beachten, dass diese Energiesparfunktion je nach Szenario zu Lasten einer leicht reduzierten Leistung gehen kann.
Der linux-cachyos-deckify-Kernel wird diese Option standardmäßig aktiviert haben, da Energieeinsparung für diese Geräte entscheidend und notwendig ist.

Um RCU Lazy zu aktivieren, füge den folgenden Parameter zur Parameterliste deiner Kernel-[Befehlszeile](/de/configuration/boot_manager_configuration/) hinzu:
```text
rcutree.enable_rcu_lazy=1
```

## NVIDIA-Fehlerbehebung

### SDDM Wayland Backend deaktivieren

:::note
Ab cachyos-kde-settings 4.3 verwendet SDDM standardmäßig KWin als Wayland-Compositor.
:::

Obwohl dies ein schöner Fortschritt ist, kann es zu einigen Ärgernissen führen, wie z.B. die Unterbrechung der Unterstützung für das Übertakten mit nvidia-settings oder Inkompatibilitäten mit älteren GPUs, die unter Wayland Schwierigkeiten haben.

Um diese Änderung rückgängig zu machen, entferne das Paket cachyos-kde-settings:
```sh
sudo pacman -R cachyos-kde-settings
```

### NVIDIA GSP-Firmware

Die NVIDIA GSP-Firmware kann **"in einigen Fällen"** zu einer verringerten Leistung führen. Obwohl der NVIDIA-Treiber 555.58.02 dieses Problem weitgehend behoben hat, kann es auf bestimmten Systemen weiterhin bestehen.
Wenn du Ruckler in KDE oder eine schlechte Leistung in einigen Fällen feststellst, kannst du die GSP-Firmware mit der folgenden Konfigurationsdatei deaktivieren:
`/etc/modprobe.d/nvidia-gsp.conf`

```text
options nvidia NVreg_EnableGpuFirmware=0
```

Nachdem du die Datei erstellt hast, führe den folgenden Befehl aus:
```sh
sudo mkinitcpio -P
```

:::note
NVIDIAs [offene Kernel-Module](https://github.com/NVIDIA/open-gpu-kernel-modules) basieren auf der GSP-Firmware. Aus diesem Grund kann GSP nicht deaktiviert werden und diese modprobe-Option wird bei deren Verwendung ignoriert. Verwende `linux-cachyos-nvidia` oder `nvidia-dkms`.
:::

Es wird generell empfohlen, die GSP-Firmware nach jeder neuen NVIDIA-Treiberinstallation zu testen, da sie oft vorteilhafte Funktionen einführt. Außerdem hat NVIDIA hauptsächlich begonnen, QA-Tests mit der GSP-Firmware durchzuführen.

## Audio- und Software-Verbesserungen

### Klang von Laptop-Lautsprechern verbessern

Laptop-Lautsprecher erzeugen aufgrund ihrer kompakten Größe und begrenzten Hardwarefähigkeiten oft einen dünnen und enttäuschenden Klang. [EasyEffects](https://wiki.archlinux.org/title/PipeWire#EasyEffects) kann die Klangqualität der eingebauten Lautsprecher deines Laptops durch die Anwendung verschiedener Audioeffekte und benutzerdefinierter Konfigurationen erheblich verbessern.

Um zu beginnen, musst du EasyEffects und die erforderlichen Abhängigkeiten installieren:

```bash
# EasyEffects installieren
sudo pacman -S easyeffects
# lsp-plugins für zusätzliche Effekte und jalv für LV2-Plugin-Unterstützung installieren
sudo pacman -S lsp-plugins-lv2
```

#### Konfiguration

Befolge diese Schritte, um EasyEffects zu konfigurieren:

1. Starte EasyEffects aus deinem Anwendungsmenü oder durch Eingabe von `easyeffects` im Terminal.
2. Navigiere zum Tab **Ausgabe**, um die auf dein Lautsprecheraudio angewendeten Effekte zu verwalten.
3. Wechsle zum Tab **Effekte**, um Audioeffekte hinzuzufügen, zu ändern oder anzupassen.

<ImageComponent imgsrc={import('~/assets/images/easyeffects.png')} />

##### Verwendung von Community-Voreinstellungen

Für eine schnelle und effektive Einrichtung beginne mit **von der Community erstellten Voreinstellungen**, die für verschiedene Audioszenarien zugeschnitten sind:

1. Lade Voreinstellungen aus dem [EasyEffects Community Presets](https://github.com/wwmm/easyeffects/wiki/Community-presets)-Repository herunter.
2. Klicke in EasyEffects auf die Schaltfläche **Voreinstellungen** und wähle **"Voreinstellung aus lokalem Speicher importieren"**.
3. Suche und wähle die heruntergeladene Voreinstellungsdatei aus.
4. Nach dem Import erscheint die Voreinstellung in deiner Liste – klicke auf **"Laden"**, um sie auf deine Audioausgabe anzuwenden.

<ImageComponent imgsrc={import('~/assets/images/easyeffects-presets.png')} />

##### Erstellen eines benutzerdefinierten Profils

Für ein persönlicheres Klangerlebnis erstelle ein benutzerdefiniertes Profil, das auf die Lautsprecher deines Laptops zugeschnitten ist:

1. Klicke auf die Schaltfläche **"+"** im Menü „Voreinstellungen“, um eine neue Voreinstellung zu erstellen (z. B. nenne sie **"Laptop-Lautsprecher"**).
2. Wähle **"Laden"**, um die neue Voreinstellung zu aktivieren.
3. Füge Effekte im Tab **Ausgabe** > **Effekte** hinzu und konfiguriere sie, indem du mit Optionen wie Equalizern, Bassverstärkern oder Stereoverbreiterern experimentierst.

##### Verwendung des Convolver-Effekts (Dolby-Atmos-Laptops)

Der **Convolver-Effekt** kann den Klang dramatisch verbessern, indem er Impulsantworten anwendet, die hochwertige Audioumgebungen simulieren. Dies erfordert jedoch eine präzise Einrichtung:

1. Füge den **Convolver**-Effekt zu deiner Effektkette im Tab **Effekte** hinzu.
2. Lade eine Impulsantwortdatei (im `.wav`-Format), die spezifisch für dein Laptop-Modell ist, falls verfügbar. Du kannst online nach diesen Dateien suchen, z. B. auf folgenden Ressourcen:
   - https://wiki.archlinux.org/title/Lenovo_ThinkPad_T14_(AMD)_Gen_4#Speakers
   - https://github.com/m4tx/thinkpad-p14s-g4-linux/#sound
   - https://github.com/shuhaowu/linux-thinkpad-speaker-improvements/
3. **Clipping verhindern**: Der Convolver-Effekt kann die Lautstärke erheblich erhöhen. Füge einen **Limiter**-Effekt nach dem Convolver in deiner Effektkette hinzu, um Spitzen zu kontrollieren und Verzerrungen zu vermeiden.

#### Tipps für optimale Ergebnisse

- **Experimentiere** mit verschiedenen Voreinstellungen, um die beste Übereinstimmung für dein spezifisches Laptop-Modell und deine persönlichen Klangpräferenzen zu finden.
- **Nimm schrittweise Anpassungen** an einzelnen Effekten vor, um Verzerrungen oder unnatürlichen Klang zu vermeiden.
- **Vergleiche durch Umschalten**: Schalte EasyEffects häufig **ein/aus**, um die Verbesserungen gegenüber dem Standard-Audio zu bewerten.
- Suche nach **gerätespezifischen Voreinstellungen oder Convolver-Impulsantworten** für beliebte Laptop-Modelle wie das **Framework Laptop 13** oder das **ThinkPad T14**, um maßgeschneiderte Ergebnisse zu erzielen.
- **Automatischer Start**: Konfiguriere EasyEffects so, dass es beim Systemstart automatisch startet, indem du dies in den Einstellungen der App festlegst, um sicherzustellen, dass dein benutzerdefiniertes Profil immer angewendet wird.
- **Voreinstellungen für mehrere Geräte automatisch laden**: Verwende den Tab **PipeWire** > **Automatisches Laden von Voreinstellungen**, um bestimmte Voreinstellungen verschiedenen Ausgabegeräten (z.B. Lautsprecher vs. Kopfhörer) zuzuordnen, um einen nahtlosen Wechsel zu ermöglichen. <ImageComponent imgsrc={import('~/assets/images/easyeffects-autoloading.png')} />
