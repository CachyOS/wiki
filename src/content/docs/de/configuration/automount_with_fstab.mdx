Diese Anleitung beschreibt die Grundlagen der Verwendung von sowohl Systemd Mount-Dateien, als auch der fstab-Datei in /etc/, um statische Laufwerke beim Hochfahren einzubinden. Sie erklärt kurz, wie du die UUID einer Partition oder eines Laufwerks findest, was einige Optionen bewirken und wo du weiterlesen kannst, falls die bereitgestellten Informationen nicht ausreichen.

## Voraussetzungen

- Root- oder Sudo-Zugriff

:::note[NTFS unter Linux]
Das NTFS-Dateisystem kann unter Linux instabil sein, egal ob du den ntfs-, ntfs3- oder ntfs-3g-Treiber verwendest. Die Nutzung erfolgt auf eigene Gefahr. Für bessere Stabilität und Leistung solltest du native Linux-Dateisysteme wie ext4, xfs oder btrfs in Betracht ziehen.
:::

## Einträge zu /etc/fstab hinzufügen

### 1. Liste die UUIDs deiner Partitionen auf

```sh title="Öffne ein Terminal und führe den folgenden Befehl aus"
lsblk -f
```

```text title="Beispielausgabe"
# NAME        FSTYPE FSVER LABEL UUID                                 FSAVAIL FSUSE% MOUNTPOINTS
# zram0                                                                              [SWAP]
# nvme0n1
# ├─nvme0n1p1 vfat   FAT32       E04D-9F05
# ├─nvme0n1p2
# ├─nvme0n1p3 ntfs               08A24E90A24E81E4                      715.4G    50%
# ├─nvme0n1p4 vfat   FAT32       E09C-D4DA                             628.1M    39% /boot
# ├─nvme0n1p5 ext4   1.0         187a9f06-9411-48d9-b941-f03c2e605812  203.6G    47% /
# └─nvme0n1p6 ntfs
```

In unserem Beispiel wissen wir, dass wir eine Windows-Partition einbinden wollen, die ntfs ist. Wir wissen auch, dass etwa die Hälfte ihres Speichers frei ist. Daher können wir feststellen, dass die Partition, die wir einbinden wollen, `nvme0n1p3` ist und ihre UUID `08A24E90A24E81E4` lautet, mit dem Dateisystem `ntfs` in diesem Beispiel.

### 2. Identifiziere deine Partition

Oft liefert `lsblk -f` an dieser Stelle bereits alle Informationen, die du brauchst, um deine Festplatte über /etc/fstab einzubinden. Wenn du dir immer noch unsicher bist, welche die richtige Partition ist, kannst du den folgenden Befehl ausführen:

```sh
sudo fdisk -l
```

```text title="Beispielausgabe"
# Device              Start        End    Sectors  Size Type
# /dev/nvme0n1p1       2048     206847     204800  100M EFI System
# /dev/nvme0n1p2     206848     239615      32768   16M Microsoft reserved
# /dev/nvme0n1p3     239616 2997384182 2997144567  1.4T Microsoft basic data
# /dev/nvme0n1p4 2997385216 2999482367    2097152    1G EFI System
# /dev/nvme0n1p5 2999482368 3905454079  905971712  432G Linux root (x86-64)
# /dev/nvme0n1p6 3905454080 3907026943    1572864  768M Windows recovery environment
```

Wir kennen unsere UUID in diesem Beispiel bereits. `fdisk -l` kann es uns aber noch etwas deutlicher machen, indem es die genaue Größe der Partition (1.4T) sowie ihren Typ (Microsoft basic data) anzeigt.

Das sollte uns überdeutlich machen, dass die gewünschte Partition `nvme0n1p3` mit der UUID `08A24E90A24E81E4` ist, wie bereits beschrieben. Wir wussten es schon vorher, aber jetzt wissen wir es ganz sicher.

Sobald du dir sicher bist, die richtige Partition gefunden zu haben, kopiere die UUID. Das Kopieren aus dem Terminalemulator erfolgt normalerweise mit `Strg+Umschalt+C`.

### 3. Einen Eintrag zu /etc/fstab hinzufügen

Jetzt, da wir die UUID unserer Partition haben, ist es an der Zeit, die fstab-Datei zu öffnen.

Du kannst gerne deinen Texteditor deiner Wahl verwenden. In diesem Beispiel werden wir nano benutzen. Um die fstab-Datei zu bearbeiten, muss sie als root geöffnet werden:

```sh
sudo nano /etc/fstab
```

Navigiere mit den Pfeiltasten zum Ende der fstab-Datei und erstelle dann unseren neuen Eintrag in einer leeren neuen Zeile:

```sh
UUID=08A24E90A24E81E4 /media/windows ntfs3 defaults,nofail,uid=1000,gid=1000,rw,user,exec,umask=000 0 0
```

:::note
`/media/windows` muss auf deinem Dateisystem existieren. Benutze `mkdir`, um das Verzeichnis zu erstellen, falls es nicht da ist.
:::

Die Aufschlüsselung dieses Eintrags ist wie folgt:

- `UUID=08A24E90A24E81E4` ist das Dateisystem, das wir einbinden wollen, identifiziert durch seine UUID. Es gibt andere Methoden, um dein Dateisystem zu identifizieren, obwohl UUID in der Regel die sicherste ist. Weitere Methoden sind [hier](https://wiki.archlinux.org/title/Fstab#Identifying_file_systems) aufgelistet.

- `/media/windows` ist der Einhängepunkt unseres Laufwerks. Der [Linux Filesystem Hierarchy Standard](https://refspecs.linuxfoundation.org/FHS_3.0/fhs/index.html) besagt, dass `/media/` der richtige Ort ist, um Wechseldatenträger einzubinden. `windows` gibt das Verzeichnis an, in das wir unser Laufwerk einbinden möchten. Jedes Laufwerk, das wir einbinden wollen, benötigt ein eigenes Verzeichnis.

- `ntfs3` ist der zu verwendende Dateisystemtyp. In unserem Beispiel verwenden wir explizit den ntfs3-Kerneltreiber. Andere Beispiele wären `ext4`, `xfs` oder Ähnliches. Diese explizite Angabe des Dateisystemtyps kann durch `auto` ersetzt werden, damit der mount-Befehl seine beste Vermutung anstellen kann.

- `defaults,nofail,uid=1000,gid=1000,rw,user,exec,umask=000`: Das sind die Einhängeoptionen:

  - `defaults`: ein Standardsatz von Optionen, einschließlich `rw, suid, dev, exec, auto, nouser und async.`

  - `nofail`: ermöglicht es dem Bootvorgang, auch dann fortzufahren, wenn dieses Einhängen fehlschlägt.

  - `uid=1000` und `gid=1000`: setzt den Benutzer- und Gruppenbesitz der eingebundenen Dateien auf den Benutzer und die Gruppe mit der ID 1000.

  - `rw`: bindet das Dateisystem als Lese-/Schreibzugriff ein.

  - `user`: erlaubt einem Nicht-Root-Benutzer, das Dateisystem einzubinden.

  - `exec`: erlaubt die Ausführung von Binärdateien auf dem eingebundenen Dateisystem.

  - `umask=000`: setzt die Dateiberechtigungsmaske, um Lese-, Schreib- und Ausführungsrechte für alle zu erlauben.

  - `die erste 0` (dump) ist in modernen Systemen typischerweise veraltet. Dies auf 0 zu lassen, schadet nicht. Du kannst gerne mehr darüber [hier](https://linux.die.net/man/8/dump) lesen.

  - `die zweite 0` legt die Reihenfolge für Dateisystemprüfungen beim Booten fest. Für eine Root-Partition sollte dies 1 sein, es sei denn, dein Root-Dateisystem ist btrfs, das ansonsten auf 0 gesetzt werden sollte. Alle anderen Dateisysteme in deiner fstab sollten entweder 0 (deaktiviert) oder 2 sein. Mehr Informationen [hier](https://man.archlinux.org/man/fsck.8).

Für einen detaillierteren Einblick in jede Option, besuche diese beiden Seiten: [fstab man page](https://man7.org/linux/man-pages/man5/fstab.5.html) und [mount man page](https://man7.org/linux/man-pages/man8/mount.8.html)

#### Mehr Infos

Nebenbei bemerkt sind alle Optionen nach der Angabe des Dateisystemtyps optional, wenn du sie nicht vom Standard abänderst.

Somit sind

`UUID=<Partitions-UUID> /media/foo somefs`

und

`UUID=<Partitions-UUID> /media/foo somefs defaults 0 0`

gleichwertig. `somefs`, gefolgt von nichts, bedeutet implizit `somefs defaults 0 0`

### 4. Fertigstellung

Wenn du das Laufwerk, für das du einen Eintrag erstellt hast, jetzt einbinden möchtest, musst du Folgendes ausführen:

```sh
sudo systemctl daemon-reload
```

und dann:

```sh
sudo mount -a
```

Dein Laufwerk sollte nun unter `/media/windows` erscheinen und wird dort bei jedem Neustart wieder auftauchen.

```sh
ls /media/windows
# '$Recycle.Bin'             Linux                  SteamLibrary
# AMD                       Modding                swapfile.sys
# Apps                      pagefile.sys          'System Volume Information'
# bootTel.dat               PerfLogs               Users

# 'Documents and Settings'  'Program Files'         Windows
# DumpStack.log.tmp        'Program Files (x86)'   XboxGames
# FanControl                Recovery               xiv_modding
# Games                     RetroArch-Win64
# Intel                    'Ship of Harkinian'
 ```

 Wenn du einen Link zu deinem neu eingebundenen Laufwerk in deinem Home-Verzeichnis erstellen möchtest, kannst du Folgendes ausführen:

 ```sh
 ln -s /media/windows ~/Windows
 ```

 Um zu zeigen, dass es funktioniert hat:


### tl;dr

- Finde die **UUID** deiner Partition

```sh
lsblk -f
```

- Öffne `/etc/fstab`

```sh
sudo nano /etc/fstab
```

- Erstelle einen Eintrag am Ende der Datei

```sh
UUID=<Partitions-UUID> /media/foo somefs defaults 0 0
```

Ersetze dabei `<Partitions-UUID>`, `foo` und `somefs` durch deine UUID, dein Verzeichnis und dein Dateisystem (z.B. ext4) und lege alle weiteren Optionen fest, die du nach `defaults` haben möchtest, wie z.B. `_netdev` für ein NAS oder `nofail` für jedes nicht-kritische Laufwerk.

- Lade deinen Daemon neu

```sh
sudo systemctl daemon-reload
```

- Binde dein Laufwerk ein

```sh
sudo mount -a
```

Dieses Laufwerk ist jetzt eingebunden und wird von nun an auch beim Start eingebunden.

## 2. Laufwerke einbinden mit Systemd Mount-Dateien

Der Vorteil des Einbindens über Systemd ist, dass selbst wenn du etwas falsch in deiner Mount-Datei machst, dein System trotzdem startet. Ein Fehler in der fstab-Datei hingegen kann dein System unstartbar machen.

### 1. Die UUIDs deiner Partitionen auflisten

```sh title="Öffne ein Terminal und führe das folgende Kommando aus"
lsblk -f
```

```text title="Ausgabebeispiel"
NAME          FSTYPE FSVER LABEL UUID                                 FSAVAIL   FSUSE% MOUNTPOINTS
zram0                                                                              [SWAP]
nvme0n1
├─nvme0n1p1   vfat   FAT32       E04D-9F05
├─nvme0n1p2
├─nvme0n1p3   ntfs               08A24E90A24E81E4                      715.4G   50%
├─nvme0n1p4   vfat   FAT32       E09C-D4DA                             628.1M   39% /boot
├─nvme0n1p5   ext4   1.0         187a9f06-9411-48d9-b941-f03c2e605812  203.6G   47% /
└─nvme0n1p6   ntfs
nvme1n1
└─nvme1n1p1   ext4               4e55896f-3f1f-4bc5-aa8a-fec099689cd9  931.5G   0%

```

In diesem Beispiel wollen wir eine zusätzliche Festplatte einhängen, die frisch als ext4 formatiert wurde. Wir wissen, dass es eine 1TB Festplatte ist und dass noch nichts auf ihr gespeichert wurde. Daraus können wir schließen, dass die einzuhängende Partition `nvme1n1p1` ist und dass sie die UUID `4e55896f-3f1f-4bc5-aa8a-fec099689cd9` hat.

### 2. Die Partition identifizieren

Oft gibt dir `lsblk -f` alle notwendigen Informationen, um deine Festplatte mit Systemd einzuhängen. Wenn du dir immer noch unsicher bist, was die richtige Partition ist, kannst du folgendes Kommando ausführen:

```sh
sudo fdisk -l
```

```text title="Beispielausgabe"
Device          Start       End         Sectors     Size    Type
/dev/nvme0n1p1  2048        206847      204800      100M    EFI System
/dev/nvme0n1p2  206848      239615      32768       16M     Microsoft reserved
/dev/nvme0n1p3  239616      2997384182  2997144567  1.4T    Microsoft basic data
/dev/nvme0n1p4  2997385216  2999482367  2097152     1G      EFI System
/dev/nvme0n1p5  2999482368  3905454079  905971712   432G    Linux root (x86-64)
/dev/nvme0n1p6  3905454080  3907026943  1572864     768M    Windows recovery environment
/dev/nvme1n1p1  2048        1953523711  1953521664  931.5G  Linux filesystem

```

In diesem Beispiel kennen wir die UUID bereits. Der Befehl `fdisk -l` schafft jedoch zusätzliche Klarheit, indem er sowohl die genaue Größe der Partition (931,5 GB) als auch deren Typ (Linux-Dateisystem) anzeigt.

Damit sollte eindeutig feststehen, dass es sich bei der gesuchten Partition um `nvme1n1p1` mit der UUID `4e55896f-3f1f-4bc5-aa8a-fec099689cd9` handelt, genau wie zuvor beschrieben. Wir hatten diese Information zwar schon, aber nun können wir uns sicher sein.

Sobald du dir sicher bist, die richtige Partition gefunden zu haben, kopiere die UUID. Das Kopieren aus dem Terminal-Emulator erfolgt üblicherweise mit der Tastenkombination `Strg+Umschalt+C`.

### 3. Erstellen der Systemd Mount-Datei
Angenommen, wir möchten dieses Laufwerk hauptsächlich für Spiele nutzen, wäre ein geeigneter Einhängepunkt dafür das Home-Verzeichnis des Benutzers. Der Ort ist zwar frei wählbar, aber der Einfachheit halber entscheiden wir uns für `/home/user` (ersetze dabei `user` durch deinen Linux-Benutzernamen). Dies ist wichtig, da der Pfad des Einhängepunkts den Namen der Systemd Mount-Datei bestimmt. Da das Laufwerk für Spiele gedacht ist, binden wir es in den Ordner `games` im Home-Verzeichnis ein: `/home/user/games`.

Für Systemd bedeutet dies, dass die Mount-Datei `home-user-games.mount` heißen muss (Schrägstriche `/` werden durch Bindestriche `-` ersetzt). Systemd Mount-Dateien werden immer im Verzeichnis `/etc/systemd/system` abgelegt.

Du kannst einen Texteditor deiner Wahl verwenden, in diesem Beispiel nutzen wir `micro`.

```sh
micro /etc/systemd/system/home-user-games.mount
```

Kopiere diese Vorlage in die leere Datei:
```
[Unit]
Description=

[Mount]
What=
Where=
Type=
Options=

[Install]
WantedBy=multi-user.target
```
Unten findest du Beschreibungen für jedes Feld in der Datei:

<Tabs>
  <TabItem label='Description'>
  Die Beschreibung kannst du frei wählen, sie dient lediglich deiner eigenen Orientierung.
  </TabItem>
  <TabItem label= 'What'>
  Füge die zuvor kopierte UUID ein. Hier lautet sie `UUID=4e55896f-3f1f-4bc5-aa8a-fec099689cd9`.
  </TabItem>
  <TabItem label= 'Where'>
  Dies ist der Einhängepunkt. Falls der Ordner noch nicht existiert, wird er erstellt. In diesem Fall lautet der Pfad `/home/user/games`.
  </TabItem>
  <TabItem label= 'Type'>
  Typ des Dateisystems, in diesem Fall `ext4`.
  </TabItem>
  <TabItem label= 'Options'>
  Beliebige Mount-Optionen nach Wahl. Hier verwenden wir `defaults,exec,rw,noatime`. Wichtig ist dabei, keine Leerzeichen zu verwenden.
  </TabItem>
</Tabs>
---

Wenn wir dem Beispiel folgen, sollte die ausgefüllte Mount-Datei wie folgt aussehen:
```
[Unit]
Description="games" Festplatte einhängen (/home/user/games)

[Mount]
What=UUID=4e55896f-3f1f-4bc5-aa8a-fec099689cd9
Where=/home/user/games
Type=ext4
Options=defaults,exec,rw,noatime

[Install]
WantedBy=multi-user.target
```

### 4. Fertigstellung
Um die Festplatte, für die wir gerade den Eintrag erstellt haben, einzuhängen, führe die folgenden Kommandos aus:

```
1. sudo systemctl daemon-reload
2. sudo systemctl enable --now home-user-games.mount
```

Du solltest den Ordner sehen, den Du als Einhängepunkt gewählt hast und kannst den Status des Einhängepunkts mit `systemctl status home-user-games.mount` überprüfen:

### tl;dr

- Finde die **UUID** deiner Partition

```sh
lsblk -f
```

- Erstelle die Mount-File

```sh
micro /etc/systemd/system/mnt-foo.mount
```

Ersetze `mnt-foo` durch den vollständigen Pfad des Einhängepunkts, wobei du den Schrägstrich `/` durch einen Bindestrich `-` ersetzen musst.

- Fülle die Mount-File aus

```sh
[Unit]
Description=Mount-Drive

[Mount]
What=UUID=<partition UUID>
Where=/mnt/foo
Type=somefs
Options=defaults

[Install]
WantedBy=multi-user.target
```

Ersetze `<partition UUID>`, `/mnt/foo` und `somefs` durch deine UUID, dein Verzeichnis und dein Dateisystem (z. B. ext4) und füge nach `defaults` bei Bedarf weitere Optionen hinzu, wie etwa `_netdev` für ein NAS oder `nofail` für nicht kritische Laufwerke.

- Starte den daemon neu

```sh
sudo systemctl daemon-reload
```

- Hänge dein Laufwerk ein und konfiguriere es so, dass es beim Systemstart automatisch eingebunden wird.

```sh
sudo systemctl enable --now mnt-foo.mount
```
