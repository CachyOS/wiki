# sbctl

[sbctl](https://github.com/Foxboron/sbctl) ist ein benutzerfreundlicher Schlüsselmanager für Secure Boot, der in der Lage ist, Secure Boot einzurichten,
Schlüsselverwaltungsfunktionen bietet und Dateien verfolgt, die in der Boot-Kette signiert werden müssen.

## sbctl installieren

```bash
sudo pacman -S sbctl
```

## Vorbereitung

### GRUB Bootmanager

Wenn du GRUB verwendest, führe den folgenden Befehl aus, um die Secure-Boot-Unterstützung in GRUB mithilfe von CA-Schlüsseln zu aktivieren.

```bash
sudo grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=cachyos --modules="tpm" --disable-shim-lock
```

:::note
Das Laden unnötiger Module in deinem Bootmanager kann ein Sicherheitsrisiko darstellen.
Führe diesen Befehl nur aus, wenn du Secure Boot tatsächlich benötigst.
:::

### Setup-Modus im UEFI aktivieren
Zuerst müssen wir in die Firmware-Einstellungen gehen und den Secure-Boot-Modus auf „Setup Mode“ (Einrichtungsmodus) stellen. Du kannst von einem
bereits laufenden System mit dem folgenden Befehl in die Firmware-Einstellungen neu starten.

```bash
systemctl reboot --firmware-setup
```

## sbctl einrichten

```bash
sudo sbctl status # Wenn der Setup-Modus aktiviert ist, können wir mit dem nächsten Schritt fortfahren
Installed:      ✘ sbctl ist nicht installiert
Setup Mode:     ✘ Enabled
Secure Boot     ✘ Disabled

sudo sbctl create-keys # Erstelle deine benutzerdefinierten Secure-Boot-Schlüssel
Created Owner UUID a9fbbdb7-a05f-48d5-b63a-08c5df45ee70
Creating secure boot keys...✔
Secure boot keys created!

sudo sbctl enroll-keys --microsoft # Registriere deine Schlüssel bei den Schlüsseln von Microsoft
Enrolling keys to EFI variables...✔
Enrolled keys to the EFI variables!

sudo sbctl status
# sbctl sollte jetzt installiert sein, wir können mit dem Signieren der Kernel-Images und des Bootmanagers fortfahren
Installed:      ✔ sbctl ist installiert
Owner GUID:     a9fbbdb7-a05f-48d5-b63a-08c5df45ee70
Setup Mode:     ✔ Disabled
Secure Boot     ✘ Disabled
Vendor Keys:    microsoft
```

## Kernel-Image und Bootmanager signieren

CachyOS stellt [sbctl-batch-sign](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/bin/sbctl-batch-sign) zur Verfügung,
ein Skript, das die Liste der zu signierenden Dateien von `sudo sbctl verify` übernimmt und sie alle signiert.

```bash
sudo sbctl verify
Verifying file database and EFI images in /boot...
✘ /boot/1c4b5246eef05ac3bc87339323cd5101/6.10.0-cn4.0.fc40.x86_64/linux ist nicht signiert
✘ /boot/EFI/BOOT/BOOTX64.EFI ist nicht signiert
✘ /boot/EFI/systemd/systemd-bootx64.efi ist nicht signiert
✘ /boot/1c4b5246eef05ac3bc87339323cd5101/0-rescue/linux ist nicht signiert
✘ /boot/1c4b5246eef05ac3bc87339323cd5101/6.10.0-cn3.0.fc40.x86_64/linux ist nicht signiert

sudo sbctl-batch-sign

sudo sbctl verify
Verifying file database and EFI images in /boot...
✔ /boot/1c4b5246eef05ac3bc87339323cd5101/6.10.0-cn4.0.fc40.x86_64/linux ist signiert
✔ /boot/EFI/BOOT/BOOTX64.EFI ist signiert
✔ /boot/EFI/systemd/systemd-bootx64.efi ist signiert
✔ /boot/1c4b5246eef05ac3bc87339323cd5101/0-rescue/linux ist signiert
✔ /boot/1c4b5246eef05ac3bc87339323cd5101/6.10.0-cn3.0.fc40.x86_64/linux ist signiert
```

:::caution
Auf Systemen mit einer separaten `/boot`- und `/boot/efi`-Partitionsaufteilung sucht `sbctl` möglicherweise nur in `/boot/efi` nach EFI-Binärdateien.
Dies führt dazu, dass Kernel-Images, die sich in `/boot` befinden, nicht erkannt werden. `sbctl-batch-sign` umgeht dies, indem es **immer**
`/boot` nach `vmlinuz-*`-Dateien durchsucht.
:::

Jetzt, da alle Dateien signiert sind, können wir zurück in die UEFI-Einstellungen neustarten und Secure Boot aktivieren.
Beachte, dass dies ein einmaliger Vorgang ist, da das Signieren von Dateien mit dem `-s`-Flag diese Dateien in der Datenbank von `sbctl` speichert.
`sbctl` wird mit einem [pacman hook](https://wiki.archlinux.org/title/Pacman_hook) geliefert, was bedeutet, dass es automatisch
alle neuen Dateien bei einem Kernel- oder Bootmanager-Update signiert.

### systemd-boot

CachyOS verwendet `systemd-boot-update.service`, das von systemd bereitgestellt wird, um den Bootmanager beim Neustart zu aktualisieren. Das bedeutet, dass der `sbctl`
Pacman-Hook die aktualisierten EFI-Binärdateien **nicht** signieren wird. Als Workaround können wir den Bootmanager direkt signieren.

```sh
sudo sbctl sign -s -o /usr/lib/systemd/boot/efi/systemd-bootx64.efi.signed /usr/lib/systemd/boot/efi/systemd-bootx64.efi
```

### Limine

Limine ist ein spezieller Bootmanager, der es ermöglicht, den Hash von Kernel-
Images und anderen Dateien, die Limine während des Bootvorgangs verwendet, zu überprüfen. Wenn dies aktiviert ist, wird jede
Art von manueller Konfiguration durch den Benutzer, z.B. das Signieren des Images über
`sbctl-batch-sign`, den Hash der entsprechenden Dateien ändern und
die Prüfsummenverifizierung von Limine fehlschlagen lassen.

Das Signieren dieser Dateien ist bei Limine jedoch nicht notwendig, da es einen speziellen
Boot-Prozess hat, der EFI-Chainloading und Signaturprüfungen umgeht. Die einzigen EFI-
Binärdateien, die signiert werden müssen, sind Limine selbst und die Backup-EFI-Binärdatei,
die auf allen UEFI-Systemen zu finden ist.

```sh
# Die spezielle EFI-Binärdatei signieren
sudo sbctl sign -s /boot/EFI/BOOT/BOOTX64.EFI

# limine-enroll-config verwenden, um die EFI-Binärdatei von Limine zu signieren
# Dies verwendet sbctl im Hintergrund
sudo limine-enroll-config
```

## Überprüfen, ob Secure Boot aktiviert ist

Um zu überprüfen, ob Secure Boot tatsächlich aktiviert ist, kannst du einen der folgenden Befehle ausführen.

```bash
sudo sbctl status
Installed:      ✓ sbctl ist installiert
Owner GUID:     a9fbbdb7-a05f-48d5-b63a-08c5df45ee70
Setup Mode:     ✓ Disabled
Secure Boot:    ✓ Enabled
Vendor Keys:    microsoft

bootctl
System:
      Firmware: UEFI 2.80 (INSYDE Corp. 28724.16435)
 Firmware Arch: x64
   Secure Boot: enabled (user)
  TPM2 Support: yes
  Measured UKI: no
  Boot into FW: supported
```
