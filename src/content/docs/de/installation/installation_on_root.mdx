## Bevor du anfängst

:::note
Wenn du nach dem Klick auf **Launch Installer** nur GRUB und Limine als Bootmanager-Optionen bekommst, dann ist das System im Legacy/BIOS-Modus gebootet.
:::

:::note[Die Installation mehrerer Desktop-Umgebungen ist während des Installationsprozesses nicht erlaubt.]
:::

:::caution[Secure Boot und CSM müssen in den BIOS/UEFI-Einstellungen bei der Installation im UEFI-Modus deaktiviert sein.]
Um Secure Boot nach der Installation einzurichten, schau in den Abschnitt [Secure Boot](/de/configuration/secure_boot_setup).

`Legacy USB Support` sollte auf `Auto` gestellt sein.
:::

:::caution
Die Optionen `Install alongside` (Parallel installieren) und `Replace partition` (Partition ersetzen) sind nicht 100% zuverlässig und können dazu führen, dass die Installation fehlschlägt.

`Manual partitioning` (Manuelle Partitionierung) wird bei der Installation von CachyOS **dringend empfohlen**.
:::

:::tip
Es wird dringend empfohlen, nach einem fehlgeschlagenen Installationsversuch erneut von der ISO zu booten.

Andernfalls können während des Installationsprozesses immer wieder Fehler auftreten.

Das passiert, weil der Installer bei einer fehlgeschlagenen Installation die Partitionen nicht richtig aushängt.

:::

## Installationsmethoden

### Manuelle Partitionierung

:::note[Bevor du mit der Partitionierung der Festplatte für eine UEFI-Installation fortfährst.]
    ```sh title='Führe diesen Befehl im Terminal aus'
    efibootmgr -v
    ```
Wenn die Ausgabe `EFI variables are not supported on this system.` lautet, dann ist das System im Legacy/BIOS-Modus gebootet, und du musst sicherstellen, dass der UEFI-Modus in den BIOS/UEFI-Einstellungen konfiguriert ist. Schau dazu in den Abschnitt [Voraussetzungen](/de/installation/installation_on_root/#bevor-du-anfängst).
:::

## Dual-Boot mit Windows und CachyOS

:::note[Diese Anleitung geht davon aus, dass Windows bereits auf dem System installiert ist und du dich entschieden hast, CachyOS parallel dazu auf demselben Laufwerk zu installieren.]
:::

:::caution
Dual-Booting von Windows und Linux ist nicht 100% zuverlässig. Windows-Updates können den Bootloader kaputtmachen, indem sie die EFI-Partition überschreiben.
In manchen Fällen treten vielleicht nie Probleme auf, aber für einige Nutzer kann es ein wiederkehrendes Problem sein.

Eine Möglichkeit, dieses Problem zu umgehen, ist, jedes Betriebssystem auf einem separaten Laufwerk zu installieren.
:::

:::caution
Die EFI-Partition muss möglicherweise in ihrer Größe angepasst werden, abhängig von der empfohlenen Mindestgröße des Ziel-Bootmanagers. Siehe [Manuelle Partitionierung](/de/installation/installation_on_root#manuelle-partitionierung).

FAT-Dateisysteme können nicht direkt in der Größe geändert werden. Um die FAT-EFI-Partition richtig zu "vergrößern", muss man das bestehende EFI-Dateisystem sichern, ein Tool wie `gparted` verwenden, um die bestehende Partition zu vergrößern und die neue Partition neu zu formatieren, und dann die vorherige Dateisystemstruktur wieder in die EFI-Partition kopieren.
:::

### Voraussetzungen

- Windows Schnellstart und Ruhezustand müssen deaktiviert sein.
  - Öffne Windows PowerShell als Administrator und führe den folgenden Befehl aus:
      ```ps
      powercfg /H off
      ```
    Starte das System neu, um sicherzustellen, dass die Änderungen wirksam werden.
- Windows BitLocker muss deaktiviert sein.
  - Überprüfen, ob BitLocker aktiviert ist:
    ```ps title='Öffne eine Eingabeaufforderung als Administrator und führe den folgenden Befehl aus'
    manage-bde -status
    ```
  Wenn bei **Verschlüsselungsmethode** `Keine` steht, dann ist BitLocker deaktiviert.
- Secure Boot muss deaktiviert sein.
- Eine leere Partition von ≥30 GB.
  - Anleitung zum Verkleinern einer Windows-Partition:
    - Drücke `Win + R`, gib `diskmgmt.msc` ein und drücke Enter, um die Datenträgerverwaltung zu öffnen.
    - Finde deine Windows-Hauptpartition (normalerweise C:) und klicke mit der rechten Maustaste darauf.
    - Klicke auf `Volume verkleinern...`, gib mindestens **30720 MB** (30 GiB) an und klicke auf `Verkleinern`.
- Ein bootfähiger USB-Stick mit CachyOS.
  - Schau dazu in den Abschnitt [Einen bootfähigen CachyOS-USB-Stick erstellen](/de/installation/installation_prepare#einen-bootfähigen-cachyos-usb-stick-erstellen).

<Tabs>
    <TabItem label='systemd-boot'>
        **Wir müssen die Windows-EFI-Binärdateien in die Linux-EFI-Partition kopieren, damit der Bootmanager sie erkennen kann.**

        <Steps>
        1. Finde die **Windows-EFI-Partition** mit `lsblk`.

            ```sh title='Führe diesen Befehl im Terminal aus'
            lsblk -o NAME,FSTYPE,SIZE,MOUNTPOINT
            ```
            ```sh title='Beispielausgabe'
                        NAME        FSTYPE   SIZE MOUNTPOINT
            zram0               15.3G [SWAP]
            nvme0n1            476.9G
            ├─nvme0n1p1 vfat     100M
            ├─nvme0n1p2           16M
            ├─nvme0n1p3 ntfs   234.4G
            ├─nvme0n1p4 ntfs     830M
            ├─nvme0n1p5 vfat       2G /boot
            └─nvme0n1p6 btrfs  239.6G /var/tmp
            ```
            EFI-Partitionen sind fast immer als `FAT32/vfat` formatiert. Da `nvme0n1p1` keinen Linux-Einhängepunkt hat, können wir davon ausgehen, dass diese Partition die Windows-EFI-Partition ist.

        2. Hänge die Windows-EFI-Partition temporär ein.

            ```sh
            sudo mkdir /mnt/WinBoot
            sudo mount /dev/nvme0n1p1 /mnt/WinBoot # Ersetze `nvme0n1p1` durch den Namen der Windows-EFI-Partition.
            ```

        3. Kopiere die EFI-Binärdateien von der **Windows-EFI-Partition** in die **Linux-EFI-Partition**.

            ```sh
            sudo cp -r /mnt/WinBoot/EFI/Microsoft/ /boot/EFI
            ```

        4. Hänge die zuvor eingehängte Partition aus. Windows sollte beim nächsten Start im Bootmenü erscheinen.

            ```sh
            sudo umount /mnt/WinBoot
            sudo rm -r /mnt/WinBoot
            ```

        </Steps>
    </TabItem>

    <TabItem label='GRUB'>
        **GRUB verwendet os-prober, um die Windows-EFI-Partition automatisch zu erkennen und zum Bootmenü hinzuzufügen.**

        <Steps>
        1. Installiere **os-prober**.

            ```sh
            sudo pacman -S os-prober
            ```

        2. Aktiviere **os-prober** in der GRUB-Konfigurationsdatei.

            ```sh title='Drücke STRG+S zum Speichern und STRG+Q zum Verlassen von Micro'
            sudo micro /etc/default/grub
            # /etc/default/grub
            # Probing for other operating systems is disabled for security reasons. Read
            # documentation on GRUB_DISABLE_OS_PROBER, if still want to enable this
            # functionality install os-prober and uncomment to detect and include other
            # operating systems.
            GRUB_DISABLE_OS_PROBER=false

            ```

        3. Aktualisiere grub.cfg, jetzt mit **os-prober**.
            ```sh
            sudo grub-mkconfig -o /boot/grub/grub.cfg
            ```

            **Windows sollte jetzt zum Bootmenü hinzugefügt sein.**

        </Steps>
    </TabItem>
</Tabs>
