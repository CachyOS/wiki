## Bevor Sie beginnen

:::note
Wenn Sie nach dem Drücken von **Launch Installer** nur GRUB und Limine als Bootmanager-Optionen erhalten, dann ist das System im Legacy/BIOS-Modus gebootet.
:::

:::note[Die Installation mehrerer Desktop-Umgebungen ist während des Installationsprozesses nicht erlaubt.]
:::

:::caution[Secure Boot und CSM müssen in den BIOS/UEFI-Einstellungen deaktiviert sein, wenn im UEFI-Modus installiert wird.]
Um Secure Boot nach der Installation einzurichten, lesen Sie den Abschnitt [Secure Boot](/de/configuration/secure_boot_setup).

`Legacy USB Support` sollte auf `Auto` eingestellt sein.
:::

:::caution
Die Optionen `Install alongside` (Nebenher installieren) und `Replace partition` (Partition ersetzen) sind nicht 100% zuverlässig und können zum Scheitern der Installation führen.

`Manual partitioning` (Manuelle Partitionierung) wird bei der Installation von CachyOS **dringend empfohlen**.
:::

:::tip
Es wird dringend empfohlen, nach einem fehlgeschlagenen Installationsversuch in die ISO neu zu booten.

Andernfalls können während des Installationsprozesses fortlaufend Fehler auftreten.

Dies geschieht, weil der Installer bei einer fehlgeschlagenen Installation die Partitionen nicht ordnungsgemäß aushängt.

:::

## Installationsmethoden

### Manuelle Partitionierung

:::note[Bevor Sie mit der Partitionierung der Festplatte für eine UEFI-Installation fortfahren.]
    ```sh title='Führen Sie diesen Befehl im Terminal aus'
    efibootmgr -v
    ```
Wenn die Ausgabe `EFI variables are not supported on this system.` lautet, dann ist das System im Legacy/BIOS-Modus gebootet, und Sie müssen sicherstellen, dass der UEFI-Modus in den BIOS/UEFI-Einstellungen konfiguriert ist. Lesen Sie den Abschnitt [Voraussetzungen](/de/installation/installation_on_root/#bevor-du-anfängst).
:::

## Dual-Boot von Windows und CachyOS

:::note[Diese Anleitung geht davon aus, dass Windows bereits auf dem System installiert ist und Sie sich entschieden haben, CachyOS daneben zu installieren, wobei dasselbe Laufwerk genutzt wird.]
:::

:::caution
Dual-Boot von Windows und Linux ist nicht 100% zuverlässig. Windows-Updates können den Bootloader beschädigen, indem sie die EFI-Partition überschreiben.
In manchen Fällen treten möglicherweise nie Probleme auf, aber für einige Benutzer kann es ein wiederkehrendes Problem sein.

Eine Möglichkeit, dieses Problem zu vermeiden, ist die Installation jedes Betriebssystems auf einem separaten Laufwerk.
:::

:::caution
Die EFI-Partition muss möglicherweise in der Größe angepasst werden, abhängig von der empfohlenen Mindestgröße des Ziel-Bootmanagers. Siehe [Manuelle Partitionierung](/de/installation/installation_on_root#manuelle-partitionierung).

FAT-Dateisysteme können nicht im laufenden Betrieb in der Größe geändert werden. Um die FAT-EFI-Partition ordnungsgemäß in der Größe zu "ändern", muss man das vorhandene EFI-Dateisystem sichern, ein Werkzeug wie `gparted` verwenden, um die vorhandene Partition in der Größe zu ändern und die neue Partition neu zu formatieren, und dann die vorherige Dateisystemstruktur wieder in die EFI-Partition kopieren.
:::

### Voraussetzungen

- Windows Schnellstart und Ruhezustand müssen deaktiviert sein.
  - Öffnen Sie Windows Powershell als Administrator und führen Sie den folgenden Befehl aus:
      ```ps
      powercfg /H off
      ```
    Starten Sie das System neu, um sicherzustellen, dass die Änderungen wirksam werden.
- Windows BitLocker muss deaktiviert sein.
  - Überprüfen, ob BitLocker aktiviert ist:
    ```ps title='Öffnen Sie eine Eingabeaufforderung als Administrator und führen Sie den folgenden Befehl aus'
    manage-bde -status
    ```
  Wenn bei **Encryption Method** (Verschlüsselungsmethode) `None` (Keine) angezeigt wird, ist BitLocker deaktiviert.
- Secure Boot muss deaktiviert sein.
- Eine leere Partition von ≥30 GB.
  - Anleitung zum Verkleinern einer Windows-Partition:
    - Drücken Sie `Win + R`, geben Sie `diskmgmt.msc` ein und drücken Sie Enter, um die Datenträgerverwaltung zu öffnen.
    - Identifizieren Sie Ihre Haupt-Windows-Partition (normalerweise C:) und klicken Sie mit der rechten Maustaste darauf.
    - Klicken Sie auf `Shrink Volume...` (Volume verkleinern...), geben Sie mindestens **30720 MB** (30 GiB) an und klicken Sie auf `Shrink` (Verkleinern).
- Ein bootfähiger USB-Stick mit CachyOS.
  - Lesen Sie den Abschnitt [Erstellen eines bootfähigen CachyOS-USB-Laufwerks](/de/installation/installation_prepare#einen-bootfähigen-cachyos-usb-stick-erstellen).

<Tabs>
    <TabItem label='systemd-boot'>
        **Wir müssen die Windows-EFI-Binärdateien in die Linux-EFI-Partition kopieren, damit der Bootmanager sie erkennen kann.**

        <Steps>
        1. Finden Sie die **Windows-EFI-Partition** mit `lsblk`.

            ```sh title='Führen Sie diesen Befehl im Terminal aus'
            lsblk -o NAME,FSTYPE,SIZE,MOUNTPOINT
            ```
            ```sh title='Beispielausgabe'
                        NAME        FSTYPE   SIZE MOUNTPOINT
            zram0               15.3G [SWAP]
            nvme0n1            476.9G
            ├─nvme0n1p1 vfat     100M
            ├─nvme0n1p2           16M
            ├─nvme0n1p3 ntfs   234.4G
            ├─nvme0n1p4 ntfs     830M
            ├─nvme0n1p5 vfat       2G /boot
            └─nvme0n1p6 btrfs  239.6G /var/tmp
            ```
            EFI-Partitionen sind fast immer als `FAT32/vfat` formatiert. Da `nvme0n1p1` keinen Linux-Einhängepunkt hat, können wir davon ausgehen, dass diese Partition die Windows-EFI-Partition ist.

        2. Hängen Sie die Windows-EFI-Partition vorübergehend ein.

            ```sh
            sudo mkdir /mnt/WinBoot
            sudo mount /dev/nvme0n1p1 /mnt/WinBoot # Ersetzen Sie `nvme0n1p1` durch den Namen der Windows-EFI-Partition.
            ```

        3. Kopieren Sie die EFI-Binärdateien von der **Windows-EFI-Partition** in die **Linux-EFI-Partition**.

            ```sh
            sudo cp -r /mnt/WinBoot/EFI/Microsoft/ /boot/EFI
            ```

        4. Hängen Sie die zuvor eingehängte Partition aus. Windows sollte beim nächsten Start im Bootmenü erscheinen.

            ```sh
            sudo umount /mnt/WinBoot
            sudo rm -r /mnt/WinBoot
            ```

        </Steps>
    </TabItem>

    <TabItem label='GRUB'>
        **GRUB verwendet os-prober, um die Windows-EFI-Partition automatisch zu erkennen und zum Bootmenü hinzuzufügen.**

        <Steps>
        1. Installieren Sie **os-prober**.

            ```sh
            sudo pacman -S os-prober
            ```

        2. Aktivieren Sie **os-prober** in der GRUB-Konfigurationsdatei.

            ```sh title='Drücken Sie STRG+S zum Speichern und STRG+Q zum Beenden von Micro'
            sudo micro /etc/default/grub
            # /etc/default/grub
            # Probing for other operating systems is disabled for security reasons. Read
            # documentation on GRUB_DISABLE_OS_PROBER, if still want to enable this
            # functionality install os-prober and uncomment to detect and include other
            # operating systems.
            GRUB_DISABLE_OS_PROBER=false

            ```

        3. Aktualisieren Sie grub.cfg, jetzt mit **os-prober**.
            ```sh
            sudo grub-mkconfig -o /boot/grub/grub.cfg
            ```

            **Windows sollte nun zum Bootmenü hinzugefügt sein.**

        </Steps>
    </TabItem>
</Tabs>
