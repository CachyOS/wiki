除了我们优化的内核和软件仓库外，我们还提供进一步改善桌面体验的设置，以及一些用于提升生活质量的辅助脚本。所有这些配置和脚本都属于 `cachyos-settings` 软件包。

查看 [CachyOS Settings 仓库](https://github.com/CachyOS/CachyOS-Settings?tab=readme-ov-file#cachyos-settings) 以了解更多我们提供的配置和脚本。

### DLSS Swapper

在某些情况下可能很有用，特别是 Valve 提供的 Proton 版本。

:::note
Proton-CachyOS 已提供内置升级功能。
:::

:::caution
不要同时使用 `PROTON_DLSS_UPGRADE=1` 和 `dlss-swapper`，因为它们执行相同操作，可能导致冲突。
:::

它的作用是尝试将 DLSS DLL 和预设更新到最新版本，这对于某些需要特定 DLSS 版本才能正常运行的游戏非常有用。

如何实现？通过向游戏进程注入环境变量：

<details>
    <summary>dlss-swapper 环境变量</summary>
    ```sh
    export PROTON_ENABLE_NGX_UPDATER=1
    export DXVK_NVAPI_DRS_NGX_DLSS_RR_OVERRIDE=on
    export DXVK_NVAPI_DRS_NGX_DLSS_SR_OVERRIDE=on
    export DXVK_NVAPI_DRS_NGX_DLSS_FG_OVERRIDE=on
    export DXVK_NVAPI_DRS_NGX_DLSS_RR_OVERRIDE_RENDER_PRESET_SELECTION=render_preset_latest
    export DXVK_NVAPI_DRS_NGX_DLSS_SR_OVERRIDE_RENDER_PRESET_SELECTION=render_preset_latest
    ```
</details>
<details>
    <summary>dlss-swapper-dll 环境变量</summary>
    ```sh
    export DXVK_NVAPI_DRS_NGX_DLSS_RR_OVERRIDE=on
    export DXVK_NVAPI_DRS_NGX_DLSS_SR_OVERRIDE=on
    export DXVK_NVAPI_DRS_NGX_DLSS_FG_OVERRIDE=on
    export DXVK_NVAPI_DRS_NGX_DLSS_RR_OVERRIDE_RENDER_PRESET_SELECTION=render_preset_latest
    export DXVK_NVAPI_DRS_NGX_DLSS_SR_OVERRIDE_RENDER_PRESET_SELECTION=render_preset_latest
    ```
</details>

- `dlss-swapper` 和 `dlss-swapper-dll` 有什么区别？
    - `dlss-swapper` 将 DLSS DLL 和预设更新为 NGX Updater 提供的最新版本，而 `dlss-swapper-dll` 依赖于游戏目录中已存在的 DLL。


### [game-performance](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/bin/game-performance)

一个小脚本，为目标进程启用 `powerprofilesctl` 的性能配置文件（可用于游戏或任何其他进程），并在进程运行时禁用屏幕保护程序。

问答：

<details>
    <summary>如何使用</summary>
    假设您想对 Steam 游戏使用 `game-performance`。您可以通过在 Steam 中将该游戏的启动选项添加 `game-performance` 命令来实现：
        <Steps>
            1. 打开 Steam 并进入您的库。
            2. 右键点击要使用 `game-performance` 的游戏，选择"属性"。
            3. 在"常规"选项卡中，找到"启动选项"部分并添加以下命令：
                ```sh
                game-performance %command%
                ```
                :::tip[如何在 Steam 中管理启动选项的指南]
                CachyOS Wiki - [如何正确设置多个启动选项](/zh/configuration/gaming#how-to-properly-set-multiple-launch-options)
                :::
            4. 关闭属性窗口并启动游戏。
        </Steps>
        <details>
            <summary>在 Steam 之外使用</summary>
            由于 `game-performance` 只是一个包装脚本，您可以使用它来启动任何启用性能配置文件的进程。只需在终端中运行以下命令：
            ```sh
            game-performance <command>
            ```
        </details>
</details>

<details>
    <summary>game-performance 对旧 CPU 有任何好处吗？</summary>
    一般来说没有。您应该避免在旧 CPU 上使用它，因为它可能弊大于利。

    粗略的指南是，在任何低于 6 核/12 线程的 CPU 上使用 game-performance 很可能不会提升甚至降低性能。与大多数选项一样，您应该自行测试它们是否提升了您特定系统的性能。
      - 对于 Intel 桌面 CPU，大致分界线是 i7 和 i9 CPU 的 8 代（Coffee Lake）和 i5 CPU 的 10 代（Comet Lake）。所有 Intel Ultra CPU 都应该适用。
      - 对于 AMD 桌面 CPU，Ryzen 7 和 Ryzen 9 CPU 为 1000 系列（Zen）。对于 Ryzen 5 CPU 也是 1000 系列，但仅限 Ryzen 5 1600 及以上。这种情况持续到 5000 系列（Zen 3），此时所有 Ryzen 5 CPU 都有 6 核 12 线程。
      - Intel i3 和 Ryzen 3 桌面 CPU 从未超过四个核心。
      - 移动、工作站和服务器的 CPU 核心数各不相同，所以研究一下您拥有什么并尝试不同的设置，这就是拥有 PC 硬件乐趣的一半！
</details>

<details>
    <summary>为什么不默认启用？</summary>
    启用性能配置文件可能并不适合所有用户，并且可能导致功耗和发热增加。不默认启用它，我们让用户在需要时自行选择启用，而不是强加给所有人。
</details>

### [paste-cachyos](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/bin/paste-cachyos)

### [pci-latency](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/bin/pci-latency)

一个简单的脚本，旨在通过更改 PCI 延迟计时器来尝试降低延迟并提高 PCI 声卡的性能。

同时提供二进制和 systemd 服务格式。systemd 服务将在启动时自动应用更改，而二进制文件可按需应用更改。

<details>
    <summary>在当前会话中单次使用</summary>
    ```sh
    sudo pci-latency
    ```
</details>
<details>
    <summary>启用 systemd 服务</summary>
    ```sh
    systemctl enable pci-latency.service
    ```
</details>
<details>
    <summary>禁用 systemd 服务</summary>
    ```sh
    systemctl disable pci-latency.service
    ```
</details>

### [sbctl-batch-sign](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/bin/sbctl-batch-sign)

:::note
不兼容 Limine。
:::

`sbctl-batch-sign` 是一个辅助脚本，旨在让用户更容易签署安全启动支持所需的文件。

此脚本帮助最大的明显场景是双启动 Windows，因为 Windows 在 EFI 中有很多文件需要签名。

执行脚本时的简要摘要：

- 使用 `sbctl verify` 扫描未签名的文件
    - 如有必要，使用 `sbctl sign` 签署检测到的文件
- 避免属于 Windows、GRUB 的文件或以下扩展名的文件：`.mui` 和 `.dll`

查看我们的 [安全启动设置](/zh/configuration/secure_boot_setup#signing-the-kernel-image-and-boot-manager) 部分以获取更多信息。

## 创建覆盖文件

什么是覆盖文件？

覆盖文件是您创建的配置文件，用于更改 `cachyos-settings` 提供的默认设置。这允许您在不修改原始文件的情况下自定义系统，这对于保持与 `cachyos-settings` 未来更新的兼容性很有用。

### sysctl

我们提供了大量旨在提升整体桌面性能的 sysctl 调整。每个 sysctl 条目都在文件 [70-cachyos-settings.conf](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/lib/sysctl.d/70-cachyos-settings.conf) 中有详细文档。

要更改其中任何值，请复制原始条目并在 `/etc/sysctl.d/` 下创建一个包含修改后值的新文件。

<details>
    <summary>sysctl 覆盖示例</summary>
    <Steps>

    1. 查看 `cachyos-settings` 中的原始值

        ```sh
        cat /usr/lib/sysctl.d/70-cachyos-settings.conf
        # Only experimental!
        # Let Realtime tasks run as long they need
        # sched: RT throttling activated
        kernel.sched_rt_runtime_us=-1
        ```
    2. 在 `/etc/sysctl.d` 中新建文件以更改 sysctl 设置

        ```sh title="将 kernel.sched_rt_runtime_us= 恢复为默认值"
        sudo micro /etc/sysctl.d/99-kernel-sched-rt.conf # 如果文件不存在，此命令将创建并让您编辑文件
        kernel.sched_rt_runtime_us=950000
        ```
    3. 按 `CTRL + S` 保存文件，然后按 `CTRL + Q` 退出编辑器。
    4. 更改 sysctl 设置后，确保应用更改：
        ```sh
        sudo sysctl --system
        ```
    </Steps>
</details>

### udev 规则

udev 规则也是如此。您可以通过在 `/etc/udev/rules.d/` 下创建与原始文件同名的新文件来创建自己的覆盖。

:::tip[使用以下命令查找原始文件]
```sh
pacman -Ql cachyos-settings | grep udev
```
:::

<details>
    <summary>udev 规则覆盖示例</summary>
    1. 检查原始 CachyOS udev 规则：
        ```sh
        cat /usr/lib/udev/rules.d/60-ioschedulers.rules
        ```
        <details>
            <summary>输出：</summary>
                ```sh
                # HDD
                ACTION=="add|change", KERNEL=="sd[a-z]*", ATTR{queue/rotational}=="1", \
                    ATTR{queue/scheduler}="bfq"

                # SSD
                ACTION=="add|change", KERNEL=="sd[a-z]*|mmcblk[0-9]*", ATTR{queue/rotational}=="0", \
                    ATTR{queue/scheduler}="mq-deadline"

                # NVMe SSD
                ACTION=="add|change", KERNEL=="nvme[0-9]*", ATTR{queue/rotational}=="0", \
                    ATTR{queue/scheduler}="none"
                ```
        </details>
        现在假设您想将 SSD 和 NVMe 的 I/O 调度器分别更改为 `kyber`，而不是 `mq-deadline` 和 `none`。您可以通过创建覆盖文件来实现。
    2. 在 `/etc/udev/rules.d` 中创建新文件以覆盖原始规则：
        ```sh
        sudo micro /etc/udev/rules.d/60-ioschedulers.rules # 如果文件不存在，此命令将创建并让您编辑文件
        # HDD
        ACTION=="add|change", KERNEL=="sd[a-z]*", ATTR{queue/rotational}=="1", \
            ATTR{queue/scheduler}="bfq"

        # SSD
        ACTION=="add|change", KERNEL=="sd[a-z]*|mmcblk[0-9]*", ATTR{queue/rotational}=="0", \
            ATTR{queue/scheduler}="kyber"

        # NVMe SSD
        ACTION=="add|change", KERNEL=="nvme[0-9]*", ATTR{queue/rotational}=="0", \
            ATTR{queue/scheduler}="kyber"
        ```
    3. 按 `CTRL + S` 保存文件，然后按 `CTRL + Q` 退出编辑器。
    4. 更改 udev 规则后，确保重新加载规则并触发它们：

        ```sh
        sudo udevadm control --reload-rules
        sudo udevadm trigger
        ```
</details>
