为了在各种设备上提供最佳体验，CachyOS 目前提供以下引导管理器：**systemd-boot、rEFInd、GRUB 和 Limine**。

本文档描述了每个引导管理器的功能集，并包含我们关于何时选择它们的建议。
有关配置，请参阅 [引导管理器配置](/zh/configuration/boot_manager_configuration)。

:::caution
**重要提示：** 某些 MSI 主板的 UEFI 固件不完全符合 UEFI 规范。这可能导致与某些引导管理器（包括 GRUB 和 rEFInd）的兼容性问题。

如果遇到此类问题，请考虑使用 `systemd-boot` 或 `Limine`。
:::

## 引导管理器详情

### systemd-boot

systemd-boot 是 systemd 家族的一部分，被设计得尽可能简单。因此，它仅支持基于 UEFI 的系统。这种简单而高效的设计确保了它的可靠性和速度，但代价是缺少其他引导管理器支持的高级功能。

#### 优点
- 配置非常简单。
- 启动条目分离到多个文件中，便于管理。
- 确保与某些使用其他引导管理器时遇到 UEFI 问题的 MSI 主板兼容。
- 在 CachyOS 上，配置开箱即用自动生成。
- 启动过程中会度量 TPM PCRs。

#### 缺点
- 不支持 BIOS/MBR。
- 非常基础：无主题或自定义选项。
- 如果使用超出固件默认支持（FAT12/16/32）的启动文件系统，则需要手动添加单独的 ESP 和 [XBOOTLDR](https://wiki.archlinux.org/title/Systemd-boot#Installation_using_XBOOTLDR) 分区及 EFI 驱动。
- 无法在自己的 ESP 或 XBOOTLDR 分区之外的分区上找到启动镜像。
- 除非配置为自动生成，否则配置不会自动生成。
- 由于需要将内核镜像存储在启动分区而非根分区，因此不支持 Btrfs 快照回滚。
  - 快照启动仅可通过自定义设置实现（CachyOS 不提供）。

---

### rEFInd

rEFInd 是 rEFIt 的一个分支，最初是为了方便 MacOS 用户多启动而开发的。然而，rEFInd 已发展为由硬件无关，使其成为任何系统上多启动的绝佳选择。rEFInd 的主要吸引力在于其能够在启动时扫描所有存储设备，并相应地显示每个找到的操作系统/内核的条目。

#### 优点
- 自动检测存储设备上的所有操作系统和内核。
- 几乎无需手动配置。
- 图形化 UI，类似于 MacOS 启动选择器。
- 出色的主题支持，可选触摸屏支持。
- 可从 EFI 文件系统（FAT12/16/32）以及 EXT4 和 BTRFS 读取启动镜像。通过安装 `efifs` 包中的 EFI 驱动，可以启用更多文件系统支持。

#### 缺点
- 不支持 BIOS 系统。
- 与某些 MSI 主板不兼容（由于 UEFI 规范违规）。
  - 可通过变通方法修复，但需要额外步骤。
- 不度量 TPM PCRs。<a href="https://github.com/fwupd/fwupd/wiki/TPM-PCR0-differs-from-reconstruction">将导致 TPM PCR0 重建测试失败</a>。
  - 可通过启动使用 systemd-stub 作为 UEFI stub 的 UKI 来修复。systemd-ukify 可以创建它。
  - 另一种变通方法是链式加载另一个度量 TPM PCR 的引导加载器（如 systemd-boot、GRUB）。
---

### GRUB

GRUB 是可用引导管理器中最古老的。它功能非常丰富，几乎可以在每台机器上工作，仍然是使用最广泛的 Linux 引导管理器。

#### 优点
- 支持几乎所有 Linux 文件系统。
- 使用广泛——文档和社区帮助丰富。
- 支持加密的 `/boot` 分区。
- 支持 Btrfs 快照启动（在 CachyOS 上通过 `grub-btrfs-support` 实现）。
- 支持 BIOS 和 UEFI 系统。
- 尽管 UI 有些过时，但仍提供主题支持。
- 启动过程中会度量 TPM PCRs。

#### 缺点
- 庞大且复杂，包含许多文件系统驱动。
- 明显慢于 systemd-boot、rEFInd 和 Limine。
- 与某些 MSI 主板不兼容（UEFI 规范违规）。

---

### Limine

Limine 是一个现代、高级且可移植的多协议引导加载器。它是 Limine 启动协议的参考实现，支持 Linux 以及链式加载其他加载器。

#### 优点
- 支持多种启动协议，包括 Multiboot2 和 Linux 启动协议。
- 可在 UEFI 和 BIOS 系统上启动。
- 具有类似于 GRUB 的主题功能。
- 通过 `limine-snapper-sync` 支持 Btrfs 快照，在 CachyOS 上使用 Btrfs 时默认启用。

#### 缺点
- `/boot` 必须使用 FAT12/16/32 或 ISO9660。其他文件系统需要额外设置。
- 不会自动向 UEFI NVRAM 添加条目。必须使用 `efibootmgr` 手动完成，或使用 `limine-entry-tool`（CachyOS 预装）自动处理。
- 不适用于 UFS（Universal Flash Storage），例如某些 Chromebook 使用的存储。
- 不度量 TPM PCRs。<a href="https://github.com/fwupd/fwupd/wiki/TPM-PCR0-differs-from-reconstruction">将导致 TPM PCR0 重建测试失败</a>。
  - 可通过启动使用 systemd-stub 作为 UEFI stub 的 UKI 来修复。systemd-ukify 可以创建它（<a href="https://github.com/fwupd/fwupd/discussions/9568" target="_blank">参见此处</a>）。
  - 另一种变通方法是链式加载另一个度量 TPM PCR 的引导加载器（如 systemd-boot、GRUB）。

---

## TL;DR

- 如果你需要加密的 `/boot`、BIOS 兼容性，或者想要使用稳定成熟的引导管理器配合 Btrfs 快照，请选择 GRUB。

- 如果你想要一个开箱即用支持 Btrfs 快照集成的现代引导加载器，同时支持 BIOS 和 UEFI 以及 Windows 双启动（通过 **limine-scan**），请选择 Limine。

- 如果你想要一个精美的图形界面和 UEFI 系统上的自动多启动检测，请选择 rEFInd。

- 如果你偏好最简单的设置，不需要快照或高级功能，请选择 systemd-boot。它也是 MSI 主板 UEFI 问题最可靠的备选方案。
