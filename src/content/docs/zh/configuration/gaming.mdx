## Proton-CachyOS

Proton-CachyOS 基于 Proton 的 `bleeding-edge` 分支，并在此基础上应用了多项修改。
- **Wine-staging 补丁**
- **Wine 全屏 FSR**
- **包含游戏过场动画所需的视频和音频编解码器**
- **支持 umu-launcher（包括 UMU-Protonfixes）**
- **为游戏添加早期热修复/变通方案（hotfixes/workarounds）**

:::note[默认已启用 NTSync]
你可以通过设置环境变量 `PROTON_NO_NTSYNC=1` 来禁用它。
:::

### 如何正确设置多个启动选项

Steam 中的启动选项使用以下模式构建。

```bash
[env variables] [wrappers] %command% [application arguments]
```

- **`[env variables]`**：这些是 `VARIABLE=value` 形式的选项
  ```bash title="示例"
  PROTON_DXVK_D3D8=1
  # 或
  DXVK_HUD="fps,memory,version,api"
  ```

- **`[wrappers]`**：这些是用于修改实际应用程序运行方式的应用程序和脚本。包装器（wrapper）的参数通常放在其可执行文件之后。
  ```bash title="示例"
  mangohud --dlsym
  # 或
  gamescope -W 1680 -H 1050 -w 1280 -h 720 -S fit -F fsr --mangoapp --
  ```

- **`%command%`**：这代表实际的应用程序。应按原样填写，Steam 会在运行应用程序时将其替换为正确的命令。

- **`[application arguments]`**：这些是传递给实际应用程序的各种参数，具体取决于应用程序本身。
  ```bash title="示例"
  %command% -dx11
  ```

**结合所有元素的完整启动选项示例：**
```bash
__GL_SHADER_DISK_CACHE_SKIP_CLEANUP=1 prime-run game-performance %command% -dx11
```

:::caution
不要把多个 `%command%` 当作分隔符来拼接多个启动选项。

示例：`__GL_SHADER_DISK_CACHE_SKIP_CLEANUP=1 %command% game-performance %command% prime-run %command%`

在这种情况下，第一个 `%command%` 之后的所有内容都会被视为游戏参数而遭到忽略，因此只有 `__GL_SHADER_DISK_CACHE_SKIP_CLEANUP=1` 会被识别为启动选项。
:::

## Wine-CachyOS

这是与 `Proton-CachyOS` 核心相同的 `Wine`，但作为独立软件包提供。它可用于 Lutris、Heroic、Bottles 等工具。**请记住，它并非为 Steam 设计。**

- **包含 Proton-CachyOS 中的所有 Wine 修改**
- **为游戏添加早期热修复/变通方案（hotfixes/workarounds）**

:::note
在 CachyOS 软件仓库中，**Wine-CachyOS** 提供两个不同的软件包。`wine-cachyos` 会将其安装为系统默认 Wine 并替换 `wine` 或 `wine-staging`。`wine-cachyos-opt` 则将其安装在不同的位置，允许系统上同时共存多个 Wine 版本。
:::

:::caution
**Wine-CachyOS** 的主要用途是**游戏**。虽然它也可以作为系统 Wine 运行桌面应用程序，但请注意，由于其包含面向游戏的修改，可能会导致意外行为和问题。

如果你想运行桌面应用程序，我们建议使用 `wine` 或 `wine-staging` 作为系统 Wine，并安装 `wine-cachyos-opt` 用于游戏。
:::

**额外配置选项**

- `WINE_WMCLASS="[name]"`：设置所有 Wine 窗口的 `WM_CLASS`，以便窗口管理器通过规则控制 Wine 窗口。
- `WINEUSERSANDBOX=1`：禁用从 Wine 用户文件夹（如 Documents 和 Pictures）到用户 `HOME` 目录中对应文件夹的符号链接创建。
- `WINE_NO_WM_DECORATION=1`：禁用窗口装饰。它可以修复**无边框全屏（borderless fullscreen）**和鼠标点击穿透窗口的问题。
- `WINE_PREFER_SDL_INPUT=1`：控制器检测问题的变通方案。

### 如何使用 wine-cachyos-opt

<Tabs>
  <TabItem label='独立运行'>
    通常，只需运行 `/opt/wine-cachyos/bin/wine` 而不是 `wine`，就足以让应用程序使用 `wine-cachyos-opt` 运行。

    如果需要更严格的配置，可以按如下方式设置：
    ```sh
    export PATH="/opt/wine-cachyos/bin/:$PATH"
    export WINEDLLPATH="/opt/wine-cachyos/lib/wine:/opt/wine-cachyos/lib32/wine:$WINEDLLPATH"
    export LD_LIBRARY_PATH="/opt/wine-cachyos/lib/:/opt/wine-cachyos/lib32/:$LD_LIBRARY_PATH"
    ```

    如果你想配合 `wine-cachyos-opt` 使用 `winetricks`，可以这样调用：
    ```sh
    WINE=/opt/wine-cachyos/bin/wine WINEPREFIX=[your prefix] winetricks [verb]
    ```

### 如何在 Steam 中设置自定义 Proton 版本

:::caution[强烈建议保持 Valve 的 Proton 作为全局默认。]
:::

- 要为特定游戏设置自定义 Proton，请导航到库（Library），右键点击游戏，
进入 **Properties** > **Compatibility**，

勾选 `Force the use of a specific Steam Play compatibility tool` 复选框
并选择你想要的 Proton 版本。

- 要将 Valve 的 Proton 设置为全局默认，请导航到 **Settings** > **Compatibility** > **Default Compatibility tool**，
并选择 Valve 的最新稳定版 Proton 或 Proton Experimental。

### 在 Steam 中应该使用哪个 Proton 版本？

:::tip
对于新用户，我们建议使用 Valve 的 Proton 或 Proton Experimental。
:::

官方 Proton 版本：

**Proton Experimental：** 来自 **Valve** 的前沿（bleeding edge）版本。如果你想玩的游戏相对较新、在当前稳定版 Proton 上表现不佳，或者大家在 **[ProtonDB](https://www.protondb.com/)** 上推荐使用它，请选择此版本。

**Proton 11.0：** 来自 **Valve** 的稳定版。如果你要玩的游戏已知在此版本上运行良好，请使用此版本。

**Proton 10.0 或更低版本：** 来自 **Valve** 的稳定版。*如果你想玩的游戏仅在旧版 Proton 上运行良好，请使用此版本。*

:::tip
对于更有经验的用户，如果想尝试额外功能、在 Steam 之外使用 Proton，或需要 Valve 官方 Proton 中尚未包含的修复，还有多种自定义 Proton 分支可供选择。请记住，它们不受 Valve 官方支持，属于社区驱动的项目，本质上具有实验性。
:::

第三方 Proton 分支：

**Proton-CachyOS：**
由 [CachyOS](https://github.com/CachyOS/proton-cachyos) 构建和维护，包含额外的使用体验改进（QoL）、修复和实验性更改。

你可以在 CachyOS 软件仓库中找到两种变体：[`proton-cachyos-native`](https://packages.cachyos.org/package/cachyos/x86_64/proton-cachyos-native) 和 [`proton-cachyos-slr`](https://packages.cachyos.org/package/cachyos/x86_64/proton-cachyos-slr)。

我们建议使用 `proton-cachyos-slr` 软件包，而不是 `proton-cachyos-native`。

**Proton-EM：**
由 [Etaash-mathamsetty](https://github.com/Etaash-mathamsetty/Proton) 制作的面向开发的自定义构建。如果你想使用 **winewayland** 和 **FSR4**，又不需要 Proton-CachyOS 提供的其他额外功能，这是一个非常好的选择。它也是 Proton-CachyOS 所包含的许多改进的来源。

*如果你对最新的 **winewayland** 开发进展感兴趣，这个版本非常适合你。*

**dwproton：**
由 [Dawn Winery](https://dawn.wine/dawn-winery/dwproton) 制作的自定义构建，它是 Proton-CachyOS 的分支，包含了**针对某些二次元/动漫游戏的额外修复和补丁**。

如果你在使用其他 Proton 分支游玩这类游戏时遇到问题，**dwproton** 是你的最佳选择。

**Proton-GE**：
由 [GloriousEggroll](https://github.com/GloriousEggroll/proton-ge-custom) 制作的自定义构建。它包含各种修复，在某些情况下非常有用。

### 修复使用 Valve Proton 时游戏中 H264 视频无法播放或显示色条的问题
:::caution
这是可选操作。仅在遇到此问题时使用。
:::
使用以下命令启动 Steam。等待其加载完成后退出 Steam，然后正常启动即可。

```sh
 steam steam://unlockh264/
```

### 修复 Steam 游戏录制功能导致的卡顿

:::caution
添加此环境变量会导致 **Steam 游戏内界面（Overlay）** 停止工作。
:::

将以下启动选项添加到你的游戏中。

```sh
LD_PRELOAD="" %command%
```

### 捕获和共享 Proton 日志

:::note
向 CachyOS 分享日志时，请将其上传到 **[paste-cachyos](https://paste.cachyos.org/)**，而不要直接粘贴发送。

你只需将日志文件拖放到该网站上，然后分享生成的链接即可。
:::

要为游戏启用 Proton 日志记录：

<Steps>
  1. 在 Steam 中右键点击你的游戏并选择 **Properties**。
  2. 在 **Launch Options** 下，设置 `PROTON_LOG` 环境变量：
      ```sh
      PROTON_LOG=1 %command%
      ```
      这将在你的主目录中创建一个名为 `steam-[AppID].log` 的日志文件（例如，Counter Strike 2 的 AppID 为 **730**，因此文件名为 `steam-730.log`）。
</Steps>

<details>
  <summary>自定义日志目录</summary>

  要设置自定义日志目录，请使用 `PROTON_LOG_DIR`：

  ```sh title='示例'
  PROTON_LOG=1 PROTON_LOG_DIR=/home/cachyos/steam-logs %command%
  ```
</details>

### 使用 Proton-CachyOS、-GE 和 -EM 预缓存着色器

:::note
建议在使用 Proton-CachyOS、Proton-GE 或 Proton-EM 时禁用 Steam 的着色器预缓存功能。它们已经包含游戏中播放视频所需的所有编解码器；而且如今相对现代的 GPU-CPU 组合完全有能力在游戏中实时编译着色器。

如果你有充裕时间，也可以忽略此提示，让 Steam 为你的游戏预编译部分着色器。

**请记住，此过程中并非所有内容都会被缓存，而且一旦用于编译着色器的 Proton 版本更新，可能就需要重新编译全部着色器。**
:::

#### 在 Steam 中禁用此功能

在 Steam 中，点击 `Steam`->`Settings`，进入 `Downloads`，并取消勾选以下设置：
- **Allow background processing of Vulkan shaders**
- **Enable Shader Pre-caching**

:::note
强烈建议在禁用 Steam 的着色器预缓存后[增加最大着色器缓存大小](#增加最大着色器缓存大小)。
:::

### 启动到 gamescope 会话

Gamescope 会话会在 gamescope 内启动你的桌面，提供一个专用的全屏游戏环境，具备更佳的显示处理、输入管理以及性能优化。

它非常适合以游戏为主的系统或掌机设备，提供类似主机的体验，同时在需要时仍允许访问桌面会话。

要使用它，请安装 `gamescope-session-cachyos` 软件包（`pacman -S gamescope-session-cachyos`）并将默认会话设置为 gamescope。

## [Lutris](https://lutris.net/)

Lutris 是 CachyOS 上的游戏启动器。使用 Lutris，你可以轻松管理包括 Wine、Proton 和模拟器在内的游戏运行器（runners）。

- 只需点击 **Play** 按钮即可通过 Lutris 启动游戏。
- 点击左上角的 **+** 添加任何你想要的游戏。
- 在左侧面板的 Sources 中配置游戏商店并连接你的账户。之后它会自动安装该商店，你就可以像在 Windows 上一样从商店内运行游戏。
- 还有更多功能！

*Lutris 支持的游戏商店：*

- [EA App](https://lutris.net/games/ea-app/)
- [Epic Games Store](https://lutris.net/games/epic-games-store/)
- [GOG Galaxy](https://lutris.net/games/gog-galaxy/)
- [Steam](https://lutris.net/games/steam/)
- [Ubisoft Connect](https://lutris.net/games/ubisoft-connect/)

### 如何在 Lutris 中正确设置多个启动选项和环境变量

- 启动选项（如 `-dx11` 或 `-fullscreen`）应在 **Game options** 选项卡下的 **Arguments** 字段中添加，使用空格作为分隔符。
- 命令包装器（例如 `mangohud --dlsym` 或 `game-performance`）应在 **System options** 选项卡下的 **Command prefix** 字段中添加，使用空格作为分隔符。
- 环境变量（如 `DXVK_HDR=1`）应在 **System options** 选项卡下的 **Environment variables** 表格中添加，点击 `+` 按钮即可添加新条目。
:::note
不要在 Key 字段中包含 `=`。该字段仅应填写变量名。
:::

### 如何在 Lutris 中正确生成日志
- 将 Output debugging info 设置为 `Inherit from environment`。
- 在 Environment variables 中添加 `PROTON_LOG`，值设为 `1`。


## 性能与杂项提示

### 不要同时使用 gamemode 和 ananicy-cpp

由于 `gamemode` 和 `ananicy-cpp` 都会尝试同时修改进程的优先级（niceness），这可能导致冲突和意外行为。如果你想使用 gamemode，建议先禁用或停止 ananicy-cpp。

要停止 ananicy-cpp，请执行以下命令：

```sh
systemctl stop ananicy-cpp
```

### 按需切换电源配置文件

:::note
此行为在 `intel_pstate` 上略有不同。在 Intel 平台上，调频器（governor）保持在 powersave，但会调整 EPP/EPB 值以偏向性能。
:::

:::caution[game-performance 在老旧 CPU 上可能不会带来任何收益。]
:::

CachyOS 包含一个包装脚本 [game-performance](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/bin/game-performance)，
它使用 `power-profiles-daemon` 临时将电源配置文件切换到 `performance`。
该配置文件会提高系统功耗限制并将 CPU 调频器设为 `performance`，同时还会将当前活动的 scx 调度器切换为其游戏配置文件（如果可用）。

使用该脚本启动游戏时，系统会保持在**性能模式（performance mode）**，直到游戏退出后再恢复之前的配置文件。

[Feral 的 GameMode](https://github.com/FeralInteractive/gamemode)
也提供类似的功能。

### 增加最大着色器缓存大小

游戏着色器会在游玩过程中自动编译，这在首次遇到这些着色器时可能会导致加载时间过长和卡顿。这些着色器会保存在系统中，以便在需要时重用。

然而，着色器缓存的文件大小存在上限，超过默认大小时旧的着色器会被清理。这可能会带来问题，因为大型游戏的着色器体积可能超过 1GB，导致每次启动都要重新编译着色器。

为了避免漫长的加载时间和卡顿，我们可以增大全局着色器缓存大小：

<Steps>

  1. 打开终端。
  2. 如果配置文件夹中不存在 `environment.d` 目录，请先创建它：
      ```sh
      mkdir -p ~/.config/environment.d
      ```
  3. 创建一个新的配置文件：
      ```sh
      touch ~/.config/environment.d/gaming.conf
      ```
  4. 使用 **Micro**（文本编辑器）打开该文件：
      ```sh
      micro ~/.config/environment.d/gaming.conf
      ```
      并根据你的 GPU 厂商粘贴以下内容：
      <details>
        <summary>AMD</summary>
        ```sh
        # Increase AMD's shader cache size to 12GB
        MESA_SHADER_CACHE_MAX_SIZE=12G
        ```
      </details>
      <details>
        <summary>NVIDIA</summary>
        ```sh
        # Increase Nvidia's shader cache size to 12GB
        __GL_SHADER_DISK_CACHE_SIZE=12000000000
        ```
      </details>
  5. 按 `CTRL+S` 保存文件，按 `CTRL+Q` 退出 Micro。重启你的系统。

</Steps>

重启后，最大着色器缓存大小应该已经永久增大。感谢 [psygreg 的 shader booster](https://github.com/psygreg/shader-booster/) 为本指南提供的帮助。

### Nvidia 在 DirectX12 游戏中的性能下降

一些用户报告称，该问题与 Nvidia 的 Linux 驱动处理 GPU 调度的方式有关——与强制执行正确调度的 Windows 不同。Nvidia 对此尚无官方声明。目前该问题没有已知的变通方法。据称 Nvidia 正在开发修复程序，但不清楚何时发布。

**这与 CachyOS 无关。**

在某些游戏中，性能下降不如其他游戏明显。你可以查看此[基准测试对比视频](https://www.youtube.com/watch?v=SU2mFqCOh5A)作为参考。

关注此 [Nvidia 论坛帖子](https://forums.developer.nvidia.com/t/directx12-performance-is-terrible-on-linux/303207/488)以了解更多关于该问题的信息。
