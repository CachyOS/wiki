## 简介

:::caution
不要把 Btrfs 快照当作常规备份的替代品。始终确保你有重要数据的适当备份。
:::

### 什么是 Btrfs 快照？

让我们从基础开始：

Btrfs 快照源于 subvolume（子卷）功能。你可能会问什么是 subvolume？把 subvolume 想象成 Btrfs 文件系统内的独立文件系统。它允许你将数据分割成不同部分。这就是为什么例如在 CachyOS 中，我们为以下内容使用不同的 subvolume：

- Root filesystem: (`/`)
- Root directory: (`/root`)
- Home directory: (`/home`)
- Var directories: (`/var/cache`, `/var/tmp`, `/var/log`)
- Srv directory: (`/srv`)

通过为这些目录使用不同的 subvolume，我们可以独立管理它们，应用不同的设置，最重要的是为它们创建快照。

这就是快照的诞生。快照本质上是在特定时间点对 subvolume 的只读或读写（**默认**）副本。这意味着你可以捕获那一刻文件系统的状态，包括所有文件和目录。

因此快照成为一个时间点参考，这意味着当目标文件偏离快照数据时，快照将保留原始文件，目标将创建一个带有更改的新文件，而快照永远保持不变，这就是为什么一些用户将快照称为"冻结在时间中的数据"。

想象在特定时刻对文件系统拍照，当你需要时，随时可以回到那张照片。

快照的关键优势之一是它们非常节省空间，因为在对原始数据进行更改之前，它只是对原始数据的引用。

但这就是快照与传统备份的分歧之处。假设你的磁盘崩溃了，如果你有传统备份，你可以从备份中恢复数据。然而，如果你只在崩溃的磁盘上有快照，你将失去对这些快照的访问，因为它们存储在同一个磁盘上。

### 快照有用和无用的恢复场景

在以下情况下有用：

- 系统更新后出现损坏或问题。
- 阻止系统启动的错误配置。
- 意外删除或修改文件。

在以下情况下无用：

- Bootloader 问题。
- 硬件故障（例如硬盘损坏）。

## 管理快照（GUI 和 CLI）

:::tip
因为 CachyOS 默认包含 `snap-pac`，Snapper 将在使用 `pacman` 安装、升级或移除任何软件包之前和之后自动创建快照。这意味着你不必为这些操作手动创建快照，Snapper 会为你处理。
:::

:::note
如果你使用 GRUB bootloader，确保你安装了 `grub-btrfs-support`，以获得所有必要的脚本和钩子，自动检测 BTRFS 快照并将其添加到 GRUB 菜单中。
```bash
sudo pacman -Syu grub-btrfs-support
```
:::

在管理快照之前需要考虑几件事。**适用于 CLI 和 GUI 方法。**

- 建议最多保留 10 个快照。超过这个数量，快照会变得太旧且不太有用。在最坏情况下，恢复到旧快照可能会与新软件版本引入兼容性问题。
- 快照理想上用于恢复目的。虽然你可以使用它们撤销对文件的更改而无需还原整个快照。
- 创建快照时添加有意义的描述。这将帮助你稍后识别每个快照的用途。

### Btrfs Assistant（GUI）

在继续之前，确保你安装了 `btrfsmaintenance`，以利用自动快照管理功能。

对于那些喜欢通过 GUI 管理 Btrfs、快照等的用户，[Btrfs Assistant](https://gitlab.com/btrfs-assistant/btrfs-assistant) 是一个非常适合初学者的项目。

#### 自动快照清理设置

我们将使用 Btrfs Assistant 设置自动快照清理。这将帮助你在无需手动干预的情况下有效管理快照。

按照以下步骤操作：

<Steps>

    1. 通过打开终端并运行以下命令启动 Btrfs Assistant：
        ```bash
        btrfs-assistant-launcher
        ```

        或者：

        ```bash
        sudo -E btrfs-assistant
        ```

  2. 导航到 Snapper Settings 选项卡：

      <ImageComponent imgsrc={import('~/assets/images/btrfs-maintenance-snapperSettingsTab.png')} />
      按如下方式修改 **Snapshot Retention** 设置：
      - 确保选择了 `root` 配置
      - 为 Hourly、Daily、Weekly、Monthly 和 Yearly 输入值 `0`。
      - 取消勾选 `Enable timeline snapshots`。
      - 为 `Number` 输入值 `10`。
      - 在 `Snapper cleanup enabled` 旁添加 ✅。
      - 点击右上角的 `Save` 按钮，然后点击右下角的 `Apply systemd changes`。
      **snapper-cleanup.timer 现在将启用，以根据你的配置自动清理旧快照。**
      :::caution
      通过检查 Snapper 配置，验证你刚刚所做的调整已正确应用：
      ```bash
      sudo nano /etc/snapper/configs/root
      ```
      预期输出片段：
      ```text
      # 数量清理的限制
      NUMBER_MIN_AGE="3600"
      NUMBER_LIMIT="10"
      NUMBER_LIMIT_IMPORTANT="10"
      ```
      如果 `NUMBER_LIMIT` 和 `NUMBER_LIMIT_IMPORTANT` 不包含值 `10`。请相应更新它们。
      按 `CTRL + O`、`Enter` 和 `CTRL + X` 保存文件并退出。
      :::
</Steps>

#### 使用 Btrfs Assistant 删除快照

<Steps>
    1. 打开 Btrfs Assistant：
        ```bash
        btrfs-assistant-launcher
        ```

        或者：

        ```bash
        sudo -E btrfs-assistant
        ```
    2. 进入 Snapper Settings 选项卡：
        <ImageComponent imgsrc={import('~/assets/images/btrfs-maintenance-snapperTab.png')} />
    3. 从列表中选择要删除的快照。
        :::tip
        - 按住 `CTRL` 可选择多个快照。
        - 按住 `SHIFT` 可选择一系列快照。
        :::
    4. 点击窗口顶部的 `Delete` 按钮。
    5. 重新生成 bootloader 条目以反映更改：
        <details>
            <summary>systemd-boot</summary>
            ```bash
            sudo sdboot-manage gen
            ```
        </details>
        <details>
            <summary>GRUB</summary>
            ```bash
            sudo grub-mkconfig -o /boot/grub/grub.cfg
            ```
        </details>
        <details>
            <summary>Limine</summary>
            ```bash
            sudo limine-mkinitcpio
            ```
        </details>
</Steps>

查看他们的 [Official Wiki](https://gitlab.com/btrfs-assistant/wiki) 以更深入地了解可以做什么。

### Snapper（CLI）

现在我们已经了解了 Btrfs 快照是什么及其用例，让我们谈谈如何使用由 [openSUSE](https://www.opensuse.org/) 的 [Arvin Schnell](https://github.com/aschnell) 创建的名为 [Snapper](http://snapper.io/) 的工具来管理它们。

<details>
<summary>CachyOS 默认使用以下 Snapper 配置：</summary>

```text
# 要快照的子卷
SUBVOLUME="/"

# 文件系统类型
FSTYPE="btrfs"

# 用于感知空间的清理算法的 btrfs qgroup
QGROUP=""

# 快照可使用的文件系统空间的比例或绝对大小
SPACE_LIMIT="0.5"

# 应保持空闲的文件系统空间的比例或绝对大小
FREE_LIMIT="0.2"

# 允许使用此配置的用户和组
ALLOW_USERS=""
ALLOW_GROUPS=""

# 将用户和组从 ALLOW_USERS 和 ALLOW_GROUPS 同步到 .snapshots
# 目录
SYNC_ACL="no"

# 创建 post-snapshot 后在后台开始比较 pre- 和 post-snapshot
BACKGROUND_COMPARISON="yes"

# 运行每日数量清理
NUMBER_CLEANUP="yes"

# 数量清理的限制
NUMBER_MIN_AGE="1800"
NUMBER_LIMIT="50"
NUMBER_LIMIT_IMPORTANT="15"

# 创建每小时快照
TIMELINE_CREATE="no"

# 一段时间后清理每小时快照
TIMELINE_CLEANUP="yes"

# 时间线清理的限制
TIMELINE_MIN_AGE="1800"
TIMELINE_LIMIT_HOURLY="5"
TIMELINE_LIMIT_DAILY="7"
TIMELINE_LIMIT_WEEKLY="0"
TIMELINE_LIMIT_MONTHLY="0"
TIMELINE_LIMIT_YEARLY="0"

# 清理空的 pre-post 对
EMPTY_PRE_POST_CLEANUP="yes"

# 空 pre-post 对清理的限制
EMPTY_PRE_POST_MIN_AGE="1800"
```

</details>

:::caution
CachyOS 的默认 Snapper 配置仅覆盖 root subvolume（`/`）。如果你有其他想用 Snapper 管理的 subvolume，你需要为每个 subvolume 创建单独的配置。

此配置需要修订以提高其有效性。
:::

        - `#`：表示快照编号，用于其他命令。
        - `Type`：表示快照是单个快照还是 pre/post 对的一部分。
            - `single`：这些快照与其他快照没有特殊关系。
            - `pre`：这些快照旨在在任何系统更改（如编辑文件或安装包）之前拍摄。
            - `post`：顾名思义，这些快照指的是系统更改发生后拍摄的快照。它们与对应的 `pre` 快照链接。

            - empty-pre-post：删除差异为空的 pre/post 快照对。
        - `Description`：快照的简要描述，通常指示创建原因。
        - `Userdata`：与快照关联的附加用户定义数据。

### Limine 建议与提示

#### 调整 Limine bootloader 快照显示设置

- 限制 Limine bootloader 菜单中显示的快照数量以避免杂乱：

<Steps>
    1. 创建 limine-snapper-sync 配置文件的备份：
        ```bash
        sudo cp /etc/limine-snapper-sync.conf /etc/limine-snapper-sync.conf.orig
        ```
    2. 编辑 limine-snapper-sync 配置文件：
        ```bash
        sudo nano /etc/limine-snapper-sync.conf
        ```
        预期输出片段：
        ```bash
        ### 最大快照条目数
        ### 设置启动菜单中显示的快照条目数量限制。
        ### 这取决于你的 FAT32 启动分区大小以及你想保留的不同内核和模块版本数量。
        ### 更大的 FAT32 启动分区允许更多快照条目。
        MAX_SNAPSHOT_ENTRIES=10
        ```
        可选地，调整快照名称格式：
        ```bash
        ### 快照名称格式
        ### 选择 Limine bootloader 中快照条目的显示格式：
        ### 0. ID=111 2023-12-20 10:59:59 (默认)
        ### 1. 111│2023-12-20 10:59:59
        ### 2. 111 │ 2023-12-20 10:59:59
        ### 3. 2023-12-20 10:59:59│111
        ### 4. 2023-12-20 10:59:59 │ 111
        ### 5. 2023-12-20 10:59:59
        ### 6. 111
        ### 7. 111│快照描述
        ### 8. 2023-12-20 10:59:59│快照描述
        ### 9. │快照描述
        SNAPSHOT_FORMAT_CHOICE=8
        ```
        `8` 是一个不错的选择，因为它显示日期时间和快照描述。
    3. 按 `CTRL+O` `Enter` `CTRL+X` 保存文件并退出
</Steps>

### 从快照恢复

:::caution
如果你想恢复的快照涉及内核更新，你将无法回滚。
:::
