### 保持耐心和尊重

CachyOS 团队和社区是由志愿者组成的，他们在空闲时间为此工作。与他们互动时请保持耐心和尊重。提供高质量的 bug 报告是快速解决问题的最佳方式。

如果您提出模糊的问题或提供的信息不足，那么您可能会得到模糊的回复甚至没有回复。

这里有一个例子：

- **好问题：**
  - 在最近一次更新后（我上次更新是在 DATE），我的系统无法启动，显示黑屏。我有一块 NVIDIA GPU（型号）。我尝试将 `linux-cachyos` 包降级到上一个版本，但问题仍然存在。以下是实时环境中 `journalctl -b -1` 和 `dmesg` 的输出。
- **不好或模糊的问题：**
  - 我的系统坏了，请帮我。

### 描述您的问题

这里有一些您应该问自己的事情：

- 什么不工作？
- 降级包 X 是否修复了问题？
- 其他人是否也遇到这个问题 / 以前是否解决过？（使用搜索功能）
- 问题是否出现在更新之后？
- 您是否自己进行了修改？
  - 例如：在 modprobe 文件中添加额外的标志
- 是否与硬件相关？（例如，GPU、Wi-Fi）
- 是否与软件相关？（例如，特定应用程序、桌面环境）
- 是新安装还是使用一段时间后出现的问题？

## 如何收集日志

有许多方法可以从系统中收集日志。以下是一些示例和您可以使用的工具：

### 创建一般 bug 报告
CachyOS 提供了一个很好的工具来收集系统日志，称为 `cachyos-bugreport.sh`。
此工具将收集以下日志：
  - `dmesg`
  - `journalctl`
  - `inxi`（收集硬件信息）

收集日志后，系统将提示用户决定是否将它们上传到我们的粘贴网站。

要运行此脚本，请在终端中输入以下命令并在报告中分享生成的链接：
  ```sh
  sudo cachyos-bugreport.sh
  ```

### 收集未启动程序的日志
图形程序无法启动的原因有很多。收集此类问题日志的最佳方法是使用终端运行该程序。这样，您可以查看可能有助于诊断问题的任何错误消息或输出。

例如，如果 Firefox 无法完全启动，请尝试从终端启动它并查看错误消息：
  ```sh
  firefox
  ```

:::tip
  如果您想将输出保存到文本文件以便于分享，可以像这样重定向输出：
    ```sh
    firefox &> firefox-log.txt
    ```
  记住在启动失败后按 `CTRL + C` 终止进程，以便终端将输出写入文件。
:::

### 检查 pacman 中最近更新的包。

要获取系统上最近更新的包列表，可以使用以下命令：

```bash
grep "\[ALPM\] upgraded" /var/log/pacman.log | tail -n 50
```

:::tip
调整 tail 的 `-n` 参数以获取更多或更少的行。
:::

### journalctl 和 dmesg 中导航的快捷键

使用 less 或人类可读模式时，浏览日志最常用的快捷键：

`ArrowUp & ArrowDown 或 J & K` 逐行向上或向下滚动。

`PageUp & PageDown 或 Ctrl + B/D` 每次滚动一页。

`G 或 Home` 跳转到日志开头。

`Shift + G 或 End` 跳转到日志末尾。

### 使用 journalctl 收集系统日志

`journalctl` 命令是一个极其有用的工具，用于查看系统日志。以下是一些最常用和最有用的命令组合。

#### 基本用法和常见示例

:::tip
组合多个选项以获得更具体的过滤。
:::

<details>
<summary>查看完整日志（从最旧到最新）：</summary>
```bash
journalctl
```
</details>

<details>
<summary>仅查看当前启动的日志：</summary>
```bash
journalctl -b
```
</details>

<details>
<summary>安全和认证问题：</summary>
```bash
journalctl -u sshd -u polkit -b -0 | grep -i "fail\|error\|denied"
```
查找认证失败和安全策略拒绝。
</details>

<details>
<summary>实时跟踪日志：</summary>
```bash
journalctl -f
```
:::tip
将其与其他过滤器结合使用。例如：
```bash
# 跟踪 Adguard Home 服务的日志：
journalctl -u adguardhome -f
```
:::
</details>

<details>
<summary>当前启动的音频问题：</summary>
```bash
journalctl --user -u pipewire -u pipewire-pulse -u wireplumber -b 0
```
查看音频服务的日志以排查声音问题。
</details>

<details>
<summary>内存（RAM）错误：</summary>
```bash
journalctl -k | grep -i "memory\|ram"
```
查找内存损坏或检测问题。
</details>

<details>
<summary>蓝牙问题：</summary>
```bash
# 从当前启动：
journalctl -u bluetooth -b 0
# 从上一次启动：
journalctl -u bluetooth -b -1
```
</details>

##### 基于时间的过滤
<details>

<summary>查看最近几分钟/几小时的日志：</summary>
```bash
journalctl --since "10 minutes ago"
journalctl --since "1 hour ago"
journalctl --since "2024-01-15 14:30:00"
```
</details>

<details>
<summary>查看特定时间范围的日志：</summary>
```bash
journalctl --since "09:00" --until "10:00"
```
</details>

##### 按优先级和服务或程序过滤

可能的优先级级别有：`debug`、`info`、`notice`、`warning`、`err`、`crit`、`alert`、`emerg`。

或使用数字：

`0` 等于 `emerg`

`1` 等于 `alert`

`2` 等于 `crit`

`3` 等于 `err`

`4` 等于 `warning`

`5` 等于 `notice`

`6` 等于 `info`

`7` 等于 `debug`。

<details>
<summary>仅显示错误、严重和紧急消息：</summary>
```bash
journalctl -p err..emerg
```
:::tip
您可以将这些与前面的示例结合使用：

例如：
```bash
journalctl -p err..emerg --since "9:00" --until "10:00"
```
:::
</details>

<details>
<summary>显示来自特定系统服务的日志：</summary>
```bash title='示例'
# 查看 NetworkManager 服务的日志：
journalctl -u NetworkManager
# 查看 GDM（GNOME Display Manager）服务的日志：
journalctl -u gdm
# 查看 SDDM（Simple Desktop Display Manager）服务的日志：
journalctl -u sddm
```
</details>

<details>
<summary>显示来自特定进程 ID（PID）的日志：</summary>
```bash
journalctl _PID=pid
# 示例：
journalctl _PID=3344
```
</details>

<details>
<summary>显示来自特定可执行文件的日志：</summary>
```bash
journalctl path/to/executable
# 示例：
journalctl /usr/bin/firefox
```
</details>

### 使用 journalctl 检查内核消息

:::note
何时使用 `journalctl -k` vs `dmesg`：

- `journalctl -k` 访问存储在 systemd journal 中的内核消息（如果配置则跨重启持久化，并提供更好的基于时间的过滤和 journal 功能集成。
- `dmesg` 读取当前内核环形缓冲区（易失性，重启后丢失）。
:::

<details>
<summary>基本内核消息查看：</summary>
```bash
journalctl -k
```
显示 journal 中的所有内核消息，相当于 `dmesg`，但是从 journal 的角度。
</details>

<details>
<summary>仅当前启动的内核消息：</summary>
```bash
journalctl -k -b 0
```
仅显示当前启动会话的内核消息。
</details>

<details>
<summary>上一次启动的内核消息：</summary>
```bash
journalctl -k -b -1
```
查看上一次启动的内核消息。对于诊断启动失败或崩溃很有用。
</details>

<details>
<summary>实时跟踪新内核消息：</summary>
```bash
journalctl -k -f
```
实时查看内核消息，非常适合监控硬件事件或驱动加载。
</details>

<details>
<summary>搜索特定驱动消息：</summary>
```bash
# 示例：
# GPU 相关消息：
journalctl -k | grep -i "nvidia\|amd\|intel"
# USB 设备消息：
journalctl -k | grep -i "usb\|pci"
```
</details>

<details>
<summary>基于时间的内核消息过滤：</summary>
```bash
journalctl -k --since "1 hour ago"
journalctl -k --since "09:00" --until "10:00"
```
查看特定时期的内核消息。
</details>

### 使用 dmesg 查看内核消息

`dmesg` 命令显示内核环形缓冲区，其中包含内核关于硬件检测、驱动初始化和系统事件的消息。

#### 基本用法和格式化

<details>
<summary>查看完整的内核消息缓冲区：</summary>
```bash
dmesg
```
</details>

<details>
<summary>以人类可读的时间戳查看：</summary>
```bash
dmesg -T
```
</details>

<details>
<summary>使用分页器查看以便阅读：</summary>
```bash
dmesg | less
```
</details>

#### 按优先级级别过滤

与 journalctl 类似，dmesg 允许按优先级级别过滤消息。

<details>
<summary>仅显示错误和严重消息：</summary>
```bash
dmesg -l err,crit,alert,emerg
```
可能的优先级级别有：`debug`、`info`、`notice`、`warning`、`err`、`crit`、`alert`、`emerg`。

或使用数字：

`0` 等于 `emerg`

`1` 等于 `alert`

`2` 等于 `crit`

`3` 等于 `err`

`4` 等于 `warning`

`5` 等于 `notice`

`6` 等于 `info`

`7` 等于 `debug`。
</details>

<details>
<summary>查看最新的内核消息：</summary>
```bash
dmesg -w
```
</details>

<details>
<summary>搜索特定硬件或驱动消息：</summary>
```bash
# 示例：
# 搜索 USB 相关消息：
dmesg | grep -i usb | less
# 蓝牙设备：
dmesg | grep -i bluetooth
# NVIDIA 相关：
dmesg | grep -i nvidia | less
# 初始化失败的设备：
dmesg | grep -i "error\|failed" | less
```
</details>

##### 使用 dmesg 排查特定问题的常见示例

<details>
<summary>USB 设备未被识别时：</summary>
```bash
dmesg -w | grep -i usb
```
然后插入设备并查看新消息。
</details>

<details>
<summary>GPU 初始化问题：</summary>
```bash
dmesg | grep -i "nvidia\|amd\|intel\|radeon\|drm\|gpu" | less
```
</details>

<details>
<summary>Wi-Fi 或网络适配器问题：</summary>
```bash
dmesg | grep -i "wlan\|wifi\|network\|firmware" | tail -20
```
检查是否有缺失的固件加载或阻止无线网卡工作的驱动错误。
</details>

<details>
<summary>HDD/SSD 检测问题：</summary>
```bash
dmesg | grep -i "sda\|sdb\|nvme\|scsi\|disk" | head -30
```
当存储设备未被检测或启动时显示错误时使用。
</details>

<details>
<summary>系统冻结或内核恐慌：</summary>
```bash
dmesg -T -l emerg,alert,crit,err | tail -30
```
检查系统崩溃或冻结前发生的严重内核消息。
</details>

<details>
<summary>内存（RAM）错误：</summary>
```bash
dmesg | grep -i "memory\|ram"
```
查找内存损坏、检测问题或 ECC 错误报告。
</details>

<details>
<summary>音频设备事件：</summary>
```bash
dmesg | grep -i "audio\|snd\|hda" | grep -i "error\|fail\|card"
```
检查声卡是否被正确检测以及驱动是否正确加载。
</details>

<details>
<summary>内核模块加载失败：</summary>
```bash
dmesg | grep -i "module\|init" | grep -i "error\|fail"
```
当特定硬件驱动未加载或初始化失败时使用。
</details>

<details>
<summary>硬件事件实时监控：</summary>
```bash
dmesg -w -l warn,err,crit,alert,emerg -T
```
在重现问题时持续查看新的重要内核消息。
</details>

<details>
<summary>BIOS/UEFI 和固件问题：</summary>
```bash
dmesg | grep -i "bios\|uefi\|firmware\|efi"
```
检查硬件固件与 Linux 内核之间的兼容性问题。
</details>

## 安装和实时环境

### 为什么 CachyOS 实时 ISO 仅包含 KDE Plasma？

我们选择将开发和精力专注于 KDE Plasma 桌面环境。这使我们能够在实时 ISO 上提供更精致、稳定和一致的用户体验。

实时环境主要用于安装 CachyOS 或使用 cachy-chroot 进行系统恢复。如需安全地**测试**其他桌面环境或窗口管理器，我们强烈建议在虚拟机（VM）中尝试它们。

### 为什么点击"启动安装程序"后安装程序需要很长时间才能启动？

:::caution
确保您有活跃的互联网连接，否则按下此按钮后不会发生任何事情。
:::

安装程序没有冻结。它正在运行必要的后台脚本来为您的系统准备安装。此过程确保您的系统密钥环和时钟是最新的，这有助于防止常见的安装问题。

[在 GitHub 上查看脚本](https://github.com/CachyOS/CachyOS-Live-ISO/blob/master/archiso/airootfs/usr/local/bin/calamares-online.sh)以更好地了解它的功能。
<Steps>
  1. 移除旧的密钥环文件。
  2. 将 Arch Linux 和 CachyOS 密钥环包更新到最新版本。
  3. 初始化并填充 pacman 密钥环。
  4. 启用网络时间同步。
  5. 检查系统的启动类型（UEFI 或 BIOS/MBR），以便根据类型提示用户选择引导加载器。
</Steps>

### 为什么我的安装卡在 33%

当安装程序难以下载包时会发生这种情况。这通常是网速非常慢或不稳定的迹象。请检查您的网络连接并重试。

## 引导加载器恢复

:::note
如果 `/boot` 分区被删除，请按照相应[分区方案](/zh/installation/installation_on_root#uefigpt)的步骤 5 创建一个新的。
:::

### 恢复引导加载器的步骤

:::tip
如果您不确定如何使用 `cachy-chroot`，请先参考 [CachyOS chroot 助手](/zh/features/cachy_chroot) 文档。
:::

<Steps>
    1. 启动到 CachyOS 实时 ISO。
    2. 打开终端并使用 `cachy-chroot` 命令 chroot 到已安装的系统。

        ```bash
        sudo cachy-chroot
        ```
        如果系统使用我们的预设 BTRFS，在提示符中输入 `y`：
         ```bash title='示例'
         Do you want to use CachyOS BTRFS preset to auto mount root subvolume? y
         Do you want to mount additional partitions? · yes
         Enter the mount point for additional partition (e.g. /boot) type 'skip' to cancel:
         # systemd-boot、Limine 或 rEFInd 输入 /boot
         # GRUB 输入 /boot/efi
         ```
    3. 根据已安装的引导加载器和系统类型（UEFI 或 MBR/BIOS）按照以下说明操作。
        <Tabs>
            <TabItem label='GRUB'>
                使用以下命令重新安装 GRUB：
                <Tabs>
                    <TabItem label='UEFI'>
                        ```bash
                        sudo grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=cachyos
                        ```
                    </TabItem>
                    <TabItem label='MBR/BIOS'>
                        ```bash
                        sudo grub-install --target=i386-pc /dev/sdX # 将 sdX 替换为您的磁盘，例如 sda
                        ```
                    </TabItem>
                </Tabs>
            </TabItem>
            <TabItem label='systemd-boot (仅 UEFI)'>
                使用以下命令重新安装 systemd-boot：
                ```bash
                sudo bootctl install
                ```
            </TabItem>
            <TabItem label='Limine'>
                使用以下命令重新安装 Limine：
                <Tabs>
                    <TabItem label='UEFI'>
                        ```bash
                        sudo limine-install
                        ```
                    </TabItem>
                    <TabItem label='MBR/BIOS'>
                        ```bash
                        sudo limine bios-install /dev/sdX # 将 sdX 替换为您的磁盘，例如 sda
                        ```
                    </TabItem>
                </Tabs>
            </TabItem>
            <TabItem label='rEFInd (仅 UEFI)'>
                使用以下命令重新安装 rEFInd：
                ```bash
                sudo refind-install
                ```
            </TabItem>
        </Tabs>
    4. 重新安装 CachyOS 内核：
        ```bash
        sudo pacman -Syu linux-cachyos linux-cachyos-headers
        ```
    5. 退出 cachy-chroot：
        ```bash
        exit
        ```
    6. 重启系统。
</Steps>

## 包管理和更新

### Pacman 故障排除

#### error: signature is invalid

此错误表示包的加密签名存在问题。通常由过时的镜像或系统上损坏的密钥环引起。

虽然镜像通常会在短时间内自行修复，但如果问题仍然存在，请尝试以下两种解决方案之一。

<Tabs>

<TabItem label='第一种解决方案：重新同步 Pacman 镜像'>

```sh
sudo pacman -Syu
```

</TabItem>

<TabItem label='第二种解决方案：评级您的镜像'>

```sh title='评级您的镜像'
sudo cachyos-rate-mirrors
```

</TabItem>

<TabItem label='第三种解决方案：重置密钥环'>

如果评级镜像不起作用，很可能是您的系统密钥环损坏了。

- 打开 CachyOS Hello 并导航到 **故障排除**。

#### error: 404 Not Found

此错误表示您尝试安装的包在当前镜像上不可用。这通常发生在您的本地包数据库与远程仓库不同步时。

**解决方案：**

运行以下命令以刷新包数据库并执行完整的系统升级。这将确保您的系统了解最新的可用包。

```sh
sudo pacman -Syu
# 然后再次尝试安装您想要的包。
```

#### error: could not remove

当 pacman 缓存包含系统无法自动管理的文件时会出现此错误。这是一个常见问题，可以轻松修复。

- 解决方案 1：使用 CachyOS Hello。
  - 最简单的修复方法是使用 CachyOS Hello。打开它并进入 **故障排除**，然后点击 **清除包缓存** 按钮。

- 解决方案 2：手动移除缓存。
  - 运行以下命令以从缓存中移除所有孤立包。
  ```sh
  sudo rm -r /var/cache/pacman/pkg/*
  ```

#### error: File is corrupted (invalid or corrupted package (PGP signature))

```sh
# 示例：
:: File /var/cache/pacman/pkg/python-charset-normalizer-3.4.0-1-any.pkg.tar.zst
is corrupted (invalid or corrupted package (PGP signature)).
```

此错误通常表示系统 pacman 密钥环有问题，密钥环用于验证包的真实性。以下命令将重置并重新填充密钥环以解决问题。

```sh
sudo rm -rf /etc/pacman.d/gnupg/
sudo pacman-key --init
sudo pacman-key --populate

sudo pacman-key --recv-keys F3B607488DB35A47 --keyserver keyserver.ubuntu.com
sudo pacman-key --lsign-key F3B607488DB35A47

sudo rm -R /var/lib/pacman/sync
```

如果上述方法不成功，则密钥环不是问题。可能是镜像有问题，因此您可以选择工作的镜像，然后运行以下命令清除缓存：

```sh
sudo cachyos-rate-mirrors
sudo pacman -Scc
```

#### error: unable to lock database

当另一个 pacman 进程已经在运行时会出现此错误，该进程会锁定数据库以防止损坏。如果前一个进程崩溃或被中断，锁定文件 `db.lck` 可能没有被移除。

- 解决方案 1：使用 CachyOS Hello
  - 最简单的修复方法是使用 CachyOS Hello 的 **故障排除** 选项卡中的 **移除 db 锁定** 功能

- 解决方案 2：手动移除锁定文件
  - 如果您不想使用 CachyOS Hello，可以手动移除锁定文件：

```sh
sudo rm /var/lib/pacman/db.lck
```

#### error: failed retrieving file ... Connection timed out

您可能会看到如下错误：

```text
# 示例错误：
error: failed retrieving file '...' from ... : Connection timed out
error: failed retrieving file '...' from ... : Couldn't resolve host name
error: failed retrieving file '...' from ... : The requested URL returned error: 526
```

这些错误几乎总是表示当前镜像存在问题。它们可能很慢、暂时宕机或从您的位置无法访问。

- 解决方案：修复此问题的最佳方法是使用更快、更可靠的镜像更新镜像列表。

```sh
sudo cachyos-rate-mirrors
# 之后，您可以使用以下命令更新系统：
sudo pacman -Syu
```

:::tip
`cachyos-rate-mirrors` 命令根据速度和同步状态测试可用的 CachyOS 镜像，然后用性能最佳的镜像更新镜像列表文件（`/etc/pacman.d/cachyos-mirrorlist`）。

建议定期运行它，尤其是在系统更新期间发现速度减慢时。
:::

#### warning: local is newer than...

当系统上的包版本比官方仓库中可用的版本更新时，会出现此警告。这可能是因为镜像过时、仓库中的包被降级或从其他来源安装了包。

- 解决方案：`pacman -Syuu` 命令执行完整的系统升级并允许降级，这将通过将本地包与仓库版本同步来修复警告。

```sh title='要移除此警告，执行以下命令：'
sudo pacman -Syuu
```

#### error: failed to commit transaction (conflicting files)

此错误表示 pacman 正在尝试安装或更新一个包含已存在于系统中的文件的包，这些文件来自不同的来源。这是一个内置的安全功能，以防止系统损坏。

- 解决方案：您可以通过手动移除冲突的文件来解决此问题。更多信息和解决方案，请参考 [Arch Wiki](https://wiki.archlinux.org/title/Pacman#%22Failed_to_commit_transaction_(conflicting_files)%22_error)。

```sh title='示例'
error: failed to commit transaction (conflicting files)
nvidia-utils: /usr/lib/environment.d/10-gsk.conf exists in filesystem
Errors occurred, no packages were upgraded.
 -> error installing repo packages
```

要修复此特定示例，您需要移除冲突的文件，然后再次运行更新命令。

```sh
sudo rm /usr/lib/environment.d/10-gsk.conf
```

#### ERROR: module not found: 'nvidia', 'nvidia_modeset', ...

```sh title='示例'
==> ERROR: module not found: 'nvidia'
==> ERROR: module not found: 'nvidia_modeset'
==> ERROR: module not found: 'nvidia_uvm'
==> ERROR: module not found: 'nvidia_drm'
```

**此错误的两个原因：**

1) 由于 chwd 中始终启用早期模块加载，mkinitcpio 始终期望存在 NVIDIA 模块；当这些模块缺失时会出现此错误。

2) 您可能缺少系统上其他已安装内核的 NVIDIA 模块。

```sh title='安装以下包以修复此错误'
sudo pacman -S nvidia
```

### 一般问题

#### 最近，我的系统启动时间变长了

由于此问题可能由许多不同原因引起。让我们从基础开始，通过检查 systemd-analyze 查看系统在哪里遇到问题：

打开终端并运行以下两个命令之一：

```sh
systemd-analyze blame
```

或：

```sh
systemd-analyze critical-chain
```

如果输出显示 `cachyos-rate-mirrors.service` 执行时间很长。那么您应该运行以下命令来屏蔽此服务，这将阻止它在启动时运行：

```sh
systemctl mask cachyos-rate-mirrors
systemctl mask cachyos-rate-mirrors.timer
```

#### CachyOS 的起源是什么，为什么叫"CachyOS"？

CachyOS 以"Cachy"调度器命名，这是 [cacULE 调度器](https://github.com/hamadmarri/cacule-cpu-scheduler)的原始名称，cacULE 是 Linux 内核的 CPU 调度器。

该项目起源于 2020-2021 年，当时 ptr1337（CachyOS 创始人之一）正在测试并与名为 Hamad 的开发者合作开发 cacULE 调度器。当他们决定创建一个基于 Arch Linux 的优化 Linux 发行版，并带有 x86-64-v3 优化包时，
他们以将他们联系在一起的调度器命名它为"CachyOS"。

#### -git 包的更新间隔是多少？

通常每周一一次，但可能有例外。

#### CachyOS 仓库中的 -bin 包是否享有相同的性能优化？

不。`-bin` 包是预编译的二进制文件，不包含 CachyOS 仓库中基于源代码的包相同的性能优化。

#### 如何禁用启动加载动画（Plymouth）

:::note[这可能解决某些系统上的黑屏问题，尤其是带有旧 NVIDIA GPU 的系统。]
:::

要禁用启动加载动画，您需要编辑[引导加载器配置](/zh/configuration/boot_manager_configuration)并添加以下内核参数：

```sh
plymouth.enable=0 disablehooks=plymouth
```

:::note[systemd-boot、GRUB 和 Limine 需要重新生成 initramfs 镜像]
systemd-boot：`sudo sdboot-manage gen`

GRUB：`sudo grub-mkconfig -o /boot/grub/grub.cfg`

Limine：`sudo limine-mkinitcpio`
:::

## 安全和最佳实践

### AUR 安全实践

AUR 提供了丰富的选择，但安全至关重要。以下是 CachyOS 系统安全使用 AUR 的简要指南。

* **理解 PKGBUILD：** 它是构建脚本。了解其结构、变量（`source`、`pkgname`）和函数（`build()`、`package()`）。
* **验证源链接：** 始终检查 `source` URL 是否指向官方项目网站或可信仓库。避免可疑或个人链接。
* **审查安装步骤：** 检查文件安装位置（`package()` 函数）以及是否有任何命令异常或触及敏感系统区域。还要检查 `.install` 脚本。
* **研究维护者：** 查看维护者在 AUR 上的历史记录，是否有任何过去的安全问题或可疑活动。
* **检查校验和和 PGP：** 绝对关键！确认所有校验和（SHA256、BLAKE2b 等）与上游匹配。如果可用，使用 PGP 签名（`validpgpkeys`）进行真实性验证。
* **对 `-bin` 包保持谨慎：** 这些使用预编译的二进制文件，意味着您无法检查源代码。对其来源和完整性进行最大程度的审查。
* **阅读社区评论：** 检查 AUR 页面评论中的警告、问题或其他用户的见解。
* **永远不要跳过完整性检查：** 使用 `--skipinteg` 或类似标志会绕过所有安全检查。不要这样做。
* **控制您的 AUR 助手：** 了解您的助手（yay、paru）如何工作。确保它向您显示 PKGBUILD 及其差异，或使用 `makepkg` 手动构建。
* **评估必要性：** 在安装之前，问问自己是否真的需要这个 AUR 包，或者是否存在官方仓库的替代方案。
* **保持系统更新：** 定期运行 `sudo pacman -Syu` 以确保所有系统组件（包括 `pacman` 和 `makepkg`）都有最新的安全补丁。

保持警惕，让您的基于 Arch 的系统保持安全！

### 选择 GUI 包管理器

虽然图形包管理器提供了便利，但某些包管理器已知会在滚动发布系统（如 CachyOS）上导致严重问题，应避免用于管理系统包。

- **Pamac：** 已知无法正确处理某些包管理任务，例如损坏系统包密钥环。这可能导致阻止您更新系统的 PGP 签名错误。
- **Discover（KDE）和 GNOME Software Center：** 这些应用商店使用 PackageKit 后端。虽然它们通常对管理 Flatpak 是安全的，但使用它们安装或更新**系统包**是有风险的。基于 PackageKit 的管理器也可能不稳定或容易崩溃，这可能在失败的交易后将系统置于损坏状态。

为了最大稳定性和可靠性，我们**强烈建议**通过命令行使用 `pacman` 管理系统包。

如果您更喜欢图形界面，GUI 前端如 **[Shelly](</zh/configuration/post_install_setup/#updating-the-system>)** 或 **CachyOS Package Installer** 被认为是安全的替代品，因为它们是 pacman 功能的更直接包装器。
