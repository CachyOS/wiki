    Instalace a odinstalace balíčků z AUR, oficiálních repozitářů, AppImage, Flatpak i místních balíčků, zobrazování podrobností o balíčcích, správa skupin balíčků a další.

<TabItem label="Použití Octopi (GUI)">

Octopi je grafický správce balíčků pro distribuce založené na Archu, který poskytuje pohodlný způsob správy balíčků a aktualizací.
Pro aktualizaci systému pomocí Octopi postupujte následovně:

<Steps>

1. Spusťte **Octopi** z nabídky aplikací.
2. V hlavním okně klikněte na tlačítko **Zkontrolovat aktualizace** (vlevo nahoře) a nyní vedle něj na **Aktualizace systému.**
3. Octopi zkontroluje dostupné aktualizace a nabídne vám jejich instalaci buď přímo v Octopi, nebo v terminálu.
4. Pro pokračování v aktualizaci klikněte na tlačítko **Použít**.
5. Octopi stáhne a nainstaluje aktualizace.
6. Po velké aktualizaci se doporučuje restartovat počítač **(zejména pokud bylo aktualizováno jádro)**.

</Steps>

</TabItem>

<TabItem label="Použití Pacmanu">

<Steps>

1. Otevřete emulátor terminálu (nebo stiskněte `ctrl + alt + t` – `mod + return` ve správci oken, např. Qtile).
2. Spusťte následující příkaz pro aktualizaci systému:

   ```sh
   sudo pacman -Syu
   ```
3. Po velké aktualizaci se doporučuje restartovat počítač **(zejména pokud bylo aktualizováno jádro)**.

</Steps>

</TabItem>

<TabItem label="Offline aktualizace systému">

*CachyOS podporuje offline aktualizace systému pomocí skriptu [`pacman-offline`](https://github.com/eworm-de/pacman-offline). To umožňuje vašemu systému stahovat aktualizace balíčků a aplikovat je při příštím restartu. (Ano, jako ve Windows)*

:::note
Nástroj `pacman-offline` se integruje s funkcí offline aktualizací systemd. Automaticky se stará o aktualizace jádra a načítání modulů.

Soubor `/etc/pacman.d/offline.conf` je klíčový pro správu toho, které balíčky jsou aktualizovány během běžných a offline aktualizací. Ujistěte se, že je správně nakonfigurován pro vaše požadované jádro, nebo přidejte balíčky, které chcete aktualizovat pouze během provádění pacman-offline a které mají být ignorovány při běžné aktualizaci. Příklad: `pacman -Syu`.

**Pokud povolíte časovač automatických aktualizací, již nebudete muset systém aktualizovat ručně.**
:::

<Steps>

1. **Nainstalujte balíček pacman-offline**

   ```bash
   sudo pacman -S pacman-offline
   ```

2. **Nastavte Pacman tak, aby četl ze samostatného seznamu ignorovaných balíčků.**

   :::note[Přidejte řádek za sekci [options]. Pro referenci se podívejte na příklad níže.]
   :::

   ```bash title='Přidejte následující řádek do souboru /etc/pacman.conf'
   Include = /etc/pacman.d/offline.conf
   ```
   *Příklad*
   ```bash
   # /etc/pacman.conf
   # REPOSITORIES
   #   - can be defined here or included from another file
   #   - pacman will search repositories in the order defined here
   #   - local/custom mirrors can be added here or in separate files
   #   - repositories listed first will take precedence when packages
   #     have identical names, regardless of version number
   #   - URLs will have $repo replaced by the name of the current repo
   #   - URLs will have $arch replaced by the name of the architecture
   #
   # Repository entries are of the format:
   #       [repo-name]
   #       Server = ServerName
   #       Include = IncludePath
   #
   # The header [repo-name] is crucial - it must be present and
   # uncommented to enable the repo.
   #
   # GENERAL OPTIONS
   [options]
   # zde mohou být další volby jako 'Color', 'CheckSpace' apod.
   Include = /etc/pacman.d/offline.conf
   ```
3. **Přidání jader CachyOS, aby je pacman ignoroval během běžných aktualizací**

   Nástroj `pacman-offline` používá tento soubor k určení, které balíčky ignorovat během tradičních aktualizací pacmanem.

   Příklad: když spustíte `sudo pacman -Syu`

   *Nahraďte obsah souboru `/etc/pacman.d/offline.conf` následujícím:*

   ```text
   # Jádra Arch Linuxu
   IgnorePkg = linux linux-headers linux-docs
   IgnorePkg = linux-lts linux-lts-headers linux-lts-docs
   IgnorePkg = linux-zen linux-zen-headers linux-zen-docs
   IgnorePkg = linux-hardened linux-hardened-headers linux-hardened-docs

   # Jádra CachyOS
   IgnorePkg = linux-cachyos linux-cachyos-headers linux-cachyos-nvidia-open linux-cachyos-zfs
   IgnorePkg = linux-cachyos-bmq linux-cachyos-bmq-headers linux-cachyos-bmq-nvidia-open linux-cachyos-bmq-zfs
   IgnorePkg = linux-cachyos-bore linux-cachyos-bore-headers linux-cachyos-bore-nvidia-open linux-cachyos-bore-zfs
   IgnorePkg = linux-cachyos-deckify linux-cachyos-deckify-headers linux-cachyos-deckify-nvidia-open linux-cachyos-deckify-zfs
   IgnorePkg = linux-cachyos-eevdf linux-cachyos-eevdf-headers linux-cachyos-eevdf-nvidia-open linux-cachyos-eevdf-zfs
   IgnorePkg = linux-cachyos-gcc linux-cachyos-gcc-headers linux-cachyos-gcc-nvidia-open linux-cachyos-gcc-zfs
   IgnorePkg = linux-cachyos-hardened linux-cachyos-hardened-headers linux-cachyos-hardened-nvidia-open linux-cachyos-nvidia-hardened-zfs
   IgnorePkg = linux-cachyos-lts linux-cachyos-lts-headers linux-cachyos-lts-nvidia-open linux-cachyos-lts-zfs
   IgnorePkg = linux-cachyos-rc linux-cachyos-rc-headers linux-cachyos-rc-nvidia-open linux-cachyos-rc-nvidia-open linux-cachyos-rc-zfs
   IgnorePkg = linux-cachyos-rt-bore linux-cachyos-rt-bore-headers linux-cachyos-rt-bore-nvidia-open
   IgnorePkg = linux-cachyos-server linux-cachyos-server-headers linux-cachyos-server-nvidia-open linux-cachyos-server-zfs
   ```

   *Nyní budou všechny tyto balíčky ignorovány při běžných aktualizacích, ale kontrolovány během přípravy na offline aktualizaci.*

3. **Spusťte přípravu na offline aktualizaci pouze jednou**

   ```bash title='Spusťte následující příkaz'
   sudo systemctl start pacman-offline-prepare.service
   ```
   Tento příkaz spustí pacman-offline jednou, synchronizuje databáze balíčků a stáhne aktualizace, ale nenainstaluje je.

</Steps>

*Pokud chcete, aby byl tento skript automatizovaný, postupujte podle následujících kroků:*

<Steps>

1. **Povolte časovač přípravy**

   Povolení `pacman-offline-prepare.timer` umožní systemd spouštět tento skript pro stahování aktualizací na denní bázi několik minut po každém spuštění systému.

   ```bash
   sudo systemctl enable pacman-offline-prepare.timer
   ```

2. **Restartujte systém:**

   Aktualizace budou nainstalovány během příštího restartu systému.

3. **(Volitelné) Automatické restarty systému:**

    Povolte `pacman-offline-reboot.timer` pro automatický restart systému, ve výchozím nastavení ve **3 hodiny ráno** (vašeho časového pásma), pokud jsou k dispozici čekající aktualizace. Mějte na paměti, že to není vždy přesně ve stejnou dobu kvůli zahrnutí `RandomizedDelaySec`, které je ve výchozím nastavení nastaveno na 2 hodiny.

    ```bash
    sudo systemctl enable pacman-offline-reboot.timer
    ```

    :::tip
    Můžete upravit soubor `pacman-offline-reboot.timer` a buď změnit čas, kdy chcete, aby se váš systém restartoval při čekajících aktualizacích, nebo zakázat náhodný časový plán.
    :::

</Steps>

</TabItem>

<TabItem label="Cachy-Update">

Fork projektu [Arch-Update](https://github.com/Antiz96/arch-update)

Nástroj pro upozorňování na aktualizace a jejich aplikaci pro Arch Linux, který vám pomáhá s důležitými úkony před a po aktualizaci.
Obsahuje dynamický a klikatelný applet v oznamovací oblasti pro snadnou integraci s jakýmkoli pracovním prostředím nebo správcem oken.

<details>
    <summary>Jak povolit Cachy-Update</summary>
    Povolte Cachy-Update v `CachyOS Hello > Apps/Tweaks > Cachy Update enabled`
</details>
<details>
    <summary>Jak zakázat Cachy-Update</summary>
        Zakažte Cachy-Update v `CachyOS Hello > Apps/Tweaks > Cachy Update disabled`
            :::tip
            Pokud si chcete Cachy-Update ponechat a pouze zakázat applet v oznamovací oblasti, otevřete terminál a spusťte následující příkazy:
            ```bash
            mkdir -p ~/.config/autostart
            echo -e "[Desktop Entry]\nHidden=true" > ~/.config/autostart/arch-update-tray.desktop
            ```
            Pokud si chcete ponechat povolený applet v oznamovací oblasti a jednoduše zakázat automatickou kontrolu aktualizací, spusťte následující příkaz:
            ```bash
            systemctl --user disable --now arch-update.timer
            ```
            :::
</details>

- Funkce:
  - Automatická kontrola a výpis dostupných aktualizací.
  - Kontrola nedávných novinek Arch Linuxu (s nabídkou jejich zobrazení, pokud nějaké jsou).
  - Kontrola osiřelých balíčků (s nabídkou jejich odstranění, pokud nějaké jsou).
  - Kontrola starých a odinstalovaných balíčků v mezipaměti (s nabídkou jejich odstranění, pokud nějaké jsou).
  - Kontrola čekající aktualizace jádra vyžadující restart (s nabídkou restartu, pokud je k dispozici).
  - Kontrola služeb vyžadujících restart po aktualizaci (s nabídkou jejich restartování, pokud nějaké jsou).
  - Podpora pro `sudo`, `sudo-rs`, `doas` a `run0`.

**Interval kontroly aktualizací:** `Jednou dvě minuty po spuštění a poté jednou denně s náhodným zpožděním jedné hodiny.`

- Jak změnit interval kontroly aktualizací:

```sh title='Spusťte následující příkaz'
systemctl --user edit --full arch-update.timer
# Tip: Můžete také použít jakýkoli textový editor dle vašeho výběru místo `nano`
# např. EDITOR=micro systemctl --user edit --full arch-update.timer
```

<details>
<summary>Výchozí obsah souboru:</summary>
    ```systemd
    [Timer]
    OnStartupSec=2min # Zkontroluje aktualizace dvě minuty po spuštění
    RandomizedDelaySec=1h # Jednohodinové náhodné zpoždění
    OnUnitActiveSec=1d # Zkontroluje aktualizace jednou denně
    ```
</details>
Hodnotu `OnUnitActiveSec` můžete v podstatě změnit na cokoli, co chcete. Například pokud chcete kontrolovat aktualizace každých 30 minut, změňte ji na `30m`, nebo každých 6 hodin na `6h`. Podrobnosti o nastavení časových intervalů naleznete v tomto [dokumentu](https://www.freedesktop.org/software/systemd/man/latest/systemd.time.html#Parsing%20Time%20Spans).

V případě, že chcete, aby Cachy-Update kontroloval nové aktualizace pouze jednou při spuštění systému, můžete řádek `OnUnitActiveSec` jednoduše úplně smazat.

Poděkování patří [Antizovi](https://github.com/Antiz96) za správu upstreamového projektu Arch-Update a za implementaci Cachy-Update.

### Konfigurace firewallu (ufw)
:::note
UFW je ve výchozím nastavení po instalaci povolen.
:::
Pro konfiguraci ufw postupujte následovně:

<Tabs>

<TabItem label="Zapnout">

```bash
sudo ufw enable
```

</TabItem>

<TabItem label="Vypnout">

```bash
sudo ufw disable
```

</TabItem>

<TabItem label="Povolit">

Ve výchozím nastavení ufw ignoruje příchozí a povoluje odchozí provoz; do firewallu můžete přidat konkrétní pravidla pro blokování nebo povolení určitých připojení.

```bash
# Příklad 1, povolení provozu ssh:
sudo ufw allow ssh
# Příklad 2, otevření portu 12345 pro provoz TCP a UDP:
sudo ufw allow 12345

# Text nebo číslo portu lze upravit podle potřeby, například 12345/udp pro povolení pouze provozu UDP nebo nahrazení ssh názvem programu
```

</TabItem>

<TabItem label="Zamítnout">

Ve výchozím nastavení ufw ignoruje příchozí a povoluje odchozí provoz; do firewallu můžete přidat konkrétní pravidla pro blokování nebo povolení určitých připojení.

```bash
# Příklad 1, zamítnutí provozu ssh:
sudo ufw deny ssh
# Příklad 2, uzavření portu 12345 pro provoz TCP a UDP:
sudo ufw deny 12345

# Text nebo číslo portu lze upravit podle potřeby, například 12345/udp pro zamítnutí pouze provozu UDP nebo nahrazení ssh názvem programu
```

</TabItem>

<TabItem label="Stav">

```bash
sudo ufw status verbose
```
:::tip
Pokud nechcete zapomenout, proč jste port otevřeli nebo zavřeli, přidejte k pravidlu komentář.
```bash
# Příklad 1, otevření portu 12345 pro provoz TCP a UDP s komentářem:
sudo ufw allow 12345 comment 'Example'
# Příklad 2, uzavření portu 6789 pro TCP s komentářem:
sudo ufw deny 6789/tcp comment 'Comments can have spaces'
```
:::
</TabItem>

</Tabs>

:::note
Buďte opatrní při konfiguraci pravidel firewallu, protože nesprávně nakonfigurovaná pravidla vás mohou odříznout od vlastního systému.
:::

:::note
Můžete jej také konfigurovat graficky pomocí sekce „Firewall“ v nastavení KDE Plasma.
:::

:::note
Změny pravidel allow/deny se projeví po restartování ufw. Pro okamžitý výsledek ufw zakažte a znovu povolte.
:::

### Správa AppImage aplikací

AppImage jsou přenosné aplikace, které běží na většině linuxových distribucí bez nutnosti instalace nebo oprávnění roota.

:::note[Všechny soubory AppImage vyžadují ke svému spuštění oprávnění ke spuštění.]
Oprávnění ke spuštění můžete nastavit pomocí následujícího příkazu:
```sh
chmod +x /path/to/your/appimage
```
Nebo klikněte pravým tlačítkem myši na soubor AppImage, přejděte do `Vlastnosti` > `Oprávnění` a zaškrtněte políčko `Je spustitelný` (nebo `Povolit spouštění souboru jako programu`).
:::

:::note[Před spuštěním AppImage aplikací se ujistěte, že máte v systému nainstalovaný FUSE (Filesystem in Userspace).]
```sh
sudo pacman -S fuse2
```
:::

Pro správu AppImage aplikací můžete použít [gearlever](https://github.com/mijorus/gearlever), který poskytuje snadný způsob, jak integrovat AppImage do vašeho systému.

`gearlever` je grafický nástroj, který zjednodušuje správu AppImage aplikací ve vašem systému. Integruje se s vaším pracovním prostředím, což usnadňuje spouštění i správu těchto aplikací.

Chcete-li nainstalovat gearlever, postupujte podle těchto kroků:

<Steps>
    1. Nainstalujte flatpak, pokud jej ještě nemáte:
        ```sh
        sudo pacman -S flatpak
        ```
    2. Restartujte systém.
    3. Nainstalujte gearlever pomocí flatpaku:
        ```sh
        flatpak install flathub it.mijorus.gearlever
        ```
    4. Po instalaci se odhlaste a znovu přihlaste, abyste gearlever viděli v nabídce aplikací.
</Steps>

### Konfigurace přístupu ke sdíleným složkám Samba

Samba je svobodná softwarová reimplementace síťového protokolu SMB. Pro připojení k vašemu serveru Samba byla uživatelům CachyOS zpřístupněna užitečná konfigurace, která však vyžaduje úpravu konfigurace vašeho serveru Samba.

#### Instalace a použití souboru smb.conf z CachyOS

Chcete-li použít tento praktický soubor `smb.conf`, nejprve nainstalujte příslušný balíček, který požadovaný `smb.conf` poskytuje. Poté tímto souborem nahraďte stávající `smb.conf` na vašem serveru a znovu nakonfigurujte své sdílené svazky.

:::note[Tento průvodce předpokládá, že již máte funkční server Samba]
:::

<Steps>
    1. Vytvořte zálohu původního souboru `smb.conf`, který se na linuxových systémech obvykle nachází v `/etc/samba/smb.conf`.
    2. Nainstalujte balíček nastavení Samba pro CachyOS na vašem klientském počítači:
        ```sh
        sudo pacman -S cachyos-samba-settings
        ```
    3. Zkopírujte soubor `smb.conf` z vašeho klientského počítače na server Samba.
    4. Otevřete a upravte soubor tak, aby obsahoval vaše sdílené adresáře, tiskárny atd.
    5. Restartujte službu Samba na vašem serveru:
        ```sh
        sudo systemctl restart --now samba
        ```
    6. Na klientském počítači přistupujte ke svým sdíleným prostředkům prostřednictvím správce souborů (např. `smb://<your_server_ip>/<share_name>`).

        Pokud je vše správně nakonfigurováno, budete vyzváni k zadání přihlašovacích údajů. Nezapomeňte případně vybrat možnost uložení přihlašovacích údajů.
</Steps>

### Podpora AppArmor pomocí profilů AppArmor.d

Citát z Wikipedie:

*AppArmor („Application Armor“) je bezpečnostní modul linuxového jádra, který umožňuje správci systému omezit oprávnění programů pomocí profilů pro jednotlivé programy. Profily mohou povolit schopnosti, jako je přístup k síti, přístup k raw soketům a oprávnění ke čtení, zápisu nebo spouštění souborů na odpovídajících cestách.*

Toto je pouze úvod do instalace základního nastavení AppArmor. Pokud AppArmor neznáte, nepokračujte, aniž byste chápali dopady tohoto nastavení.

Podrobnější informace o AppArmor.d a o tom, jak vytvářet vlastní profily, najdete v [dokumentaci AppArmor.d](https://github.com/roddhjav/apparmor.d?tab=readme-ov-file#configuration).

:::caution[Postupujte opatrně. Špatně nakonfigurovaný AppArmor může způsobit problémy.]
:::

<Steps>

1. Přidejte následující parametry jádra do vašeho zavaděče, viz [Konfigurace zavaděče](/cs/configuration/boot_manager_configuration) pro referenci:

   ```text
   lsm=landlock,lockdown,yama,integrity,apparmor,bpf
   ```

2. Nainstalujte balíčky apparmor a apparmord **(sada více než 1500 profilů)**:
   ```bash
   sudo pacman -S apparmor apparmor.d
   ```

3. Povolte a spusťte službu AppArmor:

   ```bash
   systemctl enable --now apparmor.service
   ```

4. Povolte cachování pro profily AppArmor:

   ```shell
   # /etc/apparmor/parser.conf
   ## Přidejte následující řádky:
   write-cache
   Optimize=compress-fast
   cache-loc /etc/apparmor/earlypolicy/
   ```
   Uložte soubor a restartujte.
</Steps>

### Povolení příkazu TRIM na šifrovaných zařízeních (LUKS)

CachyOS ve výchozím nastavení povoluje `fstrim.timer` pro pravidelné provádění příkazu TRIM na discích SSD a NVMe, což pomáhá udržovat výkon zápisu a životnost disku. Šifrovací vrstva linuxového device-mapperu (`dm-crypt`/LUKS) však příkazy discard (TRIM) ve výchozím nastavení blokuje. V důsledku toho pravidelný TRIM probíhá tiše bez provedení TRIM na šifrovaných oddílech, pokud není předávání příkazů discard výslovně povoleno.

:::caution[Bezpečnostní aspekty a ochrana soukromí]
Povolení příkazu TRIM na šifrovaném zařízení umožňuje řadiči podkladového SSD zjistit, které sektory jsou prázdné a které obsahují data. Ačkoli vaše data zůstávají plně šifrovaná, útočník s fyzickým přístupem k surovému úložišti by mohl odvodit přibližně využité místo na disku, rozložení souborového systému nebo datové vzorce.

Pokud je tento únik metadat pro váš model hrozeb přijatelný, můžete předávání příkazů discard bezpečně povolit pro lepší výkon SSD a životnost disku.
:::

#### Povolení předávání příkazů discard (LUKS2)

<Steps>
1. Zjistěte název svého aktivního mapování LUKS:

   ```bash
   lsblk
   ```

   Hledejte položku typu `crypt` pod vaším diskovým oddílem (např. `luks-1e647929-62c0-4922-8944-f941ed4155fd`).

2. Povolte trvalé předávání příkazů discard pro aktivní mapování LUKS:

   ```bash
   sudo cryptsetup --allow-discards --persistent refresh <mapper_name>
   ```

   :::note
   Nahraďte `<mapper_name>` vaším skutečným názvem mapování nalezeným v kroku 1 (například `sudo cryptsetup --allow-discards --persistent refresh luks-1e647929-62c0-4922-8944-f941ed4155fd`).
   :::

3. Restartujte systém, aby se změny projevily.

4. Ověřte, že předávání příkazů discard je aktivní:

   ```bash
   lsblk -D
   sudo fstrim -v /
   ```

   Příkaz `lsblk -D` by nyní měl u vašeho šifrovaného svazku zobrazit nenulové hodnoty ve sloupcích `DISC-GRAN` a `DISC-MAX` a `fstrim` vypíše množství ořezaného místa místo toho, aby zařízení přeskočil.
</Steps>
