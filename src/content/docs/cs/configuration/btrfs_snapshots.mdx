## Úvod

:::caution
Nepovažujte snímky Btrfs za náhradu pravidelných záloh. Vždy se ujistěte, že máte řádné zálohy svých důležitých dat.
:::

### Co je to snímek Btrfs?

Začněme od základů:

Snímky Btrfs vycházejí z funkce subvolumů (podsvazků). Možná se ptáte, co je to subvolum? Představte si subvolum jako samostatný souborový systém uvnitř souborového systému Btrfs, který vám umožňuje rozdělit data na různé části. Proto máme například v CachyOS různé subvolumy pro:

- Kořenový souborový systém: (`/`)
- Adresář root: (`/root`)
- Domovský adresář: (`/home`)
- Adresáře var: (`/var/cache`, `/var/tmp`, `/var/log`)
- Adresář srv: (`/srv`)

Tím, že máme pro tyto adresáře samostatné subvolumy, je můžeme spravovat nezávisle na sobě, aplikovat na ně různá nastavení a především pro ně vytvářet snímky.

Zde přichází na řadu snímek. Snímek je v podstatě kopie subvolumu určená pouze ke čtení nebo ke čtení i zápisu (**výchozí**) v určitém časovém okamžiku. To znamená, že můžete zachytit stav svého souborového systému, včetně všech souborů a adresářů, přesně v danou chvíli.

Snímky se tak stávají referenčním bodem v čase – když se cílový soubor od dat ve snímku odchýlí, snímek si zachová původní soubor a v cíli se vytvoří nový soubor se změnami, zatímco snímek zůstane navždy stejný. Proto někteří uživatelé označují snímek jako „data zmrazená v čase“.

Představte si to jako vyfocení vašeho souborového systému v konkrétním okamžiku – k této fotografii se pak můžete kdykoli vrátit, kdykoli to budete potřebovat.

Jednou z hlavních výhod snímků je jejich vysoká úspornost místa, protože jde pouze o odkaz na původní data, dokud nedojde ke změnám.

Právě v tom se však snímek liší od tradiční zálohy. Řekněme, že vám selže disk – pokud byste měli tradiční zálohu, mohli byste z ní svá data obnovit. Pokud byste ale měli pouze snímky na poškozeném disku, ztratili byste k nim přístup, protože jsou uloženy na stejném disku.

### Případy obnovy, kdy jsou snímky užitečné a kdy nikoli

Jsou užitečné pro obnovu po:

- Rozbití nebo poškození systému po aktualizacích.
- Chybných konfiguracích, které brání spuštění systému.
- Náhodném smazání nebo úpravě souborů.

Nejsou užitečné pro obnovu při:

- Problémech se zavaděčem (bootloaderem).
- Hardwarových selháních (např. porucha pevného disku).

## Správa snímků (GUI a CLI)

:::tip
Protože CachyOS ve výchozím nastavení obsahuje `snap-pac`, Snapper automaticky vytváří snímky před a po každé instalaci, aktualizaci nebo odebrání balíčku pomocí `pacman`. To znamená, že pro tyto operace nemusíte snímky vytvářet ručně, protože se o to Snapper postará za vás.
:::

:::note
Pokud používáte zavaděč GRUB, ujistěte se, že máte nainstalovaný balíček `grub-btrfs-support`, abyste měli k dispozici všechny potřebné skripty a hooky pro automatickou detekci snímků BTRFS a jejich přidání do nabídky GRUB.
```bash
sudo pacman -Syu grub-btrfs-support
```
:::

Několik věcí, které je dobré zvážit před správou snímků. **Platí pro metody v CLI i GUI.**

- Doporučuje se uchovávat maximálně 10 snímků. Nad tento počet bývají snímky příliš staré a méně užitečné. V nejhorším případě může návrat ke starému snímku způsobit problémy s kompatibilitou s novějšími verzemi softwaru.
- Snímky jsou primárně určeny pro účely obnovy. Můžete je však také použít k vrácení změn v jednotlivých souborech bez nutnosti obnovovat celý snímek.
- Při vytváření snímků přidávejte smysluplný popis. Pomůže vám to později snáze určit účel každého snímku.

### Btrfs Assistant (GUI)

Než budete pokračovat, ujistěte se, že máte nainstalovaný balíček `btrfsmaintenance`, abyste mohli využívat funkce automatické správy snímků.

Pro ty, kteří dávají přednost správě Btrfs, snímků a dalších funkcí přes grafické rozhraní (GUI), je [Btrfs Assistant](https://gitlab.com/btrfs-assistant/btrfs-assistant) skvělým projektem pro začátečníky.

#### Nastavení automatického čištění snímků

Nastavíme automatické čištění snímků pomocí programu Btrfs Assistant. To vám pomůže efektivně spravovat snímky bez ručního zásahu.

Postupujte podle následujících kroků:

<Steps>

    1. Spusťte Btrfs Assistant otevřením terminálu a zadáním příkazu:
        ```bash
        btrfs-assistant-launcher
        ```

        Případně:

        ```bash
        sudo -E btrfs-assistant
        ```

  2. Přejděte na kartu Snapper Settings:

      <ImageComponent imgsrc={import('~/assets/images/btrfs-maintenance-snapperSettingsTab.png')} />
      Upravte nastavení **Snapshot Retention** následujícím způsobem:
      - Ujistěte se, že je vybrána konfigurace `root`
      - Zadejte hodnotu `0` pro Hourly, Daily, Weekly, Monthly a Yearly.
      - Odškrtněte `Enable timeline snapshots`.
      - Zadejte hodnotu `10` do pole `Number`.
      - Zaškrtněte ✅ `Snapper cleanup enabled`.
      - Klikněte na tlačítko `Save` vpravo nahoře a `Apply systemd changes` vpravo dole.
      **snapper-cleanup.timer bude nyní povolen, aby automaticky čistil staré snímky podle vaší konfigurace.**
      :::caution
      Ověřte, zda byly provedené úpravy správně použity, kontrolou konfigurace Snapperu:
      ```bash
      sudo nano /etc/snapper/configs/root
      ```
      Očekávaná ukázka výstupu:
      ```text
      # limit for number cleanup
      NUMBER_MIN_AGE="3600"
      NUMBER_LIMIT="10"
      NUMBER_LIMIT_IMPORTANT="10"
      ```
      Pokud `NUMBER_LIMIT` a `NUMBER_LIMIT_IMPORTANT` neobsahují hodnotu `10`, odpovídajícím způsobem je upravte.
      Uložte soubor a ukončete editor stisknutím `CTRL + O`, `Enter` a `CTRL + X`.
      :::
</Steps>

#### Odstranění snímků pomocí Btrfs Assistant

<Steps>
    1. Otevřete Btrfs Assistant:
        ```bash
        btrfs-assistant-launcher
        ```

        Případně:

        ```bash
        sudo -E btrfs-assistant
        ```
    2. Přejděte na kartu Snapper Settings:
        <ImageComponent imgsrc={import('~/assets/images/btrfs-maintenance-snapperTab.png')} />
    3. Vyberte ze seznamu snímek nebo snímky, které chcete odstranit.
        :::tip
        - Podržením klávesy `CTRL` můžete vybrat více snímků.
        - Podržením klávesy `SHIFT` můžete vybrat celý rozsah snímků.
        :::
    4. Klikněte na tlačítko `Delete` v horní části okna.
    5. Znovu vygenerujte položky zavaděče, aby se změny projevily:

        </details>
</Steps>

### Snapper (CLI)

Nyní, když jsme si probrali, co je snímek Btrfs a jaké jsou jeho případy použití, pojďme se podívat, jak je spravovat pomocí nástroje [Snapper](http://snapper.io/), který vytvořil [Arvin Schnell](https://github.com/aschnell) z projektu [openSUSE](https://www.opensuse.org/).

<details>
<summary>CachyOS ve výchozím nastavení používá následující konfiguraci Snapperu:</summary>

```text
# subvolume to snapshot
SUBVOLUME="/"

# filesystem type
FSTYPE="btrfs"

# btrfs qgroup for space aware cleanup algorithms
QGROUP=""

# fraction or absolute size of the filesystems space the snapshots may use
SPACE_LIMIT="0.5"

# fraction or absolute size of the filesystems space that should be free
FREE_LIMIT="0.2"

# users and groups allowed to work with config
ALLOW_USERS=""
ALLOW_GROUPS=""

# sync users and groups from ALLOW_USERS and ALLOW_GROUPS to .snapshots
# directory
SYNC_ACL="no"

# start comparing pre- and post-snapshot in background after creating
# post-snapshot
BACKGROUND_COMPARISON="yes"

# run daily number cleanup
NUMBER_CLEANUP="yes"

# limit for number cleanup
NUMBER_MIN_AGE="1800"
NUMBER_LIMIT="50"
NUMBER_LIMIT_IMPORTANT="15"

# create hourly snapshots
TIMELINE_CREATE="no"

# cleanup hourly snapshots after some time
TIMELINE_CLEANUP="yes"

# limits for timeline cleanup
TIMELINE_MIN_AGE="1800"
TIMELINE_LIMIT_HOURLY="5"
TIMELINE_LIMIT_DAILY="7"
TIMELINE_LIMIT_WEEKLY="0"
TIMELINE_LIMIT_MONTHLY="0"
TIMELINE_LIMIT_YEARLY="0"

# cleanup empty pre-post-pairs
EMPTY_PRE_POST_CLEANUP="yes"

# limits for empty pre-post-pair cleanup
EMPTY_PRE_POST_MIN_AGE="1800"
```

</details>

:::caution
Výchozí konfigurace Snapperu v CachyOS pokrývá pouze kořenový subvolum (`/`). Pokud máte další subvolumy, které chcete pomocí Snapperu spravovat, budete muset pro každý z nich vytvořit samostatnou konfiguraci.

Tato konfigurace vyžaduje úpravu, aby se zvýšila její efektivita.
:::

            - empty-pre-post: Odstraňuje páry snímků pre/post s prázdnými rozdíly (diffy).
        - `Description`: Stručný popis snímku, který často udává důvod jeho vytvoření.
        - `Userdata`: Další uživatelsky definovaná data spojená se snímkem.
        Další podrobnosti o výstupních sloupcích

### Doporučení a tipy pro Limine

#### Úprava nastavení zobrazení snímků v zavaděči Limine

- Omezte počet snímků zobrazovaných v nabídce zavaděče Limine, aby nedocházelo k nepřehlednosti:

<Steps>
    1. Vytvořte zálohu konfiguračního souboru limine-snapper-sync:
        ```bash
        sudo cp /etc/limine-snapper-sync.conf /etc/limine-snapper-sync.conf.orig
        ```
    2. Upravte konfigurační soubor limine-snapper-sync:
        ```bash
        sudo nano /etc/limine-snapper-sync.conf
        ```
        Očekávaná ukázka výstupu:
        ```bash
        ### Max Snapshot Entries
        ### Sets the limit for how many snapshot entries show up in the boot menu.
        ### This depends on the size of your FAT32 boot partition and how many different kernel and module versions you want to keep.
        ### A larger FAT32 boot partition allows more snapshot entries.
        MAX_SNAPSHOT_ENTRIES=10
        ```
        Volitelně upravte formát názvu snímku (Snapshot Name Format):
        ```bash
        ### Snapshot Name Format
        ### Choose a format for how snapshot entries look in the Limine bootloader:
        ### 0. ID=111 2023-12-20 10:59:59 (default)
        ### 1. 111│2023-12-20 10:59:59
        ### 2. 111 │ 2023-12-20 10:59:59
        ### 3. 2023-12-20 10:59:59│111
        ### 4. 2023-12-20 10:59:59 │ 111
        ### 5. 2023-12-20 10:59:59
        ### 6. 111
        ### 7. 111│snapshot description
        ### 8. 2023-12-20 10:59:59│snapshot description
        ### 9. │snapshot description
        SNAPSHOT_FORMAT_CHOICE=8
        ```
        `8` je dobrá volba, protože zobrazuje datum a čas spolu s popisem snímku.
    3. Uložte soubor a ukončete editor stisknutím `CTRL+O` `Enter` `CTRL+X`
</Steps>
