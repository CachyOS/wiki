Πέρα από τους βελτιστοποιημένους πυρήνες και τα αποθετήριά μας, παρέχουμε επίσης ρυθμίσεις που βελτιώνουν περαιτέρω την εμπειρία χρήσης στην επιφάνεια εργασίας, καθώς και ορισμένα βοηθητικά σενάρια για βελτιώσεις ευκολίας χρήσης (QoL). Όλες αυτές οι διαμορφώσεις και τα σενάρια βρίσκονται στο πακέτο `cachyos-settings`.

Ρίξτε μια ματιά στο [αποθετήριο CachyOS Settings](https://github.com/CachyOS/CachyOS-Settings?tab=readme-ov-file#cachyos-settings) για να διαβάσετε περισσότερα σχετικά με όλες τις διαμορφώσεις και τα σενάρια που παρέχουμε.

## Σενάρια και εργαλεία

### DLSS Swapper

Μπορεί να σας φανεί χρήσιμο σε ορισμένες περιπτώσεις, ειδικά για την έκδοση του Proton που παρέχεται από τη Valve.

:::note
Το Proton-CachyOS παρέχει ήδη ενσωματωμένη λειτουργία αναβάθμισης.
:::

:::caution
Μην συνδυάζετε τα `PROTON_DLSS_UPGRADE=1` και `dlss-swapper` ταυτόχρονα, καθώς κάνουν το ίδιο πράγμα και ενδέχεται να προκαλέσουν διενέξεις.
:::

Αυτό που κάνει είναι να προσπαθεί να ενημερώσει τα αρχεία DLL και τις προεπιλογές του DLSS στην πιο πρόσφατη διαθέσιμη έκδοση, κάτι που μπορεί να είναι χρήσιμο για ορισμένα παιχνίδια που απαιτούν μια συγκεκριμένη έκδοση του DLSS για να λειτουργήσουν σωστά.

Πώς; Εισάγοντας μεταβλητές περιβάλλοντος στη διεργασία του παιχνιδιού:

<details>
    <summary>Μεταβλητές περιβάλλοντος του dlss-swapper</summary>
    ```sh
    export PROTON_ENABLE_NGX_UPDATER=1
    export DXVK_NVAPI_DRS_NGX_DLSS_RR_OVERRIDE=on
    export DXVK_NVAPI_DRS_NGX_DLSS_SR_OVERRIDE=on
    export DXVK_NVAPI_DRS_NGX_DLSS_FG_OVERRIDE=on
    export DXVK_NVAPI_DRS_NGX_DLSS_RR_OVERRIDE_RENDER_PRESET_SELECTION=render_preset_latest
    export DXVK_NVAPI_DRS_NGX_DLSS_SR_OVERRIDE_RENDER_PRESET_SELECTION=render_preset_latest
    ```
</details>
<details>
    <summary>Μεταβλητές περιβάλλοντος του dlss-swapper-dll</summary>
    ```sh
    export DXVK_NVAPI_DRS_NGX_DLSS_RR_OVERRIDE=on
    export DXVK_NVAPI_DRS_NGX_DLSS_SR_OVERRIDE=on
    export DXVK_NVAPI_DRS_NGX_DLSS_FG_OVERRIDE=on
    export DXVK_NVAPI_DRS_NGX_DLSS_RR_OVERRIDE_RENDER_PRESET_SELECTION=render_preset_latest
    export DXVK_NVAPI_DRS_NGX_DLSS_SR_OVERRIDE_RENDER_PRESET_SELECTION=render_preset_latest
    ```
</details>

- Ποια είναι η διαφορά μεταξύ του `dlss-swapper` και του `dlss-swapper-dll`;
    - Το `dlss-swapper` ενημερώνει τα αρχεία DLL και τις προεπιλογές του DLSS στις πιο πρόσφατες διαθέσιμες εκδόσεις που παρέχονται από το NGX Updater, ενώ το `dlss-swapper-dll` βασίζεται στα αρχεία DLL που βρίσκονται ήδη στον κατάλογο του παιχνιδιού.


### [game-performance](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/bin/game-performance)

Μικρό σενάριο που ενεργοποιεί το προφίλ επιδόσεων από το `powerprofilesctl` για τη διεργασία-στόχο (μπορεί να χρησιμοποιηθεί για παιχνίδια ή οποιαδήποτε άλλη διεργασία) και απενεργοποιεί την προφύλαξη οθόνης όσο εκτελείται η διεργασία.

Ερωτήσεις και απαντήσεις:

<details>
    <summary>Οδηγίες χρήσης</summary>
    Ας υποθέσουμε ότι θέλετε να χρησιμοποιήσετε το `game-performance` για ένα παιχνίδι στο Steam. Μπορείτε να το κάνετε προσθέτοντας την εντολή `game-performance` ως επιλογή εκκίνησης για το παιχνίδι στο Steam:
        <Steps>
            1. Ανοίξτε το Steam και μεταβείτε στη Συλλογή (Library) σας.
            2. Κάντε δεξί κλικ στο παιχνίδι με το οποίο θέλετε να χρησιμοποιήσετε το `game-performance` και επιλέξτε «Ιδιότητες» (Properties).
            3. Στην καρτέλα «Γενικά» (General), εντοπίστε την ενότητα «Επιλογές εκκίνησης» (Launch Options) και προσθέστε την εξής εντολή:
                ```sh
                game-performance %command%
                ```
                :::tip[Οδηγός διαχείρισης επιλογών εκκίνησης στο Steam]
                Wiki του CachyOS - [Σωστός ορισμός πολλαπλών επιλογών εκκίνησης](/el/configuration/gaming#σωστός-ορισμός-πολλαπλών-επιλογών-εκκίνησης)
                :::
            4. Κλείστε το παράθυρο ιδιοτήτων και εκκινήστε το παιχνίδι.
        </Steps>
        <details>
            <summary>Χρήση εκτός του Steam</summary>
            Εφόσον το `game-performance` είναι απλώς ένα σενάριο περιτύλιξης (wrapper script), μπορείτε να το χρησιμοποιήσετε για να εκκινήσετε οποιαδήποτε διεργασία με ενεργοποιημένο το προφίλ επιδόσεων. Απλώς εκτελέστε την εξής εντολή στο τερματικό:
            ```sh
            game-performance <command>
            ```
        </details>
</details>

<details>
    <summary>Προσφέρει το game-performance κάποιο όφελος σε έναν παλαιότερο επεξεργαστή (CPU);</summary>
    Γενικά όχι. Θα πρέπει να το αποφεύγετε σε παλαιότερους επεξεργαστές, καθώς μπορεί να προκαλέσει περισσότερα προβλήματα παρά όφελος.

    Ως μια γενική κατευθυντήρια γραμμή, η χρήση του `game-performance` σε οτιδήποτε κάτω από έναν επεξεργαστή 6 πυρήνων / 12 νημάτων (6-core/12-thread) πιθανότατα δεν θα αυξήσει ή μπορεί ακόμη και να μειώσει τις επιδόσεις. Όπως ισχύει για τις περισσότερες επιλογές, θα πρέπει να δοκιμάσετε οι ίδιοι εάν βελτιώνει τις επιδόσεις στο δικό σας σύστημα.
      - Για επιτραπέζιους επεξεργαστές Intel, το κατά προσέγγιση όριο είναι η 8η γενιά (Coffee Lake) για επεξεργαστές i7 και i9 και η 10η γενιά (Comet Lake) για επεξεργαστές i5. Όλοι οι επεξεργαστές Intel Ultra θα πρέπει να λειτουργούν.
      - Για επιτραπέζιους επεξεργαστές AMD, το όριο είναι η σειρά 1000 (Zen) για επεξεργαστές Ryzen 7 και Ryzen 9. Για τους επεξεργαστές Ryzen 5 είναι επίσης η σειρά 1000, αλλά μόνο από τον Ryzen 5 1600 και πάνω. Αυτό ισχύει μέχρι τη σειρά 5000 (Zen 3), όπου πλέον όλοι οι επεξεργαστές Ryzen 5 διαθέτουν 6 πυρήνες και 12 νήματα.
      - Οι επιτραπέζιοι επεξεργαστές Intel i3 και Ryzen 3 δεν διαθέτουν ποτέ περισσότερους από τέσσερις πυρήνες.
      - Ο αριθμός πυρήνων για επεξεργαστές φορητών υπολογιστών, σταθμών εργασίας και διακομιστών διαφέρει σημαντικά, οπότε ερευνήστε τι διαθέτει το σύστημά σας και δοκιμάστε διαφορετικές ρυθμίσεις — αυτό είναι το μισό της διασκέδασης του να έχει κανείς υλικό υπολογιστή!
</details>

<details>
    <summary>Γιατί δεν είναι ενεργοποιημένο από προεπιλογή;</summary>
    Η ενεργοποίηση του προφίλ επιδόσεων ενδέχεται να μην είναι ιδανική για όλους τους χρήστες και μπορεί να προκαλέσει αυξημένη κατανάλωση ενέργειας και παραγωγή θερμότητας. Μην ενεργοποιώντας το από προεπιλογή, δίνουμε στους χρήστες την επιλογή να το ενεργοποιούν όταν το χρειάζονται, χωρίς να το επιβάλλουμε σε όλους.
</details>

### [paste-cachyos](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/bin/paste-cachyos)

Ένα απλό εργαλείο γραμμής εντολών (CLI) που σας επιτρέπει να ανεβάζετε κείμενο στην [υπηρεσία pastebin](https://paste.cachyos.org) μας. Μπορεί να είναι χρήσιμο για την κοινοποίηση αρχείων καταγραφής (logs) και άλλου περιεχομένου κειμένου όταν αναφέρετε σφάλματα ή ζητάτε βοήθεια.

Για να χρησιμοποιήσετε το `paste-cachyos`, πρέπει να διοχετεύσετε (pipe `|`) το περιεχόμενο που θέλετε να ανεβάσετε στην εντολή.

:::

Ακολουθούν ορισμένα παραδείγματα χρήσης του `paste-cachyos`:

### [pci-latency](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/bin/pci-latency)

Ένα απλό σενάριο που στοχεύει στη μείωση της καθυστέρησης (latency) και στη βελτίωση των επιδόσεων για κάρτες ήχου PCI, αλλάζοντας το χρονόμετρο καθυστέρησης PCI (PCI latency timer).

Διατίθεται τόσο σε μορφή εκτελέσιμου αρχείου όσο και ως υπηρεσία systemd. Η υπηρεσία systemd θα εφαρμόζει αυτόματα τις αλλαγές κατά την εκκίνηση, ενώ το εκτελέσιμο αρχείο μπορεί να χρησιμοποιηθεί για την εφαρμογή των αλλαγών κατ' απαίτηση.

<details>
    <summary>Εφάπαξ χρήση για την τρέχουσα συνεδρία</summary>
    ```sh
    sudo pci-latency
    ```
</details>
<details>
    <summary>Ενεργοποίηση υπηρεσίας systemd</summary>
    ```sh
    systemctl enable pci-latency.service
    ```
</details>
<details>
    <summary>Απενεργοποίηση υπηρεσίας systemd</summary>
    ```sh
    systemctl disable pci-latency.service
    ```
</details>

### [sbctl-batch-sign](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/bin/sbctl-batch-sign)

:::note
Δεν είναι συμβατό με το Limine.
:::

Το `sbctl-batch-sign` είναι ένα βοηθητικό σενάριο σχεδιασμένο να διευκολύνει τους χρήστες στην υπογραφή αρχείων που απαιτούνται για την υποστήριξη του Secure Boot.

Η προφανής περίπτωση στην οποία αυτό το σενάριο βοηθάει ιδιαίτερα είναι σε διατάξεις dual boot με τα Windows, καθώς υπάρχουν πολλά αρχεία των Windows στο EFI που πρέπει να υπογραφούν.

Σύντομη σύνοψη κατά την εκτέλεση του σεναρίου:

- Σαρώνει για ανυπόγραφα αρχεία χρησιμοποιώντας το `sbctl verify`
    - Εάν είναι απαραίτητο, υπογράφει τα εντοπισμένα αρχεία χρησιμοποιώντας το `sbctl sign`
- Αποφεύγει αρχεία που ανήκουν στα Windows, στο GRUB ή με βάση την επέκταση αρχείου: `.mui` και `.dll`

Δείτε την ενότητα [Ρύθμιση του Secure Boot](/el/configuration/secure_boot_setup#υπογραφή-του-ειδώλου-του-πυρήνα-και-του-διαχειριστή-εκκίνησης) για περισσότερες πληροφορίες.

## Δημιουργία παρακάμψεων

Τι είναι μια παράκαμψη (override);

Μια παράκαμψη είναι ένα αρχείο διαμόρφωσης που δημιουργείτε για να αλλάξετε τις προεπιλεγμένες ρυθμίσεις που παρέχονται από το `cachyos-settings`. Αυτό σας επιτρέπει να προσαρμόσετε το σύστημά σας χωρίς να τροποποιήσετε τα αρχικά αρχεία, κάτι που είναι χρήσιμο για τη διατήρηση της συμβατότητας με μελλοντικές ενημερώσεις του `cachyos-settings`.

### sysctl

Παρέχουμε πολλές προσαρμογές για το sysctl που στοχεύουν στη βελτίωση των συνολικών επιδόσεων της επιφάνειας εργασίας. Κάθε καταχώρηση sysctl είναι επαρκώς τεκμηριωμένη
στο αρχείο [70-cachyos-settings.conf](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/lib/sysctl.d/70-cachyos-settings.conf).

Για να πραγματοποιήσετε αλλαγές σε οποιαδήποτε από αυτές τις τιμές, αντιγράψτε την αρχική καταχώρηση και δημιουργήστε ένα νέο αρχείο στο `/etc/sysctl.d/` με την τροποποιημένη τιμή.

<details>
    <summary>Παράδειγμα παράκαμψης sysctl</summary>
    <Steps>

    1. Ρίξτε μια ματιά στην αρχική τιμή από το `cachyos-settings`

        ```sh
        cat /usr/lib/sysctl.d/70-cachyos-settings.conf
        # Only experimental!
        # Let Realtime tasks run as long they need
        # sched: RT throttling activated
        kernel.sched_rt_runtime_us=-1
        ```
    2. Δημιουργήστε ένα νέο αρχείο στο `/etc/sysctl.d` για να κάνετε αλλαγές στις ρυθμίσεις του sysctl

        ```sh title="Επαναφορά του kernel.sched_rt_runtime_us= στην προεπιλεγμένη του τιμή"
        sudo micro /etc/sysctl.d/99-kernel-sched-rt.conf # Εάν το αρχείο δεν υπάρχει, αυτή η εντολή το δημιουργεί και σας επιτρέπει να το επεξεργαστείτε
        kernel.sched_rt_runtime_us=950000
        ```
    3. Αποθηκεύστε το αρχείο πατώντας `CTRL + S` και κλείστε το πρόγραμμα επεξεργασίας πατώντας `CTRL + Q`.
    4. Αφού κάνετε αλλαγές στις ρυθμίσεις του sysctl, βεβαιωθείτε ότι θα τις εφαρμόσετε:
        ```sh
        sudo sysctl --system
        ```
    </Steps>
</details>

### Κανόνες udev

Το ίδιο ισχύει και για τους κανόνες udev. Μπορείτε να δημιουργήσετε τις δικές σας παρακάμψεις φτιάχνοντας ένα νέο αρχείο στο `/etc/udev/rules.d/` με το ίδιο όνομα με το αρχικό αρχείο.

:::tip[Χρησιμοποιήστε την εξής εντολή για να βρείτε τα αρχικά αρχεία]
```sh
pacman -Ql cachyos-settings | grep udev
```
:::

<details>
    <summary>Παράδειγμα παράκαμψης κανόνα udev</summary>
    1. Ελέγξτε τον αρχικό κανόνα udev του CachyOS:
        ```sh
        cat /usr/lib/udev/rules.d/60-ioschedulers.rules
        ```
        <details>
            <summary>Έξοδος:</summary>
                ```sh
                # HDD
                ACTION=="add|change", KERNEL=="sd[a-z]*", ATTR{queue/rotational}=="1", \
                    ATTR{queue/scheduler}="bfq"

                # SSD
                ACTION=="add|change", KERNEL=="sd[a-z]*|mmcblk[0-9]*", ATTR{queue/rotational}=="0", \
                    ATTR{queue/scheduler}="mq-deadline"

                # NVMe SSD
                ACTION=="add|change", KERNEL=="nvme[0-9]*", ATTR{queue/rotational}=="0", \
                    ATTR{queue/scheduler}="none"
                ```
        </details>
        Τώρα φανταστείτε ότι θέλετε να αλλάξετε τον χρονοπρογραμματιστή I/O για δίσκους SSD και NVMe σε `kyber` αντί για `mq-deadline` και `none`, αντίστοιχα. Μπορείτε να το κάνετε δημιουργώντας ένα αρχείο παράκαμψης.
    2. Δημιουργήστε ένα νέο αρχείο στο `/etc/udev/rules.d` για να παρακάμψετε τον αρχικό κανόνα:
        ```sh
        sudo micro /etc/udev/rules.d/60-ioschedulers.rules # Εάν το αρχείο δεν υπάρχει, αυτή η εντολή το δημιουργεί και σας επιτρέπει να το επεξεργαστείτε
        # HDD
        ACTION=="add|change", KERNEL=="sd[a-z]*", ATTR{queue/rotational}=="1", \
            ATTR{queue/scheduler}="bfq"

        # SSD
        ACTION=="add|change", KERNEL=="sd[a-z]*|mmcblk[0-9]*", ATTR{queue/rotational}=="0", \
            ATTR{queue/scheduler}="kyber"

        # NVMe SSD
        ACTION=="add|change", KERNEL=="nvme[0-9]*", ATTR{queue/rotational}=="0", \
            ATTR{queue/scheduler}="kyber"
        ```
    3. Αποθηκεύστε το αρχείο πατώντας `CTRL + S` και κλείστε το πρόγραμμα επεξεργασίας πατώντας `CTRL + Q`.
    4. Αφού κάνετε αλλαγές στους κανόνες του udev, βεβαιωθείτε ότι θα επαναφορτώσετε τους κανόνες και θα τους ενεργοποιήσετε:

        ```sh
        sudo udevadm control --reload-rules
        sudo udevadm trigger
        ```
