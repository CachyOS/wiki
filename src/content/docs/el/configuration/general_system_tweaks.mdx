## Βελτιώσεις επιδόσεων AMD

### Οδηγός AMD P-State
---------------------------

Το `amd-pstate` είναι ο οδηγός κλιμάκωσης επιδόσεων επεξεργαστή της AMD που εισάγει έναν νέο μηχανισμό ελέγχου συχνότητας CPU στις σύγχρονες σειρές APU και CPU της AMD στον πυρήνα Linux. Ο νέος μηχανισμός βασίζεται στο Collaborative Processor Performance Control (CPPC), το οποίο παρέχει πιο λεπτομερή διαχείριση συχνότητας από τα παλαιότερα ACPI hardware P-States.

Οι παλαιότερες πλατφόρμες CPU/APU της AMD χρησιμοποιούν τον οδηγό ACPI P-states για τη διαχείριση της συχνότητας και των ρολογιών της CPU με εναλλαγή μόνο σε 3 P-states. Το CPPC αντικαθιστά τα στοιχεία ελέγχου του ACPI P-states και προσφέρει μια ευέλικτη διεπαφή χαμηλής καθυστέρησης, ώστε ο πυρήνας Linux να επικοινωνεί απευθείας τις υποδείξεις επιδόσεων στο υλικό.

Παρακάτω παρατίθενται οι 3 λειτουργίες του οδηγού `amd_pstate` και οι αντίστοιχες καταχωρήσεις στη γραμμή εντολών του πυρήνα (cmdline) για τη χρήση τους κατά την εκκίνηση:

- AMD P-State (Μη αυτόνομη λειτουργία): `amd_pstate=passive`
- AMD P-State Guided (Καθοδηγούμενη αυτόνομη λειτουργία): `amd_pstate=guided`
- AMD P-State EPP (Αυτόνομη λειτουργία): `amd_pstate=active`

:::note
Ο οδηγός AMD P-State EPP χρησιμοποιείται από προεπιλογή όταν δεν έχει γίνει καμία ρητή ρύθμιση.
:::

Μπορείτε επίσης να κάνετε εναλλαγή μεταξύ των λειτουργιών κατά τον χρόνο εκτέλεσης για να δοκιμάσετε τις επιλογές:

- **Αυτόνομη λειτουργία**: η πλατφόρμα λαμβάνει υπόψη μόνο τις τιμές που έχουν οριστεί για Minimum performance, Maximum performance και Energy Performance Preference.
   ```sh
   echo active | sudo tee /sys/devices/system/cpu/amd_pstate/status
   ```

- **Καθοδηγούμενη αυτόνομη λειτουργία**: η πλατφόρμα ορίζει το επίπεδο επιδόσεων λειτουργίας ανάλογα με τον τρέχοντα φόρτο εργασίας και εντός των ορίων που καθορίζονται από το λειτουργικό σύστημα μέσω των καταχωρητών ελάχιστων και μέγιστων επιδόσεων.
   ```sh
   echo guided | sudo tee /sys/devices/system/cpu/amd_pstate/status
   ```

- **Μη αυτόνομη λειτουργία**: η πλατφόρμα λαμβάνει το επιθυμητό επίπεδο επιδόσεων απευθείας από το λειτουργικό σύστημα μέσω του Desired Performance Register.
   ```sh
   echo passive | sudo tee /sys/devices/system/cpu/amd_pstate/status
   ```

### Ρύθμιση του AMD P-State EPP

Για να χρησιμοποιήσετε το P-State EPP, υπάρχουν δύο διαθέσιμοι κυβερνήτες (governors) κλιμάκωσης συχνότητας CPU: `powersave` και `performance`. Συνιστάται να χρησιμοποιείτε τον κυβερνήτη `powersave` και να ορίζετε μια προτίμηση (preference).

*   Ορισμός κυβερνήτη powersave: `sudo cpupower frequency-set -g powersave`
*   Ορισμός κυβερνήτη performance: `sudo cpupower frequency-set -g performance`

Για να ορίσετε μια προτίμηση, εκτελέστε την παρακάτω εντολή με την επιθυμητή τιμή:

```sh
echo power | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/energy_performance_preference
```

Διαθέσιμες προτιμήσεις: `performance`, `power`, `balance_power`, `balance_performance`

<LinkButton icon="external" href="https://lore.kernel.org/lkml/20221219064042.661122-1-perry.yuan@amd.com/">Επίσημο benchmark για κάθε προτίμηση</LinkButton>

### Βελτιστοποίηση AMD 3D V-Cache

Η AMD δημοσίευσε μια διόρθωση (patch) για τη βελτιστοποίηση του χρονοπρογραμματισμού κρυφής μνήμης (Cache Scheduling) σε επεξεργαστές Dual CCD 3D, όπως οι 7950X3D και 7900X3D.
Θα πρέπει να ορίσετε στο BIOS, στην επιλογή CPPC, την τιμή «Driver». Αυτό θα επιτρέψει την παράκαμψη της χρησιμοποιούμενης λειτουργίας μέσω του sysfs.

Υπάρχουν δύο λειτουργίες:

1. Frequency
2. Cache

Εάν οριστεί η επιλογή `cache`, ο οδηγός θα προσπαθήσει να τοποθετεί πρώτα τις διεργασίες στο CCD με τη μεγαλύτερη κρυφή μνήμη (Cache), κάτι που είναι κυρίως επωφελές στα παιχνίδια.
Η επιλογή `frequency` θα προσπαθήσει να τοποθετεί τις διεργασίες στο δεύτερο CCD, το οποίο έχει υψηλότερη συχνότητα από το CCD της μνήμης 3D Cache.

Frequency (Προεπιλογή):
```sh
echo frequency | sudo tee /sys/bus/platform/drivers/amd_x3d_vcache/AMDI0101:00/amd_x3d_mode
```

Cache:
```sh
echo cache | sudo tee /sys/bus/platform/drivers/amd_x3d_vcache/AMDI0101:00/amd_x3d_mode
```

Αφού αλλάξετε λειτουργία, τα στατιστικά προτιμώμενων πυρήνων της AMD (preferred core stats) θα πρέπει να εμφανίζουν διαφορετική κατάταξη. Μπορείτε να την προβάλετε με την εντολή:
```sh
grep -v /sys/devices/system/cpu/cpu*/cpufreq/amd_pstate_prefcore_ranking
```

### AMD P-State Core Performance Boost

Το AMD Core Performance Boost (γνωστό και ως AMD Turbo Core) είναι μια τεχνολογία δυναμικής κλιμάκωσης συχνότητας της AMD που επιτρέπει στον επεξεργαστή να προσαρμόζει και να ελέγχει δυναμικά τη συχνότητα λειτουργίας του σε ορισμένα μοντέλα επεξεργαστών, προσφέροντας αυξημένες επιδόσεις όταν χρειάζεται, διατηρώντας παράλληλα χαμηλότερη κατανάλωση ενέργειας και θερμοκρασίες κατά την κανονική λειτουργία.

Για να διαχειριστείτε το AMD CPB στο CachyOS, μπορείτε να χρησιμοποιήσετε τις παρακάτω εντολές:

```sh
❯ echo 0 | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/boost # Απενεργοποίηση του boost για όλους τους πυρήνες
❯ lscpu -ae # Δείχνει ότι το AMD CPB είναι απενεργοποιημένο καθολικά
CPU NODE SOCKET CORE L1d:L1i:L2:L3 ONLINE    MAXMHZ   MINMHZ       MHZ
  0    0      0    0 0:0:0:0          yes 3301.0000 400.0000 1212.8250
  1    0      0    0 0:0:0:0          yes 3301.0000 400.0000 1394.2180
  2    0      0    1 1:1:1:0          yes 3301.0000 400.0000 1204.4600

❯ echo 1 | sudo tee /sys/devices/system/cpu/cpu0/cpufreq/boost # Ενεργοποιεί το boost στον cpu0
❯ lscpu -ae
CPU NODE SOCKET CORE L1d:L1i:L2:L3 ONLINE    MAXMHZ   MINMHZ       MHZ
  0    0      0    0 0:0:0:0          yes 4564.0000 400.0000 1393.2380
  1    0      0    0 0:0:0:0          yes 3301.0000 400.0000  400.0000
  2    0      0    1 1:1:1:0          yes 3301.0000 400.0000 2157.8469
```

Το CachyOS παρέχει επίσης μια έκδοση του `power-profiles-daemon` που ενσωματώνει (backport) ένα commit το οποίο ενεργοποιεί την υποστήριξη για το AMD CPB. Το AMD CPB θα απενεργοποιείται όταν χρησιμοποιείται το προφίλ `powersave` και θα ενεργοποιείται στα προφίλ `balanced` ή `performance`.

## Βελτιώσεις επιδόσεων

### [Χρονοπρογραμματιστής I/O ADIOS](https://github.com/firelzrd/adios)

Δημιουργήθηκε από τον [firelzrd](https://github.com/firelzrd)

:::note
Το CachyOS περιλαμβάνει τη σταθερή έκδοση (stable branch) του ADIOS στον πυρήνα.

Τρέχουσα έκδοση στο **linux-cachyos**: `3.2.0`

Τρέχουσα έκδοση στο **linux-cachyos-rc**: `3.2.0`
:::

Σύντομη εισαγωγή από το README:

- *Το ADIOS (Adaptive Deadline I/O Scheduler) είναι ένας χρονοπρογραμματιστής εισόδου/εξόδου επιπέδου μπλοκ (block layer I/O scheduler) για τον πυρήνα Linux, σχεδιασμένος για σύγχρονες συσκευές μπλοκ πολλαπλών ουρών (blk-mq). Στοχεύει στην παροχή χαμηλής καθυστέρησης (latency) για λειτουργίες I/O συνδυάζοντας αρχές χρονοπρογραμματισμού προθεσμιών (deadline scheduling) με έναν προσαρμοστικό μηχανισμό ελέγχου καθυστέρησης βασισμένο στη μάθηση.*
  - *Εμπνέεται και βασίζεται σε έννοιες από τους χρονοπρογραμματιστές I/O mq-deadline και Kyber. Το βασικό του χαρακτηριστικό είναι η ικανότητα να προβλέπει την καθυστέρηση ολοκλήρωσης I/O με βάση προηγούμενες επιδόσεις και τα χαρακτηριστικά του αιτήματος (τύπος λειτουργίας, μέγεθος) και να χρησιμοποιεί αυτήν την πρόβλεψη για να προσαρμόζει δυναμικά τις προθεσμίες αιτημάτων και τη συμπεριφορά ομαδοποίησης (batching).*

Με λίγα λόγια: Το ADIOS λειτουργεί μαθαίνοντας το προφίλ καθυστέρησης της συσκευής αποθήκευσής σας και χρησιμοποιώντας αυτή τη γνώση για να ορίζει δυναμικά προθεσμίες για τα αιτήματα I/O. Κατατάσσει τα αιτήματα σε τέσσερα επίπεδα προτεραιότητας, από κρίσιμες λειτουργίες συστήματος (Tier 0) έως εργασίες παρασκηνίου (Tier 3), ώστε να εξασφαλίζει μια ομαλή εμπειρία χρήσης. Αν και εστιάζει στην απόκριση, η συμπεριφορά του μπορεί να ρυθμιστεί λεπτομερώς μέσω του sysfs για ισορροπία μεταξύ καθυστέρησης και διαμεταγωγής (throughput).

Για μια ζωντανή επίδειξη, μπορείτε να παρακολουθήσετε αυτό το [βίντεο](https://www.youtube.com/watch?v=L9WDcEeHgy4).

#### Πώς να ενεργοποιήσετε το ADIOS

        ```sh
        sync && echo adios | sudo tee /sys/block/<yourdrive>/queue/scheduler
            # Αντικαταστήστε το <yourdrive> με το πραγματικό αναγνωριστικό του δίσκου (π.χ. sda, sdb, nvme0n1)
        ```

        <Steps>
            1. Ανοίξτε ή δημιουργήστε ένα νέο αρχείο κανόνων udev στον επεξεργαστή κειμένου της επιλογής σας (π.χ. nano, micro, vim)
                ```sh title='Παράδειγμα'
                sudo nano /etc/udev/rules.d/60-ioschedulers.rules
                ```
            2. Προσθέστε τους παρακάτω κανόνες στο αρχείο. Αυτοί οι κανόνες εφαρμόζουν αυτόματα έναν συγκεκριμένο χρονοπρογραμματιστή I/O ανάλογα με τον τύπο του δίσκου (HDD, SSD ή NVMe).
                ```text
                # HDD
                ACTION=="add|change", KERNEL=="sd[a-z]*", ATTR{queue/rotational}=="1", \
                    ATTR{queue/scheduler}="bfq"

                # SSD
                ACTION=="add|change", KERNEL=="sd[a-z]*|mmcblk[0-9]*", ATTR{queue/rotational}=="0", \
                    ATTR{queue/scheduler}="adios"

                # NVMe SSD
                ACTION=="add|change", KERNEL=="nvme[0-9]*", ATTR{queue/rotational}=="0", \
                    ATTR{queue/scheduler}="adios"
                ```
              3.  Αποθηκεύστε το αρχείο και κλείστε τον επεξεργαστή κειμένου.
              4.  Επαναφορτώστε τους κανόνες `udev` για να εφαρμοστούν αμέσως οι αλλαγές χωρίς επανεκκίνηση.
                  ```sh
                  sudo udevadm control --reload-rules
                  sudo udevadm trigger
                  ```
        </Steps>
    </TabItem>
</Tabs>

Συχνές ερωτήσεις (FAQ):

- Αφού βελτιώνει την απόκριση, γιατί δεν είναι ενεργοποιημένο από προεπιλογή;
  - Το ADIOS βρίσκεται ακόμα υπό ενεργή ανάπτυξη και συνεχείς δοκιμές. Παρόλο που προσφέρει σημαντικά οφέλη στην απόκριση της επιφάνειας εργασίας, δεν θεωρείται ακόμα αρκετά σταθερό ώστε να αποτελεί την προεπιλογή για όλους τους φόρτους εργασίας και όλους τους τύπους υλικού. Σε ορισμένες ακραίες περιπτώσεις, σφάλματα θα μπορούσαν να οδηγήσουν σε προβλήματα όπως «πάγωμα» του συστήματος. Για τον λόγο αυτό, αποτελεί προαιρετική δυνατότητα για χρήστες που επιθυμούν να το δοκιμάσουν και να επωφεληθούν από τις νεότερες βελτιώσεις του.

### NVIDIA Smooth Motion (Σειρές RTX 40xx & 50xx)

:::note[Συμβατότητα παιχνιδιών.]
Παιχνίδια που εκτελούνται σε DX11, DX12 και Vulkan. Δείτε τις συχνές ερωτήσεις για μια εναλλακτική λύση για το OpenGL.

Τόσο το DXVK όσο και το VKD3D λειτουργούν κανονικά.

**Υποστηρίζονται μόνο εφαρμογές 64bit. Το Smooth Motion δεν θα λειτουργήσει με εφαρμογές 32bit (π.χ. παλιά παιχνίδια DX11).**

:::

Απευθείας παράθεση από την τεκμηρίωση της NVIDIA:

*Το NVIDIA Smooth Motion είναι ένα νέο μοντέλο τεχνητής νοημοσύνης βασισμένο στον οδηγό, το οποίο προσφέρει ομαλότερο gameplay παρεμβάλλοντας ένα επιπλέον καρέ ανάμεσα σε δύο καρέ που έχουν αποδοθεί. Για παιχνίδια χωρίς DLSS Frame Generation, το NVIDIA Smooth Motion αποτελεί μια νέα επιλογή για τη βελτίωση της εμπειρίας σας σε κάρτες γραφικών GeForce RTX 40 Series και νεότερες.*

- Πώς να ενεργοποιήσετε το NVIDIA Smooth Motion για ένα παιχνίδι:
  - Προσθέστε την παρακάτω μεταβλητή περιβάλλοντος:
    ```text
    NVPRESENT_ENABLE_SMOOTH_MOTION=1
    ```

Συχνές ερωτήσεις (FAQ):

- Γιατί να χρησιμοποιήσω το Smooth Motion αντί για το DLSS Frame Generation;
  - Όταν ένα παιχνίδι δεν υποστηρίζει DLSS Frame Generation, το Smooth Motion λειτουργεί ως εναλλακτική χάρη στο μοντέλο AI που βασίζεται στον οδηγό.
- Υπάρχουν μειονεκτήματα στη χρήση του Smooth Motion;
  - Ναι, η ενεργοποίηση του Smooth Motion ενδέχεται να εισαγάγει μια ελαφριά καθυστέρηση εισόδου (input lag) λόγω της πρόσθετης διαδικασίας πρόβλεψης καρέ.
  - Τείνει να προκαλεί προβλήματα με overlays τρίτων. Για να το αποφύγετε αυτό, συμπεριλάβετε την παρακάτω μεταβλητή περιβάλλοντος:
    ```text
    NVPRESENT_QUEUE_FAMILY=1
    ```
    :::note[Ενδέχεται να παρατηρηθεί επίπτωση στις επιδόσεις κατά τη χρήση αυτής της μεταβλητής.]
    :::
- Γιατί το MangoHud δεν αναφέρει τον αυξημένο ρυθμό καρέ (framerate);
  - Προς το παρόν, το MangoHud δεν λαμβάνει υπόψη τα επιπλέον καρέ που παράγονται από το Smooth Motion, με αποτέλεσμα να εμφανίζει παραπλανητικό ρυθμό καρέ.
    - Η χρήση του ενσωματωμένου μετρητή FPS της οθόνης σας θα δείξει τον σωστό ρυθμό καρέ.
- Πώς είναι η ποιότητα εικόνας σε σύγκριση με το DLSS Frame Generation;
  - Η ποιότητα εικόνας δεν είναι εξίσου καλή και ενδέχεται να εμφανιστούν οπτικές αλλοιώσεις (artifacts), ειδικά σε σκηνές με γρήγορη κίνηση.
- Είναι συμβατό με εξωτερικά εργαλεία περιορισμού καρέ (frame capping), όπως το MangoHud;
  - Όχι. Ο ενσωματωμένος περιοριστής καρέ του παιχνιδιού θα πρέπει να λειτουργεί κανονικά.
- Μπορεί το Smooth Motion να συνδυαστεί με το DLSS Frame Generation;
  - Όχι. Μόνο μία μέθοδος παραγωγής καρέ (frame generation) μπορεί να είναι ενεργή κάθε φορά.
- Μπορεί το Smooth Motion να χρησιμοποιηθεί με εφαρμογές OpenGL;
  - Όχι απευθείας, καθώς υλοποιείται ως Vulkan layer, αλλά είναι εφικτό αξιοποιώντας το [Zink](https://docs.mesa3d.org/drivers/zink.html) για τη μετάφραση των κλήσεων OpenGL σε Vulkan:
    ```text
    NVPRESENT_ENABLE_SMOOTH_MOTION=1 zink-run <command>
    ```
    :::note
    Η χρήση του Zink είναι πιθανό να έχει επίπτωση στις επιδόσεις και ενδέχεται να προκαλέσει γραφικές αλλοιώσεις σε ορισμένα παιχνίδια.

    Οι χρήστες με διπλή κάρτα γραφικών (Dual GPU) πρέπει να ορίσουν το `DRI_PRIME=1` για να αξιοποιήσουν την αποκλειστική GPU της Nvidia αντί για τις συνηθισμένες μεθόδους επιλογής GPU.
    :::

## Βελτιώσεις εξοικονόμησης ενέργειας

### thermald

Το `thermald` είναι ένας δαίμονας θερμικής διαχείρισης για συστήματα Intel. Παρακολουθεί τους αισθητήρες θερμοκρασίας και εφαρμόζει ενέργειες ψύξης, όπως όρια ισχύος CPU ή αλλαγές κατάστασης επιδόσεων (performance-state), προτού το υλικολογισμικό χρειαστεί να εφαρμόσει πιο επιθετικό θερμικό περιορισμό (throttling).

Είναι ιδιαίτερα χρήσιμο σε φορητούς υπολογιστές Intel, convertibles, tablets, φορητές συσκευές gaming (handhelds) και υπολογιστές μικρού μεγέθους (small form factor PCs) που εκθέτουν στοιχεία ελέγχου θερμοκρασίας της Intel μέσω του `/sys/class/thermal`. Τα υποστηριζόμενα συστήματα χρησιμοποιούν συνήθως αισθητήρες θερμοκρασίας Intel CPU, Intel P-state, Intel power clamp, RAPL, `INT340X` ή πίνακες ACPI DPTF / προσαρμοστικής θερμικής διαχείρισης. Οι επεξεργαστές AMD δεν υποστηρίζονται από το `thermald`.

Εγκαταστήστε και ενεργοποιήστε το με:

```sh
sudo pacman -S thermald
sudo systemctl enable --now thermald.service
```

Ελέγξτε αν ξεκίνησε σωστά:

```sh
systemctl status thermald.service
journalctl -u thermald.service -b
```

### Ενεργοποίηση του RCU Lazy

Το RCU Lazy βοηθά στη μείωση της κατανάλωσης ενέργειας σε συστήματα που βρίσκονται σε αδράνεια ή υπό ελαφρύ φόρτο. Αυτό μπορεί να είναι χρήσιμο για φορητούς υπολογιστές και φορητές συσκευές (handhelds).
Η βελτίωση κυμαίνεται μεταξύ 5-10% σε εξοικονόμηση ενέργειας. Ωστόσο, είναι σημαντικό να σημειωθεί ότι αυτή η λειτουργία εξοικονόμησης ενέργειας ενδέχεται να επιφέρει ελαφρώς μειωμένες επιδόσεις ανάλογα με το σενάριο χρήσης.
Ο πυρήνας linux-cachyos-deckify έχει αυτήν την επιλογή ενεργοποιημένη από προεπιλογή, καθώς η εξοικονόμηση ενέργειας είναι καθοριστική και απαραίτητη για αυτές τις συσκευές.

Για να ενεργοποιήσετε το RCU Lazy, προσθέστε την παρακάτω παράμετρο στη λίστα παραμέτρων [cmdline](/el/configuration/boot_manager_configuration/) του πυρήνα σας:
```text
rcutree.enable_rcu_lazy=1
```

## Αντιμετώπιση προβλημάτων NVIDIA

### Υλικολογισμικό NVIDIA GSP

Το υλικολογισμικό NVIDIA GSP μπορεί **«σε ορισμένες περιπτώσεις»** να οδηγήσει σε μειωμένες επιδόσεις. Παρόλο που ο οδηγός NVIDIA 555.58.02 έχει αντιμετωπίσει σε μεγάλο βαθμό αυτό το ζήτημα, ενδέχεται να επιμένει σε ορισμένα συστήματα.
Εάν αντιμετωπίζετε κολλήματα (hiccups) στο KDE ή χαμηλές επιδόσεις σε ορισμένες περιπτώσεις, μπορείτε να απενεργοποιήσετε το υλικολογισμικό GSP με το ακόλουθο αρχείο ρυθμίσεων:
`/etc/modprobe.d/nvidia-gsp.conf`

```text
options nvidia NVreg_EnableGpuFirmware=0
```

Αφού δημιουργήσετε το αρχείο, εκτελέστε την παρακάτω εντολή:
```sh
sudo mkinitcpio -P
```

:::note
Τα [ανοιχτά αρθρώματα πυρήνα](https://github.com/NVIDIA/open-gpu-kernel-modules) της NVIDIA βασίζονται στο υλικολογισμικό GSP. Για τον λόγο αυτό, το GSP δεν μπορεί να απενεργοποιηθεί και αυτή η επιλογή του modprobe θα αγνοηθεί όταν τα χρησιμοποιείτε. Χρησιμοποιήστε το `linux-cachyos-nvidia` ή το `nvidia-dkms`.
:::

Συνιστάται γενικά να δοκιμάζετε το υλικολογισμικό GSP μετά από κάθε νέα εγκατάσταση οδηγού NVIDIA, καθώς συχνά εισάγει ωφέλιμα χαρακτηριστικά. Επιπλέον, η NVIDIA έχει ξεκινήσει να διεξάγει δοκιμές ποιότητας (QA) κυρίως με χρήση του υλικολογισμικού GSP.

## Βελτιώσεις ήχου και λογισμικού

### Βελτίωση ήχου ηχείων φορητού υπολογιστή

Τα ηχεία των φορητών υπολογιστών συχνά παράγουν λεπτό και αδύναμο ήχο λόγω του μικρού τους μεγέθους και των περιορισμένων δυνατοτήτων του υλικού. Το [EasyEffects](https://wiki.archlinux.org/title/PipeWire#EasyEffects) μπορεί να βελτιώσει σημαντικά την ποιότητα ήχου των ενσωματωμένων ηχείων του φορητού σας υπολογιστή εφαρμόζοντας διάφορα ηχητικά εφέ και προσαρμοσμένες ρυθμίσεις.

Για να ξεκινήσετε, πρέπει να εγκαταστήσετε το EasyEffects και τις απαραίτητες εξαρτήσεις:

```bash
# Εγκατάσταση του EasyEffects
sudo pacman -S easyeffects
# Εγκατάσταση πρόσθετων προσθέτων (plugins) για περισσότερα εφέ
sudo pacman -S lsp-plugins-lv2
sudo pacman -S zam-plugins
sudo pacman -S calf
sudo pacman -S mda.lv2
```

#### Ρύθμιση

Ακολουθήστε τα παρακάτω βήματα για να ρυθμίσετε το EasyEffects:

1. Εκκινήστε το EasyEffects από το μενού εφαρμογών σας ή πληκτρολογώντας `easyeffects` στο τερματικό.
2. Μεταβείτε στην καρτέλα **Output** για να διαχειριστείτε τα εφέ που εφαρμόζονται στον ήχο των ηχείων σας.
3. Μεταβείτε στην καρτέλα **Effects** για να προσθέσετε, να τροποποιήσετε ή να προσαρμόσετε τα ηχητικά εφέ.

<ImageComponent imgsrc={import('~/assets/images/easyeffects.png')} />

##### Χρήση προεπιλογών της κοινότητας

Για μια γρήγορη και αποτελεσματική ρύθμιση, ξεκινήστε με **προεπιλογές που έχουν δημιουργηθεί από την κοινότητα** και είναι προσαρμοσμένες για διάφορα σενάρια ήχου:

1. Κατεβάστε προεπιλογές από το αποθετήριο [EasyEffects Community Presets](https://github.com/wwmm/easyeffects/wiki/Community-presets).
2. Στο EasyEffects, πατήστε το κουμπί **Presets** και επιλέξτε **«Import preset from local storage»**.
3. Εντοπίστε και επιλέξτε το αρχείο προεπιλογής που κατεβάσατε.
4. Μόλις εισαχθεί, η προεπιλογή θα εμφανιστεί στη λίστα σας — πατήστε **«Load»** για να την εφαρμόσετε στην έξοδο ήχου σας.

<ImageComponent imgsrc={import('~/assets/images/easyeffects-presets.png')} />

##### Δημιουργία προσαρμοσμένου προφίλ

Για μια πιο εξατομικευμένη εμπειρία ήχου, δημιουργήστε ένα προσαρμοσμένο προφίλ προσαρμοσμένο στα ηχεία του φορητού σας υπολογιστή:

1. Πατήστε το κουμπί **«+»** στο μενού Presets για να δημιουργήσετε μια νέα προεπιλογή (π.χ. ονομάστε την **«Laptop Speakers»**).
2. Επιλέξτε **«Load»** για να ενεργοποιήσετε τη νέα προεπιλογή.
3. Προσθέστε και ρυθμίστε εφέ στην καρτέλα **Output** > **Effects**, πειραματιζόμενοι με επιλογές όπως ισοσταθμιστές (equalizers), ενισχυτές μπάσων (bass enhancers) ή διεύρυνση στερεοφωνικού ήχου (stereo wideners).

##### Χρήση του εφέ Convolver (Φορητοί υπολογιστές με Dolby Atmos)

Το **εφέ Convolver** μπορεί να βελτιώσει εντυπωσιακά τον ήχο εφαρμόζοντας αποκρίσεις κρούσης (impulse responses) που προσομοιώνουν ηχητικά περιβάλλοντα υψηλής ποιότητας. Ωστόσο, απαιτεί προσεκτική ρύθμιση:

1. Προσθέστε το εφέ **Convolver** στην αλυσίδα εφέ σας στην καρτέλα **Effects**.
2. Φορτώστε ένα αρχείο απόκρισης κρούσης (σε μορφή `.wav`) ειδικό για το μοντέλο του φορητού σας υπολογιστή, εφόσον υπάρχει διαθέσιμο. Μπορείτε να αναζητήσετε τέτοια αρχεία στο διαδίκτυο σε πηγές όπως:
   - https://wiki.archlinux.org/title/Lenovo_ThinkPad_T14_(AMD)_Gen_4#Speakers
   - https://github.com/m4tx/thinkpad-p14s-g4-linux/#sound
   - https://github.com/shuhaowu/linux-thinkpad-speaker-improvements/
3. **Αποτροπή ψαλιδισμού (clipping)**: Το εφέ Convolver ενδέχεται να αυξήσει σημαντικά την ένταση. Προσθέστε ένα εφέ **Limiter** μετά το Convolver στην αλυσίδα εφέ σας για να ελέγχετε τις κορυφές και να αποφεύγετε την παραμόρφωση.

<ImageComponent imgsrc={import('~/assets/images/easyeffects-convolver.png')} />

#### Συμβουλές για βέλτιστα αποτελέσματα

- **Πειραματιστείτε** με διαφορετικές προεπιλογές για να εντοπίσετε τον καλύτερο συνδυασμό για το συγκεκριμένο μοντέλο του φορητού σας υπολογιστή και τις προσωπικές σας προτιμήσεις ήχου.
- **Κάντε σταδιακές προσαρμογές** σε επιμέρους εφέ ώστε να αποτρέψετε την παραμόρφωση ή ένα αφύσικο ηχητικό αποτέλεσμα.
- **Συγκρίνετε με εναλλαγή**: Ενεργοποιείτε και απενεργοποιείτε συχνά το EasyEffects (**on/off**) για να αξιολογείτε τις βελτιώσεις σε σύγκριση με τον προεπιλεγμένο ήχο.
- Αναζητήστε **προεπιλογές ειδικές για τη συσκευή σας ή αρχεία απόκρισης κρούσης Convolver** για δημοφιλή μοντέλα φορητών υπολογιστών όπως τα **Framework Laptop 13** ή **ThinkPad T14** για εξατομικευμένα αποτελέσματα.
- **Αυτοματοποίηση εκκίνησης**: Ρυθμίστε το EasyEffects ώστε να εκκινεί αυτόματα κατά την εκκίνηση του συστήματος από τις προτιμήσεις της εφαρμογής, εξασφαλίζοντας ότι το προσαρμοσμένο προφίλ σας εφαρμόζεται πάντα.
- **Αυτόματη φόρτωση προεπιλογών για πολλαπλές συσκευές**: Χρησιμοποιήστε την καρτέλα **PipeWire** > **Presets Autoloading** για να συσχετίσετε συγκεκριμένες προεπιλογές με διαφορετικές συσκευές εξόδου (π.χ. Ηχεία έναντι Ακουστικών) για απρόσκοπτη εναλλαγή. <ImageComponent imgsrc={import('~/assets/images/easyeffects-autoloading.png')} />

#### Εναλλακτική του EasyEffects

Ως εναλλακτική λύση μπορείτε να δοκιμάσετε το [JDSP4Linux](https://github.com/Audio4Linux/JDSP4Linux), το οποίο είναι ένας επεξεργαστής ηχητικών εφέ για πελάτες PipeWire και PulseAudio.

### OBS Studio

Παρέχουμε ένα προσαρμοσμένο πακέτο obs-studio-browser στο αποθετήριό μας, το οποίο συνιστάται έναντι του τυπικού πακέτου `obs-studio`. Περιέχει διορθώσεις (patches) για συνηθισμένα προβλήματα όπως σφάλματα CUDA και προβλήματα εικονικής κάμερας.

```sh title='Ανοίξτε ένα τερματικό και εκτελέστε την παρακάτω εντολή'
sudo pacman -S obs-studio-browser
# Εάν είχατε εγκατεστημένο το obs-studio προηγουμένως, το pacman θα σας ρωτήσει
# αν θέλετε να το αντικαταστήσετε — σε αυτή την περίπτωση πληκτρολογήστε "Y".
```

## Διαμόρφωση Swap

### Μετάβαση από ZRam σε Zswap

Από προεπιλογή, το CachyOS χρησιμοποιεί το ZRam για τη διαχείριση του swap. Ωστόσο, εάν προτιμάτε να χρησιμοποιήσετε το Zswap στη θέση του, μπορείτε να μεταβείτε εύκολα ακολουθώντας τα παρακάτω βήματα:

:::note
Αυτός ο οδηγός προϋποθέτει ότι έχετε την προεπιλεγμένη ρύθμιση του CachyOS με ενεργοποιημένο το ZRam και ότι δεν δημιουργήθηκε κατάτμηση ή αρχείο swap κατά την εγκατάσταση.
:::

<Steps>
    1. Απενεργοποιήστε το ZRam προσθέτοντας μια παράμετρο πυρήνα. [Επεξεργαστείτε τις ρυθμίσεις του διαχειριστή εκκίνησης](/el/configuration/boot_manager_configuration) και προσθέστε την παρακάτω γραμμή:
        ```text
        systemd.zram=0
        ```
    2. Ενεργοποιήστε το Zswap προσθέτοντας την παρακάτω παράμετρο πυρήνα:
        ```text
        zswap.enabled=1 zswap.shrinker_enabled=1 zswap.compressor=lz4 zswap.max_pool_percent=30
        ```
    3. Δημιουργήστε ένα κενό αρχείο παράκαμψης (override) για να απενεργοποιήσετε τον [κανόνα udev του CachyOS](https://github.com/CachyOS/CachyOS-Settings/blob/master/usr/lib/udev/rules.d/30-zram.rules) που απενεργοποιεί το Zswap:
        ```bash
        sudo touch /etc/udev/rules.d/30-zram.rules
        ```
    4. Δημιουργήστε ένα αρχείο swap για το Zswap.
        <details>
            <summary>Εάν χρησιμοποιείτε Btrfs:</summary>
                <Steps>
                    1. Δημιουργήστε έναν υποτόμο (subvolume) Btrfs για το αρχείο swap:
                        ```bash
                        sudo btrfs subvolume create /swap
                        ```
                    2. Δημιουργήστε ένα αρχείο swap με το επιθυμητό μέγεθος (π.χ. 8GB) αλλάζοντας την παράμετρο `--size`:
                        ```bash "--size"
                        sudo btrfs filesystem mkswapfile --size 4g --uuid clear /swap/swapfile
                        ```
                    3. Ενεργοποιήστε το αρχείο swap:
                        ```bash
                        sudo swapon /swap/swapfile
                        ```
                    4. Προσθέστε το αρχείο swap στο `/etc/fstab` ώστε να παραμένει ενεργό μετά από επανεκκινήσεις:
                        ```bash
                        echo "/swap/swapfile none swap defaults 0 0" | sudo tee -a /etc/fstab
                        ```
                </Steps>
        </details>
        <details>
            <summary>Εάν δεν χρησιμοποιείτε Btrfs:</summary>
            <Steps>
                1. Δημιουργήστε ένα αρχείο swap με το επιθυμητό μέγεθος (π.χ. 8GB) αλλάζοντας την παράμετρο `count=`:
                    ```bash "count=8"
                    sudo dd if=/dev/zero of=/swapfile bs=1G count=8
                    ```
                2. Ορίστε τα σωστά δικαιώματα για το αρχείο swap:
                    ```bash
                    sudo chmod 0600 /swapfile
                    ```
                3. Μορφοποιήστε το αρχείο swap:
                    ```bash
                    sudo mkswap /swapfile
                    ```
                4. Προσθέστε το αρχείο swap στο `/etc/fstab` ώστε να παραμένει ενεργό μετά από επανεκκινήσεις:
                    ```bash
                    echo "/swapfile none swap defaults 0 0" | sudo tee -a /etc/fstab
                    ```
                5. Ενεργοποιήστε το αρχείο swap:
                    ```bash
                    sudo swapon /swapfile
                    ```
            </Steps>
        </details>
    5. Προσθέστε το άρθρωμα συμπίεσης lz4 στο αρχείο ρυθμίσεων `mkinitcpio.conf`:
        1. Ανοίξτε το αρχείο με έναν επεξεργαστή κειμένου:
            ```bash
            sudo nano /etc/mkinitcpio.conf
            ```
        2. Βρείτε τον πίνακα `MODULES` και προσθέστε το `lz4` σε αυτόν. Θα πρέπει να μοιάζει κάπως έτσι:
            ```text
            MODULES=(... lz4)
            ```
        3. Αποθηκεύστε το αρχείο πατώντας `Ctrl + O` και `Enter` για επιβεβαίωση, και έπειτα βγείτε από τον επεξεργαστή με `Ctrl + X`.
    6. Δημιουργήστε ξανά το initramfs για να εφαρμοστούν οι αλλαγές. Η εντολή διαφέρει ανάλογα με τον διαχειριστή εκκίνησης που χρησιμοποιείτε:
        <details>
            <summary>systemd-boot</summary>
            ```bash
            sudo sdboot-manage gen
            ```
        </details>
        <details>
            <summary>GRUB</summary>
            ```bash
            sudo grub-mkconfig -o /boot/grub/grub.cfg
            ```
        </details>
        <details>
            <summary>Limine</summary>
            ```bash
            sudo limine-mkinitcpio
            ```
        </details>
    7. Κάντε επανεκκίνηση του συστήματός σας για να εφαρμοστούν όλες οι αλλαγές.
</Steps>
