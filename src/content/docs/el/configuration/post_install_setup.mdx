## Προτεινόμενα βήματα μετά την εγκατάσταση

### Ενημέρωση του συστήματος

:::tip
Βεβαιωθείτε ότι έχετε ελέγξει την ενότητα [Ασφάλεια και βέλτιστες πρακτικές](/el/cachyos_basic/faq#ασφάλεια-και-βέλτιστες-πρακτικές) για να αποφύγετε συνηθισμένες παγίδες και να διατηρήσετε το σύστημά σας ασφαλές.
:::

<Tabs>

<TabItem label="Shelly (GUI και CLI)">
    <LinkButton icon="external" href="https://www.seafoam-labs.org/shelly-alpm/overview/">Wiki του Shelly</LinkButton>
    <LinkButton icon="external" href="https://www.seafoam-labs.org/shelly-alpm/docs/cli-reference/">Shelly CLI</LinkButton>

    Το [Shelly](https://github.com/Seafoam-Labs/Shelly-ALPM) είναι μια σύγχρονη επανασχεδίαση του διαχειριστή πακέτων του Arch Linux, σχεδιασμένη ώστε να αποτελεί μια πιο διαισθητική και φιλική προς τον χρήστη εναλλακτική λύση αντί των pacman και octopi.

    Ανάπτυξη: [Seafoam-Labs](https://github.com/Seafoam-Labs)

    Επιτρέπει στους χρήστες να διαχειρίζονται τα πακέτα τους χωρίς να χρειάζεται να χρησιμοποιούν το τερματικό.

    Ορισμένες από τις δυνατότητες του Shelly περιλαμβάνουν:

    Εγκατάσταση/απεγκατάσταση πακέτων από το AUR, τα επίσημα αποθετήρια, AppImages, Flatpaks και τοπικά πακέτα, προβολή λεπτομερειών πακέτων, διαχείριση ομάδων πακέτων και πολλά άλλα.

    Γιατί να προτιμήσετε το Shelly αντί του Octopi;
    - Διαθέτει πιο σύγχρονο και φιλικό προς τον χρήστη περιβάλλον.
    - Συνεχής ανάπτυξη και ενημερώσεις με νέες δυνατότητες και βελτιώσεις.
    - Υποστηρίζει περισσότερες μορφές πακέτων (AUR, AppImages, Flatpaks κ.λπ.).
    - Λειτουργίες ασφαλείας, όπως η επαλήθευση των αρχείων PKGBUILD· ανατρέξτε στους [Ελέγχους ασφαλείας](https://www.seafoam-labs.org/shelly-alpm/docs/security/) για περισσότερες πληροφορίες.

<TabItem label="Με το Octopi (GUI)">

Το Octopi είναι ένας γραφικός διαχειριστής πακέτων για διανομές που βασίζονται στο Arch και παρέχει έναν εύχρηστο τρόπο διαχείρισης πακέτων και ενημερώσεων.
Για να ενημερώσετε το σύστημά σας με το Octopi, ακολουθήστε τα εξής βήματα:

<Steps>

1. Ανοίξτε το **Octopi** από το μενού εφαρμογών.
2. Στο κύριο παράθυρο, κάντε κλικ στο κουμπί **Check updates** (επάνω αριστερά) και έπειτα, δίπλα του, στο **System upgrade**.
3. Το Octopi θα ελέγξει τώρα για διαθέσιμες ενημερώσεις και θα σας ζητήσει να τις εγκαταστήσετε είτε μέσα από το ίδιο το Octopi είτε σε ένα τερματικό.
4. Για να προχωρήσετε με την ενημέρωση, κάντε κλικ στο κουμπί **Apply**.
5. Το Octopi θα πραγματοποιήσει λήψη και εγκατάσταση των ενημερώσεων.
6. Συνιστάται να κάνετε επανεκκίνηση του υπολογιστή σας μετά από μια μεγάλη ενημέρωση **(ειδικά αν ενημερώθηκε ο πυρήνας)**.

</Steps>

</TabItem>

<TabItem label="Με το Pacman">

<Steps>

1. Ανοίξτε έναν προσομοιωτή τερματικού (ή πατήστε `ctrl + alt + t` — `mod + return` σε έναν διαχειριστή παραθύρων, π.χ. Qtile).
2. Εκτελέστε την παρακάτω εντολή για να ενημερώσετε το σύστημα:

   ```sh
   sudo pacman -Syu
   ```
3. Συνιστάται να κάνετε επανεκκίνηση του υπολογιστή σας μετά από μια μεγάλη ενημέρωση **(ειδικά αν ενημερώθηκε ο πυρήνας)**.

</Steps>

</TabItem>

<TabItem label="Ενημέρωση εκτός σύνδεσης">

*Το CachyOS υποστηρίζει αναβαθμίσεις συστήματος εκτός σύνδεσης χρησιμοποιώντας το σενάριο [`pacman-offline`](https://github.com/eworm-de/pacman-offline). Αυτό επιτρέπει στο σύστημά σας να κατεβάζει τις ενημερώσεις πακέτων και να τις εφαρμόζει στην επόμενη επανεκκίνηση. (Ναι, όπως στα Windows)*

:::note
Το εργαλείο `pacman-offline` ενσωματώνεται στη λειτουργία ενημερώσεων εκτός σύνδεσης του systemd. Διαχειρίζεται αυτόματα τις ενημερώσεις του πυρήνα και τη φόρτωση αρθρωμάτων.

Το αρχείο `/etc/pacman.d/offline.conf` είναι καθοριστικής σημασίας για τη διαχείριση των πακέτων που ενημερώνονται κατά τις κανονικές ενημερώσεις και τις ενημερώσεις εκτός σύνδεσης. Βεβαιωθείτε ότι έχει ρυθμιστεί σωστά για τον επιθυμητό πυρήνα σας ή προσθέστε τα πακέτα που θέλετε, ώστε να ενημερώνονται μόνο κατά την εκτέλεση του `pacman-offline` και να αγνοούνται σε μια κανονική ενημέρωση. Παράδειγμα: `pacman -Syu`.

**Εάν ενεργοποιήσετε το χρονόμετρο αυτόματης ενημέρωσης, δεν χρειάζεται πλέον να ενημερώνετε χειροκίνητα το σύστημά σας.**
:::

<Steps>

1. **Εγκατάσταση του πακέτου pacman-offline**

   ```bash
   sudo pacman -S pacman-offline
   ```

2. **Ορισμός στο Pacman να διαβάζει από τη ξεχωριστή λίστα αγνοημένων πακέτων.**

   :::note[Προσθέστε τη γραμμή μετά την ενότητα [options]. Δείτε το παρακάτω παράδειγμα για αναφορά.]
   :::

   ```bash title='Προσθέστε την εξής γραμμή στο αρχείο /etc/pacman.conf'
   Include = /etc/pacman.d/offline.conf
   ```
   *Παράδειγμα*
   ```bash
   # /etc/pacman.conf
   # REPOSITORIES
   #   - can be defined here or included from another file
   #   - pacman will search repositories in the order defined here
   #   - local/custom mirrors can be added here or in separate files
   #   - repositories listed first will take precedence when packages
   #     have identical names, regardless of version number
   #   - URLs will have $repo replaced by the name of the current repo
   #   - URLs will have $arch replaced by the name of the architecture
   #
   # Repository entries are of the format:
   #       [repo-name]
   #       Server = ServerName
   #       Include = IncludePath
   #
   # The header [repo-name] is crucial - it must be present and
   # uncommented to enable the repo.
   #
   # GENERAL OPTIONS
   [options]
   # other options like 'Color', 'CheckSpace', etc. can be here
   Include = /etc/pacman.d/offline.conf
   ```
3. **Προσθήκη των πυρήνων του CachyOS ώστε το pacman να τους αγνοεί κατά τις κανονικές ενημερώσεις**

   Το εργαλείο `pacman-offline` χρησιμοποιεί αυτό το αρχείο για να καθορίσει ποια πακέτα θα αγνοούνται κατά τις παραδοσιακές ενημερώσεις του pacman.

   Παράδειγμα: όταν εκτελείτε `sudo pacman -Syu`

   *Αντικαταστήστε τα περιεχόμενα του αρχείου `/etc/pacman.d/offline.conf` με τα εξής:*

   ```text
   # Arch Linux kernels
   IgnorePkg = linux linux-headers linux-docs
   IgnorePkg = linux-lts linux-lts-headers linux-lts-docs
   IgnorePkg = linux-zen linux-zen-headers linux-zen-docs
   IgnorePkg = linux-hardened linux-hardened-headers linux-hardened-docs

   # CachyOS kernels
   IgnorePkg = linux-cachyos linux-cachyos-headers linux-cachyos-nvidia-open linux-cachyos-zfs
   IgnorePkg = linux-cachyos-bmq linux-cachyos-bmq-headers linux-cachyos-bmq-nvidia-open linux-cachyos-bmq-zfs
   IgnorePkg = linux-cachyos-bore linux-cachyos-bore-headers linux-cachyos-bore-nvidia-open linux-cachyos-bore-zfs
   IgnorePkg = linux-cachyos-deckify linux-cachyos-deckify-headers linux-cachyos-deckify-nvidia-open linux-cachyos-deckify-zfs
   IgnorePkg = linux-cachyos-eevdf linux-cachyos-eevdf-headers linux-cachyos-eevdf-nvidia-open linux-cachyos-eevdf-zfs
   IgnorePkg = linux-cachyos-gcc linux-cachyos-gcc-headers linux-cachyos-gcc-nvidia-open linux-cachyos-gcc-zfs
   IgnorePkg = linux-cachyos-hardened linux-cachyos-hardened-headers linux-cachyos-hardened-nvidia-open linux-cachyos-nvidia-hardened-zfs
   IgnorePkg = linux-cachyos-lts linux-cachyos-lts-headers linux-cachyos-lts-nvidia-open linux-cachyos-lts-zfs
   IgnorePkg = linux-cachyos-rc linux-cachyos-rc-headers linux-cachyos-rc-nvidia-open linux-cachyos-rc-nvidia-open linux-cachyos-rc-zfs
   IgnorePkg = linux-cachyos-rt-bore linux-cachyos-rt-bore-headers linux-cachyos-rt-bore-nvidia-open
   IgnorePkg = linux-cachyos-server linux-cachyos-server-headers linux-cachyos-server-nvidia-open linux-cachyos-server-zfs
   ```

   *Τώρα όλα αυτά τα πακέτα θα αγνοούνται στις κανονικές ενημερώσεις, αλλά θα ελέγχονται κατά την προετοιμασία της ενημέρωσης εκτός σύνδεσης.*

3. **Εκτέλεση της προετοιμασίας για την ενημέρωση εκτός σύνδεσης μόνο μία φορά**

   ```bash title='Εκτελέστε την παρακάτω εντολή'
   sudo systemctl start pacman-offline-prepare.service
   ```
   Αυτή η εντολή θα εκτελέσει το `pacman-offline` μία φορά, θα συγχρονίσει τις βάσεις δεδομένων των πακέτων και θα προχωρήσει στη λήψη των ενημερώσεων χωρίς να τις εγκαταστήσει.

</Steps>

*Εάν θέλετε αυτό το σενάριο να εκτελείται αυτόματα, ακολουθήστε τα παρακάτω βήματα:*

<Steps>

1. **Ενεργοποίηση του χρονομέτρου προετοιμασίας**

   Η ενεργοποίηση του `pacman-offline-prepare.timer` θα επιτρέψει στο systemd να ενεργοποιεί αυτό το σενάριο για τη λήψη ενημερώσεων σε καθημερινή βάση, λίγα λεπτά μετά από κάθε εκκίνηση του συστήματος.

   ```bash
   sudo systemctl enable pacman-offline-prepare.timer
   ```

2. **Επανεκκίνηση του συστήματός σας:**

   Οι ενημερώσεις θα εγκατασταθούν κατά την επόμενη επανεκκίνηση του συστήματος.

3. **(Προαιρετικό) Αυτόματες επανεκκινήσεις συστήματος:**

    Ενεργοποιήστε το `pacman-offline-reboot.timer` για να γίνεται αυτόματα επανεκκίνηση του συστήματός σας από προεπιλογή στις **3 π.μ.** (στη ζώνη ώρας σας), εάν υπάρχουν εκκρεμείς ενημερώσεις. Λάβετε υπόψη ότι δεν εκτελείται πάντα την ίδια ακριβώς ώρα λόγω της παραμέτρου `RandomizedDelaySec`, η οποία έχει οριστεί σε 2 ώρες από προεπιλογή.

    ```bash
    sudo systemctl enable pacman-offline-reboot.timer
    ```

    :::tip
    Μπορείτε να επεξεργαστείτε το αρχείο `pacman-offline-reboot.timer` είτε για να τροποποιήσετε την ώρα που θέλετε να επανεκκινείται το σύστημά σας όταν υπάρχουν εκκρεμείς ενημερώσεις, είτε για να απενεργοποιήσετε τον τυχαίο προγραμματισμό.
    :::

</Steps>

</TabItem>

<TabItem label="Cachy-Update">

Παράγωγο του [Arch-Update](https://github.com/Antiz96/arch-update)

Ένα εργαλείο ειδοποίησης και εφαρμογής ενημερώσεων για το Arch Linux που σας βοηθά με σημαντικές εργασίες πριν και μετά την ενημέρωση.
Περιλαμβάνει ένα δυναμικό εικονίδιο στην περιοχή ειδοποιήσεων (systray) με δυνατότητα κλικ, για εύκολη ενσωμάτωση σε οποιοδήποτε περιβάλλον επιφάνειας εργασίας ή διαχειριστή παραθύρων.

<details>
    <summary>Πώς να ενεργοποιήσετε το Cachy-Update</summary>
    Ενεργοποιήστε το Cachy-Update από το `CachyOS Hello > Apps/Tweaks > Cachy Update enabled`
</details>
<details>
    <summary>Πώς να απενεργοποιήσετε το Cachy-Update</summary>
        Απενεργοποιήστε το Cachy-Update από το `CachyOS Hello > Apps/Tweaks > Cachy Update disabled`
            :::tip
            Εάν θέλετε να διατηρήσετε το Cachy-Update και απλώς να απενεργοποιήσετε το εικονίδιο της περιοχής ειδοποιήσεων, ανοίξτε ένα τερματικό και εκτελέστε τις παρακάτω εντολές:
            ```bash
            mkdir -p ~/.config/autostart
            echo -e "[Desktop Entry]\nHidden=true" > ~/.config/autostart/arch-update-tray.desktop
            ```
            Εάν θέλετε να διατηρήσετε ενεργοποιημένο το εικονίδιο της περιοχής ειδοποιήσεων και απλώς να απενεργοποιήσετε τον αυτόματο έλεγχο ενημερώσεων, εκτελέστε την εξής εντολή:
            ```bash
            systemctl --user disable --now arch-update.timer
            ```
            :::
</details>

- Δυνατότητες:
  - Αυτόματος έλεγχος και εμφάνιση λίστας διαθέσιμων ενημερώσεων.
  - Έλεγχος για πρόσφατα νέα του Arch Linux (με επιλογή προβολής τους, εφόσον υπάρχουν).
  - Έλεγχος για ορφανά πακέτα (με επιλογή κατάργησής τους, εφόσον υπάρχουν).
  - Έλεγχος για παλιά και απεγκατεστημένα πακέτα στην προσωρινή μνήμη (με επιλογή εκκαθάρισής τους, εφόσον υπάρχουν).
  - Έλεγχος για εκκρεμή ενημέρωση πυρήνα που απαιτεί επανεκκίνηση (με επιλογή εκτέλεσής της, εφόσον υπάρχει).
  - Έλεγχος για υπηρεσίες που απαιτούν επανεκκίνηση μετά την αναβάθμιση (με επιλογή επανεκκίνησής τους, εφόσον υπάρχουν).
  - Υποστήριξη για `sudo`, `sudo-rs`, `doas` και `run0`.

**Διάστημα ελέγχου ενημερώσεων:** `Μία φορά δύο λεπτά μετά την εκκίνηση και έπειτα μία φορά την ημέρα με τυχαία καθυστέρηση μίας ώρας.`

- Πώς να αλλάξετε το διάστημα ελέγχου ενημερώσεων:

```sh title='Εκτελέστε την παρακάτω εντολή'
systemctl --user edit --full arch-update.timer
# Συμβουλή: Μπορείτε επίσης να χρησιμοποιήσετε οποιονδήποτε επεξεργαστή κειμένου της επιλογής σας αντί για το `nano`
# π.χ. EDITOR=micro systemctl --user edit --full arch-update.timer
```

<details>
<summary>Προεπιλεγμένα περιεχόμενα του αρχείου:</summary>
    ```systemd
    [Timer]
    OnStartupSec=2min # Έλεγχος για ενημερώσεις δύο λεπτά μετά την εκκίνηση
    RandomizedDelaySec=1h # Τυχαία καθυστέρηση μίας ώρας
    OnUnitActiveSec=1d # Έλεγχος για ενημερώσεις μία φορά την ημέρα
    ```
</details>
Ουσιαστικά, μπορείτε να αλλάξετε την τιμή `OnUnitActiveSec` σε ό,τι επιθυμείτε. Για παράδειγμα, αν θέλετε να γίνεται έλεγχος για ενημερώσεις κάθε 30 λεπτά, αλλάξτε την σε `30m`, ή κάθε 6 ώρες, αλλάξτε την σε `6h`. Δείτε αυτό το [έγγραφο](https://www.freedesktop.org/software/systemd/man/latest/systemd.time.html#Parsing%20Time%20Spans) για περισσότερες λεπτομέρειες σχετικά με τον ορισμό του χρονικού διαστήματος.

Σε περίπτωση που θέλετε το Cachy-Update να ελέγχει για νέες ενημερώσεις μόνο μία φορά κατά την εκκίνηση, μπορείτε απλώς να διαγράψετε εντελώς τη γραμμή `OnUnitActiveSec`.

Ευχαριστούμε τον [Antiz](https://github.com/Antiz96) για τη συντήρηση του αρχικού έργου Arch-Update και για την υλοποίηση του Cachy-Update.

### Ρύθμιση του τείχους προστασίας (ufw)
:::note
Το UFW είναι ενεργοποιημένο από προεπιλογή μετά την εγκατάσταση.
:::
Για να ρυθμίσετε το ufw, ακολουθήστε τα εξής βήματα:

<Tabs>

<TabItem label="Ενεργοποίηση">

```bash
sudo ufw enable
```

</TabItem>

<TabItem label="Απενεργοποίηση">

```bash
sudo ufw disable
```

</TabItem>

<TabItem label="Αποδοχή">

Από προεπιλογή, το ufw αγνοεί την εισερχόμενη κίνηση και επιτρέπει την εξερχόμενη· μπορείτε να προσθέσετε συγκεκριμένους κανόνες στο τείχος προστασίας για να αποκλείσετε ή να επιτρέψετε συγκεκριμένες συνδέσεις.

```bash
# Παράδειγμα 1, αποδοχή κίνησης ssh:
sudo ufw allow ssh
# Παράδειγμα 2, άνοιγμα της θύρας 12345 για κίνηση TCP & UDP:
sudo ufw allow 12345

# Το κείμενο ή ο αριθμός θύρας μπορούν να προσαρμοστούν ανάλογα με τις ανάγκες, όπως 12345/udp για να επιτρέπεται μόνο κίνηση UDP ή αντικαθιστώντας το ssh με το όνομα ενός προγράμματος
```

</TabItem>

<TabItem label="Απόρριψη">

Από προεπιλογή, το ufw αγνοεί την εισερχόμενη κίνηση και επιτρέπει την εξερχόμενη· μπορείτε να προσθέσετε συγκεκριμένους κανόνες στο τείχος προστασίας για να αποκλείσετε ή να επιτρέψετε συγκεκριμένες συνδέσεις.

```bash
# Παράδειγμα 1, απόρριψη κίνησης ssh:
sudo ufw deny ssh
# Παράδειγμα 2, κλείσιμο της θύρας 12345 για κίνηση TCP & UDP:
sudo ufw deny 12345

# Το κείμενο ή ο αριθμός θύρας μπορούν να προσαρμοστούν ανάλογα με τις ανάγκες, όπως 12345/udp για απόρριψη μόνο κίνησης UDP ή αντικαθιστώντας το ssh με το όνομα ενός προγράμματος
```

</TabItem>

<TabItem label="Κατάσταση">

```bash
sudo ufw status verbose
```
:::tip
Εάν δεν θέλετε να ξεχάσετε γιατί ανοίξατε/κλείσατε μια θύρα, προσθέστε ένα σχόλιο στον κανόνα.
```bash
# Παράδειγμα 1, άνοιγμα της θύρας 12345 για κίνηση TCP & UDP με σχόλιο:
sudo ufw allow 12345 comment 'Example'
# Παράδειγμα 2, κλείσιμο της θύρας 6789 για TCP με σχόλιο:
sudo ufw deny 6789/tcp comment 'Comments can have spaces'
```
:::
</TabItem>

</Tabs>

:::note
Να είστε προσεκτικοί κατά τη ρύθμιση κανόνων του τείχους προστασίας, καθώς εσφαλμένα ρυθμισμένοι κανόνες μπορούν να σας αποκλείσουν από το δικό σας σύστημα.
:::

:::note
Μπορείτε επίσης να το ρυθμίσετε γραφικά χρησιμοποιώντας την ενότητα «Firewall» (Τείχος προστασίας) στις ρυθμίσεις του KDE Plasma.
:::

:::note

:::

<Tabs>
   <TabItem label='bash'>

      Αυτό είναι το προεπιλεγμένο κέλυφος στις περισσότερες διανομές Linux. Χρησιμοποιείται επίσης ακόμη ως το κέλυφος σύνδεσης του χρήστη root. Το bash

      chsh -s /usr/bin/bash
      ```

   </TabItem>

   <TabItem label='zsh'>

      Παρέχουμε μια [διαμόρφωση για το zsh](https://github.com/CachyOS/cachyos-zsh-config) με συνήθως χρησιμοποιούμενα πρόσθετα και ρυθμίσεις.
      Στοχεύει σε αντιστοιχία 1:1 σε λειτουργικότητα με τη [διαμόρφωσή μας για το fish](https://github.com/CachyOS/cachyos-fish-config).
      Αυτό είναι επίσης το προεπιλεγμένο κέλυφος που χρησιμοποιείται στο macOS.

      chsh -s /usr/bin/zsh
      ```

   </TabItem>

### Διαχείριση AppImage

Τα AppImage είναι φορητές εφαρμογές που εκτελούνται στις περισσότερες διανομές Linux χωρίς να απαιτούν εγκατάσταση ή δικαιώματα root.

:::note[Όλα τα AppImage απαιτούν δικαιώματα εκτέλεσης για να τρέξουν.]
Μπορείτε να ορίσετε το δικαίωμα εκτέλεσης με την παρακάτω εντολή:
```sh
chmod +x /path/to/your/appimage
```
Ή κάντε δεξί κλικ στο αρχείο AppImage, μεταβείτε στις `Ιδιότητες` > `Δικαιώματα` (Properties > Permissions) και επιλέξτε το πλαίσιο `Να επιτρέπεται η εκτέλεση του αρχείου ως πρόγραμμα` (Allow executing file as program).
:::

:::note[Πριν εκτελέσετε AppImage, βεβαιωθείτε ότι το FUSE (Filesystem in Userspace) είναι εγκατεστημένο στο σύστημά σας.]
```sh
sudo pacman -S fuse2
```
:::

Για να διαχειριστείτε τα AppImage, μπορείτε να χρησιμοποιήσετε το [gearlever](https://github.com/mijorus/gearlever), το οποίο παρέχει έναν εύκολο τρόπο ενσωμάτωσης των AppImage στο σύστημά σας.

Το `gearlever` είναι ένα γραφικό εργαλείο που απλοποιεί τη διαχείριση των AppImage στο σύστημά σας. Ενσωματώνεται στο περιβάλλον επιφάνειας εργασίας σας, καθιστώντας εύκολη την εκτέλεση και διαχείριση των AppImage.

Για να εγκαταστήσετε το gearlever, ακολουθήστε τα εξής βήματα:

<Steps>
    1. Εγκαταστήστε το flatpak αν δεν το έχετε ήδη κάνει:
        ```sh
        sudo pacman -S flatpak
        ```
    2. Επανεκκινήστε το σύστημά σας.
    3. Εγκαταστήστε το gearlever μέσω flatpak:
        ```sh
        flatpak install flathub it.mijorus.gearlever
        ```
    4. Μετά την εγκατάσταση, αποσυνδεθείτε και συνδεθείτε ξανά για να δείτε το gearlever στο μενού εφαρμογών σας.
</Steps>

### Ρύθμιση πρόσβασης σε κοινόχρηστους φακέλους Samba

Το Samba είναι μια υλοποίηση ελεύθερου λογισμικού του πρωτοκόλλου δικτύωσης SMB. Για να συνδεθείτε στον διακομιστή Samba σας, διατίθεται μια χρήσιμη διαμόρφωση για τους χρήστες του CachyOS, η οποία όμως απαιτεί αλλαγή της ρύθμισης του διακομιστή Samba σας.

#### Εγκατάσταση και χρήση του αρχείου smb.conf του CachyOS

Για να χρησιμοποιήσετε το βολικό αρχείο `smb.conf`, εγκαταστήστε πρώτα ένα συγκεκριμένο πακέτο που παρέχει το απαιτούμενο αρχείο `smb.conf`. Στη συνέχεια, αντικαταστήστε το υπάρχον `smb.conf` του διακομιστή σας με αυτό το αρχείο και ρυθμίστε ξανά τους κοινόχρηστους τόμους σας.

:::note[Αυτός ο οδηγός προϋποθέτει ότι διαθέτετε ήδη έναν λειτουργικό διακομιστή Samba]
:::

<Steps>
    1. Δημιουργήστε ένα αντίγραφο ασφαλείας του αρχικού σας αρχείου `smb.conf`, το οποίο συνήθως βρίσκεται στο `/etc/samba/smb.conf` σε συστήματα Linux.
    2. Εγκαταστήστε το πακέτο ρυθμίσεων Samba του CachyOS στον υπολογιστή-πελάτη σας:
        ```sh
        sudo pacman -S cachyos-samba-settings
        ```
    3. Αντιγράψτε το `smb.conf` από τον υπολογιστή-πελάτη στον διακομιστή Samba.
    4. Ανοίξτε και επεξεργαστείτε το αρχείο για να προσθέσετε τους κοινόχρηστους καταλόγους, τους εκτυπωτές σας κ.λπ.
    5. Επανεκκινήστε την υπηρεσία Samba στον διακομιστή σας:
        ```sh
        sudo systemctl restart --now samba
        ```
    6. Στον υπολογιστή-πελάτη, αποκτήστε πρόσβαση στους κοινόχρηστους πόρους σας μέσω του διαχειριστή αρχείων σας (π.χ. `smb://<your_server_ip>/<share_name>`).

        Εάν έχει ρυθμιστεί σωστά, θα σας ζητηθούν τα διαπιστευτήρια σύνδεσης. Θυμηθείτε να επιλέξετε την αποθήκευση των στοιχείων σύνδεσής σας, εφόσον το επιθυμείτε.
</Steps>

### Υποστήριξη AppArmor με προφίλ AppArmor.d

Παράθεση από τη Βικιπαίδεια:

*Το AppArmor («Application Armor») είναι ένα άρθρωμα ασφαλείας του πυρήνα Linux που επιτρέπει στον διαχειριστή συστήματος να περιορίζει τις δυνατότητες των προγραμμάτων μέσω προφίλ ανά πρόγραμμα. Τα προφίλ μπορούν να επιτρέπουν δυνατότητες όπως πρόσβαση στο δίκτυο, πρόσβαση σε raw sockets και δικαιώματα ανάγνωσης, εγγραφής ή εκτέλεσης αρχείων σε αντίστοιχες διαδρομές.*

Αυτή είναι μόνο μια εισαγωγή για το πώς να εγκαταστήσετε μια βασική ρύθμιση AppArmor· εάν δεν είστε εξοικειωμένοι με το AppArmor, παρακαλούμε μην προχωρήσετε χωρίς να κατανοήσετε τις επιπτώσεις.

Για πιο αναλυτικές πληροφορίες σχετικά με το AppArmor.d και τον τρόπο δημιουργίας των δικών σας προφίλ, ανατρέξτε στην [τεκμηρίωση του AppArmor.d](https://github.com/roddhjav/apparmor.d?tab=readme-ov-file#configuration).

:::caution[Προχωρήστε με προσοχή. Μια εσφαλμένα ρυθμισμένη εγκατάσταση AppArmor μπορεί να προκαλέσει προβλήματα.]
:::

<Steps>

1. Προσθέστε τις ακόλουθες παραμέτρους πυρήνα στον διαχειριστή εκκίνησής σας· ανατρέξτε στη σελίδα [Ρύθμιση του διαχειριστή εκκίνησης](/el/configuration/boot_manager_configuration) για αναφορά:

   ```text
   lsm=landlock,lockdown,yama,integrity,apparmor,bpf
   ```

2. Εγκαταστήστε τα πακέτα `apparmor` και `apparmor.d` **(σύνολο άνω των 1.500 προφίλ)**:
   ```bash
   sudo pacman -S apparmor apparmor.d
   ```

3. Ενεργοποιήστε και εκκινήστε την υπηρεσία AppArmor:

   ```bash
   systemctl enable --now apparmor.service
   ```

4. Ενεργοποιήστε την προσωρινή αποθήκευση (caching) για τα προφίλ του AppArmor:

   ```shell
   # /etc/apparmor/parser.conf
   ## Προσθέστε τις εξής γραμμές:
   write-cache
   Optimize=compress-fast
   cache-loc /etc/apparmor/earlypolicy/
   ```
   Αποθηκεύστε το αρχείο και κάντε επανεκκίνηση.
</Steps>

### Ενεργοποίηση TRIM σε κρυπτογραφημένες συσκευές (LUKS)

Το CachyOS ενεργοποιεί από προεπιλογή το `fstrim.timer` για περιοδική εκτέλεση TRIM σε μονάδες SSD και NVMe, συμβάλλοντας στη διατήρηση της απόδοσης εγγραφής και της μακροζωίας του δίσκου. Ωστόσο, το επίπεδο κρυπτογράφησης device-mapper του Linux (`dm-crypt`/LUKS) αποκλείει από προεπιλογή τις εντολές discard (TRIM). Ως αποτέλεσμα, το περιοδικό TRIM εκτελείται σιωπηλά χωρίς να εφαρμόζεται σε κρυπτογραφημένες κατατμήσεις, εκτός εάν ενεργοποιηθεί ρητά η διέλευση discard (discard passthrough).

:::caution[Ζητήματα ασφαλείας και απορρήτου]
Η ενεργοποίηση του TRIM σε μια κρυπτογραφημένη συσκευή επιτρέπει στον ελεγκτή του SSD να γνωρίζει ποιοι τομείς είναι κενοί και ποιοι περιέχουν δεδομένα. Παρόλο που τα δεδομένα σας παραμένουν πλήρως κρυπτογραφημένα, ένας επιτιθέμενος με φυσική πρόσβαση στον δίσκο θα μπορούσε να συμπεράνει κατά προσέγγιση τον χρησιμοποιούμενο αποθηκευτικό χώρο, τη διάταξη του συστήματος αρχείων ή μοτίβα δεδομένων.

Εάν αυτή η διαρροή μεταδεδομένων είναι αποδεκτή για το μοντέλο απειλών σας, μπορείτε να ενεργοποιήσετε με ασφάλεια τη διέλευση discard για βελτιωμένη απόδοση και υγεία του SSD.
:::

#### Ενεργοποίηση διέλευσης Discard (LUKS2)

<Steps>
1. Εντοπίστε το ενεργό όνομα αντιστοίχισης (mapper) του LUKS:

   ```bash
   lsblk
   ```

   Αναζητήστε την καταχώρηση τύπου `crypt` κάτω από την κατάτμηση του δίσκου σας (π.χ. `luks-1e647929-62c0-4922-8944-f941ed4155fd`).

2. Ενεργοποιήστε τη μόνιμη διέλευση discard στην ενεργή αντιστοίχιση LUKS:

   ```bash
   sudo cryptsetup --allow-discards --persistent refresh <mapper_name>
   ```

   :::note
   Αντικαταστήστε το `<mapper_name>` με το πραγματικό όνομα αντιστοίχισης που βρήκατε στο βήμα 1 (για παράδειγμα, `sudo cryptsetup --allow-discards --persistent refresh luks-1e647929-62c0-4922-8944-f941ed4155fd`).
   :::

3. Επανεκκινήστε το σύστημά σας για να εφαρμοστούν οι αλλαγές.

4. Επαληθεύστε ότι η διέλευση discard είναι ενεργή:

   ```bash
   lsblk -D
   sudo fstrim -v /
   ```

   Η εντολή `lsblk -D` θα πρέπει πλέον να εμφανίζει μη μηδενικές τιμές κάτω από τις στήλες `DISC-GRAN` και `DISC-MAX` για τον κρυπτογραφημένο τόμο σας, και η `fstrim` θα εμφανίζει το μέγεθος του χώρου που καθαρίστηκε αντί να παραλείπει τη συσκευή.
</Steps>
