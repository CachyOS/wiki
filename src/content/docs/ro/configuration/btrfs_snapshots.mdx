## Introducere

:::caution
Nu considera snapshot-urile Btrfs ca pe un înlocuitor pentru backup-urile obișnuite. Asigură-te întotdeauna că ai backup-uri adecvate pentru datele tale importante.
:::

### Ce este un snapshot Btrfs?

Să începem cu elementele de bază:

Snapshot-urile Btrfs provin din funcția de subvolum. Ce este un subvolum? Gândește-te la un subvolum ca la un sistem de fișiere separat în cadrul sistemului de fișiere Btrfs. Acesta îți permite să-ți fragmentezi datele în diferite părți. De aceea, de exemplu, în CachyOS avem subvolume diferite pentru:

- Sistemul de fișiere root: (`/`)
- Directorul root: (`/root`)
- Directorul home: (`/home`)
- Directoarele var: (`/var/cache`, `/var/tmp`, `/var/log`)
- Directorul srv: (`/srv`)

Având subvolume diferite pentru aceste directoare, le putem gestiona independent, putem aplica setări diferite și, cel mai important, putem crea snapshot-uri pentru ele.

Aici se naște un snapshot. Un snapshot este, în esență, o copie read-only sau read-write (**implicită**) a unui subvolum la un anumit moment în timp. Acest lucru înseamnă că poți surprinde starea sistemului tău de fișiere, inclusiv toate fișierele și directoarele, în acel moment.

Prin urmare, snapshot-urile devin o referință punct-în-timp, ceea ce înseamnă că atunci când fișierul țintă deviază de la datele din snapshot, snapshot-ul va păstra fișierul original, iar ținta va crea un fișier nou cu modificările, în timp ce snapshot-ul rămâne neschimbat pentru totdeauna. De aceea, unii utilizatori se referă la un snapshot ca la „date înghețate în timp”.

Imaginează-ți că faci o fotografie a sistemului tău de fișiere la un moment specific și te poți întoarce oricând la acea fotografie ori de câte ori ai nevoie.

Unul dintre avantajele cheie ale snapshot-urilor este că sunt foarte eficiente din punct de vedere al spațiului, deoarece sunt doar o referință la datele originale până când se fac modificări.

Dar aici un snapshot diferă de un backup tradițional. Să presupunem că discul tău se defectează; dacă ai fi avut un backup tradițional, ți-ai putea restaura datele din acel backup. Totuși, dacă ai fi avut doar snapshot-uri pe discul defect, ai pierde accesul la acele snapshot-uri, deoarece ele sunt stocate pe același disc.

### Cazuri de recuperare unde snapshot-urile sunt utile și unde nu sunt

Sunt utile pentru recuperarea după:

- Defectări sau coruperi după actualizările sistemului.
- Configurări greșite care împiedică pornirea sistemului.
- Ștergeri sau modificări accidentale ale fișierelor.

Nu sunt utile pentru recuperarea după:

- Probleme cu bootloader-ul.
- Defecțiuni hardware (ex. hard disk-uri defecte).

## Gestionarea snapshot-urilor (GUI și CLI)

:::tip
Deoarece CachyOS include `snap-pac` implicit, Snapper va crea automat snapshot-uri înainte și după orice instalare, actualizare sau eliminare de pachete folosind `pacman`. Aceasta înseamnă că nu trebuie să creezi manual snapshot-uri pentru aceste operațiuni, deoarece Snapper se ocupă de asta pentru tine.
:::

:::note
Dacă folosești bootloader-ul GRUB, asigură-te că ai `grub-btrfs-support` pentru a avea toate scripturile și hook-urile necesare pentru a detecta automat snapshot-urile BTRFS și a le adăuga în meniul GRUB.
```bash
sudo pacman -Syu grub-btrfs-support
```
:::

Câteva lucruri de luat în considerare înainte de a gestiona snapshot-urile. **Se aplică atât metodelor CLI, cât și GUI.**

- Se recomandă păstrarea a maximum 10 snapshot-uri. Peste acest număr, snapshot-urile devin prea vechi și mai puțin utile. În cel mai rău caz, revenirea la un snapshot vechi poate introduce probleme de compatibilitate cu versiunile mai noi de software.
- Snapshot-urile sunt destinate ideal scopurilor de recuperare. Totuși, le poți folosi pentru a anula modificările aduse fișierelor fără a restaura întregul snapshot.
- Adaugă o descriere sugestivă atunci când creezi snapshot-uri. Acest lucru te va ajuta să identifici ulterior scopul fiecărui snapshot.

### Btrfs Assistant (GUI)

Înainte de a continua, asigură-te că ai instalat `btrfsmaintenance` pentru a profita de funcțiile de gestionare automată a snapshot-urilor.

Pentru cei care preferă gestionarea Btrfs, a snapshot-urilor și a altor elemente printr-o interfață grafică, [Btrfs Assistant](https://gitlab.com/btrfs-assistant/btrfs-assistant) este un proiect excelent pentru începători.

#### Configurarea curățării automate a snapshot-urilor

Vom configura curățarea automată a snapshot-urilor folosind Btrfs Assistant. Acest lucru va ajuta la gestionarea eficientă a snapshot-urilor tale fără intervenție manuală.

Urmează acești pași:

<Steps>

    1. Lansează Btrfs Assistant deschizând un terminal și rulând:
        ```bash
        btrfs-assistant-launcher
        ```

        Alternativ:

        ```bash
        sudo -E btrfs-assistant
        ```

  2. Navighează la tab-ul Snapper Settings:

      <ImageComponent imgsrc={import('~/assets/images/btrfs-maintenance-snapperSettingsTab.png')} />
      Modifică setările **Snapshot Retention** după cum urmează:
      - Asigură-te că este selectată configurația `root`.
      - Introdu valoarea `0` pentru Hourly, Daily, Weekly, Monthly și Yearly.
      - Debifează `Enable timeline snapshots`.
      - Introdu valoarea `10` la `Number`.
      - Bifează ✅ la `Snapper cleanup enabled`.
      - Apasă pe butonul `Save` din dreapta sus și pe `Apply systemd changes` din dreapta jos.
      **snapper-cleanup.timer va fi acum activat pentru a curăța automat snapshot-urile vechi pe baza configurației tale.**
      :::caution
      Verifică dacă ajustările pe care tocmai le-ai făcut au fost aplicate corect verificând configurația Snapper:
      ```bash
      sudo nano /etc/snapper/configs/root
      ```
      Snippet de ieșire așteptat:
      ```text
      # limit for number cleanup
      NUMBER_MIN_AGE="3600"
      NUMBER_LIMIT="10"
      NUMBER_LIMIT_IMPORTANT="10"
      ```
      Dacă `NUMBER_LIMIT` și `NUMBER_LIMIT_IMPORTANT` nu conțin valoarea `10`, actualizează-le corespunzător.
      Salvează fișierul și ieși apăsând `CTRL + O`, `Enter` și `CTRL + X`.
      :::
</Steps>

#### Eliminarea snapshot-urilor folosind Btrfs Assistant

<Steps>
    1. Deschide Btrfs Assistant:
        ```bash
        btrfs-assistant-launcher
        ```

        Alternativ:

        ```bash
        sudo -E btrfs-assistant
        ```
    2. Mergi la tab-ul Snapper Settings:
        <ImageComponent imgsrc={import('~/assets/images/btrfs-maintenance-snapperTab.png')} />
    3. Selectează snapshot-ul/snapshot-urile pe care dorești să le ștergi din listă.
        :::tip
        - Ține apăsat `CTRL` pentru a selecta mai multe snapshot-uri.
        - Ține apăsat `SHIFT` pentru a selecta un interval de snapshot-uri.
        :::
    4. Apasă pe butonul `Delete` situat în partea de sus a ferestrei.
    5. Regenerează intrările bootloader-ului pentru a reflecta modificările:
        <details>

        </details>
        <details>

        </details>
        <details>

        </details>
</Steps>

### Snapper (CLI)

Acum că am acoperit ce este un snapshot Btrfs și cazurile sale de utilizare, să vorbim despre cum să le gestionăm folosind o unealtă numită [Snapper](http://snapper.io/) creată de [Arvin Schnell](https://github.com/aschnell) de la [openSUSE](https://www.opensuse.org/).

<details>
<summary>CachyOS folosește următoarea configurație Snapper implicită:</summary>

```text
# subvolume to snapshot
SUBVOLUME="/"

# filesystem type
FSTYPE="btrfs"

# btrfs qgroup for space aware cleanup algorithms
QGROUP=""

# fraction or absolute size of the filesystems space the snapshots may use
SPACE_LIMIT="0.5"

# fraction or absolute size of the filesystems space that should be free
FREE_LIMIT="0.2"

# users and groups allowed to work with config
ALLOW_USERS=""
ALLOW_GROUPS=""

# sync users and groups from ALLOW_USERS and ALLOW_GROUPS to .snapshots
# directory
SYNC_ACL="no"

# start comparing pre- and post-snapshot in background after creating
# post-snapshot
BACKGROUND_COMPARISON="yes"

# run daily number cleanup
NUMBER_CLEANUP="yes"

# limit for number cleanup
NUMBER_MIN_AGE="1800"
NUMBER_LIMIT="50"
NUMBER_LIMIT_IMPORTANT="15"

# create hourly snapshots
TIMELINE_CREATE="no"

# cleanup hourly snapshots after some time
TIMELINE_CLEANUP="yes"

# limits for timeline cleanup
TIMELINE_MIN_AGE="1800"
TIMELINE_LIMIT_HOURLY="5"
TIMELINE_LIMIT_DAILY="7"
TIMELINE_LIMIT_WEEKLY="0"
TIMELINE_LIMIT_MONTHLY="0"
TIMELINE_LIMIT_YEARLY="0"

# cleanup empty pre-post-pairs
EMPTY_PRE_POST_CLEANUP="yes"

# limits for empty pre-post-pair cleanup
EMPTY_PRE_POST_MIN_AGE="1800"
```

</details>

:::caution
Configurația Snapper implicită a CachyOS acoperă doar subvolumul root (`/`). Dacă ai alte subvolume pe care dorești să le gestionezi cu Snapper, va trebui să creezi configurații separate pentru fiecare dintre ele.

Această configurație necesită o revizuire pentru a-i crește eficacitatea.
:::

      - Iată un rezumat al coloanelor:
        - `#`: Indică numărul snapshot-ului care este folosit în alte comenzi.
        - `Type`: Indică dacă snapshot-ul este unul individual (single) sau face parte dintr-o pereche pre/post.
            - `single`: Aceste snapshot-uri nu au nicio relație specială cu alte snapshot-uri.
            - `pre`: Aceste snapshot-uri sunt menite să fie făcute înainte de orice tip de modificare a sistemului (cum ar fi editarea unui fișier sau instalarea unui pachet).
            - `post`: După cum sugerează și numele, acestea se referă la snapshot-uri făcute după ce a avut loc o modificare a sistemului. Ele sunt legate de snapshot-ul `pre` corespunzător.

        - `Date`: Data și ora la care a fost creat snapshot-ul.
        - `User`: Utilizatorul care a creat snapshot-ul.

            - empty-pre-post: Șterge perechile de snapshot-uri pre/post cu diferențe goale.
        - `Description`: O scurtă descriere a snapshot-ului, indicând adesea motivul creării acestuia.
        - `Userdata`: Date suplimentare definite de utilizator asociate snapshot-ului.

### Recomandări și sfaturi Limine

#### Ajustarea setărilor de afișare a snapshot-urilor în bootloader-ul Limine

- Limitează numărul de snapshot-uri afișate în meniul bootloader-ului Limine pentru a evita aglomerația:

<Steps>
    1. Creează o copie de rezervă a fișierului de configurare limine-snapper-sync:
        ```bash
        sudo cp /etc/limine-snapper-sync.conf /etc/limine-snapper-sync.conf.orig
        ```
    2. Editează fișierul de configurare limine-snapper-sync:
        ```bash
        sudo nano /etc/limine-snapper-sync.conf
        ```
        Snippet de ieșire așteptat:
        ```bash
        ### Max Snapshot Entries
        ### Setează limita pentru câte intrări de snapshot apar în meniul de boot.
        ### Aceasta depinde de dimensiunea partiției tale de boot FAT32 și de câte versiuni diferite de kernel și module vrei să păstrezi.
        ### O partiție de boot FAT32 mai mare permite mai multe intrări de snapshot.
        MAX_SNAPSHOT_ENTRIES=10
        ```
        Opțional, ajustează formatul numelui snapshot-ului:
        ```bash
        ### Snapshot Name Format
        ### Alege un format pentru modul în care apar intrările de snapshot în bootloader-ul Limine:
        ### 0. ID=111 2023-12-20 10:59:59 (implicit)
        ### 1. 111│2023-12-20 10:59:59
        ### 2. 111 │ 2023-12-20 10:59:59
        ### 3. 2023-12-20 10:59:59│111
        ### 4. 2023-12-20 10:59:59 │ 111
        ### 5. 2023-12-20 10:59:59
        ### 6. 111
        ### 7. 111│descriere snapshot
        ### 8. 2023-12-20 10:59:59│descriere snapshot
        ### 9. │descriere snapshot
        SNAPSHOT_FORMAT_CHOICE=8
        ```
        `8` este o alegere bună deoarece arată data și ora împreună cu descrierea snapshot-ului.
    3. Salvează fișierul și ieși apăsând `CTRL+O`, `Enter`, `CTRL+X`.
</Steps>
