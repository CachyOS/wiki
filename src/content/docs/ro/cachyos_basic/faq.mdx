## Cum să raportezi o problemă sau un bug către CachyOS

:::danger
Ai grijă când te bazezi pe ajutorul și comenzile oferite de un model AI (cum ar fi ChatGPT) fără a verifica informațiile din surse oficiale. Modelele AI pot oferi uneori informații incorecte sau înșelătoare, în special în contexte tehnice. Verifică întotdeauna cu documentația de încredere sau resursele comunității.

Altfel, te poți trezi cu un sistem complet defect sau poți înrăutăți problema.
:::

:::tip
Reține: În lumea Linux există un citat minunat: „Cel mai probabil, altcineva a avut aceeași problemă înaintea ta.” Așadar, te rugăm să folosești funcția de căutare pe Google, Arch Wiki sau Forumul/Discord-ul CachyOS înainte de a raporta o problemă, deoarece s-ar putea să fi fost deja rezolvată.
:::

:::tip
Nu uita să folosești comanda `tldr` pentru a vedea o versiune simplificată a manualelor (paginile man) pentru comenzile cu care nu ești familiarizat. Exemplu:

Unele dintre cele mai comune comenzi și descrieri pentru git:
```bash
tldr git
```

Poți combina `tldr` cu o comandă git specifică pentru a obține informații mai detaliate despre un parametru, de exemplu:
```bash
tldr git add
```
:::

### Descrie-ți problema

Iată câteva lucruri pe care ar trebui să le analizezi:

- Ce nu funcționează?
- Revenirea la versiunea anterioară a pachetului X rezolvă problema?
- Alți oameni experimentează această problemă / a fost rezolvată înainte? (folosește funcția de căutare)
- Problema a apărut după o actualizare?
- Ai făcut modificări pe cont propriu?
  - Exemplu: adăugarea unui flag suplimentar într-un fișier modprobe
- Este legat de hardware? (ex: GPU, Wi-Fi)
- Este legat de software? (ex: o aplicație specifică, mediul desktop)
- Este o instalare proaspătă sau problema a apărut după un timp de utilizare?

## Cum să colectezi log-uri

Există multe modalități de a colecta log-uri de pe sistemul tău. Iată câteva exemple și unelte pe care le poți folosi:

### Crearea unui raport de bug general
CachyOS oferă o unealtă excelentă pentru a colecta log-urile de sistem, numită `cachyos-bugreport.sh`.
Această unealtă va colecta log-uri de la:
  - `dmesg`
  - `journalctl`
  - `inxi` (pentru a colecta informații hardware)

După ce log-urile sunt colectate, utilizatorul va fi întrebat dacă dorește să le încarce pe site-ul nostru de paste.

Pentru a rula acest script, introdu următoarea comandă în terminal și partajează link-ul generat în raportul tău:
  ```sh
  sudo cachyos-bugreport.sh
  ```

### Colectarea log-urilor de la un program care nu pornește
Există multe motive pentru care un program grafic ar putea să nu pornească. Cea mai bună metodă de a colecta log-uri pentru acest tip de problemă este să rulezi programul dintr-un terminal. Astfel, poți vedea orice mesaje de eroare sau informații care te pot ajuta la diagnosticarea problemei.

De exemplu, dacă Firefox nu pornește complet, încearcă să-l pornești din terminal și caută mesajele de eroare:
  ```sh
  firefox
  ```

:::tip
  Dacă vrei să salvezi rezultatul într-un fișier text pentru a-l partaja mai ușor, poți redirecționa ieșirea astfel:
    ```sh
    firefox &> firefox-log.txt
    ```
  Nu uita să apeși `CTRL + C` pentru a opri procesul după ce acesta nu reușește să pornească, astfel încât terminalul să scrie rezultatul în fișier.
:::

### Verifică ultimele pachete actualizate în pacman.

Pentru a obține o listă cu cele mai recent actualizate pachete de pe sistemul tău, poți folosi următoarea comandă:

```bash
grep "\[ALPM\] upgraded" /var/log/pacman.log | tail -n 50
```

:::tip
Ajustează parametrul `-n` al comenzii `tail` pentru a obține mai multe sau mai puține linii.
:::

### Taste de navigare în journalctl și dmesg

Cele mai comune scurtături de tastatură pentru a naviga prin log-uri când se folosește `less` sau modul citibil pentru oameni:

`Săgeată Sus & Săgeată Jos` sau `J & K` pentru a derula în sus sau în jos linie cu linie.

`PageUp & PageDown` sau `Ctrl + B/D` pentru a derula în sus sau în jos cu o pagină.

`G` sau `Home` pentru a sări la începutul log-ului.

`Shift + G` sau `End` pentru a sări la sfârșitul log-ului.

### Utilizarea journalctl pentru a colecta log-uri de sistem

Comanda `journalctl` este o unealtă extrem de utilă pentru vizualizarea log-urilor de sistem. Iată câteva dintre cele mai comune și utile combinații de comenzi.

#### Utilizare de bază și exemple comune

:::tip
Combină mai multe opțiuni pentru o filtrare mai specifică.
:::

<details>
<summary>Vezi întregul log (de la cel mai vechi la cel mai nou):</summary>
```bash
journalctl
```
</details>

<details>
<summary>Vezi log-urile doar pentru pornirea (boot) curentă:</summary>
```bash
journalctl -b
```
</details>

<details>
<summary>Probleme de securitate și autentificare:</summary>
```bash
journalctl -u sshd -u polkit -b -0 | grep -i "fail\|error\|denied"
```
Caută eșecuri de autentificare și respingeri de politici de securitate.
</details>

<details>
<summary>Urmărește log-urile în timp real:</summary>
```bash
journalctl -f
```
:::tip
Combină acest lucru cu alte filtre. De exemplu:
```bash
# Urmărirea log-urilor de la serviciul Adguard Home:
journalctl -u adguardhome -f
```
:::
</details>

<details>
<summary>Probleme audio din pornirea curentă:</summary>
```bash
journalctl --user -u pipewire -u pipewire-pulse -u wireplumber -b 0
```
Vezi log-urile de la serviciile audio pentru a depana problemele de sunet.
</details>

<details>
<summary>Erori de memorie (RAM):</summary>
```bash
journalctl -k | grep -i "memory\|ram"
```
Caută probleme de corupere sau de detectare a memoriei.
</details>

<details>
<summary>Probleme Bluetooth:</summary>
```bash
# Din pornirea curentă:
journalctl -u bluetooth -b 0
# Din pornirea anterioară:
journalctl -u bluetooth -b -1
```
</details>

##### Filtrare bazată pe timp
<details>

<summary>Vezi log-urile din ultimele minute/ore:</summary>
```bash
journalctl --since "10 minutes ago"
journalctl --since "1 hour ago"
journalctl --since "2024-01-15 14:30:00"
```
</details>

<details>
<summary>Vezi log-urile dintr-un interval specific de timp:</summary>
```bash
journalctl --since "09:00" --until "10:00"
```
</details>

##### Filtrare după prioritate și serviciu sau program

Nivelurile de prioritate posibile sunt: `debug`, `info`, `notice`, `warning`, `err`, `crit`, `alert`, `emerg`.

Sau folosind cifre:

`0` înseamnă `emerg`

`1` înseamnă `alert`

`2` înseamnă `crit`

`3` înseamnă `err`

`4` înseamnă `warning`

`5` înseamnă `notice`

`6` înseamnă `info`

și `7` înseamnă `debug`.

<details>
<summary>Arată doar mesajele de eroare, critice și de urgență:</summary>
```bash
journalctl -p err..emerg
```
:::tip
Poți combina acestea cu exemplele anterioare:

Exemplu:
```bash
journalctl -p err..emerg --since "9:00" --until "10:00"
```
:::
</details>

<details>
<summary>Arată log-urile de la un anumit serviciu de sistem:</summary>
```bash title='Exemple'
# Vezi log-urile de la serviciul NetworkManager:
journalctl -u NetworkManager
# Vezi log-urile de la serviciul GDM (GNOME Display Manager):
journalctl -u gdm
# Vezi log-urile de la serviciul SDDM (Simple Desktop Display Manager):
journalctl -u sddm
```
</details>

<details>
<summary>Arată log-urile de la un anumit Process ID (PID):</summary>
```bash
journalctl _PID=pid
# Exemplu:
journalctl _PID=3344
```
</details>

<details>
<summary>Arată log-urile de la un anumit executabil:</summary>
```bash
journalctl path/to/executable
# Exemplu:
journalctl /usr/bin/firefox
```
</details>

### Utilizarea journalctl pentru a verifica mesajele Kernelului

:::note
Când să folosești `journalctl -k` față de `dmesg`:

- `journalctl -k` accesează mesajele de kernel stocate în journal-ul systemd (persistente între reporniri dacă sunt configurate astfel) și oferă o integrare mai bună cu filtrarea pe bază de timp și funcțiile journal-ului.
- `dmesg` citește buffer-ul inelar curent al kernelului (volatil, se pierde după repornire).
:::

<details>
<summary>Vizualizarea de bază a mesajelor de kernel:</summary>
```bash
journalctl -k
```
Arată toate mesajele de kernel din journal, echivalent cu `dmesg` dar din perspectiva journal-ului.
</details>

<details>
<summary>Mesajele de kernel doar pentru pornirea curentă:</summary>
```bash
journalctl -k -b 0
```
Afișează mesajele de kernel doar pentru sesiunea curentă.
</details>

<details>
<summary>Mesajele de kernel din pornirea anterioară:</summary>
```bash
journalctl -k -b -1
```
Vezi mesajele de kernel din pornirea anterioară. Util pentru diagnosticarea eșecurilor de boot sau a crash-urilor.
</details>

<details>
<summary>Urmărește mesajele de kernel noi în timp real:</summary>
```bash
journalctl -k -f
```
Urmărește mesajele de kernel pe măsură ce apar, excelent pentru monitorizarea evenimentelor hardware sau încărcarea driverelor.
</details>

<details>
<summary>Caută mesaje de driver specifice:</summary>
```bash
# Exemple:
# Mesaje legate de GPU:
journalctl -k | grep -i "nvidia\|amd\|intel"
# Mesaje dispozitive USB:
journalctl -k | grep -i "usb\|pci"
```
</details>

<details>
<summary>Filtrarea mesajelor de kernel după timp:</summary>
```bash
journalctl -k --since "1 hour ago"
journalctl -k --since "09:00" --until "10:00"
```
Vezi mesajele de kernel din perioade specifice.
</details>

### Utilizarea dmesg pentru mesaje de Kernel

Comanda `dmesg` afișează buffer-ul inelar al kernelului, care conține mesaje despre detectarea hardware-ului, inițializarea driverelor și evenimentele de sistem.

#### Utilizare de bază și formatare

<details>
<summary>Vezi întregul buffer de mesaje de kernel:</summary>
```bash
dmesg
```
</details>

<details>
<summary>Vezi cu timestamp-uri citibile pentru oameni:</summary>
```bash
dmesg -T
```
</details>

<details>
<summary>Vezi într-un pager pentru o citire mai ușoară:</summary>
```bash
dmesg | less
```
</details>

#### Filtrarea după nivelul de prioritate

Similar cu journalctl, dmesg permite filtrarea mesajelor după nivelul de prioritate.

<details>
<summary>Arată doar erorile și mesajele critice:</summary>
```bash
dmesg -l err,crit,alert,emerg
```
Nivelurile de prioritate posibile sunt: `debug`, `info`, `notice`, `warning`, `err`, `crit`, `alert`, `emerg`.

Sau folosind cifre:

`0` înseamnă `emerg`

`1` înseamnă `alert`

`2` înseamnă `crit`

`3` înseamnă `err`

`4` înseamnă `warning`

`5` înseamnă `notice`

`6` înseamnă `info`

și `7` înseamnă `debug`.
</details>

<details>
<summary>Urmărește cele mai recente mesaje de kernel:</summary>
```bash
dmesg -w
```
</details>

<details>
<summary>Caută mesaje specifice de hardware sau driver:</summary>
```bash
# Exemple:
# Pentru a căuta mesaje legate de USB:
dmesg | grep -i usb | less
# Dispozitive Bluetooth:
dmesg | grep -i bluetooth
# Legate de NVIDIA:
dmesg | grep -i nvidia | less
# Dispozitive care nu reușesc să se inițializeze:
dmesg | grep -i "error\|failed" | less
```
</details>

##### Exemple comune pentru probleme specifice folosind dmesg

<details>
<summary>Când un dispozitiv USB nu este recunoscut:</summary>
```bash
dmesg -w | grep -i usb
```
Apoi introdu dispozitivul și urmărește mesajele noi.
</details>

<details>
<summary>Probleme de inițializare GPU:</summary>
```bash
dmesg | grep -i "nvidia\|amd\|intel\|radeon\|drm\|gpu" | less
```
</details>

<details>
<summary>Probleme Wi-Fi sau placă de rețea:</summary>
```bash
dmesg | grep -i "wlan\|wifi\|network\|firmware" | tail -20
```
Verifică dacă lipsesc încărcări de firmware sau dacă există erori de driver care împiedică placa wireless să funcționeze.
</details>

<details>
<summary>Probleme de detectare HDD/SSD:</summary>
```bash
dmesg | grep -i "sda\|sdb\|nvme\|scsi\|disk" | head -30
```
Folosește asta când un dispozitiv de stocare nu este detectat sau arată erori în timpul pornirii.
</details>

<details>
<summary>Sistemul se blochează sau apar kernel panics:</summary>
```bash
dmesg -T -l emerg,alert,crit,err | tail -30
```
Verifică cele mai severe mesaje de kernel care au apărut înainte de un crash sau blocaj de sistem.
</details>

<details>
<summary>Erori de memorie (RAM):</summary>
```bash
dmesg | grep -i "memory\|ram"
```
Caută coruperea memoriei, probleme de detectare sau rapoarte de erori ECC.
</details>

<details>
<summary>Evenimente dispozitive audio:</summary>
```bash
dmesg | grep -i "audio\|snd\|hda" | grep -i "error\|fail\|card"
```
Verifică dacă placa de sunet este detectată corect și dacă driverele se încarcă cum trebuie.
</details>

<details>
<summary>Eșecuri de încărcare a modulelor de kernel:</summary>
```bash
dmesg | grep -i "module\|init" | grep -i "error\|fail"
```
Când driverele hardware specifice nu se încarcă sau eșuează la inițializare.
</details>

<details>
<summary>Monitorizarea în timp real pentru evenimente hardware:</summary>
```bash
dmesg -w -l warn,err,crit,alert,emerg -T
```
Urmărește continuu mesaje de kernel importante noi în timp ce reproduci o problemă.
</details>

<details>
<summary>Probleme de BIOS/UEFI și firmware:</summary>
```bash
dmesg | grep -i "bios\|uefi\|firmware\|efi"
```
Verifică problemele de compatibilitate între firmware-ul hardware-ului tău și kernelul Linux.
</details>

## Instalare și Mediul Live

### De ce ISO-ul live CachyOS include doar KDE Plasma?

Am ales să ne concentrăm eforturile de dezvoltare și întreținere exclusiv pe mediul desktop KDE Plasma. Acest lucru ne permite să oferim o experiență de utilizare mai finisată, mai stabilă și mai consistentă pe ISO-ul nostru live.

Mediul live este destinat în principal instalării CachyOS sau folosirii `cachy-chroot` pentru recuperarea sistemului. Pentru o modalitate sigură de a **testa** alte medii desktop sau window manager-e, îți recomandăm cu tărie să le încerci într-o mașină virtuală (VM).

### De ce durează atât de mult să pornească instalatorul după ce apăs pe „Launch Installer”?

:::caution
Asigură-te că ai o conexiune la internet activă/funcțională, altfel nu se va întâmpla nimic după ce apeși acest buton.
:::

Instalatorul nu este blocat. Acesta rulează un script necesar în fundal pentru a-ți pregăti sistemul de instalare. Acest proces se asigură că inelele de chei (keyrings) și ceasul sistemului sunt la zi, ceea ce ajută la prevenirea problemelor comune de instalare.

[Vezi scriptul pe GitHub](https://github.com/CachyOS/CachyOS-Live-ISO/blob/master/archiso/airootfs/usr/local/bin/calamares-online.sh) pentru a înțelege mai bine ce face.
<Steps>
  1. Șterge fișierele vechi ale inelelor de chei.
  2. Actualizează pachetele Arch Linux și CachyOS keyring la cea mai recentă versiune.
  3. Inițializează și populează inelul de chei pacman.
  4. Activează sincronizarea timpului prin rețea.
  5. Verifică tipul de boot al sistemului tău (UEFI sau BIOS/MBR) pentru a solicita utilizatorului alegerea unui bootloader în funcție de tip.
</Steps>

### De ce instalarea mea se blochează la 33%?

Acest lucru se întâmplă atunci când instalatorul are dificultăți în descărcarea pachetelor. De obicei, este un semn al unei conexiuni la internet foarte lente sau instabile. Te rugăm să îți verifici conexiunea la rețea și să încerci din nou.

## Recuperarea Bootloader-ului și Snapshot-uri Btrfs

:::note
În cazul unei partiții `/boot` șterse, te rugăm să creezi una nouă urmând [schema de partiționare](/ro/installation/installation_on_root#uefigpt) respectivă de la pasul 5.
:::

### Pași pentru a-ți recupera bootloader-ul

:::tip
Dacă nu ești sigur cum să folosești `cachy-chroot`, te rugăm să consulți mai întâi documentația [CachyOS chroot Helper](/ro/features/cachy_chroot).
:::

<Steps>
    1. Pornește de pe ISO-ul Live CachyOS.
    2. Deschide un terminal și intră în chroot în sistemul instalat folosind comanda `cachy-chroot`.

        ```bash
        sudo cachy-chroot
        ```
        Dacă sistemul folosește BTRFS cu presetarea noastră, răspunde cu `y` la întrebare:
         ```bash title='Exemplu'
         Do you want to use CachyOS BTRFS preset to auto mount root subvolume? y
         Do you want to mount additional partitions? · yes
         Enter the mount point for additional partition (e.g. /boot) type 'skip' to cancel:
         # Introdu /boot pentru systemd-boot, Limine sau rEFInd
         # Introdu /boot/efi pentru GRUB
         ```
    3. Urmează instrucțiunile de mai jos pentru bootloader-ul instalat și tipul de sistem (UEFI sau MBR/BIOS).
        <Tabs>
            <TabItem label='GRUB'>
                Reinstalează GRUB cu următoarea comandă:
                <Tabs>
                    <TabItem label='UEFI'>
                        ```bash
                        sudo grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=cachyos
                        ```
                    </TabItem>
                    <TabItem label='MBR/BIOS'>
                        ```bash
                        sudo grub-install --target=i386-pc /dev/sdX # Înlocuiește sdX cu discul tău, ex: sda
                        ```
                    </TabItem>
                </Tabs>
            </TabItem>
            <TabItem label='systemd-boot (doar UEFI)'>
                Reinstalează systemd-boot cu următoarea comandă:
                ```bash
                sudo bootctl install
                ```
            </TabItem>
            <TabItem label='Limine'>
                Reinstalează Limine cu următoarea comandă:
                <Tabs>
                    <TabItem label='UEFI'>
                        ```bash
                        sudo limine-install
                        ```
                    </TabItem>
                    <TabItem label='MBR/BIOS'>
                        ```bash
                        sudo limine bios-install /dev/sdX # Înlocuiește sdX cu discul tău, ex: sda
                        ```
                    </TabItem>
                </Tabs>
            </TabItem>
            <TabItem label='rEFInd (doar UEFI)'>
                Reinstalează rEFInd cu următoarea comandă:
                ```bash
                sudo refind-install
                ```
            </TabItem>
        </Tabs>
    4. Reinstalează kernelul CachyOS:
        ```bash
        sudo pacman -Syu linux-cachyos linux-cachyos-headers
        ```
    5. Ieși din cachy-chroot:
        ```bash
        exit
        ```
    6. Repornește sistemul.
</Steps>

### Folosirea unui snapshot Btrfs ca punct de revenire (rollback)

:::note
Deși CachyOS creează automat snapshot-uri Btrfs înainte de fiecare actualizare a sistemului folosind hook-uri pacman, este întotdeauna o idee bună să-ți creezi propriile snapshot-uri înainte de a face schimbări majore sistemului.
:::

Pentru mai multe informații despre snapshot-urile Btrfs, te rugăm să consulți [documentația Btrfs.](https://btrfs.readthedocs.io/en/latest/)

Un snapshot BTRFS apare ca o intrare suplimentară de boot în meniul bootloader-ului tău și are de obicei un nume de forma:
- `10 | 10-30-2025 14:37:10`

## Gestionarea Pachetelor și Actualizări

### Depanare Pacman

#### error: signature is invalid

Această eroare indică o problemă cu semnătura criptografică a unui pachet. De obicei este cauzată de un mirror învechit sau de un inel de chei defect pe sistemul tău.

Deși mirror-urile se repară adesea singure după scurt timp, dacă problema persistă, ar trebui să încerci una dintre următoarele trei soluții.

<Tabs>

<TabItem label='Prima soluție: Resincronizează Mirror-urile Pacman'>

```sh
sudo pacman -Syu
```

</TabItem>

<TabItem label='A doua soluție: Clasifică-ți Mirror-urile'>

```sh title='Clasifică-ți mirror-urile'
sudo cachyos-rate-mirrors
```

</TabItem>

<TabItem label='A treia soluție: Resetează inelele de chei'>

Dacă clasificarea mirror-urilor nu funcționează, este probabil ca inelele de chei ale sistemului tău să fie defecte.

- Deschide CachyOS Hello și navighează la **Apps/Tweaks**.
- Apasă pe butonul **Reset keyrings**.

</TabItem>

</Tabs>

#### error: 404 Not Found

Această eroare înseamnă că pachetul pe care încerci să-l instalezi nu este disponibil pe mirror-ul tău curent. Acest lucru se întâmplă de obicei când baza ta de date locală de pachete este desincronizată față de repozitoriile la distanță.

**Soluție:**

Rulează următoarea comandă pentru a reîmprospăta baza de date de pachete și pentru a efectua o actualizare completă a sistemului. Acest lucru se va asigura că sistemul tău știe despre cele mai recente pachete disponibile.

```sh
sudo pacman -Syu
# Apoi încearcă să instalezi din nou pachetul dorit.
```

#### error: could not remove

Această eroare apare când cache-ul pacman conține fișiere pe care sistemul nu le poate gestiona automat. Aceasta este o problemă comună care poate fi rezolvată ușor.

- Soluția 1: Folosește CachyOS Hello.
  - Cel mai simplu mod de a repara asta este cu CachyOS Hello. Deschide-l și mergi la **Apps/Tweaks**, apoi apasă pe butonul **Clear package cache**.

- Soluția 2: Șterge manual cache-ul.
  - Rulează următoarea comandă pentru a elimina toate pachetele orfane din cache.
  ```sh
  sudo rm -r /var/cache/pacman/pkg/*
  ```

#### error: File is corrupted (invalid or corrupted package (PGP signature))

```sh
# Exemplu:
:: File /var/cache/pacman/pkg/python-charset-normalizer-3.4.0-1-any.pkg.tar.zst
is corrupted (invalid or corrupted package (PGP signature)).
```

Această eroare indică de obicei o problemă cu inelele de chei pacman ale sistemului tău, care verifică autenticitatea pachetelor. Următoarele comenzi vor reseta și repopula inelele de chei pentru a rezolva problema.

```sh
sudo rm -rf /etc/pacman.d/gnupg/
sudo pacman-key --init
sudo pacman-key --populate

sudo pacman-key --recv-keys F3B607488DB35A47 --keyserver keyserver.ubuntu.com
sudo pacman-key --lsign-key F3B607488DB35A47

sudo rm -R /var/lib/pacman/sync
```

Dacă pașii de mai sus nu funcționează, înseamnă că inelul tău de chei nu este problema. Ar putea fi o problemă cu mirror-urile tale, deci poți selecta mirror-uri funcționale și apoi să-ți cureți cache-ul rulând următoarele:

```sh
sudo cachyos-rate-mirrors
sudo pacman -Scc
```

#### error: unable to lock database

Această eroare apare când un alt proces pacman rulează deja, ceea ce blochează baza de date pentru a preveni coruperea acesteia. Dacă procesul anterior s-a blocat sau a fost întrerupt, fișierul de blocare `db.lck` s-ar putea să nu fi fost șters.

- Soluția 1: Folosește CachyOS Hello
  - Cel mai simplu mod de a repara asta este cu funcția **Remove db lock** din tab-ul **Apps/Tweaks** al CachyOS Hello.

- Soluția 2: Șterge manual fișierul de blocare
  - Dacă preferi să nu folosești CachyOS Hello, poți șterge manual fișierul de blocare:

```sh
sudo rm /var/lib/pacman/db.lck
```

#### error: failed retrieving file ... Connection timed out

S-ar putea să vezi erori de genul:

```text
# Exemple de erori:
error: failed retrieving file '...' from ... : Connection timed out
error: failed retrieving file '...' from ... : Couldn't resolve host name
error: failed retrieving file '...' from ... : The requested URL returned error: 526
```

Aceste erori indică aproape întotdeauna o problemă cu mirror-urile tale actuale. Acestea pot fi lente, temporar indisponibile sau inaccesibile din locația ta.

- Soluție: Cea mai bună metodă de a repara asta este să-ți actualizezi lista de mirror-uri cu unele mai rapide și mai fiabile.

```sh
sudo cachyos-rate-mirrors
# Apoi, îți poți actualiza sistemul cu:
sudo pacman -Syu
```

:::tip
Comanda `cachyos-rate-mirrors` testează mirror-urile CachyOS disponibile pe baza vitezei și a stării de sincronizare, apoi îți actualizează fișierul cu lista de mirror-uri (`/etc/pacman.d/cachyos-mirrorlist`) cu cele care au cea mai bună performanță.

Ia în considerare rularea ei periodică, în special dacă observi încetiniri în timpul actualizărilor de sistem.
:::

#### warning: local is newer than...

Această avertizare apare când o versiune a unui pachet de pe sistemul tău este mai nouă decât versiunea disponibilă în repozitoriile oficiale. Acest lucru se poate întâmpla dacă un mirror este învechit, dacă un pachet a fost retrogradat în repozitorii sau dacă un pachet a fost instalat dintr-o altă sursă.

- Soluție: comanda `pacman -Syuu` efectuează o actualizare completă a sistemului și permite retrogradările, ceea ce va rezolva avertizarea prin sincronizarea pachetelor tale locale cu versiunile din repozitoriu.

```sh title='Pentru a elimina aceste avertizări, execută următoarea comandă:'
sudo pacman -Syuu
```

#### error: failed to commit transaction (conflicting files)

Această eroare indică faptul că pacman încearcă să instaleze sau să actualizeze un pachet care conține fișiere prezente deja pe sistemul tău dintr-o altă sursă. Aceasta este o funcție de siguranță încorporată pentru a preveni stricarea sistemului.

- Soluție: Poți rezolva această problemă ștergând manual fișierele aflate în conflict. Pentru mai multe informații și soluții, te rugăm să consulți [Arch Wiki](https://wiki.archlinux.org/title/Pacman#%22Failed_to_commit_transaction_(conflicting_files)%22_error).

```sh title='Exemplu'
error: failed to commit transaction (conflicting files)
nvidia-utils: /usr/lib/environment.d/10-gsk.conf exists in filesystem
Errors occurred, no packages were upgraded.
 -> error installing repo packages
```

Pentru a repara acest exemplu specific, ar trebui să ștergi fișierul în conflict și apoi să rulezi din nou comanda de actualizare.

```sh
sudo rm /usr/lib/environment.d/10-gsk.conf
```

#### ERROR: module not found: 'nvidia', 'nvidia_modeset', ...

```sh title='Exemplu'
==> ERROR: module not found: 'nvidia'
==> ERROR: module not found: 'nvidia_modeset'
==> ERROR: module not found: 'nvidia_uvm'
==> ERROR: module not found: 'nvidia_drm'
```

**Două motive pentru această eroare:**

1) Deoarece „Early Module Loading” este întotdeauna activat în chwd, mkinitcpio se așteaptă constant la prezența modulelor NVIDIA; această eroare apare atunci când acele module lipsesc.

2) S-ar putea să-ți lipsească modulele NVIDIA pentru alte kerneluri instalate pe sistemul tău.

```sh title='Instalează următorul pachet pentru a repara această eroare'
sudo pacman -S nvidia
```

### Întrebări generale

#### Care este originea CachyOS și de ce se numește „CachyOS”?

CachyOS este numit după planificatorul (scheduler) „Cachy”, care a fost numele original al [planificatorului cacULE](https://github.com/hamadmarri/cacule-cpu-scheduler), un planificator CPU pentru kernelul Linux.

Proiectul a luat naștere în 2020-2021 când ptr1337 (unul dintre fondatorii CachyOS) testa și colabora cu un dezvoltator pe nume Hamad la planificatorul cacULE. Când au decis să creeze o distribuție Linux optimizată bazată pe Arch Linux, cu pachete optimizate x86-64-v3, au numit-o „CachyOS” după planificatorul care i-a adus împreună.

#### Care este intervalul la care sunt actualizate pachetele -git?

De obicei o dată pe săptămână, lunea, deși pot exista excepții.

#### Pachetele -bin din repozitoriile CachyOS beneficiază de aceleași optimizări de performanță?

Nu. Pachetele `-bin` sunt binare precompilate și nu includ aceleași optimizări de performanță ca pachetele bazate pe sursă din repozitoriile CachyOS.

#### Cum să dezactivezi animația de pornire (Plymouth)

:::note[Acest lucru ar putea rezolva problema ecranului negru pe unele sisteme, în special pe cele cu GPU-uri NVIDIA vechi.]
:::

Pentru a dezactiva animația de pornire, trebuie să-ți editezi [configurația bootloader-ului](/ro/configuration/boot_manager_configuration) și să adaugi următorii parametri de kernel:

```sh
plymouth.enable=0 disablehooks=plymouth
```

:::note[systemd-boot, GRUB și Limine necesită regenerarea imaginilor initramfs]
systemd-boot: `sudo sdboot-manage gen`

GRUB: `sudo grub-mkconfig -o /boot/grub/grub.cfg`

Limine: `sudo limine-mkinitcpio`
:::

#### Trimiterea cererilor de pachete către CachyOS

CachyOS oferă o listă extinsă de pachete AUR precompilate, care sunt utilizate în mod obișnuit.
Utilizatorii pot crea cereri pentru pachete AUR, care, dacă sunt aprobate, sunt actualizate automat de serverul nostru de build.

Dacă vrei să adăugăm un pachet, poți trimite o cerere pe GitHub sau pe forum.

- [GitHub](https://github.com/CachyOS/distribution/issues)
- [Forum](https://discuss.cachyos.org/c/feedback/repository/11)
- [Canalul de feedback de pe Discord](https://discord.com/channels/862292009423470592/1150723027986813018)

## Securitate și bune practici

### Practici de siguranță pentru AUR

AUR oferă o selecție vastă, dar securitatea este primordială. Iată un ghid concis pentru utilizarea sigură a AUR pe sistemul tău CachyOS.

* **Înțelege PKGBUILD-ul:** Este scriptul de build. Cunoaște-i structura, variabilele (`source`, `pkgname`) și funcțiile (`build()`, `package()`).
* **Verifică link-urile sursă:** Verifică întotdeauna ca URL-urile din `source` să indice către site-urile oficiale ale proiectelor sau către repozitorii de încredere. Evită link-urile suspecte sau personale.
* **Revizuiește pașii de instalare:** Inspectează unde sunt instalate fișierele (funcția `package()`) și dacă există comenzi neobișnuite sau care ating zone sensibile ale sistemului. Verifică și scripturile `.install`.
* **Cercetează menținătorul (maintainer):** Verifică istoricul menținătorului pe AUR pentru orice probleme de securitate trecute sau activitate suspectă.
* **Verifică Checksum-urile și PGP:** Absolut crucial! Confirmă că toate checksum-urile (SHA256, BLAKE2b etc.) se potrivesc cu cele oficiale. Folosește semnăturile PGP (`validpgpkeys`) pentru autenticitate atunci când sunt disponibile.
* **Fii precaut cu pachetele `-bin`:** Acestea folosesc binare precompilate, ceea ce înseamnă că nu poți inspecta sursa. Aplică o examinare maximă originilor și integrității lor.
* **Citește comentariile comunității:** Verifică comentariile de pe pagina AUR pentru avertismente, probleme sau informații de la alți utilizatori.
* **Nu sări niciodată peste verificările de integritate:** Folosirea `--skipinteg` sau a flag-urilor similare ocolește toate verificările de securitate. Nu o face.
* **Controlează-ți asistentul AUR (AUR helper):** Înțelege cum funcționează asistentul tău (yay, paru). Asigură-te că îți arată PKGBUILD-ul și diferențele (diffs), sau construiește manual cu `makepkg`.
* **Evaluează necesitatea:** Înainte de a instala, întreabă-te dacă ai cu adevărat nevoie de acest pachet AUR sau dacă există o alternativă în repozitoriile oficiale.
* **Păstrează-ți sistemul actualizat:** Rulează regulat `sudo pacman -Syu` pentru a te asigura că toate componentele sistemului tău, inclusiv `pacman` și `makepkg`, au cele mai recente patch-uri de securitate.

Rămâi vigilent pentru a-ți păstra sistemul bazat pe Arch în siguranță!

### Alegerea unui manager de pachete GUI

Deși managerii de pachete grafici oferă confort, unii dintre ei sunt cunoscuți pentru faptul că provoacă probleme grave pe sistemele de tip rolling-release precum CachyOS și ar trebui evitați pentru gestionarea pachetelor de sistem.

- **Pamac:** este cunoscut pentru gestionarea necorespunzătoare a anumitor sarcini, cum ar fi coruperea inelelor de chei ale pachetelor de sistem. Acest lucru poate duce la erori de semnătură PGP care te împiedică să-ți actualizezi sistemul.
- **Discover (KDE) și GNOME Software Center:** Aceste magazine de aplicații folosesc backend-ul PackageKit. Deși sunt în general sigure pentru gestionarea Flatpak-urilor, folosirea lor pentru a instala sau actualiza **pachete de sistem** este riscantă. Managerii bazați pe PackageKit pot fi, de asemenea, instabili sau predispuși la blocări, ceea ce ți-ar putea lăsa sistemul într-o stare defectuoasă după o tranzacție eșuată.

Pentru stabilitate și fiabilitate maximă, **îți recomandăm cu tărie** gestionarea pachetelor de sistem prin linia de comandă cu `pacman`.

Dacă preferi o interfață grafică, soluțiile de tip front-end precum **[Octopi](</ro/configuration/post_install_setup/#actualizarea-sistemului>)** sau **CachyOS Package Installer** sunt considerate alternative sigure, deoarece sunt doar interfețe directe pentru funcționalitatea pacman.
