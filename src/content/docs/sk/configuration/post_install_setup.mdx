<TabItem label="Použitím Octopi (GUI)">

Octopi je grafický správca balíkov pre distribúcie založené na Archu, ktorý poskytuje pohodlný spôsob správy balíkov a aktualizácií.
Ak chcete aktualizovať svoj systém pomocou Octopi, postupujte podľa týchto krokov:

<Steps>

1. Spustite **Octopi** z ponuky aplikácií.
2. V hlavnom okne kliknite na tlačidlo **Skontrolovať aktualizácie** (vľavo hore) a potom vedľa neho na **Aktualizácia systému**.
3. Octopi teraz skontroluje dostupné aktualizácie a vyzve vás, aby ste ich nainštalovali buď priamo v Octopi, alebo v termináli.
4. Ak chcete pokračovať v aktualizácii, kliknite na tlačidlo **Použiť**.
5. Octopi stiahne a nainštaluje aktualizácie.
6. Odporúča sa reštartovať počítač po rozsiahlej aktualizácii **(najmä ak sa aktualizovalo jadro)**.

</Steps>

</TabItem>

<TabItem label="Použitím Pacman">

<Steps>

1. Otvorte emulátor terminálu (alebo stlačte `ctrl + alt + t` – `mod + return` v správcovi okien, napr. Qtile).
2. Spustite nasledujúci príkaz na aktualizáciu systému:

   ```sh
   sudo pacman -Syu
   ```
3. Odporúča sa reštartovať počítač po rozsiahlej aktualizácii **(najmä ak sa aktualizovalo jadro)**.

</Steps>

</TabItem>

<TabItem label="Offline aktualizácia systému">

*CachyOS podporuje offline aktualizácie systému pomocou skriptu [`pacman-offline`](https://github.com/eworm-de/pacman-offline). To umožňuje vášmu systému stiahnuť aktualizácie balíkov a použiť ich pri nasledujúcom reštarte. (Áno, ako vo Windows)*

:::note
Nástroj `pacman-offline` sa integruje s funkciou offline aktualizácií systému systemd. Automaticky spracováva aktualizácie jadra a načítanie modulov.

Súbor `/etc/pacman.d/offline.conf` je kľúčový pre správu toho, ktoré balíky sa aktualizujú počas bežných a offline aktualizácií. Uistite sa, že je správne nakonfigurovaný pre vaše požadované jadro, alebo pridajte balíky, ktoré chcete aktualizovať iba počas vykonávania `pacman-offline` a ignorovať ich pri bežnej aktualizácii. Príklad: `pacman -Syu`.

**Ak povolíte časovač automatických aktualizácií, už nemusíte manuálne aktualizovať svoj systém.**
:::

<Steps>

1. **Nainštalujte balík pacman-offline**

   ```bash
   sudo pacman -S pacman-offline
   ```

2. **Nastavte Pacman tak, aby čítal zo samostatného zoznamu ignorovaných balíkov.**

   :::note[Pridajte tento riadok za sekciu [options]. Ako referenciu si pozrite príklad nižšie.]
   :::

   ```bash title='Pridajte nasledujúci riadok do súboru /etc/pacman.conf'
   Include = /etc/pacman.d/offline.conf
   ```
   *Príklad*
   ```bash
   # /etc/pacman.conf
   # REPOSITORIES
   #   - can be defined here or included from another file
   #   - pacman will search repositories in the order defined here
   #   - local/custom mirrors can be added here or in separate files
   #   - repositories listed first will take precedence when packages
   #     have identical names, regardless of version number
   #   - URLs will have $repo replaced by the name of the current repo
   #   - URLs will have $arch replaced by the name of the architecture
   #
   # Repository entries are of the format:
   #       [repo-name]
   #       Server = ServerName
   #       Include = IncludePath
   #
   # The header [repo-name] is crucial - it must be present and
   # uncommented to enable the repo.
   #
   # GENERAL OPTIONS
   [options]
   # other options like 'Color', 'CheckSpace', etc. can be here
   Include = /etc/pacman.d/offline.conf
   ```
3. **Pridanie jadier CachyOS, aby ich Pacman ignoroval počas bežných aktualizácií**

   Nástroj `pacman-offline` používa tento súbor na určenie, ktoré balíky sa majú ignorovať počas tradičných aktualizácií pomocou Pacmanu.

   Príklad: keď spustíte `sudo pacman -Syu`

   *Nahraďte obsah súboru `/etc/pacman.d/offline.conf` nasledujúcim:*

   ```text
   # Jadrá Arch Linuxu
   IgnorePkg = linux linux-headers linux-docs
   IgnorePkg = linux-lts linux-lts-headers linux-lts-docs
   IgnorePkg = linux-zen linux-zen-headers linux-zen-docs
   IgnorePkg = linux-hardened linux-hardened-headers linux-hardened-docs

   # Jadrá CachyOS
   IgnorePkg = linux-cachyos linux-cachyos-headers linux-cachyos-nvidia-open linux-cachyos-zfs
   IgnorePkg = linux-cachyos-bmq linux-cachyos-bmq-headers linux-cachyos-bmq-nvidia-open linux-cachyos-bmq-zfs
   IgnorePkg = linux-cachyos-bore linux-cachyos-bore-headers linux-cachyos-bore-nvidia-open linux-cachyos-bore-zfs
   IgnorePkg = linux-cachyos-deckify linux-cachyos-deckify-headers linux-cachyos-deckify-nvidia-open linux-cachyos-deckify-zfs
   IgnorePkg = linux-cachyos-eevdf linux-cachyos-eevdf-headers linux-cachyos-eevdf-nvidia-open linux-cachyos-eevdf-zfs
   IgnorePkg = linux-cachyos-gcc linux-cachyos-gcc-headers linux-cachyos-gcc-nvidia-open linux-cachyos-gcc-zfs
   IgnorePkg = linux-cachyos-hardened linux-cachyos-hardened-headers linux-cachyos-hardened-nvidia-open linux-cachyos-nvidia-hardened-zfs
   IgnorePkg = linux-cachyos-lts linux-cachyos-lts-headers linux-cachyos-lts-nvidia-open linux-cachyos-lts-zfs
   IgnorePkg = linux-cachyos-rc linux-cachyos-rc-headers linux-cachyos-rc-nvidia-open linux-cachyos-rc-nvidia-open linux-cachyos-rc-zfs
   IgnorePkg = linux-cachyos-rt-bore linux-cachyos-rt-bore-headers linux-cachyos-rt-bore-nvidia-open
   IgnorePkg = linux-cachyos-server linux-cachyos-server-headers linux-cachyos-server-nvidia-open linux-cachyos-server-zfs
   ```

   *Teraz sa všetky tieto balíky budú ignorovať pri bežných aktualizáciách, ale budú sa kontrolovať počas offline prípravy.*

3. **Spustite prípravu na offline aktualizáciu iba raz**

   ```bash title='Spustite nasledujúci príkaz'
   sudo systemctl start pacman-offline-prepare.service
   ```
   Tento príkaz spustí `pacman-offline` jedenkrát, synchronizuje databázy balíkov a stiahne aktualizácie, ale nenainštaluje ich.

</Steps>

*Ak chcete, aby bol tento skript zautomatizovaný, postupujte podľa nasledujúcich krokov:*

<Steps>

1. **Povoľte časovač prípravy**

   Povolenie `pacman-offline-prepare.timer` umožní systemd spúšťať tento skript na sťahovanie aktualizácií denne, niekoľko minút po každom spustení systému.

   ```bash
   sudo systemctl enable pacman-offline-prepare.timer
   ```

2. **Reštartujte systém:**

   Aktualizácie sa nainštalujú počas nasledujúceho reštartu systému.

3. **(Voliteľné) Automatické reštarty systému:**

    Povoľte `pacman-offline-reboot.timer` na automatické reštartovanie systému predvolene o **3:00** (vaše časové pásmo), ak sú k dispozícii čakajúce aktualizácie. Uvedomte si, že to nie je vždy v presne rovnakom čase kvôli voľbe `RandomizedDelaySec`, ktorá je predvolene nastavená na 2 hodiny.

    ```bash
    sudo systemctl enable pacman-offline-reboot.timer
    ```

    :::tip
    Môžete upraviť súbor `pacman-offline-reboot.timer`, ak chcete zmeniť čas, kedy sa má systém reštartovať pri čakajúcich aktualizáciách, alebo zakázať náhodné posunutie plánu.
    :::

</Steps>

</TabItem>

<TabItem label="Cachy-Update">

Fork nástroja [Arch-Update](https://github.com/Antiz96/arch-update)

Oznamovateľ a aplikátor aktualizácií pre Arch Linux, ktorý vám pomáha s dôležitými úlohami pred aktualizáciou a po nej.
Obsahuje dynamický a klikateľný applet v oznamovacej oblasti na jednoduchú integráciu s akýmkoľvek pracovným prostredím alebo správcom okien.

<details>
    <summary>Ako povoliť Cachy-Update</summary>
    Povoľte Cachy-Update v ponuke `CachyOS Hello > Apps/Tweaks > Cachy Update enabled`
</details>
<details>
    <summary>Ako zakázať Cachy-Update</summary>
        Zakážte Cachy-Update v ponuke `CachyOS Hello > Apps/Tweaks > Cachy Update disabled`
            :::tip
            Ak si chcete Cachy-Update ponechať a zakázať iba applet v oznamovacej oblasti, otvorte terminál a spustite nasledujúce príkazy:
            ```bash
            mkdir -p ~/.config/autostart
            echo -e "[Desktop Entry]\nHidden=true" > ~/.config/autostart/arch-update-tray.desktop
            ```
            Ak si chcete ponechať applet v oznamovacej oblasti zapnutý a iba zakázať automatickú kontrolu aktualizácií, spustite nasledujúci príkaz:
            ```bash
            systemctl --user disable --now arch-update.timer
            ```
            :::
</details>

- Funkcie:
  - Automatická kontrola a zobrazenie dostupných aktualizácií.
  - Kontrola najnovších noviniek Arch Linuxu (s možnosťou ich zobrazenia, ak existujú).
  - Kontrola osirotených balíkov (s možnosťou ich odstránenia, ak existujú).
  - Kontrola starých a odinštalovaných balíkov vo vyrovnávacej pamäti (s možnosťou ich odstránenia, ak existujú).
  - Kontrola čakajúcej aktualizácie jadra vyžadujúcej reštart (s možnosťou reštartu, ak je potrebný).
  - Kontrola služieb vyžadujúcich reštart po aktualizácii (s možnosťou ich reštartu, ak existujú).
  - Podpora pre `sudo`, `sudo-rs`, `doas` a `run0`.

**Interval kontroly aktualizácií:** `Raz dve minúty po spustení a potom raz denne s hodinovým náhodným oneskorením.`

- Ako zmeniť interval kontroly aktualizácií:

```sh title='Spustite nasledujúci príkaz'
systemctl --user edit --full arch-update.timer
# Tip: Namiesto `nano` môžete použiť aj ľubovoľný textový editor podľa vlastného výberu
# napr. EDITOR=micro systemctl --user edit --full arch-update.timer
```

<details>
<summary>Predvolený obsah súboru:</summary>
    ```systemd
    [Timer]
    OnStartupSec=2min # Kontrola aktualizácií dve minúty po spustení
    RandomizedDelaySec=1h # Jednohodinové náhodné oneskorenie
    OnUnitActiveSec=1d # Kontrola aktualizácií raz denne
    ```
</details>
Hodnotu `OnUnitActiveSec` môžete zmeniť prakticky na čokoľvek chcete. Ak chcete napríklad kontrolovať aktualizácie každých 30 minút, zmeňte ju na `30m`, alebo každých 6 hodín na `6h`. Podrobnosti o tom, ako nastaviť časový interval, nájdete v tomto [dokumente](https://www.freedesktop.org/software/systemd/man/latest/systemd.time.html#Parsing%20Time%20Spans).

V prípade, že chcete, aby Cachy-Update kontroloval nové aktualizácie iba raz pri spustení systému, môžete riadok `OnUnitActiveSec` jednoducho úplne odstrániť.

Poďakovanie patrí [Antiz](https://github.com/Antiz96) za udržiavanie nadradeného projektu Arch-Update a za implementáciu Cachy-Update.

### Konfigurácia firewallu (ufw)
:::note
UFW je po inštalácii predvolene zapnutý.
:::
Ak chcete konfigurovať ufw, postupujte podľa týchto krokov:

<Tabs>

<TabItem label="Zapnúť">

```bash
sudo ufw enable
```

</TabItem>

<TabItem label="Vypnúť">

```bash
sudo ufw disable
```

</TabItem>

<TabItem label="Povoliť">

Predvolene ufw ignoruje prichádzajúcu a povoľuje odchádzajúcu prevádzku; do firewallu môžete pridať konkrétne pravidlá na blokovanie alebo povolenie konkrétnych pripojení.

```bash
# Príklad 1, povolenie ssh prevádzky:
sudo ufw allow ssh
# Príklad 2, otvorenie portu 12345 pre TCP a UDP prevádzku:
sudo ufw allow 12345

# Text alebo číslo portu je možné upraviť podľa potreby, napríklad 12345/udp na povolenie iba UDP prevádzky alebo nahradenie ssh názvom programu
```

</TabItem>

<TabItem label="Zamietnuť">

Predvolene ufw ignoruje prichádzajúcu a povoľuje odchádzajúcu prevádzku; do firewallu môžete pridať konkrétne pravidlá na blokovanie alebo povolenie konkrétnych pripojení.

```bash
# Príklad 1, zamietnutie ssh prevádzky:
sudo ufw deny ssh
# Príklad 2, zatvorenie portu 12345 pre TCP a UDP prevádzku:
sudo ufw deny 12345

# Text alebo číslo portu je možné upraviť podľa potreby, napríklad 12345/udp na zamietnutie iba UDP prevádzky alebo nahradenie ssh názvom programu
```

</TabItem>

<TabItem label="Stav">

```bash
sudo ufw status verbose
```
:::tip
Ak nechcete zabudnúť, prečo ste port otvorili alebo zatvorili, pridajte k pravidlu komentár.
```bash
# Príklad 1, otvorenie portu 12345 pre TCP a UDP prevádzku s komentárom:
sudo ufw allow 12345 comment 'Example'
# Príklad 2, zatvorenie portu 6789 pre TCP s komentárom:
sudo ufw deny 6789/tcp comment 'Comments can have spaces'
```
:::
</TabItem>

</Tabs>

:::note
Pri konfigurácii pravidiel firewallu buďte opatrní, pretože nesprávne nakonfigurované pravidlá vás môžu vymknúť z vlastného systému.
:::

:::note
Môžete ho konfigurovať aj graficky pomocou sekcie „Firewall“ v nastaveniach KDE Plasma.
:::

:::note
Zmeny v pravidlách povolenia/zamietnutia sa prejavia až po reštartovaní ufw. Pre okamžitý výsledok ufw vypnite a znova zapnite.
:::

## Voliteľné konfigurácie

### Zmena predvoleného shellu

V súčasnosti CachyOS používa [fish](https://fishshell.com/) ako predvolený prihlasovací shell používateľa. Môžete ho však zmeniť
na ľubovoľný iný shell.

<Tabs>
   <TabItem label='bash'>

      Toto je predvolený shell takmer v každej distribúcii Linuxu. Stále sa používa aj ako prihlasovací shell pre používateľa root. bash
      má základnú funkciu automatického dopĺňania a jednoduchú správu histórie. Od zsh a fish sa líši tým, že nemá
      pokročilé možnosti prispôsobenia a ekosystém zásuvných modulov, ktorými disponujú fish aj zsh.


      ```sh title='Zmena predvoleného shellu na bash'
      chsh -s /usr/bin/bash
      ```

   </TabItem>

   <TabItem label='zsh'>

      Poskytujeme [konfiguráciu pre zsh](https://github.com/CachyOS/cachyos-zsh-config) s bežne používanými zásuvnými modulmi a nastaveniami.
      Jej cieľom je mať funkčnosť 1:1 s našou [konfiguráciou pre fish](https://github.com/CachyOS/cachyos-fish-config).
      Toto je tiež predvolený shell používaný v systéme macOS.

      ```sh title='Zmena predvoleného shellu na zsh'
      chsh -s /usr/bin/zsh
      ```

   </TabItem>
</Tabs>

### Správa AppImage balíkov

AppImage sú prenosné aplikácie, ktoré bežia na väčšine distribúcií Linuxu bez potreby inštalácie alebo oprávnení root.

:::note[Všetky súbory AppImage vyžadujú na spustenie povolenie na spúšťanie.]
Povolenie na spúšťanie môžete nastaviť pomocou nasledujúceho príkazu:
```sh
chmod +x /cesta/k/vasmu/appimage
```
Alebo kliknite pravým tlačidlom na súbor AppImage, prejdite do `Properties` > `Permissions` a začiarknite políčko `Allow executing file as program`.
:::

:::note[Pred spustením súborov AppImage sa uistite, že máte v systéme nainštalovaný FUSE (Filesystem in Userspace).]
```sh
sudo pacman -S fuse2
```
:::

Na správu súborov AppImage môžete použiť nástroj [gearlever](https://github.com/mijorus/gearlever), ktorý poskytuje jednoduchý spôsob integrácie AppImage do vášho systému.

`gearlever` je grafický nástroj, ktorý zjednodušuje správu súborov AppImage vo vašom systéme. Integruje sa s vaším pracovným prostredím, čo uľahčuje spúšťanie a správu AppImage aplikácií.

Ak chcete nainštalovať gearlever, postupujte podľa týchto krokov:

<Steps>
    1. Nainštalujte flatpak, ak ho ešte nemáte:
        ```sh
        sudo pacman -S flatpak
        ```
    2. Reštartujte systém.
    3. Nainštalujte gearlever pomocou nástroja flatpak:
        ```sh
        flatpak install flathub it.mijorus.gearlever
        ```
    4. Po inštalácii sa odhláste a znova prihláste, aby sa gearlever zobrazil v ponuke aplikácií.
</Steps>

### Konfigurácia prístupu k zdieľaniam Samba

Samba je slobodná softvérová reimplementácia sieťového protokolu SMB. Na pripojenie k vášmu serveru Samba je pre používateľov CachyOS pripravená užitočná konfigurácia, vyžaduje si však úpravu konfigurácie vášho servera Samba.

#### Inštalácia a používanie súboru smb.conf z CachyOS

Ak chcete použiť pripravený súbor `smb.conf`, najprv nainštalujte príslušný balík, ktorý poskytuje požadovaný súbor `smb.conf`. Potom nahraďte existujúci súbor `smb.conf` na vašom serveri týmto súborom a znova nakonfigurujte zdieľané priečinky.

:::note[Táto príručka predpokladá, že už máte funkčný server Samba]
:::

<Steps>
    1. Vytvorte zálohu pôvodného súboru `smb.conf`, ktorý sa na linuxových systémoch zvyčajne nachádza v `/etc/samba/smb.conf`.
    2. Nainštalujte balík nastavení CachyOS Samba na klientskom počítači:
        ```sh
        sudo pacman -S cachyos-samba-settings
        ```
    3. Skopírujte `smb.conf` z klientskeho počítača na server Samba.
    4. Otvorte a upravte súbor tak, aby obsahoval vaše zdieľané priečinky, tlačiarne atď.
    5. Reštartujte službu Samba na serveri:
        ```sh
        sudo systemctl restart --now samba
        ```
    6. Na klientskom počítači otvorte zdieľané prostriedky prostredníctvom správcu súborov (napr. `smb://<ip_adresa_servera>/<nazov_zdielania>`).

        Ak je všetko nakonfigurované správne, zobrazí sa výzva na zadanie prihlasovacích údajov. Ak chcete, nezabudnite vybrať možnosť uloženia prihlasovacích údajov.
</Steps>

### Podpora AppArmor pomocou profilov AppArmor.d

Citát z Wikipédie:

*AppArmor („Application Armor“) je bezpečnostný modul linuxového jadra, ktorý umožňuje správcovi systému obmedzovať oprávnenia programov pomocou profilov pre jednotlivé programy. Profily môžu povoľovať možnosti, ako je prístup k sieti, prístup k surovým soketom a oprávnenie na čítanie, zápis alebo spúšťanie súborov na zodpovedajúcich cestách.*

Ide len o úvod do inštalácie základného nastavenia AppArmor. Ak nie ste s AppArmor oboznámení, nepokračujte bez pochopenia dôsledkov.

Podrobnejšie informácie o AppArmor.d a o tom, ako si vytvoriť vlastné profily, nájdete v [dokumentácii AppArmor.d](https://github.com/roddhjav/apparmor.d?tab=readme-ov-file#configuration).

:::caution[Postupujte opatrne. Nesprávne nakonfigurovaný AppArmor môže spôsobiť problémy.]
:::

<Steps>

1. Pridajte nasledujúce parametre jadra do svojho zavádzača, pozrite si [Konfigurácia zavádzača](/sk/configuration/boot_manager_configuration) ako referenciu

   ```text
   lsm=landlock,lockdown,yama,integrity,apparmor,bpf
   ```

2. Nainštalujte balíky apparmor a apparmor.d **(Sada viac ako 1500 profilov)**
   ```bash
   sudo pacman -S apparmor apparmor.d
   ```

3. Povoľte a spustite službu AppArmor

   ```bash
   systemctl enable --now apparmor.service
   ```

4. Povoľte ukladanie profilov AppArmor do vyrovnávacej pamäte

   ```shell
   # /etc/apparmor/parser.conf
   ## Pridajte nasledujúce riadky:
   write-cache
   Optimize=compress-fast
   cache-loc /etc/apparmor/earlypolicy/
   ```
   Uložte súbor a reštartujte.
</Steps>

### Povolenie príkazu TRIM na šifrovaných zariadeniach (LUKS)

CachyOS predvolene zapína `fstrim.timer`, ktorý pravidelne vykonáva TRIM na diskoch SSD a NVMe, čím pomáha udržiavať výkon zápisu a životnosť disku. Šifrovacia vrstva device-mapper v Linuxe (`dm-crypt`/LUKS) však príkazy discard (TRIM) predvolene blokuje. Výsledkom je, že pravidelný TRIM prebieha potichu bez toho, aby šifrované partície skutočne čistil, pokiaľ nie je preposielanie príkazu discard výslovne povolené.

:::caution[Bezpečnostné aspekty a ochrana súkromia]
Povolenie príkazu TRIM na šifrovanom zariadení umožňuje radiču SSD vidieť, ktoré sektory sú prázdne a ktoré obsahujú dáta. Hoci vaše dáta zostávajú plne zašifrované, útočník s fyzickým prístupom k surovému úložisku by mohol odvodiť približne využitý priestor úložiska, rozloženie súborového systému alebo vzory dát.

Ak je takýto únik metadát prijateľný pre váš model ohrozenia, môžete preposielanie príkazu discard bezpečne povoliť pre lepší výkon a dlhšiu životnosť SSD.
:::

#### Povolenie preposielania discard (LUKS2)

<Steps>
1. Zistite názov vášho aktívneho mapovania LUKS:

   ```bash
   lsblk
   ```

   Vyhľadajte záznam typu `crypt` pod svojou diskovou partíciou (napr. `luks-1e647929-62c0-4922-8944-f941ed4155fd`).

2. Povoľte trvalé preposielanie príkazu discard na aktívnom mapovaní LUKS:

   ```bash
   sudo cryptsetup --allow-discards --persistent refresh <mapper_name>
   ```

   :::note
   Nahraďte `<mapper_name>` vaším skutočným názvom mapovania z kroku 1 (napríklad `sudo cryptsetup --allow-discards --persistent refresh luks-1e647929-62c0-4922-8944-f941ed4155fd`).
   :::

3. Reštartujte systém, aby sa zmeny prejavili.

4. Overte, či je preposielanie príkazu discard aktívne:

   ```bash
   lsblk -D
   sudo fstrim -v /
   ```

   `lsblk -D` by teraz malo v stĺpcoch `DISC-GRAN` a `DISC-MAX` pre váš šifrovaný zväzok zobrazovať nenulové hodnoty a `fstrim` vypíše množstvo uvoľneného miesta namiesto preskočenia zariadenia.
</Steps>
