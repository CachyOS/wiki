## Ako nahlásiť problém alebo chybu v CachyOS

*Pamätajte si, že vo svete Linuxu platí skvelé príslovie: „S najväčšou pravdepodobnosťou mal rovnaký problém už niekto pred vami.“ Preto pred nahlásením problému najprv použite vyhľadávanie na Google, Arch Wiki alebo na CachyOS Fóre/Discorde, pretože riešenie už možno existuje.*

Nezabudnite použiť príkaz `tldr` na zobrazenie zjednodušenej verzie manuálových stránok pre príkazy, ktoré nepoznáte. Príklad:

Niektoré z najbežnejších príkazov a popisov pre git:
```bash
tldr git
```

Môžete tiež skombinovať `tldr` s konkrétnym príkazom git, aby ste získali podrobnejšie informácie o parametri, napríklad:
```bash
tldr git add
```

### Buďte trpezliví a úctiví

Tím CachyOS a komunita sú dobrovoľníci, ktorí na projekte pracujú vo svojom voľnom čase. Pri komunikácii s nimi buďte prosím trpezliví a úctiví. Kvalitné hlásenie chyby je najlepší spôsob, ako svoj problém vyriešiť rýchlo.

Ak položíte nejasnú otázku alebo poskytnete nedostatočné informácie, pravdepodobne dostanete nejasnú odpoveď alebo žiadnu.

Tu je príklad:

- **Dobrá otázka:**
  - Po nedávnej aktualizácii (poslednú aktualizáciu som vykonal dňa DÁTUM) sa môj systém nespustí a zobrazí sa iba čierna obrazovka. Mám GPU NVIDIA (model). Skúšal som znížiť verziu balíka `linux-cachyos` na predchádzajúcu verziu, ale problém pretrváva. Tu je výstup príkazov `journalctl -b -1` a `dmesg` z live prostredia.
- **Zlá alebo nejasná otázka:**
  - Môj systém je rozbitý, prosím, pomôžte mi.

### Popíšte svoj problém

Tu je niekoľko otázok, ktoré by ste si mali položiť:

- Čo nefunguje?
- Vyrieši problém prechod na staršiu verziu balíka X?
- Majú tento problém aj iní ľudia / bol už niekedy vyriešený? (použite funkciu vyhľadávania)
- Objavil sa problém po aktualizácii?
- Vykonali ste vlastné úpravy?
  - Príklad: pridanie ďalšieho príznaku do súboru modprobe
- Súvisí problém s hardvérom? (napr. GPU, Wi-Fi)
- Súvisí problém so softvérom? (napr. konkrétna aplikácia, pracovné prostredie)
- Ide o čerstvú inštaláciu, alebo sa problém objavil po určitom čase používania?

## Ako získať záznamy (logy)

Existuje mnoho spôsobov, ako získať záznamy zo systému. Tu je niekoľko príkladov a nástrojov, ktoré môžete použiť:

### Vytvorenie všeobecného hlásenia o chybe
CachyOS poskytuje skvelý nástroj na zhromažďovanie systémových záznamov s názvom `cachyos-bugreport.sh`.
Tento nástroj zhromaždí záznamy z:
  - `dmesg`
  - `journalctl`
  - `inxi` (na zhromaždenie informácií o hardvéri)

Po zhromaždení záznamov budete vyzvaní, aby ste sa rozhodli, či ich chcete nahrať na našu webovú stránku typu paste.

Ak chcete tento skript spustiť, zadajte do terminálu nasledujúci príkaz a zdieľajte vygenerovaný odkaz vo svojom hlásení:
  ```sh
  sudo cachyos-bugreport.sh
  ```

### Získanie záznamov z programu, ktorý sa nespúšťa
Existuje mnoho dôvodov, prečo sa grafický program nemusí spustiť. Najlepším spôsobom, ako získať záznamy pri takomto probléme, je spustiť program z terminálu. Takto uvidíte všetky chybové hlásenia alebo výstup, ktorý môže pomôcť pri diagnostike problému.

Ak sa napríklad Firefox nespustí úplne, skúste ho spustiť z terminálu a sledujte chybové hlásenia:
  ```sh
  firefox
  ```

:::tip
  Ak chcete výstup uložiť do textového súboru pre jednoduchšie zdieľanie, môžete ho presmerovať takto:
    ```sh
    firefox &> firefox-log.txt
    ```
  Nezabudnite stlačiť `CTRL + C` na ukončenie procesu po tom, čo sa nepodarí spustiť, aby terminál zapísal výstup do súboru.
:::

### Kontrola naposledy aktualizovaných balíkov v pacmane

Ak chcete získať zoznam naposledy aktualizovaných balíkov vo vašom systéme, môžete použiť nasledujúci príkaz:

```bash
grep "\[ALPM\] upgraded" /var/log/pacman.log | tail -n 50
```

:::tip
Upravte parameter `-n` príkazu `tail`, ak chcete zobraziť viac alebo menej riadkov.
:::

### Klávesové skratky na navigáciu v journalctl a dmesg

Najbežnejšie klávesové skratky na pohyb v záznamoch pri použití programu `less` alebo režimu čitateľného pre človeka:

`ArrowUp` a `ArrowDown` alebo `J` a `K` na posúvanie nahor alebo nadol po riadkoch.

`PageUp` a `PageDown` alebo `Ctrl + B/D` na posúvanie nahor alebo nadol po jednej strane.

`G` alebo `Home` na skok na začiatok záznamu.

`Shift + G` alebo `End` na skok na koniec záznamu.

### Používanie journalctl na získanie systémových záznamov

Príkaz `journalctl` je mimoriadne užitočný nástroj na prezeranie systémových záznamov. Tu sú niektoré z najbežnejších a najužitočnejších kombinácií príkazov.

#### Základné použitie a bežné príklady

:::tip
Kombinujte viacero možností pre presnejšie filtrovanie.
:::

<details>
<summary>Zobrazenie celého záznamu (od najstaršieho po najnovší):</summary>
```bash
journalctl
```
</details>

<details>
<summary>Zobrazenie záznamov iba z aktuálneho spustenia systému:</summary>
```bash
journalctl -b
```
</details>

<details>
<summary>Problémy so zabezpečením a overovaním:</summary>
```bash
journalctl -u sshd -u polkit -b -0 | grep -i "fail\|error\|denied"
```
Vyhľadá zlyhania overovania a zamietnutia bezpečnostných politík.
</details>

<details>
<summary>Sledovanie záznamov v reálnom čase:</summary>
```bash
journalctl -f
```
:::tip
Skombinujte tento príkaz s ďalšími filtrami. Napríklad:
```bash
# Sledovanie záznamov služby Adguard Home:
journalctl -u adguardhome -f
```
:::
</details>

<details>
<summary>Problémy so zvukom z aktuálneho spustenia systému:</summary>
```bash
journalctl --user -u pipewire -u pipewire-pulse -u wireplumber -b 0
```
Zobrazí záznamy zvukových služieb na riešenie problémov so zvukom.
</details>

<details>
<summary>Chyby pamäte (RAM):</summary>
```bash
journalctl -k | grep -i "memory\|ram"
```
Vyhľadá poškodenie pamäte alebo problémy s jej detekciou.
</details>

<details>
<summary>Problémy s Bluetooth:</summary>
```bash
# Z aktuálneho spustenia systému:
journalctl -u bluetooth -b 0
# Z predchádzajúceho spustenia systému:
journalctl -u bluetooth -b -1
```
</details>

##### Filtrovanie podľa času
<details>

<summary>Zobrazenie záznamov za posledných niekoľko minút/hodín:</summary>
```bash
journalctl --since "10 minutes ago"
journalctl --since "1 hour ago"
journalctl --since "2024-01-15 14:30:00"
```
</details>

<details>
<summary>Zobrazenie záznamov z konkrétneho časového intervalu:</summary>
```bash
journalctl --since "09:00" --until "10:00"
```
</details>

##### Filtrovanie podľa priority a služby alebo programu

Možné úrovne priority sú: `debug`, `info`, `notice`, `warning`, `err`, `crit`, `alert`, `emerg`.

Alebo pomocou čísel:

`0` zodpovedá `emerg`

`1` zodpovedá `alert`

`2` zodpovedá `crit`

`3` zodpovedá `err`

`4` zodpovedá `warning`

`5` zodpovedá `notice`

`6` zodpovedá `info`

a `7` zodpovedá `debug`.

<details>
<summary>Zobrazenie iba chybových, kritických a núdzových správ:</summary>
```bash
journalctl -p err..emerg
```
:::tip
Tieto možnosti môžete kombinovať s predchádzajúcimi príkladmi:

Príklad:
```bash
journalctl -p err..emerg --since "9:00" --until "10:00"
```
:::
</details>

<details>
<summary>Zobrazenie záznamov konkrétnej systémovej služby:</summary>
```bash title='Príklady'
# Zobrazenie záznamov služby NetworkManager:
journalctl -u NetworkManager
# Zobrazenie záznamov služby GDM (GNOME Display Manager):
journalctl -u gdm
# Zobrazenie záznamov služby SDDM (Simple Desktop Display Manager):
journalctl -u sddm
```
</details>

<details>
<summary>Zobrazenie záznamov konkrétneho ID procesu (PID):</summary>
```bash
journalctl _PID=pid
# Príklad:
journalctl _PID=3344
```
</details>

<details>
<summary>Zobrazenie záznamov konkrétneho spustiteľného súboru:</summary>
```bash
journalctl path/to/executable
# Príklad:
journalctl /usr/bin/firefox
```
</details>

### Používanie journalctl na kontrolu správ jadra

:::note
Kedy použiť `journalctl -k` verzus `dmesg`:

- `journalctl -k` pristupuje k správam jadra uloženým v žurnáli systemd (pri správnej konfigurácii zostávajú zachované aj po reštarte) a ponúka lepšiu integráciu s časovým filtrovaním a funkciami žurnálu.
- `dmesg` číta aktuálny kruhový buffer jadra (dočasný, po reštarte sa stratí).
:::

<details>
<summary>Základné zobrazenie správ jadra:</summary>
```bash
journalctl -k
```
Zobrazí všetky správy jadra zo žurnálu, čo je ekvivalentné príkazu `dmesg`, ale z pohľadu žurnálu.
</details>

<details>
<summary>Správy jadra iba z aktuálneho spustenia systému:</summary>
```bash
journalctl -k -b 0
```
Zobrazí správy jadra iba z aktuálnej relácie spustenia systému.
</details>

<details>
<summary>Správy jadra z predchádzajúceho spustenia systému:</summary>
```bash
journalctl -k -b -1
```
Zobrazí správy jadra z predchádzajúceho spustenia systému. Užitočné na diagnostiku zlyhaní spustenia alebo pádov systému.
</details>

<details>
<summary>Sledovanie nových správ jadra v reálnom čase:</summary>
```bash
journalctl -k -f
```
Sledujte správy jadra tak, ako vznikajú; skvelé na monitorovanie hardvérových udalostí alebo načítavania ovládačov.
</details>

<details>
<summary>Vyhľadávanie správ konkrétnych ovládačov:</summary>
```bash
# Príklady:
# Správy súvisiace s GPU:
journalctl -k | grep -i "nvidia\|amd\|intel"
# Správy zariadení USB:
journalctl -k | grep -i "usb\|pci"
```
</details>

<details>
<summary>Časové filtrovanie správ jadra:</summary>
```bash
journalctl -k --since "1 hour ago"
journalctl -k --since "09:00" --until "10:00"
```
Zobrazí správy jadra z konkrétnych časových období.
</details>

### Používanie dmesg na zobrazenie správ jadra

Príkaz `dmesg` zobrazuje kruhový buffer jadra, ktorý obsahuje správy jadra o detekcii hardvéru, inicializácii ovládačov a systémových udalostiach.

#### Základné použitie a formátovanie

<details>
<summary>Zobrazenie celého buffera správ jadra:</summary>
```bash
dmesg
```
</details>

<details>
<summary>Zobrazenie s časovými značkami čitateľnými pre človeka:</summary>
```bash
dmesg -T
```
</details>

<details>
<summary>Zobrazenie v stránkovači na jednoduchšie čítanie:</summary>
```bash
dmesg | less
```
</details>

#### Filtrovanie podľa úrovne priority

Podobne ako `journalctl`, aj `dmesg` umožňuje filtrovať správy podľa úrovne priority.

<details>
<summary>Zobrazenie iba chybových a kritických správ:</summary>
```bash
dmesg -l err,crit,alert,emerg
```
Možné úrovne priority sú: `debug`, `info`, `notice`, `warning`, `err`, `crit`, `alert`, `emerg`.

Alebo pomocou čísel:

`0` zodpovedá `emerg`

`1` zodpovedá `alert`

`2` zodpovedá `crit`

`3` zodpovedá `err`

`4` zodpovedá `warning`

`5` zodpovedá `notice`

`6` zodpovedá `info`

a `7` zodpovedá `debug`.
</details>

<details>
<summary>Zobrazenie najnovších správ jadra:</summary>
```bash
dmesg -w
```
</details>

<details>
<summary>Vyhľadávanie správ konkrétneho hardvéru alebo ovládača:</summary>
```bash
# Príklady:
# Vyhľadanie správ súvisiacich s USB:
dmesg | grep -i usb | less
# Zariadenia Bluetooth:
dmesg | grep -i bluetooth
# Správy súvisiace s NVIDIA:
dmesg | grep -i nvidia | less
# Zariadenia, ktoré sa nepodarilo inicializovať:
dmesg | grep -i "error\|failed" | less
```
</details>

##### Bežné príklady pre konkrétne problémy pomocou dmesg

<details>
<summary>Keď nie je rozpoznané zariadenie USB:</summary>
```bash
dmesg -w | grep -i usb
```
Potom pripojte zariadenie a sledujte nové správy.
</details>

<details>
<summary>Problémy s inicializáciou GPU:</summary>
```bash
dmesg | grep -i "nvidia\|amd\|intel\|radeon\|drm\|gpu" | less
```
</details>

<details>
<summary>Problémy s Wi-Fi alebo sieťovým adaptérom:</summary>
```bash
dmesg | grep -i "wlan\|wifi\|network\|firmware" | tail -20
```
Skontrolujte chýbajúce načítanie firmvéru alebo chyby ovládača, ktoré bránia bezdrôtovej karte v práci.
</details>

<details>
<summary>Problémy s detekciou HDD/SSD:</summary>
```bash
dmesg | grep -i "sda\|sdb\|nvme\|scsi\|disk" | head -30
```
Použite vtedy, keď úložné zariadenie nie je detegované alebo počas spúšťania zobrazuje chyby.
</details>

<details>
<summary>Zamrznutia systému alebo kernel panics:</summary>
```bash
dmesg -T -l emerg,alert,crit,err | tail -30
```
Skontrolujte najzávažnejšie správy jadra, ktoré sa vyskytli pred pádom alebo zamrznutím systému.
</details>

<details>
<summary>Chyby pamäte (RAM):</summary>
```bash
dmesg | grep -i "memory\|ram"
```
Vyhľadajte poškodenie pamäte, problémy s detekciou alebo hlásenia chýb ECC.
</details>

<details>
<summary>Udalosti zvukového zariadenia:</summary>
```bash
dmesg | grep -i "audio\|snd\|hda" | grep -i "error\|fail\|card"
```
Skontrolujte, či je vaša zvuková karta správne detegovaná a či sa ovládače načítavajú správne.
</details>

<details>
<summary>Zlyhania načítania modulov jadra:</summary>
```bash
dmesg | grep -i "module\|init" | grep -i "error\|fail"
```
Keď sa konkrétne ovládače hardvéru nenačítavajú alebo zlyhávajú pri inicializácii.
</details>

<details>
<summary>Monitorovanie hardvérových udalostí v reálnom čase:</summary>
```bash
dmesg -w -l warn,err,crit,alert,emerg -T
```
Nepretržite sledujte nové dôležité správy jadra, kým reprodukujete problém.
</details>

<details>
<summary>Problémy s BIOS/UEFI a firmvérom:</summary>
```bash
dmesg | grep -i "bios\|uefi\|firmware\|efi"
```
Skontrolujte problémy s kompatibilitou medzi firmvérom vášho hardvéru a jadrom Linuxu.
</details>

## Inštalácia a Live prostredie

### Prečo CachyOS live ISO obsahuje iba KDE Plasma?

Rozhodli sme sa sústrediť naše úsilie v oblasti vývoja a údržby výhradne na pracovné prostredie KDE Plasma. To nám umožňuje poskytovať prepracovanejší, stabilnejší a konzistentnejší používateľský zážitok na našom live ISO.

Live prostredie je určené predovšetkým na inštaláciu CachyOS alebo na použitie nástroja `cachy-chroot` na obnovu systému. Na bezpečné **otestovanie** iných pracovných prostredí alebo správcov okien vám dôrazne odporúčame vyskúšať ich vo virtuálnom stroji (VM).

### Prečo sa inštalátor po kliknutí na „Launch Installer“ spúšťa tak dlho?

:::caution
Uistite sa, že máte aktívne/funkčné internetové pripojenie, inak sa po stlačení tohto tlačidla nič nestane.
:::

Inštalátor nie je zamrznutý. Na pozadí spúšťa potrebný skript, ktorý pripravuje systém na inštaláciu. Tento proces zabezpečuje, aby boli kľúče (keyringy) a hodiny vášho systému aktuálne, čo pomáha predchádzať bežným problémom pri inštalácii.

[Pozrite si skript na GitHube](https://github.com/CachyOS/CachyOS-Live-ISO/blob/master/archiso/airootfs/usr/local/bin/calamares-online.sh), aby ste lepšie pochopili, čo robí.
<Steps>
  1. Odstráni staré súbory keyringu.
  2. Aktualizuje balíky keyringu pre Arch Linux a CachyOS na najnovšiu verziu.
  3. Inicializuje a naplní pacman keyring.
  4. Povolí sieťovú synchronizáciu času.
  5. Skontroluje typ zavádzania vášho systému (UEFI alebo BIOS/MBR), aby používateľa vyzval na výber zavádzača v závislosti od daného typu.
</Steps>

### Prečo sa inštalácia zasekla na 33 %

Stáva sa to vtedy, keď má inštalátor problémy so sťahovaním balíkov. Zvyčajne ide o znak veľmi pomalého alebo nestabilného internetového pripojenia. Skontrolujte svoje sieťové pripojenie a skúste to znova.

## Obnova zavádzača

:::note
V prípade odstráneného oddielu `/boot` vytvorte nový podľa príslušnej [schémy rozdelenia disku](/sk/installation/installation_on_root#manuálne-rozdelenie-disku) od kroku 5.
:::

### Kroky na obnovu zavádzača

Užitočné v prípadoch, keď po aktualizácii BIOS-u zmiznú položky zavádzača alebo keď ho jednoducho potrebujete obnoviť.

:::tip
Ak si nie ste istí, ako používať `cachy-chroot`, prečítajte si najskôr dokumentáciu k [Pomocníkovi CachyOS chroot](/sk/features/cachy_chroot).
:::

<Steps>
    1. Spustite systém z CachyOS Live ISO.
    2. Otvorte terminál a vstúpte do nainštalovaného systému cez chroot pomocou príkazu `cachy-chroot`.

        ```bash
        sudo cachy-chroot
        ```
        Ak systém používa BTRFS s našou predvoľbou, zadajte na výzve `y`:
         ```bash title='Príklad'
         Do you want to use CachyOS BTRFS preset to auto mount root subvolume? y
         Do you want to mount additional partitions? · yes
         Enter the mount point for additional partition (e.g. /boot) type 'skip' to cancel:
         ```

## Správa balíkov a aktualizácie

### Riešenie problémov s Pacmanom

#### error: signature is invalid

Táto chyba signalizuje problém s kryptografickým podpisom balíka. Zvyčajne je spôsobená zastaraným zrkadlom alebo poškodeným keyringom vo vašom systéme.

Zrkadlá sa často opravia samy po krátkom čase, no ak problém pretrváva, mali by ste vyskúšať jedno z nasledujúcich riešení.

<Tabs>

<TabItem label='Prvé riešenie: Znovu synchronizujte zrkadlá Pacmanu'>

```sh
sudo pacman -Syu
```

</TabItem>

<TabItem label='Druhé riešenie: Ohodnoťte svoje zrkadlá'>

```sh title='Ohodnoťte svoje zrkadlá'
sudo cachyos-rate-mirrors
```

</TabItem>

<TabItem label='Tretie riešenie: Obnovte keyringy'>

Ak ohodnotenie zrkadiel nepomôže, pravdepodobne sú poškodené keyringy vášho systému.

- Otvorte CachyOS Hello a prejdite do časti **Troubleshooting**.
- Kliknite na tlačidlo **Reset keyrings**.

</TabItem>

</Tabs>

#### error: 404 Not Found

Táto chyba znamená, že balík, ktorý sa pokúšate nainštalovať, nie je na vašom aktuálnom zrkadle dostupný. Zvyčajne sa to stáva, keď vaša lokálna databáza balíkov nie je synchronizovaná so vzdialenými repozitármi.

**Riešenie:**

Spustite nasledujúci príkaz na obnovenie databázy balíkov a vykonanie úplnej aktualizácie systému. Tým zabezpečíte, že váš systém bude vedieť o najnovších dostupných balíkoch.

```sh
sudo pacman -Syu
# Potom sa pokúste požadovaný balík nainštalovať znova.
```

#### error: could not remove

Táto chyba nastáva, keď vyrovnávacia pamäť (cache) pacmanu obsahuje súbory, ktoré systém nedokáže automaticky spravovať. Ide o bežný problém, ktorý sa dá jednoducho vyriešiť.

- Riešenie 1: Použite CachyOS Hello.
  - Najjednoduchší spôsob, ako to opraviť, je pomocou aplikácie CachyOS Hello. Otvorte ju, prejdite do časti **Troubleshooting** a potom kliknite na tlačidlo **Clear package cache**.

- Riešenie 2: Odstráňte vyrovnávaciu pamäť manuálne.
  - Spustite nasledujúci príkaz na odstránenie všetkých osirelých balíkov z vyrovnávacej pamäte.
  ```sh
  sudo rm -r /var/cache/pacman/pkg/*
  ```

#### error: File is corrupted (invalid or corrupted package (PGP signature))

```sh
# Príklad:
:: File /var/cache/pacman/pkg/python-charset-normalizer-3.4.0-1-any.pkg.tar.zst
is corrupted (invalid or corrupted package (PGP signature)).
```

Táto chyba zvyčajne signalizuje problém s keyringmi pacmanu vo vašom systéme, ktoré overujú pravosť balíkov. Nasledujúce príkazy obnovia a znovu naplnia keyringy, čím problém vyriešia.

```sh
sudo rm -rf /etc/pacman.d/gnupg/
sudo pacman-key --init
sudo pacman-key --populate

sudo pacman-key --recv-keys F3B607488DB35A47 --keyserver keyserver.ubuntu.com
sudo pacman-key --lsign-key F3B607488DB35A47

sudo rm -R /var/lib/pacman/sync
```

Ak vyššie uvedený postup nepomôže, problémom nie je váš keyring. Problém môže byť vo vašich zrkadlách, takže môžete vybrať funkčné zrkadlá a následne vyčistiť vyrovnávaciu pamäť spustením nasledujúcich príkazov:

```sh
sudo cachyos-rate-mirrors
sudo pacman -Scc
```

#### error: unable to lock database

Táto chyba nastáva, keď už beží iný proces pacmanu, ktorý uzamkne databázu, aby zabránil jej poškodeniu. Ak predchádzajúci proces spadol alebo bol prerušený, súbor zámku `db.lck` nemusel byť odstránený.

- Riešenie 1: Použite CachyOS Hello
  - Najjednoduchší spôsob, ako to opraviť, je použiť funkciu **Remove db lock** na karte **Troubleshooting** v aplikácii CachyOS Hello.

- Riešenie 2: Odstráňte súbor zámku manuálne
  - Ak uprednostňujete nepoužívať CachyOS Hello, súbor zámku môžete odstrániť manuálne:

```sh
sudo rm /var/lib/pacman/db.lck
```

#### error: failed retrieving file ... Connection timed out

Môžete vidieť chyby podobné týmto:

```text
# Príklady chýb:
error: failed retrieving file '...' from ... : Connection timed out
error: failed retrieving file '...' from ... : Couldn't resolve host name
error: failed retrieving file '...' from ... : The requested URL returned error: 526
```

Tieto chyby takmer vždy naznačujú problém s vašimi aktuálnymi zrkadlami. Môžu byť pomalé, dočasne nedostupné alebo nedosiahnuteľné z vašej polohy.

- Riešenie: Najlepším spôsobom, ako to opraviť, je aktualizovať zoznam zrkadiel rýchlejšími a spoľahlivejšími zrkadlami.

```sh
sudo cachyos-rate-mirrors
# Následne môžete systém aktualizovať pomocou:
sudo pacman -Syu
```

:::tip
Príkaz `cachyos-rate-mirrors` otestuje dostupné zrkadlá CachyOS na základe rýchlosti a stavu synchronizácie a potom aktualizuje váš súbor so zoznamom zrkadiel (`/etc/pacman.d/cachyos-mirrorlist`) najvýkonnejšími zrkadlami.

Zvážte jeho pravidelné spúšťanie, najmä ak si počas aktualizácií systému všimnete spomalenie.
:::

#### warning: local is newer than...

Toto varovanie sa zobrazí, keď je verzia balíka vo vašom systéme novšia ako verzia dostupná v oficiálnych repozitároch. Môže sa to stať, ak je zrkadlo zastarané, ak bola verzia balíka v repozitároch znížená alebo ak bol balík nainštalovaný z iného zdroja.

- Riešenie: Príkaz `pacman -Syuu` vykoná úplnú aktualizáciu systému a umožní aj prechod na staršie verzie (downgrade), čím varovanie odstráni synchronizáciou vašich lokálnych balíkov s verziami v repozitároch.

```sh title='Na odstránenie týchto varovaní spustite nasledujúci príkaz:'
sudo pacman -Syuu
```

#### error: failed to commit transaction (conflicting files)

Táto chyba znamená, že pacman sa pokúša nainštalovať alebo aktualizovať balík, ktorý obsahuje súbory už prítomné vo vašom systéme z iného zdroja. Ide o vstavanú bezpečnostnú funkciu na zabránenie poškodeniu systému.

- Riešenie: Tento problém môžete vyriešiť manuálnym odstránením konfliktných súborov. Viac informácií a riešení nájdete na [Arch Wiki](https://wiki.archlinux.org/title/Pacman#%22Failed_to_commit_transaction_(conflicting_files)%22_error).

```sh title='Príklad'
error: failed to commit transaction (conflicting files)
nvidia-utils: /usr/lib/environment.d/10-gsk.conf exists in filesystem
Errors occurred, no packages were upgraded.
 -> error installing repo packages
```

Na vyriešenie tohto konkrétneho príkladu by ste odstránili konfliktný súbor a potom znova spustili príkaz na aktualizáciu.

```sh
sudo rm /usr/lib/environment.d/10-gsk.conf
```

#### ERROR: module not found: 'nvidia', 'nvidia_modeset', ...

```sh title='Príklad'
==> ERROR: module not found: 'nvidia'
==> ERROR: module not found: 'nvidia_modeset'
==> ERROR: module not found: 'nvidia_uvm'
==> ERROR: module not found: 'nvidia_drm'
```

**Dva dôvody tejto chyby:**

1) Keďže skoré načítanie modulov (Early Module Loading) je v `chwd` vždy povolené, `mkinitcpio` dôsledne očakáva prítomnosť modulov NVIDIA; táto chyba nastáva, keď tieto moduly chýbajú.

2) Môžu vám chýbať moduly NVIDIA pre iné nainštalované jadrá vo vašom systéme.

```sh title='Na opravu tejto chyby nainštalujte nasledujúci balík'
sudo pacman -S nvidia
```

#### V poslednom čase trvá spustenie môjho systému dlho

Keďže tento problém môže byť spôsobený mnohými rôznymi faktormi, začnime základmi a skontrolujme pomocou `systemd-analyze`, kde má systém problém:

Otvorte terminál a spustite jeden z nasledujúcich dvoch príkazov:

```sh
systemd-analyze blame
```

alebo:

```sh
systemd-analyze critical-chain
```

Ak výstup ukazuje, že služba `cachyos-rate-mirrors.service` trvá dlho, mali by ste spustiť nasledujúci príkaz na zamaskovanie tejto služby, čím zabránite jej spúšťaniu pri štarte systému:

```sh
systemctl mask cachyos-rate-mirrors
systemctl mask cachyos-rate-mirrors.timer
```

#### Aký je pôvod CachyOS a prečo sa volá „CachyOS“?

CachyOS je pomenovaný podľa plánovača „Cachy“, čo bol pôvodný názov [plánovača cacULE](https://github.com/hamadmarri/cacule-cpu-scheduler), CPU plánovača pre jadro Linuxu.

Projekt vznikol v rokoch 2020 – 2021, keď ptr1337 (jeden zo zakladateľov CachyOS) testoval a spolupracoval s vývojárom menom Hamad na plánovači cacULE. Keď sa rozhodli vytvoriť optimalizovanú linuxovú distribúciu založenú na Arch Linuxe s balíkmi optimalizovanými pre x86-64-v3, pomenovali ju „CachyOS“ podľa plánovača, ktorý ich dal dokopy.

#### Aký je interval aktualizácie balíkov -git?

Zvyčajne raz týždenne v pondelok, hoci môžu existovať výnimky.

#### Využívajú balíky -bin v repozitároch CachyOS rovnaké optimalizácie výkonu?

Nie. Balíky `-bin` sú predkompilované binárne súbory a neobsahujú rovnaké optimalizácie výkonu ako balíky zostavené zo zdrojového kódu v repozitároch CachyOS.

## Bezpečnosť a osvedčené postupy

### Bezpečnostné postupy pre AUR

AUR ponúka obrovský výber, ale bezpečnosť je prvoradá. Tu je stručný sprievodca bezpečným používaním AUR vo vašom systéme CachyOS.

* **Pochopte PKGBUILD:** Je to zostavovací skript. Spoznajte jeho štruktúru, premenné (`source`, `pkgname`) a funkcie (`build()`, `package()`).
* **Overte zdrojové odkazy:** Vždy skontrolujte, či adresy URL v `source` smerujú na oficiálne stránky projektu alebo dôveryhodné repozitáre. Vyhýbajte sa podozrivým alebo osobným odkazom.
* **Skontrolujte kroky inštalácie:** Preskúmajte, kam sa súbory inštalujú (funkcia `package()`) a či nie sú niektoré príkazy nezvyčajné alebo nezasahujú do citlivých oblastí systému. Skontrolujte aj skripty `.install`.
* **Preverte správcu (maintainer):** Pozrite si históriu správcu v AUR, či nemá minulé bezpečnostné incidenty alebo podozrivú aktivitu.
* **Skontrolujte kontrolné súčty a PGP:** Absolútne kľúčové! Potvrďte, že všetky kontrolné súčty (SHA256, BLAKE2b atď.) zodpovedajú pôvodnému zdroju (upstream). Ak sú k dispozícii, použite podpisy PGP (`validpgpkeys`) na overenie pravosti.
* **Buďte opatrní pri balíkoch `-bin`:** Tieto používajú predkompilované binárne súbory, čo znamená, že nemôžete skontrolovať zdrojový kód. Venujte maximálnu pozornosť ich pôvodu a integrite.
* **Čítajte komentáre komunity:** Skontrolujte komentáre na stránke AUR, či neobsahujú varovania, problémy alebo postrehy od ostatných používateľov.
* **Nikdy nepreskakujte kontroly integrity:** Používanie `--skipinteg` alebo podobných prepínačov obchádza všetky bezpečnostné kontroly. Nerobte to.
* **Majte pod kontrolou svoj AUR pomocník:** Pochopte, ako váš pomocník (`yay`, `paru`) funguje. Uistite sa, že vám zobrazuje `PKGBUILD` a jeho zmeny (diffy), alebo zostavujte manuálne pomocou `makepkg`.
* **Zhodnoťte nevyhnutnosť:** Pred inštaláciou sa opýtajte samých seba, či tento balík z AUR naozaj potrebujete, alebo či existuje alternatíva v oficiálnych repozitároch.
* **Udržiavajte svoj systém aktualizovaný:** Pravidelne spúšťajte `sudo pacman -Syu`, aby ste zabezpečili, že všetky súčasti vášho systému, vrátane `pacman` a `makepkg`, majú najnovšie bezpečnostné záplaty.

Zostaňte ostražití, aby bol váš systém založený na Arch Linuxe bezpečný!

### Výber grafického správcu balíkov

Hoci grafickí správcovia balíkov ponúkajú pohodlie, o niektorých z nich je známe, že v systémoch s priebežným vydávaním (rolling-release), ako je CachyOS, spôsobujú vážne problémy a pri správe systémových balíkov by ste sa im mali vyhnúť.

- **Pamac:** je známy tým, že nesprávne spracúva niektoré úlohy správy balíkov, napríklad poškodzuje keyringy systémových balíkov. To môže viesť k chybám podpisu PGP, ktoré vám zabránia aktualizovať systém.
- **Discover (KDE) a GNOME Software Center:** Tieto obchody s aplikáciami používajú backend PackageKit. Hoci sú vo všeobecnosti bezpečné na správu balíkov Flatpak, ich používanie na inštaláciu alebo aktualizáciu **systémových balíkov** je riskantné. Správcovia založení na PackageKit môžu byť tiež nestabilní alebo náchylní na pády, čo by po zlyhanej transakcii mohlo zanechať váš systém v nefunkčnom stave.

Pre maximálnu stabilitu a spoľahlivosť **dôrazne odporúčame** spravovať systémové balíky prostredníctvom príkazového riadka pomocou `pacman`.

Ak uprednostňujete grafické rozhranie, grafické nadstavby ako **[Shelly](</sk/configuration/post_install_setup/#aktualizácia-systému>)** alebo **CachyOS Package Installer** sa považujú za bezpečné alternatívy, pretože sú priamejšími nadstavbami pre funkcionalitu pacmanu.
