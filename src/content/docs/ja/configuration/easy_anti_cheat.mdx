[Easy Anti-Cheat Linux v2](https://onlineservices.epicgames.com/news/introducing-easy-anti-cheat-linux-v2) は、システムがどのように起動されたかを検証できる場合にのみゲームの起動を許可します。具体的には以下を確認します。

- セキュアブートが有効であり、Epic が信頼するキーでカーネルに署名されていること
- システムに TPM 2.0 が搭載されており、起動のすべてのステップが記録されていること (メジャーブート)
- カーネルが lockdown の integrity モードで動作し、署名済みモジュールのみを読み込むこと
- IOMMU が有効、kexec が無効、BPF LSM が有効であること

CachyOS は、これらの要件を満たす専用カーネル `linux-cachyos-eac` と、同じキーで署名された systemd-boot を提供しています。お使いのセキュアブートキーはそのまま保持されます。追加されるのは、ファームウェアが CachyOS の署名済みファイルを受け入れられるようにするための、セキュアブートデータベース内の **CachyOS EAC CA** 証明書のみです。

EAC カーネルには専用のブートエントリが作成されます。通常のブートエントリは変更されないため、EAC を使用するゲームをプレイしたいときだけ EAC エントリで起動します。

EAC には、読み込むすべてのものをセキュアブートデータベースと照合して検証し、TPM に記録するブートマネージャーが必要です。systemd-boot はこれを行いますが、Limine は行いません。rEFInd は行いますが、独自のキーで署名されているため EAC に受け入れられず、GRUB も同様です。そのため、Limine、rEFInd、GRUB ユーザーは現在のブートマネージャーをデフォルトのまま維持し、CachyOS によって署名された systemd-boot 経由で EAC カーネルを起動します。この systemd-boot には専用のファームウェアブートエントリが作成され、EAC の起動にのみ使用されます。

[`eac-setup` スクリプト](#eac-setup-によるセットアップ)を使うと、セットアップを自動で行えます。[手動セットアップ](#手動セットアップ)では、同じ手順を手動で行う方法を説明しています。

## 要件

- **systemd-boot**、**Limine**、または **rEFInd** をブートマネージャーとして UEFI モードでインストールされた CachyOS。rEFInd の場合、CachyOS インストーラーの構成どおり、EFI システムパーティションが `/boot` にマウントされている必要があります。**GRUB** は実験的にサポートされています。[GRUB (実験的)](#grub-実験的) を参照してください。
- 最新の状態に更新されたシステム (`sudo pacman -Syu`)。`eac-setup` には `cachyos-settings` 1.4.4 以降、`eac-status` および `sbctl-batch-sign` での EAC サポートには 1.4.2 以降が必要です。
- ファームウェア設定で **TPM 2.0** が有効になっていること。ファームウェア TPM (AMD fTPM、Intel PTT) でも問題ありません。
- ファームウェア設定で **IOMMU** が有効になっていること (AMD では AMD-Vi / "IOMMU"、Intel では VT-d)。
- NVIDIA GPU: Maxwell 以降 (GTX 750、GTX 900 シリーズ以降)。EAC カーネルは NVIDIA モジュールをパッケージとして提供しています。Turing 以降 (GTX 16 / RTX 20 シリーズ以降) 向けには `linux-cachyos-eac-nvidia-open`、Maxwell、Pascal、Volta 向けには `linux-cachyos-eac-nvidia-580xx` を使用します。

:::caution[DKMS モジュールは非対応]
EAC カーネルは、カーネルのビルド時に署名されたモジュールのみを読み込みます。NVIDIA、ZFS、Realtek r8125 のモジュールは `linux-cachyos-eac-*` パッケージとして提供されていますが、DKMS でビルドされるその他のモジュール (例: `virtualbox-host-dkms`) は EAC ブートエントリでは読み込まれません。`linux-cachyos-eac-headers` はインストールしないでください。
:::

:::danger[BitLocker と TPM ディスクロック解除]
このセットアップではセキュアブートキーが変更されるため、TPM が記録する内容も変化します。その結果、Windows デュアルブート環境の BitLocker で回復キーの入力を求められたり、ご自身で TPM にバインドした LUKS ディスクでパスフレーズの入力を求められたりする場合があります。開始する前にこれらが手元にあることを確認してください。そうでないとデータにアクセスできなくなるおそれがあります。
:::

:::danger[Steam Deck]
Steam Deck のファームウェア設定には標準のセキュアブートの切り替え項目がなく、現在サポートされていません。キーを登録すると起動不能になり、セキュアブートを無効化する簡単な方法もなくなります。Steam Deck ではこのガイドの手順を実行しないでください。
:::

## eac-setup によるセットアップ

`cachyos-settings` に含まれる `eac-setup` は、systemd-boot、Limine、rEFInd、GRUB 向けのセットアップを実行します。すでに完了している項目を確認するため、修復などの目的でいつでも再実行できます。ユーザーが行う必要があるのは、ファームウェア設定の変更だけです。

<Steps>

1. **ファームウェアをセットアップモードにする**

    [セキュアブートガイド](/ja/configuration/secure_boot_setup)などで作成した `sbctl` のキーを使ってすでにセキュアブートを使用している場合は、この手順をスキップしてください。その場合、`eac-setup` はセキュアブートを有効にしたまま CachyOS EAC CA をセキュアブートデータベースに追加します。

    それ以外の場合は、[UEFI でセットアップモードを有効化](/ja/configuration/secure_boot_setup#uefi-でセットアップモードを有効化) にしたがって操作し、この時点ではセキュアブートを**無効**のままにしておいてください。

    ```bash
    systemctl reboot --firmware-setup
    ```

2. **eac-setup を実行する**

    ```bash
    sudo eac-setup
    ```

    スクリプトはセキュアブートキーを登録する前に確認を求め、pacman はパッケージをインストールする前に確認を求めます。スクリプトは以下の手順を実行します。

    - TPM、IOMMU、および使用しているブートマネージャーを確認します。
    - CachyOS EAC CA を登録します。セットアップモードでは、まず独自のキーを作成し、Microsoft のキーとともに登録します。
    - `linux-cachyos-eac`、`systemd-boot-cachyos-signed`、およびお使いのシステムに合う `linux-cachyos-eac-*` モジュールパッケージ (NVIDIA、ZFS、r8125) をインストールします。
    - セキュアブートを有効にしても通常の起動が機能し続けるよう、通常のカーネルおよび Limine、rEFInd、または GRUB に独自のキーで署名します。
    - `sbctl` が CachyOS 署名済みファイルに触れないようにし、もし `sbctl` が再署名してしまった場合は署名を復元します。
    - 実行中システムのカーネルオプションと EAC オプションを組み合わせて EAC ブートエントリを作成します。Limine、rEFInd、GRUB の場合は、CachyOS 署名済みの systemd-boot を独自のファームウェアブートエントリ "CachyOS EAC" としてインストールします。

    ファームウェアがセットアップモードではなく、キーも `sbctl` で作成されたものではない場合、スクリプトは停止してファームウェアをセットアップモードにするよう求めます。その場合は設定を変更してから再実行してください。

    EAC エントリは、システムの起動時に使われていたカーネルオプションを使用します。あとから通常ブートエントリのカーネルオプションを変更した場合は、再起動して `sudo eac-setup` をもう一度実行してください。

3. **セキュアブートを有効にする**

    セキュアブートがまだ無効な場合、`eac-setup` の最後にその旨が表示されます。すでに有効になっている場合は、この手順をスキップしてください。

    ファームウェア設定に再起動してセキュアブートを有効にしてください。マザーボードにセキュアブートの切り替え項目がない場合は、[セキュアブートガイド](/ja/configuration/secure_boot_setup#カーネルイメージとブートマネージャーへの署名) の ASUS に関する注意書きを参照してください。

    ```bash
    systemctl reboot --firmware-setup
    ```

4. **EAC で起動する**

    ```bash
    sudo eac-setup boot
    ```

    これにより、次の 1 回だけ EAC エントリで再起動します。ゲームセッション後に再起動すると、再び通常のシステムが起動します。systemd-boot の場合は、ブートメニューで **CachyOS (EAC)** を選択することもできます。

    :::caution
    Limine や GRUB のメニューにも `linux-cachyos-eac` のエントリが表示されますが、Limine や GRUB 経由で起動しても EAC のチェックを**通過しません**。かならず `sudo eac-setup boot` を使用してください。
    :::

    起動後、[セットアップの確認](#セットアップの確認) の説明にしたがって結果を確認してください。

</Steps>

### GRUB (実験的)

GRUB サポートは新しく、まだ十分なテストが行われていません。`cachyos-settings` 1.4.5 以降が必要です。問題が発生した場合は、[CachyOS-Settings の Issue トラッカー](https://github.com/CachyOS/CachyOS-Settings/issues) まで報告してください。

GRUB のセットアップは `eac-setup` のみに対応しており、手動ガイドはありません。手順は上記と同じですが、スクリプトは追加で以下の変更を行います。

- `tpm` モジュールを含め、shim lock を無効にして GRUB を再インストールし、独自のキーで署名します。これを行わないと、セキュアブートが有効な状態で GRUB が通常のカーネルを起動できません。
- systemd-boot はルートファイルシステム上の `/boot` から読み取れないため、EAC カーネルとその initramfs を EFI システムパーティションにコピーします。これには約 40 MiB の空き容量が必要です。スクリプトは `cachyos-eac-grub-hook` をインストールし、EAC カーネルや initramfs が変更されるたびにその mkinitcpio フックがコピーを更新します。
- GRUB メニューを再生成します。メニューの UEFI ファームウェアエントリ配下に **CachyOS EAC (EFI BootNext)** エントリが追加され、`sudo eac-setup boot` と同じ動作を行います。
- GRUB がデフォルトで `linux-cachyos-eac` を起動してしまう場合、`/etc/default/grub` の `GRUB_TOP_LEVEL` を通常のカーネルに設定します。このオプションがまだ設定されていない場合、GRUB がカーネルを名前順でソートするためこの現象が発生します。

:::caution
`/etc/default/grub` に `GRUB_SAVEDEFAULT=true` が設定されている場合、**CachyOS EAC (EFI BootNext)** エントリを選択しないでください。GRUB がそのエントリを記憶し、毎回の起動時に EAC が起動するようになってしまいます。かわりに `sudo eac-setup boot` を使用してください。すでに記憶されてしまった場合は、`sudo eac-setup` をもう一度実行すると保存されたエントリが削除されます。
:::

GRUB でのディスク暗号化はまだサポートされていません。CachyOS インストーラーは `/boot` を暗号化されたルートパーティション内に配置し、ディスクのキーを initramfs 内に格納します。暗号化されていない EFI システムパーティションに initramfs をコピーするとそのキーが露出してしまうため、`/boot` が暗号化されている場合 `eac-setup` は停止します。

## 手動セットアップ

ここでは、`eac-setup` が実行する手順を説明します。手動で設定したり、スクリプトが何を変更するかを確認したりするときに使用してください。どの時点からでもスクリプトに切り替えられ、スクリプトはすでに完了している処理から続行します。

:::note[コマンドは bash で実行してください]
このページのコマンドは bash 向けに書かれています。CachyOS のデフォルトシェルは fish であり、`Unsupported use of '='` などのエラーで一部のコマンドを受け付けません。先にターミナルで `bash` を実行してからコマンドを実行してください。
:::

### すでにセキュアブートを使用している場合

[セキュアブートガイド](/ja/configuration/secure_boot_setup) などで `sbctl` を使ってすでにセキュアブートを設定している場合、セットアップモードは不要です。`sbctl` はセキュアブートを有効にしたまま CachyOS EAC CA をセキュアブートデータベースに追加できます。変更はファームウェアが受け入れる独自の Key Exchange Key (KEK) で署名されます。

{/* TODO: only tested in OVMF so far, test on real hardware */}

<Steps>

1. **セキュアブートの状態を確認する**

    ```bash
    sudo sbctl status
    ```

    出力に `sbctl is installed`、`Setup Mode: Disabled`、`Secure Boot: Enabled` が表示されている必要があります。キーが `sbctl` で作成されたものではない場合は、お使いのブートマネージャー向けの設定の手順 1 から進めてください。

2. **CachyOS EAC CA を登録する**

    ```bash
    sudo pacman -S cachyos-eac-signing-key
    sudo sbctl enroll-keys --append --partial db --custom --ignore-immutable
    ```

    `--append` はすでに登録されているすべての証明書を保持し、`--partial db` はセキュアブートデータベース (`db`) のみを変更し、`--ignore-immutable` は Linux がデフォルトで読み取り専用にしているデータベースへの書き込みを `sbctl` に許可します。

    :::caution[1 回だけ実行してください]
    `sbctl` はどの証明書がすでに登録されているかを確認しません。実行するたびに独自の Database Key とともに CachyOS EAC CA が追加で登録されてしまいますが、ファームウェア側の容量には限りがあります。
    :::

    証明書が登録されたことを確認します。

    ```bash
    sudo sbctl list-enrolled-keys
    ```

    `db` セクションに、以前からのエントリと並んで `CachyOS EAC CA` が表示されている必要があります。独自の `Database Key` が 2 回表示されますが、問題ありません。

    `sbctl` がエラーを報告した場合、ファームウェアが変更を受け入れなかったことを意味します。通常は、登録されている KEK が sbctl のキーディレクトリにあるものと異なることが原因です。この場合は、お使いのブートマネージャー向けの設定の手順 1 から進めてください。

3. **お使いのブートマネージャー向けの設定を続ける**

    [お使いのブートマネージャー向けの設定](#お使いのブートマネージャー向けの設定) の手順 2 から進めてください。CA の登録とブートマネージャーへの署名は完了しているため、手順 3 はスキップします。手順 6 でもセキュアブートはすでに有効になっているため、EAC エントリを起動するだけで済みます。

</Steps>

### お使いのブートマネージャー向けの設定

<Tabs syncKey="boot-manager">
<TabItem label='Limine'>

Limine はデフォルトのブートマネージャーのまま維持されます。CachyOS 署名済みの systemd-boot は、EFI システムパーティション上の専用ディレクトリと独自のファームウェアブートエントリを使って隣にインストールされます。ゲームをプレイするときは、次の起動時のみ 1 回だけ systemd-boot を起動する (`BootNext`) ようファームウェアに指示します。すると systemd-boot が EAC カーネルを直接起動します。その後は、通常どおり Limine から起動します。

<Steps>

1. **ファームウェアをセットアップモードにする**

    すでに `sbctl` でセキュアブートを使用している場合は、かわりに [すでにセキュアブートを使用している場合](#すでにセキュアブートを使用している場合) の手順を実行し、手順 2 に進んでください。

    [UEFI でセットアップモードを有効化](/ja/configuration/secure_boot_setup#uefi-でセットアップモードを有効化) にしたがって操作し、この時点ではセキュアブートを**無効**のままにしておいてください。

    ```bash
    systemctl reboot --firmware-setup
    ```

2. **パッケージをインストールする**

    Limine に切り替える前に [セキュアブートガイド](/ja/configuration/secure_boot_setup) にしたがって systemd-boot を使用していた場合は、その際に作成された自己署名の systemd-boot を最初に削除してください。そうしないと、pacman が `systemd-boot-cachyos-signed` のインストールを拒否し、`sbctl` が CachyOS 署名済みの systemd-boot を上書きしてしまいます。

    ```bash
    sudo sbctl remove-file /usr/lib/systemd/boot/efi/systemd-bootx64.efi
    sudo rm -f /usr/lib/systemd/boot/efi/systemd-bootx64.efi.signed
    ```

    次にパッケージをインストールします。

    ```bash
    sudo pacman -S sbctl sbsigntools tpm2-tools efibootmgr cachyos-eac-signing-key linux-cachyos-eac systemd-boot-cachyos-signed
    ```

    NVIDIA GPU を搭載したシステムでは、`linux-cachyos-eac-nvidia-open` (Turing 以降) または `linux-cachyos-eac-nvidia-580xx` (Maxwell、Pascal、Volta) もインストールしてください。ZFS を使用している場合は `linux-cachyos-eac-zfs` もインストールしてください。Realtek 2.5 GbE ネットワークカード用に `r8125-dkms` を使用している場合は `linux-cachyos-eac-r8125` もインストールしてください。

    :::danger
    `bootctl install` は**実行しないでください**。systemd-boot がデフォルトのブートマネージャーになり、EFI システムパーティション上のフォールバックブートローダーが置き換わってしまいます。
    :::

    :::caution
    `/etc/default/limine` の `ENABLE_UKI=no` (デフォルト) はそのままにしておいてください。UKI を有効にすると、EAC カーネルが新しいイメージにパックされ、`sbctl` が独自のキーで署名してしまうため、EAC に受け入れられなくなります。
    :::

3. **セキュアブートキーを登録して Limine に署名する**

    [すでにセキュアブートを使用している場合](#すでにセキュアブートを使用している場合) の手順で CA を登録した場合は、この手順をスキップしてください。

    `cachyos-eac-signing-key` は、CachyOS EAC CA 証明書を sbctl のカスタム証明書用ディレクトリに配置します。独自のキーを、Microsoft のキー、ファームウェアの組み込みキー、および CachyOS EAC CA とともに登録します。

    :::caution[ASUS 製および Gigabyte 製マザーボード]
    これらのマザーボードでは、以下の最後のコマンドを `--firmware-builtin` なしで `sudo sbctl enroll-keys --microsoft --custom` として実行してください。一部のボードではこのフラグにより重複したキーエントリが作成され、セキュアブートを有効にした際に **Secure Boot Violation** で停止します。すでにこの状態になった場合は、ファームウェア設定ですべてのセキュアブートキーを削除して再度セットアップモードに入り ([UEFI でセットアップモードを有効化](/ja/configuration/secure_boot_setup#uefi-でセットアップモードを有効化) を参照)、CachyOS を起動して `sudo sbctl enroll-keys --microsoft --custom` を実行してください。セキュアブートガイドにあるコマンドは CachyOS EAC CA が含まれないため、ここでは使用しないでください。
    :::

    ```bash
    sudo sbctl create-keys
    sudo sbctl enroll-keys --microsoft --firmware-builtin --custom
    ```

    `sbctl` が `could not enroll built-in firmware keys` で停止した場合、ファームウェアに組み込みキーが存在せず、まだ何も登録されていません。`--firmware-builtin` を外して最後のコマンドを再実行してください。

    証明書が登録されたことを確認します。

    ```bash
    sudo sbctl list-enrolled-keys
    ```

    `db` セクションに `CachyOS EAC CA` が表示されている必要があります。

    セキュアブートを有効にしても通常の起動が機能し続けるよう、Limine 自体にも独自のキーで署名する必要があります。[カーネルイメージとブートマネージャーへの署名](/ja/configuration/secure_boot_setup#カーネルイメージとブートマネージャーへの署名) の Limine タブにしたがってください。

    :::caution
    EAC カーネルや CachyOS 署名済みの systemd-boot には、絶対に `sbctl` で署名しないでください。`sbctl verify` で未署名として表示されたとしても、これらに対して `sbctl-batch-sign` や `sbctl sign` を実行しないでください。これらは CachyOS によって署名されています。
    :::

4. **systemd-boot を別のファームウェアブートエントリとして追加する**

    `sbctl` はカーネルや EFI バイナリが更新されるたびに、データベース内のすべてのファイルに再署名します。たとえば以前の `sbctl sign -s` などにより、CachyOS 署名済みファイルがデータベースに含まれていないか確認します。

    ```bash
    sudo sbctl list-files
    ```

    一覧に `cachyos-eac` を含むパス、または `/usr/lib/systemd/boot/efi/systemd-bootx64.efi` が表示されている場合は、`sudo sbctl remove-file <path>` で削除してください。その後、パッケージを再インストールして CachyOS の署名を復元します。

    ```bash
    sudo pacman -S linux-cachyos-eac systemd-boot-cachyos-signed
    ```

    署名済みの systemd-boot を EFI システムパーティション上の専用ディレクトリにコピーします。

    ```bash
    ESP="$(bootctl --print-esp-path)"
    sudo install -Dm644 /usr/lib/systemd/boot/efi/systemd-bootx64.efi.signed "$ESP/EFI/cachyos-eac/systemd-bootx64.efi"
    ```

    `EFI/cachyos-eac` が存在する限り、`systemd-boot-cachyos-signed` はこのコピーを自動的に更新します。

    次にファームウェアブートエントリを作成します。`--create-only` は起動順序を変更せずにエントリを追加するため、Limine がデフォルトのまま維持されます。

    ```bash
    ESP_DEV="$(findmnt -no SOURCE "$ESP")"
    ESP_DISK="/dev/$(lsblk -no PKNAME "$ESP_DEV")"
    ESP_PART="$(cat "/sys/class/block/$(basename "$ESP_DEV")/partition")"
    sudo efibootmgr --create-only --disk "$ESP_DISK" --part "$ESP_PART" \
      --label "CachyOS EAC" --loader '\EFI\cachyos-eac\systemd-bootx64.efi'
    ```

    新しいエントリが一覧にあり、`BootOrder` の先頭が引き続き Limine であることを確認します。

    ```bash
    efibootmgr
    ```

5. **EAC ブートエントリを作成する**

    systemd-boot は EFI システムパーティションから設定を読み込みます。Limine のフックは、マシン ID にちなんだ名前のディレクトリ内で EAC カーネルとその initramfs を最新の状態に保ちます。両方が存在することを確認します。

    ```bash
    ESP="$(bootctl --print-esp-path)"
    KERNEL="/$(cat /etc/machine-id)/linux-cachyos-eac/vmlinuz"
    INITRD="/$(cat /etc/machine-id)/linux-cachyos-eac/initramfs"
    sudo ls -l "$ESP$KERNEL" "$ESP$INITRD"
    ```

    次に、実行中システムのカーネルコマンドラインに EAC オプションを追加して構築します。

    ```bash
    EAC_REQ="lockdown=integrity lsm=landlock,lockdown,yama,integrity,bpf iommu.passthrough=0 intel_iommu=on module.sig_enforce=1 sysctl.kernel.kexec_load_disabled=1"
    EAC_OPTS="$(sed -E 's/(^| )(BOOT_IMAGE|initrd)=[^ ]*//g' /proc/cmdline) $EAC_REQ"
    echo "$EAC_OPTS"
    ```

    出力に `root=` オプションが含まれ、末尾が EAC オプションで終わっている必要があります。エントリを書き込み、systemd-boot がメニューを表示せずに起動するようデフォルトに設定します。これにより既存の `loader/loader.conf` が置き換えられますが、ここでは systemd-boot が EAC エントリのみを起動するため問題ありません。

    ```bash
    printf 'title   CachyOS (EAC)\nlinux   %s\ninitrd  %s\noptions %s\n' "$KERNEL" "$INITRD" "$EAC_OPTS" \
      | sudo install -Dm644 /dev/stdin "$ESP/loader/entries/cachyos-eac.conf"
    printf 'default cachyos-eac.conf\ntimeout 0\n' | sudo install -Dm644 /dev/stdin "$ESP/loader/loader.conf"
    ```

    それでも systemd-boot のメニューを表示したい場合は、起動中に <kbd>Space</kbd> を押し続けてください。

    :::caution
    Limine のメニューにも `linux-cachyos-eac` のエントリが表示されますが、Limine 経由で起動しても EAC のチェックを**通過しません**。かならず "CachyOS EAC" ファームウェアエントリを使用してください。
    :::

    {/* TODO: hide the linux-cachyos-eac entry in Limine (limine-entry-tool has no per-kernel exclude yet) */}

6. **セキュアブートを有効にして EAC で起動する**

    セキュアブートがすでに有効になっている場合は、EAC での起動手順までスキップしてください。

    ファームウェア設定に再起動してセキュアブートを有効にしてください。マザーボードにセキュアブートの切り替え項目がない場合は、[セキュアブートガイド](/ja/configuration/secure_boot_setup#カーネルイメージとブートマネージャーへの署名) の ASUS に関する注意書きを参照してください。

    ```bash
    systemctl reboot --firmware-setup
    ```

    EAC で起動するには、"CachyOS EAC" エントリを `BootNext` に設定して再起動します。`sudo eac-setup boot` も同じ処理を行います。

    ```bash
    EAC_BOOTNUM="$(efibootmgr | sed -n 's/^Boot\([0-9A-F]\{4\}\)\* CachyOS EAC.*/\1/p')"
    sudo efibootmgr --bootnext "$EAC_BOOTNUM" && systemctl reboot
    ```

    `BootNext` は次の起動にのみ適用されます。ゲームセッション後に再起動すると、再び Limine が起動します。

1. **ファームウェアをセットアップモードにする**

    ```bash

    sudo rm -f /usr/lib/systemd/boot/efi/systemd-bootx64.efi.signed
    ```

    次にパッケージをインストールします。

    ```bash
    sudo pacman -S sbctl sbsigntools tpm2-tools cachyos-eac-signing-key linux-cachyos-eac systemd-boot-cachyos-signed

    ```

    NVIDIA GPU を搭載したシステムでは、`linux-cachyos-eac-nvidia-open` (Turing 以降) または `linux-cachyos-eac-nvidia-580xx` (Maxwell、Pascal、Volta) もインストールしてください。ZFS を使用している場合は `linux-cachyos-eac-zfs` もインストールしてください。Realtek 2.5 GbE ネットワークカード用に `r8125-dkms` を使用している場合は `linux-cachyos-eac-r8125` もインストールしてください。

    `bootctl install` は CachyOS 署名済みの systemd-boot を EFI システムパーティションにインストールします。今後の systemd-boot のアップデートも CachyOS によって署名されるため、ご自身で署名する必要はありません。

3. **セキュアブートキーを登録する**

    [すでにセキュアブートを使用している場合](#すでにセキュアブートを使用している場合) の手順で CA を登録した場合は、この手順をスキップしてください。

    `cachyos-eac-signing-key` は、CachyOS EAC CA 証明書を sbctl のカスタム証明書用ディレクトリに配置します。`sbctl` は (まだない場合) 独自のキーを作成し、Microsoft のキー、ファームウェアの組み込みキー、および CachyOS EAC CA とともに登録します。

    :::caution[ASUS 製および Gigabyte 製マザーボード]
    これらのマザーボードでは、以下の最後のコマンドを `--firmware-builtin` なしで `sudo sbctl enroll-keys --microsoft --custom` として実行してください。一部のボードではこのフラグにより重複したキーエントリが作成され、セキュアブートを有効にした際に **Secure Boot Violation** で停止します。すでにこの状態になった場合は、ファームウェア設定ですべてのセキュアブートキーを削除して再度セットアップモードに入り ([UEFI でセットアップモードを有効化](/ja/configuration/secure_boot_setup#uefi-でセットアップモードを有効化) を参照)、CachyOS を起動して `sudo sbctl enroll-keys --microsoft --custom` を実行してください。セキュアブートガイドにあるコマンドは CachyOS EAC CA が含まれないため、ここでは使用しないでください。
    :::

    ```bash
    sudo sbctl create-keys
    sudo sbctl enroll-keys --microsoft --firmware-builtin --custom
    ```

    `sbctl` が `could not enroll built-in firmware keys` で停止した場合、ファームウェアに組み込みキーが存在せず、まだ何も登録されていません。`--firmware-builtin` を外して最後のコマンドを再実行してください。

    証明書が登録されたことを確認します。

    ```bash
    sudo sbctl list-enrolled-keys
    ```

    `db` セクションに `CachyOS EAC CA` が表示されている必要があります。

    次に、通常のカーネルに署名します。これを行わないと、セキュアブートを有効にしたときに通常のカーネルが起動しなくなります。このコマンドは、すでに CachyOS によって署名されている EAC カーネルをスキップします。

    ```bash
    sudo find /boot -maxdepth 1 -name 'vmlinuz-*' ! -name vmlinuz-linux-cachyos-eac -exec sbctl sign -s {} \;
    sudo sbctl list-files
    ```

    出力に、各通常カーネルが署名済み (signed) として表示されている必要があります。

4. **sbctl が CachyOS 署名済みファイルに触れないようにする**

    EAC カーネルと systemd-boot はすでに CachyOS によって署名されています。`sbctl` がこれらに独自のキーで再署名すると、EAC はそれらを認識できなくなります。`cachyos-eac-signing-key` は sbctl の initramfs フックが EAC カーネルに署名しないようにしますが、`sbctl-batch-sign` や `sbctl sign -s` を実行したあとなど、`sbctl` は引き続きデータベース内のすべてのファイルに署名します。

    ```bash
    sudo sbctl list-files
    ```

    `vmlinuz-linux-cachyos-eac`、`systemd-bootx64.efi`、または `BOOTX64.EFI` が一覧に表示されている場合は、それらを削除してパッケージを再インストールし、CachyOS の署名を復元してください。

    ```bash
    sudo sbctl remove-file /boot/vmlinuz-linux-cachyos-eac
    sudo sbctl remove-file /boot/EFI/systemd/systemd-bootx64.efi
    sudo sbctl remove-file /boot/EFI/BOOT/BOOTX64.EFI
    sudo sbctl remove-file /usr/lib/systemd/boot/efi/systemd-bootx64.efi
    sudo pacman -S linux-cachyos-eac systemd-boot-cachyos-signed
    sudo bootctl install
    ```

    一覧にないファイルについては、`sbctl` が `doesn't exist in database` と表示しますが問題ありません。

    署名を確認します。各ファイルに `CachyOS EAC CA` によって発行された署名がちょうど **1 つ** だけあり、続いて `Signature verification OK` と表示される必要があります。

    ```bash
    for f in /boot/vmlinuz-linux-cachyos-eac /boot/EFI/systemd/systemd-bootx64.efi; do
      sudo sbverify --list "$f"
      sudo sbverify --cert /usr/share/cachyos-eac/cachyos-eac-ca.crt "$f"
    done
    ```

    `sbctl verify` は独自のキーで作成された署名のみをカウントするため、これらのファイルを未署名 (not signed) として表示し続けますが、署名しないでください。`sbctl-batch-sign` はこれらをスキップします。

5. **EAC ブートエントリを作成する**

    EAC はカーネルコマンドラインに必要なオプションがあるか確認するため、EAC カーネルには専用のブートエントリが必要です。`sdboot-manage` が自動的に作成するエントリ ("Linux CachyOS Eac") にはこれらのオプションがなく、アップデート時に上書きされるため、実行中システムのコマンドラインをもとに別のエントリを作成します。

    {/* TODO: replace with automatic entry generation (sdboot-manage or package hook) */}

    ```bash
    EAC_REQ="lockdown=integrity lsm=landlock,lockdown,yama,integrity,bpf iommu.passthrough=0 intel_iommu=on module.sig_enforce=1 sysctl.kernel.kexec_load_disabled=1"
    EAC_OPTS="$(sed -E 's/(^| )(BOOT_IMAGE|initrd)=[^ ]*//g' /proc/cmdline) $EAC_REQ"
    echo "$EAC_OPTS"
    ```

    出力に `root=` オプションが含まれ、末尾が EAC オプションで終わっている必要があります。次にエントリを書き込みます。

    ```bash
    printf 'title   CachyOS (EAC)\nlinux   /vmlinuz-linux-cachyos-eac\ninitrd  /initramfs-linux-cachyos-eac.img\noptions %s\n' "$EAC_OPTS" \
      | sudo install -Dm644 /dev/stdin /boot/loader/entries/cachyos-eac.conf
    ```

    :::caution
    このエントリから EAC オプションを 1 つも削除しないでください。これらがないと、EAC はゲームの起動を拒否します。
    :::

6. **セキュアブートを有効にして EAC エントリを起動する**

    セキュアブートがすでに有効になっている場合は、EAC エントリの起動手順までスキップしてください。

    ファームウェア設定に再起動してセキュアブートを有効にしてください。マザーボードにセキュアブートの切り替え項目がない場合は、[セキュアブートガイド](/ja/configuration/secure_boot_setup#カーネルイメージとブートマネージャーへの署名) の ASUS に関する注意書きを参照してください。

    ```bash
    systemctl reboot --firmware-setup
    ```

    EAC エントリを起動するには、systemd-boot メニューで **CachyOS (EAC)** を選択するか、以下を実行します。

    ```bash
    systemctl reboot --boot-loader-entry=cachyos-eac.conf
    ```

<TabItem label='rEFInd'>

rEFInd はデフォルトのブートマネージャーのまま維持されます。Limine と同様に、CachyOS 署名済みの systemd-boot は EFI システムパーティション上の専用ディレクトリにインストールされ、独自のファームウェアブートエントリが作成されます。ゲームをプレイするときは、次の起動時のみ 1 回だけ systemd-boot を起動する (`BootNext`) ようファームウェアに指示します。すると systemd-boot が EAC カーネルを直接起動します。その後は、通常どおり rEFInd から起動します。

これらの手順では、CachyOS インストーラーが rEFInd を構成するのと同様に、EFI システムパーティションが `/boot` にマウントされている必要があります。確認してください。

```bash
bootctl --print-esp-path
```

出力が `/boot` である必要があります。古いインストール環境などで EFI システムパーティションが `/boot/efi` にあるようなほかの構成はサポートされていません。

4. **systemd-boot を別のファームウェアブートエントリとして追加する**

    `sbctl` はカーネルや EFI バイナリが更新されるたびに、データベース内のすべてのファイルに再署名します。たとえば以前の `sbctl sign -s` などにより、CachyOS 署名済みファイルがデータベースに含まれていないか確認します。

    ```bash
    sudo sbctl list-files
    ```

    一覧に `cachyos-eac` を含むパス、または `/usr/lib/systemd/boot/efi/systemd-bootx64.efi` が表示されている場合は、`sudo sbctl remove-file <path>` で削除してください。その後、パッケージを再インストールして CachyOS の署名を復元します。

    ```bash
    sudo pacman -S linux-cachyos-eac systemd-boot-cachyos-signed
    ```

    署名済みの systemd-boot を EFI システムパーティション上の専用ディレクトリにコピーします。

    ```bash
    ESP="$(bootctl --print-esp-path)"
    sudo install -Dm644 /usr/lib/systemd/boot/efi/systemd-bootx64.efi.signed "$ESP/EFI/cachyos-eac/systemd-bootx64.efi"
    ```

    `EFI/cachyos-eac` が存在する限り、`systemd-boot-cachyos-signed` はこのコピーを自動的に更新します。

    次にファームウェアブートエントリを作成します。`--create-only` は起動順序を変更せずにエントリを追加するため、rEFInd がデフォルトのまま維持されます。

    ```bash
    ESP_DEV="$(findmnt -no SOURCE "$ESP")"
    ESP_DISK="/dev/$(lsblk -no PKNAME "$ESP_DEV")"
    ESP_PART="$(cat "/sys/class/block/$(basename "$ESP_DEV")/partition")"
    sudo efibootmgr --create-only --disk "$ESP_DISK" --part "$ESP_PART" \
      --label "CachyOS EAC" --loader '\EFI\cachyos-eac\systemd-bootx64.efi'
    ```

    新しいエントリが一覧にあり、`BootOrder` の先頭が引き続き rEFInd であることを確認します。

    ```bash
    efibootmgr
    ```

5. **EAC ブートエントリを作成する**

    systemd-boot は、すでに EAC カーネルとその initramfs が存在する EFI システムパーティションから設定を読み込みます。実行中システムのカーネルコマンドラインに EAC オプションを追加して構築します。

    ```bash
    EAC_REQ="lockdown=integrity lsm=landlock,lockdown,yama,integrity,bpf iommu.passthrough=0 intel_iommu=on module.sig_enforce=1 sysctl.kernel.kexec_load_disabled=1"
    EAC_OPTS="$(sed -E 's/(^| )(BOOT_IMAGE|initrd)=[^ ]*//g' /proc/cmdline) $EAC_REQ"
    echo "$EAC_OPTS"
    ```

    出力に `root=` オプションが含まれ、末尾が EAC オプションで終わっている必要があります。エントリを書き込み、systemd-boot がメニューを表示せずに起動するようデフォルトに設定します。

    ```bash
    ESP="$(bootctl --print-esp-path)"
    printf 'title   CachyOS (EAC)\nlinux   /vmlinuz-linux-cachyos-eac\ninitrd  /initramfs-linux-cachyos-eac.img\noptions %s\n' "$EAC_OPTS" \
      | sudo install -Dm644 /dev/stdin "$ESP/loader/entries/cachyos-eac.conf"
    printf 'default cachyos-eac.conf\ntimeout 0\n' | sudo install -Dm644 /dev/stdin "$ESP/loader/loader.conf"
    ```

    それでも systemd-boot のメニューを表示したい場合は、起動中に <kbd>Space</kbd> を押し続けてください。

    rEFInd は EAC カーネルと systemd-boot を自動的に見つけてメニューに追加します。rEFInd は独自のキーで署名されているため、rEFInd メニューから起動したものは EAC のチェックを**通過しません**。両方のエントリを非表示にします。

    ```bash
    printf '\n# Easy Anti-Cheat: boot these only through the "CachyOS EAC" firmware entry\ndont_scan_files +,vmlinuz-linux-cachyos-eac\ndont_scan_dirs +,EFI/cachyos-eac\n' \
      | sudo tee -a "$ESP/EFI/refind/refind.conf" >/dev/null
    ```

    `+` を付けることで、rEFInd がすでにスキップしているファイルとディレクトリを維持します。次回の起動からは、rEFInd メニューに通常のカーネルのみが表示されるようになります。

6. **セキュアブートを有効にして EAC で起動する**

    セキュアブートがすでに有効になっている場合は、EAC での起動手順までスキップしてください。

    ファームウェア設定に再起動してセキュアブートを有効にしてください。マザーボードにセキュアブートの切り替え項目がない場合は、[セキュアブートガイド](/ja/configuration/secure_boot_setup#カーネルイメージとブートマネージャーへの署名) の ASUS に関する注意書きを参照してください。

    ```bash
    systemctl reboot --firmware-setup
    ```

    EAC で起動するには、"CachyOS EAC" エントリを `BootNext` に設定して再起動します。`sudo eac-setup boot` も同じ処理を行います。

    ```bash
    EAC_BOOTNUM="$(efibootmgr | sed -n 's/^Boot\([0-9A-F]\{4\}\)\* CachyOS EAC.*/\1/p')"
    sudo efibootmgr --bootnext "$EAC_BOOTNUM" && systemctl reboot
    ```

    `BootNext` は次の起動にのみ適用されます。ゲームセッション後に再起動すると、再び rEFInd が起動します。

## セットアップの確認

EAC エントリで起動したあと、`cachyos-settings` に含まれる `eac-status` を実行します。

```bash
sudo eac-status
```

このコマンドは、セキュアブートとセットアップモード、TPM、登録された CachyOS EAC CA、EAC カーネルと systemd-boot の署名、カーネルコマンドライン、lockdown、モジュール署名、kexec、IOMMU、および (TPM イベントログから) ファームウェアが起動の検証に使用した証明書を確認します。すべてのチェックが `[ OK ]` となり、最後の行に `All checks passed` と表示される必要があります。通常のブートエントリで実行した場合は、ファームウェアとブートファイルのみを確認し、準備が整っていれば末尾に `The boot files are ready` と表示されます。

これらのチェックはシステム側のみを対象としています。実際にゲームが起動するかどうかは、引き続き Easy Anti-Cheat およびゲーム側の対応に依存します。

TPM イベントログに Microsoft の証明書が含まれていることは正常であり (GPU ファームウェア用に使用されます)、報告されません。独自の "Database Key" など、それ以外の証明書が使われた場合は `[WARN] Boot was also verified by` として報告されます。

## トラブルシューティング

### `eac-status` で 2 つの署名または自分のキーが報告される

`has 2 signatures` または `Boot was also verified by Database Key` と表示される場合、`sbctl` が EAC カーネルまたは systemd-boot に独自のキーで再署名したことを意味します。`cachyos-eac-signing-key` の 1-2 より前のバージョンでは、initramfs が再構築されるたびに sbctl の initramfs フックがこれを行っていたため、まずシステムを更新してください。

```bash
sudo pacman -Syu
```

その後、`sudo eac-setup` をもう一度実行してください。sbctl のデータベースから対象ファイルを削除し、CachyOS の署名を復元します。手動で行う場合は、以下の手順にしたがってください。

systemd-boot を使用している場合は、[お使いのブートマネージャー向けの設定](#お使いのブートマネージャー向けの設定) の systemd-boot タブの手順 4 を繰り返して、sbctl のデータベースからファイルを削除し、パッケージを再インストールしてください。

Limine または rEFInd を使用している場合は、その手順には**したがわないでください**。含まれる `bootctl install` により systemd-boot がデフォルトのブートマネージャーになり、EFI システムパーティション上のフォールバックブートローダーが置き換わってしまいます。かわりに sbctl のデータベースを確認してください。

```bash
sudo sbctl list-files
```

一覧に `cachyos-eac` を含むパス、または (セキュアブートガイドの systemd-boot の手順から残った) `/usr/lib/systemd/boot/efi/systemd-bootx64.efi` が含まれている場合は、`sudo sbctl remove-file <path>` で削除してください。その後、パッケージを再インストールし、署名済みの systemd-boot を再度コピーします。

```bash
sudo pacman -S linux-cachyos-eac systemd-boot-cachyos-signed
ESP="$(bootctl --print-esp-path)"
sudo install -Dm644 /usr/lib/systemd/boot/efi/systemd-bootx64.efi.signed "$ESP/EFI/cachyos-eac/systemd-bootx64.efi"
```

### `eac-status` で CachyOS EAC CA によって検証されなかったと報告される

`Boot was not verified by CachyOS EAC CA` とともにカーネルコマンドラインのチェック失敗も表示されている場合は、誤ったエントリで起動しています。[ゲームでシステムが非対応と表示される](#ゲームでシステムが非対応と表示される) を参照してください。

失敗したチェックがそれだけの場合、ファームウェアがブートファイルの検証に使用した証明書を記録しなかったことを意味します。MSI 製マザーボードでは、デフォルトのセキュアブートポリシーが原因である可能性が最も高く、セキュアブートが有効であってもファームウェアが検証なしですべてのブートファイルを起動してしまいます。

ファームウェア設定のセキュアブート画面を開いてください。マザーボードによって、**Settings > Advanced > Windows OS Configuration > Secure Boot** または **Settings > Security > Secure Boot** の配下にあります。オプション名はファームウェアのバージョンによって異なります。

| オプション             | 値                                                                 |
| ---------------------- | ------------------------------------------------------------------ |
| Image Execution Policy | **Fixed Media** および **Removable Media** に対して **Deny Execute** |
| Secure Boot Preset     | **Maximum Security**                                               |
| Target OS              | **Windows UEFI OS**                                                |

:::caution
**Secure Boot Mode** を **Standard** に切り替えたり、ファクトリーキーを復元したりしないでください。どちらも CachyOS EAC CA と独自のキーを削除してしまいます。
:::

変更を保存して EAC エントリを起動し、`sudo eac-status` をもう一度実行してください。ここで CachyOS EAC CA が登録されていないと報告された場合は、ファームウェアがキーをリセットしています。`sudo eac-setup` をもう一度実行してください。

### ゲームでシステムが非対応と表示される

EAC エントリで `sudo eac-status` を実行し、`[FAIL]` と表示されたチェックをすべて修正してください。多くの場合、誤ったエントリで起動しており、`eac-status` がカーネルコマンドラインに EAC オプションが不足していると報告します。`sudo eac-setup boot` で再起動してください。systemd-boot の場合は、自動生成された "Linux CachyOS Eac" エントリではなく **CachyOS (EAC)** を選択することもできます。Limine、rEFInd、GRUB を使用している場合は、お使いのブートマネージャーのメニューから EAC カーネルを起動しないでください。

### EAC エントリではなく Limine や rEFInd が起動する

再起動前に `BootNext` が設定されていたか確認してください。

```bash
efibootmgr | grep -E 'BootNext|CachyOS EAC'
```

"CachyOS EAC" エントリがない場合は、ファームウェアによって削除されています (ファームウェアの更新やリセット後に発生するボードがあります)。`sudo eac-setup` を実行して再作成するか、[お使いのブートマネージャー向けの設定](#お使いのブートマネージャー向けの設定) の Limine または rEFInd タブの手順 4 を繰り返してください。ファームウェアのワンタイムブートメニューから "CachyOS EAC" を選択することもできます。

### EAC エントリでモジュールが読み込まれない

DKMS でビルドされたモジュールはカーネルのキーで署名されていないため読み込めません。EAC カーネル向けに提供されているモジュール (`linux-cachyos-eac-nvidia-open`、`linux-cachyos-eac-nvidia-580xx`、`linux-cachyos-eac-zfs`、または `linux-cachyos-eac-r8125`) を使用するか、DKMS モジュールが必要な作業を行う際は通常のカーネルで起動してください。
