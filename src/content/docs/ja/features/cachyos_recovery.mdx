[CachyOS Recovery](https://github.com/CachyOS/cachyos-recovery) は、カーネルと並んでインストールされ、ブートメニューから起動できる小型のリカバリーシステムです。アップデートや設定変更によってシステムが破損した際、ライブ USB を使わずに以下の操作を行えます。

- **Btrfs スナップショットの起動**: システムを変更せずに、正常に動作するかを確認できます。
- **スナップショットへのロールバック**: 対応するカーネルやブートファイルを含め、システムを恒久的にスナップショットへ復元します。
- **コンテナ内でインストール済みシステムを開く**: 手動でシステムを修復できます。

リカバリー環境のサイズは約 70 MB です。インストール済みシステムの状態に依存しないため、システム自体が起動しなくなった場合でも動作します。

:::caution
スナップショットはバックアップではありません。システムと同じディスク上に保存されるため、ディスクの故障や `/home` 内のファイルの誤削除からは保護されません。重要なデータは定期的にバックアップを取ってください。
:::

## 要件

リカバリー自体は、Btrfs、ext4、XFS、または F2FS をルートファイルシステムとする任意の CachyOS 環境で起動できます。スナップショット関連の操作には、さらに以下の要件が必要です。

- CachyOS インストーラーが構成するように、`@` サブボリュームにルートが配置された **Btrfs** ルートファイルシステム。
- ルートサブボリュームの**読み取り専用スナップショット**。Snapper はデフォルトでこれを作成し、`cachyos-snapper-support` パッケージを使用すると、CachyOS は `pacman` トランザクションの前後に自動的にスナップショットを作成します。systemd-boot を使用している環境にはまだこのパッケージが含まれていないため、[「No snapshots were found」](#no-snapshots-were-found) を参照してください。[Btrfs スナップショット](/ja/configuration/btrfs_snapshots)もあわせてご覧ください。
- initramfs ジェネレーターとしての **mkinitcpio**（CachyOS のデフォルトです）。

UEFI システムでは、EFI システムパーティションが `/etc/fstab` にタイプ `vfat` として記載され、`/boot`、`/efi`、または `/boot/efi` にマウントされている必要があります。

EFI システムパーティションが `/boot` にマウントされている場合、ロールバック時には **Limine**、**systemd-boot**（`sdboot-manage` を使用）、および **GRUB** のカーネル、initramfs イメージ、ブートマネージャー設定も再生成されます。**rEFInd** は設定の更新を必要としません。EFI システムパーティションが `/efi` または `/boot/efi` にある場合や、`/boot` がルートファイルシステムの一部となっている BIOS システムでは、カーネル自体がスナップショットに含まれているため、ロールバック時に一緒に復元されます。

### 暗号化されたディスクとキーボード配列

**LUKS** で暗号化されたディスクに対応しています。ディスクがまだロック解除されていない場合、リカバリーは起動時に LUKS パスフレーズの入力を求めます。通常は TPM2 や FIDO2 でディスクをロック解除している場合でも、パスフレーズを手元に用意しておいてください。

リカバリーでは、パスフレーズの入力や chroot へのログインを含め、常に **US キーボード配列**が使用されます。パスフレーズやパスワードにお使いのキーボードで配置が異なる文字が含まれている場合は、US キーボードの配置に従って入力してください。

## インストール

<Tabs syncKey="firmware">
  <TabItem label="UEFI">
    ```bash
    sudo pacman -S cachyos-recovery
    ```

    インストール中、pacman フックによってすべてが自動的にセットアップされます。

    - EFI システムパーティション上の `EFI/Linux/cachyos-recovery.efi` にリカバリーイメージをコピーします。
    - ルートファイルシステム（および LUKS デバイスがある場合はそれ）の場所を、イメージの隣にある小さなアドオン `EFI/Linux/cachyos-recovery.efi.extra.d/root.addon.efi` に書き込みます。
    - `sbctl` でセキュアブートがセットアップされている場合、両方のファイルを `sbctl` で署名します（[セキュアブート](#セキュアブート)を参照）。
    - **Limine** の場合、ブートメニューに **CachyOS Recovery** エントリーを追加します。
    - **GRUB** の場合、**CachyOS Recovery** エントリーを `/etc/grub.d/50-cachyos-recovery` に書き込み、GRUB の設定を再生成します。
    - ファームウェアのブートメニューに **CachyOS Recovery** エントリーを追加します（`efibootmgr` が必要です）。このエントリーはブート順序の最後に追加されるため、通常のブートマネージャーがデフォルトのまま維持されます。

    **systemd-boot** は `EFI/Linux` 内のイメージを自動的に一覧表示し、**rEFInd** は EFI システムパーティションをスキャンする際にイメージを検出します。その他のブートマネージャーを使用している場合は、ファームウェアのブートメニューからリカバリーを起動してください。
  </TabItem>
  <TabItem label="BIOS">
    ```bash
    sudo pacman -S cachyos-recovery-legacy
    ```

    インストール中、pacman フックによって **Limine** または **GRUB** のブートメニューに **CachyOS Recovery** エントリーが追加されます。GRUB の場合は、リカバリーカーネルと initramfs を `/boot/cachyos-recovery.vmlinuz` と `/boot/cachyos-recovery.initrd` にコピーし、エントリーを `/etc/grub.d/50-cachyos-recovery` に書き込んで GRUB の設定を再生成します。

    `cachyos-recovery` と `cachyos-recovery-legacy` は同時にインストールできません。BIOS システムに `cachyos-recovery` をインストールしないでください（UEFI イメージのみが含まれています）。
  </TabItem>
</Tabs>

パッケージを更新するたびにこのフックが再実行されます。新しいディスクへの移行や暗号化のセットアップなどでシステムのインストール場所を変更した場合は、リカバリーがルートファイルシステムを再び検出できるようにパッケージを再インストールしてください（UEFI の場合は `sudo pacman -S cachyos-recovery`、BIOS の場合は `sudo pacman -S cachyos-recovery-legacy`）。

パッケージのインストールおよび再インストールは、通常通り起動したシステムから行ってください。スナップショットから起動している間は、ルートファイルシステムを検出できません。

### セキュアブート

[セキュアブートのセットアップ](/ja/configuration/secure_boot_setup)の手順に従って `sbctl` でセキュアブートをセットアップしている場合、リカバリーイメージとそのアドオンは自動的に署名されます。これは以下の条件を満たす場合に実行されます。

- `sbctl` がインストールされており、鍵が作成されている。
- セキュアブートが有効になっており、ファームウェアがセットアップモード（Setup Mode）ではない。
- 鍵が登録（Enroll）されている。

署名の状態は以下のコマンドで確認できます。

```bash
sudo sbctl verify | grep cachyos-recovery
```

たとえばパッケージをインストールした後にセキュアブートを有効にした場合など、ファイルが署名されていない場合は、リカバリーイメージを削除してからパッケージを再インストールしてください。すでに EFI システムパーティション上に変更されていないイメージが存在する場合、フックはイメージの再コピーと再署名を行わないため、再インストールだけでは不十分です。

```bash
sudo rm /boot/EFI/Linux/cachyos-recovery.efi
sudo pacman -S cachyos-recovery
```

EFI システムパーティションが `/efi` または `/boot/efi` にマウントされている場合はパスを調整してください。これにより、フックが両方のファイルに署名し、Limine を使用している場合はブートメニューのエントリーも更新します。

:::caution
セキュアブートが有効な状態では、ファームウェアが未署名のリカバリーイメージの起動を拒否し、Limine はリカバリーメニューの代わりにエラーを表示します。Limine が前回のエントリーを記憶する設定になっている場合は、ブートメニューで別のエントリーを選択してシステムを再度起動し、ファイルに署名してください。
:::

## リカバリーの起動

<Steps>
1. コンピューターを再起動します。
2. ブートメニューで **CachyOS Recovery** を選択します。ブートマネージャーにエントリーがない場合は、代わりにファームウェアのブートメニュー（通常は起動中に <kbd>F8</kbd>、<kbd>F11</kbd>、または <kbd>F12</kbd> キー）を開き、そこから **CachyOS Recovery** を選択してください。

   <ImageComponent imgsrc={import('~/assets/images/cachyos-recovery-limine-entry.png')} />
3. ディスクが暗号化されている場合は、LUKS パスフレーズを入力します。5 回まで試行できます。
4. リカバリーメニューが開きます。

   <ImageComponent imgsrc={import('~/assets/images/cachyos-recovery-main-menu.png')} />
</Steps>

矢印キーと <kbd>Enter</kbd> キーで項目を選択し、<kbd>Esc</kbd> キーで戻ります。リスト表示では、文字を入力して項目を絞り込むことができます。下部のボックスには選択中のアクションの説明が表示されます。

リカバリーはシステムを読み取り専用でマウントします。ロールバックを開始するか chroot 内で変更を加えるまで、ディスク上のデータは何も変更されません。

| アクション | 説明 |
| --- | --- |
| **Boot Btrfs snapshot** | 一時的な書き込み可能ルートを使用してスナップショットを起動します。最初に試す方法として推奨されます。 |
| **Rollback Btrfs snapshot** | スナップショットを恒久的に復元します。 |
| **Chroot into target system** | インストール済みシステムをコンテナ内で起動します（上級者向け）。 |
| **Reboot** | コンピューターを再起動します。 |

スナップショットに関する 2 つのアクションは、ルートファイルシステムが Btrfs の場合にのみ表示されます。

## スナップショットの起動

スナップショットの起動は、正常に動作する状態を見つけるための最も安全な方法です。スナップショットを通常のシステムのように使用でき、保持することを決定するまで何も復元されません。

<Steps>
1. **Boot Btrfs snapshot** を選択します。
2. スナップショットを選択します。リストには Btrfs サブボリューム ID と作成日時（UTC）が表示されます。右側にはスナップショットのパスと、Snapper スナップショットの場合はその説明とタイプが表示されます。ルートファイルシステムのスナップショットを選択してください。パスは `.snapshots/<number>/snapshot` のような形式です。

   <ImageComponent imgsrc={import('~/assets/images/cachyos-recovery-snapshot-list.png')} />
3. 起動するカーネルを選択します。このスナップショット内にインストールされているカーネルのみが一覧表示されます。

   <ImageComponent imgsrc={import('~/assets/images/cachyos-recovery-kernel-picker.png')} />
4. リカバリーがスナップショットを準備して起動します。システムが通常通り起動します。ディスクが暗号化されている場合は、再度パスフレーズの入力を求められることがあります。
</Steps>

スナップショットから起動している間の挙動は以下の通りです。

- システムへの変更（ルートサブボリューム上のすべての内容）はメモリ上に保持され、再起動すると失われます。
- `/home` などその他のサブボリュームやパーティションは通常通りマウントされます。**これらへの変更は保持されます。**
- ご自身で設定したカーネルパラメーターは適用されません。スナップショットはシステムの検出に必要なパラメーターを使用して起動します。

### スナップショットの保持

デスクトップにログインすると、スナップショットを保持するかどうかを尋ねる通知が表示されます。

<ImageComponent imgsrc={import('~/assets/images/cachyos-recovery-notifier.png')} />

- **Rollback snapshot** を選択するとターミナルが開き、パスワードの入力を求められます。`y` で確定すると、スナップショットが現在のシステムを置き換えます（[ロールバックで行われる処理](#ロールバックで行われる処理)を参照）。完了後に再起動してください。
- **Stay in snapshot** を選択すると通知が閉じます。何も復元されず、インストール済みシステムは変更されないままとなります。

通知機能のないウィンドウマネージャーを使用している場合などで通知が表示されない場合や、ターミナルが開かない場合は、ターミナルからロールバックを開始してください。

```bash
sudo cachyos-recovery rollback
```

このコマンドは、リカバリーからスナップショットを起動している間にのみ利用できます。

:::tip
スナップショットのカーネルへの再起動にハードウェアが対応していないなどの理由でスナップショットが起動しない場合は、代わりにリカバリーメニューの **Rollback Btrfs snapshot** を使用してください。
:::

## スナップショットのロールバック

どのスナップショットが正常に動作するか分かっている場合や、スナップショットの起動に失敗する場合に使用します。

<Steps>
1. **Rollback Btrfs snapshot** を選択します。
2. [スナップショットの起動](#スナップショットの起動)の説明に従って、復元するスナップショットを選択します。
3. `y` を入力して <kbd>Enter</kbd> キーを押し、確定します。
4. ロールバックが完了するまで待ちます。その後、リカバリーは再起動するかどうかを尋ねます。
5. **Yes, reboot** を選択して、復元されたシステムを起動します。
</Steps>

:::danger[現在のシステム状態は削除されます]
ロールバックを実行すると、現在のルートサブボリュームが置き換えられ、ロールバックが成功した時点で古いものは削除されます。この操作を取り消すには、それ以前に作成された別のスナップショットを使用するしかありません。ホームディレクトリおよびその他のサブボリュームは影響を受けず、既存のスナップショットも保持されます。
:::

### ロールバックで行われる処理

<Steps>
1. EFI システムパーティションが `/boot` にマウントされている場合、リカバリーはスナップショット内のツールを使用して、スナップショットのカーネルをコピーし、対応する initramfs イメージとブートマネージャーの設定を生成します。これらのファイルはまず一時的な場所に準備されるため、この時点では EFI システムパーティションはまだ変更されません。スナップショット内に存在しないカーネルはブートメニューから削除され、`sbctl` でセキュアブートがセットアップされている場合はファイルに署名が行われます。
2. スナップショットから新しいルートサブボリュームを作成し、現在のルートと入れ替えます。
3. `/.snapshots` などのネストされたサブボリュームを古いルートから新しいルートへ移動し、スナップショットを引き続き利用できるようにします。
4. 準備したブートファイルを EFI システムパーティションにコピーします。
5. 古いルートサブボリュームを削除します。
</Steps>

ブートファイルがコピーされる前のステップで失敗した場合、リカバリーは古いルートを元に戻し、EFI システムパーティションを変更しないままにします。

EFI システムパーティションが `/efi` または `/boot/efi` にある場合は、カーネル自体がスナップショットに含まれているため、手順 1 と手順 4 はスキップされます。

:::caution[セキュアブートと古いスナップショット]
新しいブートファイルは、**スナップショット内の** `sbctl` を使用して署名されます。セキュアブートを設定する前に作成されたスナップショットへロールバックすると、署名が行われないため、セキュアブートが有効な状態ではシステムが起動しなくなります。リカバリーはこの点について警告を表示しません。また、`/var/lib/sbctl` にある `sbctl` の鍵も古いルートと一緒に削除されます。

リカバリーイメージ自体は署名されたまま残ります。より新しいスナップショットに `sbctl` とその鍵がまだ含まれている場合は、ファームウェアのブートメニューから **CachyOS Recovery** を起動し、そのスナップショットへロールバックしてください。ロールバックによりブートファイルが再び署名されます。

それ以外の場合は、ファームウェアでセキュアブートを無効にしてシステムを起動してください。`sbctl` をインストールし、`/.snapshots` 内のより新しいスナップショットから `/var/lib/sbctl` をコピーして戻します。その後、[カーネルイメージとブートマネージャーへの署名](/ja/configuration/secure_boot_setup#カーネルイメージとブートマネージャーへの署名)の説明に従ってカーネルとブートマネージャーに署名し、セキュアブートを再度有効にしてください。`/var/lib/sbctl` を含む新しいスナップショットが存在しない場合は、[セキュアブートのセットアップ](/ja/configuration/secure_boot_setup)を最初からやり直して新しい鍵を作成し、登録（Enroll）してください。
:::

:::note[Easy Anti-Cheat カーネル]
ロールバックでは `linux-cachyos-eac` カーネルをご自身の鍵で署名しないため、[Easy Anti-Cheat](/ja/configuration/easy_anti_cheat) のブートエントリーに必要な CachyOS の署名が維持されます。ロールバック後に Easy Anti-Cheat のエントリーが起動しない場合は、`linux-cachyos-eac` を再インストールするか、Limine の場合は `sudo limine-mkinitcpio` を実行して、CachyOS 署名済みカーネルを `/boot` に再度コピーしてください。
:::

## システムへの chroot

**Chroot into target system** は、`systemd-nspawn` を使用してインストール済みシステムをコンテナ内で起動します。インストール済みシステムのログインプロンプトが表示され、ユーザー名とパスワードでログインできます。このモードではルートファイルシステムが書き込み可能になるため、加えた変更は保持されます。

これは、`/etc` 内の壊れた設定ファイルの修正や、起動を妨げているサービスの無効化など、ルートファイルシステム上のオフライン修復に使用してください。コンテナには**ネットワークアクセスがなく**、ルートファイルシステムのみがマウントされます。Btrfs では、`/home`、`/var/cache`、`/var/log` などの他のサブボリュームや、EFI システムパーティションを含む他のパーティションは利用できない場合があります。パッケージのインストールや再インストールなど、これらを必要とする修復には、ライブ ISO から [cachy-chroot](/ja/features/cachy_chroot) を使用してください。

コンテナを終了してリカバリーメニューに戻るには、1 秒以内に <kbd>Ctrl</kbd>+<kbd>]</kbd> を 3 回押してください。

## CachyOS Recovery の削除

<Tabs syncKey="firmware">
  <TabItem label="UEFI">
    ```bash
    sudo pacman -Rns cachyos-recovery
    ```

    pacman フックによって、EFI システムパーティションからリカバリーイメージとそのアドオンが削除され、Limine または GRUB のブートメニューエントリー、およびファームウェアのブートメニュー内の **CachyOS Recovery** エントリーも削除されます。
  </TabItem>
  <TabItem label="BIOS">
    ```bash
    sudo pacman -Rns cachyos-recovery-legacy
    ```

    pacman フックによって、Limine のブートメニューエントリーが削除されます。GRUB の場合は、コピーされたリカバリーカーネルと initramfs、および `/etc/grub.d` 内のエントリーが削除され、GRUB の設定が再生成されます。
  </TabItem>
</Tabs>

## トラブルシューティング

### ブートメニューに CachyOS Recovery のエントリーがない

パッケージ（UEFI の場合は `cachyos-recovery`、BIOS の場合は `cachyos-recovery-legacy`）を再インストールし、**Installing system recovery image...** ステップの出力を確認してください。

```bash
sudo pacman -S cachyos-recovery
```

Limine のエントリーには `limine-entry-tool` が、ファームウェアのエントリーには `efibootmgr` が必要です。systemd-boot の場合は、systemd-boot がインストールされているのと同じ EFI システムパーティション上にイメージが配置されている必要があります。

### セキュアブートが有効な状態でリカバリーが起動しない

リカバリーイメージまたはそのアドオンが署名されていません。[セキュアブート](#セキュアブート)の説明に従って確認し、署名してください。

### 「No snapshots were found」

リカバリーは読み取り専用のスナップショットのみを一覧表示します。Snapper がルートファイルシステムのスナップショットを作成しているか確認してください。

```bash
sudo snapper list
```

コマンドが設定 `root` が存在しないと報告する場合、Snapper がセットアップされていません。これは、インストーラーがまだ Snapper をセットアップしない **systemd-boot** 環境で発生します。ルートファイルシステム用の Snapper 設定を作成し、`pacman` トランザクションの前後にスナップショットを取得するための `snap-pac` を導入する `cachyos-snapper-support` をインストールしてください。

```bash
sudo pacman -S cachyos-snapper-support
```

これ以降に取得されたスナップショットをリカバリーで使用できるようになります。

### スナップショットの起動に失敗する、または画面が真っ暗になる

リカバリーからスナップショットのカーネルを直接起動する方法は、すべてのデバイスで動作するわけではありません。代わりに **Rollback Btrfs snapshot** を使用してスナップショットを復元してください。

### 「No ESP partition was found」

パッケージのインストールおよびロールバックは、どちらも `/etc/fstab`（ロールバック時はスナップショット内の `/etc/fstab`）から EFI システムパーティションの場所を読み取ります。パーティションはタイプ `vfat` として記載され、`/boot`、`/efi`、または `/boot/efi` にマウントされている必要があります。

### ロールバックがエラーで停止する

メッセージの上にあるエラーを確認してください。リカバリーがブートファイルを準備できなかった場合は、何も変更されておらず、古いシステムがそのまま残っています。

スナップショットは復元されたものの `/boot` が不整合な状態であるというメッセージが表示された場合は、スナップショットの復元自体は完了していますが、ブートファイルのコピーに失敗しています。ライブ ISO から起動し、[cachy-chroot](/ja/features/cachy_chroot) でシステムに入ってブートファイルを再生成してください。

- **Limine** の場合は `limine-mkinitcpio` を実行します。
- その他のブートマネージャーの場合は、`pacman -S linux-cachyos` などを実行してカーネルパッケージを再インストールします。これは、インストール済みのカーネルバージョンがまだパッケージキャッシュに残っている場合に有効です。`pacman` がダウンロードできない場合は、代わりに `pacman -Syu` でシステム全体を更新してください。
