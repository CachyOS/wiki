<TabItem label="Met Octopi (GUI)">

Octopi is een grafische pakketbeheerder voor op Arch gebaseerde distributies die een handige manier biedt om pakketten en updates te beheren.
Volg deze stappen om je systeem met Octopi bij te werken:

<Steps>

1. Start **Octopi** vanuit het applicatiemenu.
2. Klik in het hoofdvenster op de knop **Check updates** (linksboven) en daarna op **System upgrade** ernaast.
3. Octopi controleert nu op beschikbare updates en vraagt of je ze in Octopi zelf of in een terminal wilt installeren.
4. Klik op de knop **Apply** om verder te gaan met de update.
5. Octopi downloadt en installeert de updates.
6. Het wordt aangeraden je computer na een grote update opnieuw op te starten **(vooral als de kernel is bijgewerkt)**.

</Steps>

</TabItem>

<TabItem label="Met Pacman">

<Steps>

1. Open een terminalemulator (of druk op `ctrl + alt + t` - `mod + return` in een WM, bijv. Qtile).
2. Voer het volgende commando uit om het systeem bij te werken:

   ```sh
   sudo pacman -Syu
   ```
3. Het wordt aangeraden je computer na een grote update opnieuw op te starten **(vooral als de kernel is bijgewerkt)**.

</Steps>

</TabItem>

<TabItem label="Offline systeemupdate">

*CachyOS ondersteunt offline systeemupgrades met het script [`pacman-offline`](https://github.com/eworm-de/pacman-offline). Hiermee kan je systeem pakketupdates downloaden en ze bij de volgende herstart toepassen. (Ja, net als op Windows)*

:::note
Het hulpmiddel `pacman-offline` integreert met de functie voor offline updates van systemd. Het handelt kernelupdates en het laden van modules automatisch af.

Het bestand `/etc/pacman.d/offline.conf` is cruciaal om te bepalen welke pakketten tijdens gewone en offline updates worden bijgewerkt. Zorg dat het correct is ingesteld voor je gewenste kernel, of voeg de pakketten toe die alleen tijdens het uitvoeren van pacman-offline moeten worden bijgewerkt en bij een gewone update moeten worden genegeerd. Voorbeeld: `pacman -Syu`.

**Als je de timer voor automatische updates inschakelt, hoef je je systeem niet meer handmatig bij te werken.**
:::

<Steps>

1. **Installeer het pakket pacman-offline**

   ```bash
   sudo pacman -S pacman-offline
   ```

2. **Pacman laten lezen uit de aparte lijst met te negeren pakketten.**

   :::note[Voeg de regel toe na de sectie [options]. Bekijk het voorbeeld hieronder ter referentie.]
   :::

   ```bash title='Voeg de volgende regel toe aan het bestand /etc/pacman.conf'
   Include = /etc/pacman.d/offline.conf
   ```
   *Voorbeeld*
   ```bash
   # /etc/pacman.conf
   # REPOSITORIES
   #   - can be defined here or included from another file
   #   - pacman will search repositories in the order defined here
   #   - local/custom mirrors can be added here or in separate files
   #   - repositories listed first will take precedence when packages
   #     have identical names, regardless of version number
   #   - URLs will have $repo replaced by the name of the current repo
   #   - URLs will have $arch replaced by the name of the architecture
   #
   # Repository entries are of the format:
   #       [repo-name]
   #       Server = ServerName
   #       Include = IncludePath
   #
   # The header [repo-name] is crucial - it must be present and
   # uncommented to enable the repo.
   #
   # GENERAL OPTIONS
   [options]
   # other options like 'Color', 'CheckSpace', etc. can be here
   Include = /etc/pacman.d/offline.conf
   ```
3. **De CachyOS-kernels toevoegen zodat pacman ze negeert tijdens gewone updates**

   Het hulpmiddel `pacman-offline` gebruikt dit bestand om te bepalen welke pakketten moeten worden genegeerd tijdens de gewone pacman-updates.

   Bijvoorbeeld: wanneer je `sudo pacman -Syu` uitvoert

   *Vervang de inhoud van het bestand `/etc/pacman.d/offline.conf` door het volgende:*

   ```text
   # Arch Linux kernels
   IgnorePkg = linux linux-headers linux-docs
   IgnorePkg = linux-lts linux-lts-headers linux-lts-docs
   IgnorePkg = linux-zen linux-zen-headers linux-zen-docs
   IgnorePkg = linux-hardened linux-hardened-headers linux-hardened-docs

   # CachyOS kernels
   IgnorePkg = linux-cachyos linux-cachyos-headers linux-cachyos-nvidia-open linux-cachyos-zfs
   IgnorePkg = linux-cachyos-bmq linux-cachyos-bmq-headers linux-cachyos-bmq-nvidia-open linux-cachyos-bmq-zfs
   IgnorePkg = linux-cachyos-bore linux-cachyos-bore-headers linux-cachyos-bore-nvidia-open linux-cachyos-bore-zfs
   IgnorePkg = linux-cachyos-deckify linux-cachyos-deckify-headers linux-cachyos-deckify-nvidia-open linux-cachyos-deckify-zfs
   IgnorePkg = linux-cachyos-eevdf linux-cachyos-eevdf-headers linux-cachyos-eevdf-nvidia-open linux-cachyos-eevdf-zfs
   IgnorePkg = linux-cachyos-gcc linux-cachyos-gcc-headers linux-cachyos-gcc-nvidia-open linux-cachyos-gcc-zfs
   IgnorePkg = linux-cachyos-hardened linux-cachyos-hardened-headers linux-cachyos-hardened-nvidia-open linux-cachyos-nvidia-hardened-zfs
   IgnorePkg = linux-cachyos-lts linux-cachyos-lts-headers linux-cachyos-lts-nvidia-open linux-cachyos-lts-zfs
   IgnorePkg = linux-cachyos-rc linux-cachyos-rc-headers linux-cachyos-rc-nvidia-open linux-cachyos-rc-nvidia-open linux-cachyos-rc-zfs
   IgnorePkg = linux-cachyos-rt-bore linux-cachyos-rt-bore-headers linux-cachyos-rt-bore-nvidia-open
   IgnorePkg = linux-cachyos-server linux-cachyos-server-headers linux-cachyos-server-nvidia-open linux-cachyos-server-zfs
   ```

   *Nu worden al die pakketten genegeerd bij gewone updates, maar gecontroleerd tijdens de offline voorbereiding.*

3. **Start de voorbereiding voor de offline update eenmalig**

   ```bash title='Voer het volgende commando uit'
   sudo systemctl start pacman-offline-prepare.service
   ```
   Dit commando laat pacman-offline eenmalig uitvoeren: het synchroniseert de pakketdatabases en downloadt updates, maar installeert ze niet.

</Steps>

*Als je dit script wilt automatiseren, volg dan de volgende stappen:*

<Steps>

1. **Schakel de timer voor de voorbereiding in**

   Als `pacman-offline-prepare.timer` is ingeschakeld, laat systemd dit script dagelijks updates downloaden, enkele minuten na elke keer dat het systeem opstart.

   ```bash
   sudo systemctl enable pacman-offline-prepare.timer
   ```

2. **Start je systeem opnieuw op:**

   De updates worden tijdens de volgende herstart van het systeem geïnstalleerd.

3. **(Optioneel) Automatisch opnieuw opstarten:**

    Schakel `pacman-offline-reboot.timer` in om je systeem standaard om **3 uur 's nachts** (jouw tijdzone) automatisch opnieuw op te starten als er updates klaarstaan. Houd er rekening mee dat dit niet altijd op precies hetzelfde tijdstip gebeurt, vanwege `RandomizedDelaySec`, dat standaard op 2 uur staat.

    ```bash
    sudo systemctl enable pacman-offline-reboot.timer
    ```

    :::tip
    Je kunt het bestand `pacman-offline-reboot.timer` bewerken om aan te passen op welk tijdstip je systeem opnieuw moet opstarten als er updates klaarstaan, of om de willekeurige planning uit te schakelen.
    :::

</Steps>

</TabItem>

Een hulpmiddel voor Arch Linux dat updates meldt en toepast en je helpt met belangrijke taken vóór en na een update.
Bevat een dynamische en klikbare applet voor het systeemvak, voor eenvoudige integratie met elke bureaubladomgeving/window manager.

    <summary>Cachy-Update inschakelen</summary>

<details>
    <summary>Cachy-Update uitschakelen</summary>
        Schakel Cachy-Update uit via `CachyOS Hello > Apps/Tweaks > Cachy Update disabled`
            :::tip
            Als je Cachy-Update wilt behouden en alleen de applet in het systeemvak wilt uitschakelen, open dan een terminal en voer de volgende commando's uit:
            ```bash
            mkdir -p ~/.config/autostart
            echo -e "[Desktop Entry]\nHidden=true" > ~/.config/autostart/arch-update-tray.desktop
            ```
            Als je de applet in het systeemvak ingeschakeld wilt houden en alleen de automatische controle op updates wilt uitschakelen, voer dan het volgende commando uit:
            ```bash
            systemctl --user disable --now arch-update.timer
            ```
            :::
</details>

- Functies:
  - Automatische controle en weergave van beschikbare updates.
  - Controle op recent Arch Linux-nieuws (en biedt aan het te tonen als dat er is).
  - Controle op verweesde pakketten (en biedt aan ze te verwijderen als ze er zijn).
  - Controle op oude & verwijderde pakketten in de cache (en biedt aan ze te verwijderen als ze er zijn).
  - Controle op een kernelupdate die een herstart vereist (en biedt aan opnieuw op te starten als dat zo is).
  - Controle op services die na een upgrade opnieuw moeten worden gestart (en biedt aan dat te doen als ze er zijn).
  - Ondersteuning voor `sudo`, `sudo-rs`, `doas` & `run0`.

**Interval voor het controleren op updates:** `Eén keer twee minuten na het opstarten en daarna eenmaal per dag met een willekeurige vertraging van een uur.`

- Het interval voor het controleren op updates wijzigen:

```sh title='Voer het volgende commando uit'
systemctl --user edit --full arch-update.timer
# Tip: je kunt in plaats van `nano` ook elke andere teksteditor naar keuze gebruiken
# bijv. EDITOR=micro systemctl --user edit --full arch-update.timer
```

<details>
<summary>Standaardinhoud van het bestand:</summary>
    ```systemd
    [Timer]
    OnStartupSec=2min # Twee minuten na het opstarten controleren op updates
    RandomizedDelaySec=1h # Willekeurige vertraging van een uur
    OnUnitActiveSec=1d # Eenmaal per dag controleren op updates
    ```
</details>
In principe kun je de waarde van `OnUnitActiveSec` wijzigen naar wat je maar wilt. Als je bijvoorbeeld elke 30 minuten op updates wilt controleren, wijzig je het naar `30m`, of naar `6h` voor elke 6 uur. Bekijk dit [document](https://www.freedesktop.org/software/systemd/man/latest/systemd.time.html#Parsing%20Time%20Spans) voor meer details over het instellen van het tijdsinterval.

Als je wilt dat Cachy-Update alleen bij het opstarten één keer op nieuwe updates controleert, kun je de regel `OnUnitActiveSec` gewoon helemaal verwijderen.

Met dank aan [Antiz](https://github.com/Antiz96) voor het onderhouden van het upstream-project Arch-Update en voor de implementatie van Cachy-Update

### De firewall configureren (ufw)
:::note
UFW is na de installatie standaard ingeschakeld.
:::
Volg deze stappen om ufw te configureren:

<Tabs>

<TabItem label="Inschakelen">

```bash
sudo ufw enable
```

</TabItem>

<TabItem label="Uitschakelen">

```bash
sudo ufw disable
```

</TabItem>

<TabItem label="Toestaan">

Standaard negeert ufw inkomend verkeer en staat het uitgaand verkeer toe. Je kunt specifieke regels aan de firewall toevoegen om bepaalde verbindingen te blokkeren of toe te staan.

```bash
# Voorbeeld 1, ssh-verkeer toestaan:
sudo ufw allow ssh
# Voorbeeld 2, poort 12345 openen voor TCP- & UDP-verkeer:
sudo ufw allow 12345

# Tekst of poortnummer kan naar behoefte worden aangepast, zoals 12345/udp om alleen UDP-verkeer toe te staan, of door ssh te vervangen door de naam van een programma
```

</TabItem>

<TabItem label="Weigeren">

Standaard negeert ufw inkomend verkeer en staat het uitgaand verkeer toe. Je kunt specifieke regels aan de firewall toevoegen om bepaalde verbindingen te blokkeren of toe te staan.

```bash
# Voorbeeld 1, ssh-verkeer weigeren:
sudo ufw deny ssh
# Voorbeeld 2, poort 12345 sluiten voor TCP- & UDP-verkeer:
sudo ufw deny 12345

# Tekst of poortnummer kan naar behoefte worden aangepast, zoals 12345/udp om alleen UDP-verkeer te weigeren, of door ssh te vervangen door de naam van een programma
```

</TabItem>

<TabItem label="Status">

```bash
sudo ufw status verbose
```
:::tip
Als je niet wilt vergeten waarom je een poort hebt geopend/gesloten, voeg dan een opmerking toe aan de regel.
```bash
# Voorbeeld 1, poort 12345 openen voor TCP- & UDP-verkeer met een opmerking:
sudo ufw allow 12345 comment 'Example'
# Voorbeeld 2, poort 6789 sluiten voor TCP met een opmerking:
sudo ufw deny 6789/tcp comment 'Comments can have spaces'
```
:::
</TabItem>

</Tabs>

:::note
Wees voorzichtig bij het configureren van firewallregels, omdat verkeerd ingestelde regels je kunnen buitensluiten van je eigen systeem.
:::

:::note
Je kunt het ook grafisch configureren via de sectie "Firewall" in de instellingen van KDE Plasma.
:::

:::note
Wijzigingen in toestaan/weigeren worden van kracht nadat ufw opnieuw is gestart. Schakel ufw uit en daarna weer in voor direct resultaat.
:::

### AppImages beheren

AppImages zijn draagbare applicaties die op de meeste Linux-distributies draaien zonder installatie of rootrechten.

:::note[Alle AppImages hebben uitvoerrechten nodig om te kunnen draaien.]
Je kunt de uitvoerrechten instellen met het volgende commando:
```sh
chmod +x /path/to/your/appimage
```
Of klik met de rechtermuisknop op het AppImage-bestand, ga naar `Properties` > `Permissions` en vink het vakje `Allow executing file as program.` aan
:::

:::note[Zorg ervoor dat FUSE (Filesystem in Userspace) op je systeem is geïnstalleerd voordat je AppImages uitvoert.]
```sh
sudo pacman -S fuse2
```
:::

Om AppImages te beheren, kun je [gearlever](https://github.com/mijorus/gearlever) gebruiken, dat een eenvoudige manier biedt om AppImages in je systeem te integreren.

`gearlever` is een grafisch hulpmiddel dat het beheer van AppImages op je systeem vereenvoudigt. Het integreert met je bureaubladomgeving, waardoor het eenvoudig is om AppImages te starten en te beheren.

Volg deze stappen om gearlever te installeren:

<Steps>
    1. Installeer flatpak als je dat nog niet hebt gedaan:
        ```sh
        sudo pacman -S flatpak
        ```
    2. Start je systeem opnieuw op.
    3. Installeer gearlever met flatpak:
        ```sh
        flatpak install flathub it.mijorus.gearlever
        ```
    4. Log na de installatie uit en weer in om gearlever in je applicatiemenu te zien.
</Steps>

### Toegang tot Samba-shares configureren

Samba is een herimplementatie van het SMB-netwerkprotocol als vrije software. Om verbinding te maken met je samba-server is er een handige configuratie beschikbaar gesteld voor CachyOS-gebruikers, maar daarvoor moet de configuratie van je samba-server worden aangepast.

#### Het smb.conf-bestand van CachyOS installeren en gebruiken

Om het handige smb.conf-bestand te gebruiken, installeer je eerst een specifiek pakket dat het benodigde smb.conf-bestand levert. Vervang daarna de bestaande smb.conf van je server door dit bestand en configureer je gedeelde volumes opnieuw.

:::note[Deze handleiding gaat ervan uit dat je al een werkende Samba-server hebt]
:::

<Steps>
    1. Maak een back-up van je originele `smb.conf`-bestand, dat op Linux-systemen meestal in `/etc/samba/smb.conf` staat.
    2. Installeer het pakket met Samba-instellingen van CachyOS op je clientmachine:
        ```sh
        sudo pacman -S cachyos-samba-settings
        ```
    3. Kopieer de `smb.conf` van je clientmachine naar de Samba-server.
    4. Open en bewerk het bestand om je gedeelde mappen, printers, enz. toe te voegen.
    5. Herstart de Samba-service op je server:
        ```sh
        sudo systemctl restart --now samba
        ```
    6. Open op de clientmachine je gedeelde bronnen via je bestandsbeheerder (bijv. `smb://<your_server_ip>/<share_name>`).

        Als alles correct is geconfigureerd, wordt je om inloggegevens gevraagd. Selecteer desgewenst de optie om je inloggegevens op te slaan.
</Steps>

### Ondersteuning voor AppArmor met AppArmor.d-profielen

Citaat van Wikipedia:

*AppArmor ("Application Armor") is een beveiligingsmodule voor de Linux-kernel waarmee de systeembeheerder de mogelijkheden van programma's kan beperken met profielen per programma. Profielen kunnen mogelijkheden toestaan zoals netwerktoegang, toegang tot raw sockets en de toestemming om bestanden op overeenkomende paden te lezen, te schrijven of uit te voeren.*

Dit is slechts een introductie in het installeren van een basisopstelling van AppArmor. Als je niet bekend bent met AppArmor, ga dan niet verder zonder de gevolgen te begrijpen.

Voor meer gedetailleerde informatie over AppArmor.d en het maken van je eigen profielen, zie de [AppArmor.d-documentatie](https://github.com/roddhjav/apparmor.d?tab=readme-ov-file#configuration).

:::caution[Ga voorzichtig te werk. Een slecht geconfigureerde AppArmor-opstelling kan problemen veroorzaken.]
:::

<Steps>

1. Voeg de volgende kernelparameters toe aan je bootmanager; zie [Configuratie van de bootmanager](/nl/configuration/boot_manager_configuration) ter referentie

   ```text
   lsm=landlock,lockdown,yama,integrity,apparmor,bpf
   ```

2. Installeer de pakketten apparmor en apparmor.d **(set van meer dan 1500 profielen)**
   ```bash
   sudo pacman -S apparmor apparmor.d
   ```

3. Schakel de AppArmor-service in/start deze

   ```bash
   systemctl enable --now apparmor.service
   ```

4. Schakel caching in voor AppArmor-profielen

   ```shell
   # /etc/apparmor/parser.conf
   ## Voeg de volgende regels toe:
   write-cache
   Optimize=compress-fast
   cache-loc /etc/apparmor/earlypolicy/
   ```
   Sla het bestand op en start opnieuw op.
</Steps>

### TRIM inschakelen op versleutelde (LUKS-)apparaten

CachyOS schakelt `fstrim.timer` standaard in om SSD's en NVMe-schijven periodiek te trimmen, wat helpt de schrijfprestaties en levensduur van de schijf te behouden. De versleutelingslaag van de Linux device-mapper (`dm-crypt`/LUKS) blokkeert echter standaard discard-commando's (TRIM). Daardoor draait de periodieke TRIM zonder melding, maar zonder versleutelde partities te trimmen, tenzij discard passthrough expliciet is ingeschakeld.

:::caution[Overwegingen rond beveiliging & privacy]
Het inschakelen van TRIM op een versleuteld apparaat laat de onderliggende SSD-controller weten welke sectoren leeg zijn en welke gegevens bevatten. Hoewel je gegevens volledig versleuteld blijven, kan een aanvaller met fysieke toegang tot de ruwe opslag bij benadering afleiden hoeveel opslagruimte in gebruik is, hoe het bestandssysteem is ingedeeld of welke patronen de gegevens hebben.

Als dit lekken van metadata acceptabel is voor jouw dreigingsmodel, kun je discard passthrough veilig inschakelen voor betere SSD-prestaties en een gezondere schijf.
:::

#### Discard passthrough inschakelen (LUKS2)

<Steps>
1. Bepaal de naam van je actieve LUKS-mapper:

   ```bash
   lsblk
   ```

   Zoek het item van het type `crypt` onder je schijfpartitie (bijv. `luks-1e647929-62c0-4922-8944-f941ed4155fd`).

2. Schakel blijvende discard passthrough in op de actieve LUKS-mapping:

   ```bash
   sudo cryptsetup --allow-discards --persistent refresh <mapper_name>
   ```

   :::note
   Vervang `<mapper_name>` door de werkelijke mapper-naam die je in stap 1 hebt gevonden (bijvoorbeeld `sudo cryptsetup --allow-discards --persistent refresh luks-1e647929-62c0-4922-8944-f941ed4155fd`).
   :::

3. Start je systeem opnieuw op om de wijzigingen toe te passen.

4. Controleer of discard passthrough actief is:

   ```bash
   lsblk -D
   sudo fstrim -v /
   ```

   `lsblk -D` zou nu waarden groter dan nul moeten tonen onder `DISC-GRAN` en `DISC-MAX` voor je versleutelde volume, en `fstrim` toont de hoeveelheid getrimde ruimte in plaats van het apparaat over te slaan.
</Steps>
