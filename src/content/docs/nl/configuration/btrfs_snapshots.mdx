## Inleiding

:::caution
Beschouw Btrfs-snapshots niet als vervanging voor regelmatige back-ups. Zorg altijd voor goede back-ups van je belangrijke gegevens.
:::

### Wat is een Btrfs-snapshot?

Laten we met de basis beginnen:

Btrfs-snapshots komen voort uit de functie subvolume. Wat is een subvolume, vraag je je misschien af? Zie een subvolume als een apart bestandssysteem binnen het Btrfs-bestandssysteem, waarmee je je gegevens in verschillende delen kunt opsplitsen. Daarom hebben we in CachyOS bijvoorbeeld verschillende subvolumes voor:

- Root-bestandssysteem: (`/`)
- Root-map: (`/root`)
- Homemap: (`/home`)
- Var-mappen: (`/var/cache`, `/var/tmp`, `/var/log`)
- Srv-map: (`/srv`)

Door verschillende subvolumes voor deze mappen te hebben, kunnen we ze onafhankelijk beheren, verschillende instellingen toepassen en, het allerbelangrijkst, er snapshots van maken.

Hier ontstaat een snapshot. Een snapshot is in wezen een read-only of read-write (**standaard**) kopie van een subvolume op een bepaald moment. Dit betekent dat je de toestand van je bestandssysteem, inclusief alle bestanden en mappen, op dat moment kunt vastleggen.

Snapshots worden daardoor een referentie naar een bepaald moment: wanneer het doelbestand gaat afwijken van de gegevens in de snapshot, behoudt de snapshot het originele bestand, maakt het doel een nieuw bestand aan met de wijzigingen en blijft de snapshot voor altijd hetzelfde. Daarom noemen sommige gebruikers een snapshot "in de tijd bevroren gegevens".

Stel je voor dat je op een bepaald moment een foto van je bestandssysteem maakt, en dat je altijd naar die foto kunt teruggaan wanneer dat nodig is.

Een van de grote voordelen van snapshots is dat ze zeer ruimte-efficiënt zijn, omdat ze slechts een verwijzing naar de originele gegevens zijn totdat er wijzigingen worden aangebracht.

Maar hier verschilt een snapshot van een traditionele back-up. Stel dat je schijf crasht: met een traditionele back-up kun je je gegevens vanuit die back-up herstellen. Als je echter alleen snapshots op de gecrashte schijf had, verlies je ook de toegang tot die snapshots, omdat ze op dezelfde schijf staan.

### Herstelsituaties waarin snapshots wel en niet nuttig zijn

Ze zijn nuttig om te herstellen van:

- Een kapot of beschadigd systeem na systeemupdates.
- Verkeerde configuraties die verhinderen dat het systeem opstart.
- Per ongeluk verwijderde of gewijzigde bestanden.

Ze zijn niet nuttig om te herstellen van:

- Problemen met de bootloader.
- Hardwarestoringen (bijv. defecte harde schijven).

## Snapshots beheren (GUI & CLI)

:::tip
Omdat CachyOS standaard `snap-pac` bevat, maakt Snapper automatisch snapshots vóór en na elke installatie, upgrade of verwijdering van pakketten met `pacman`. Je hoeft voor deze handelingen dus niet handmatig snapshots te maken; Snapper regelt dat voor je.
:::

:::note
Als je de GRUB-bootloader gebruikt, zorg dan dat je `grub-btrfs-support` hebt, zodat je over alle benodigde scripts en hooks beschikt om BTRFS-snapshots automatisch te detecteren en aan het GRUB-menu toe te voegen.
```bash
sudo pacman -Syu grub-btrfs-support
```
:::

Een paar dingen om rekening mee te houden voordat je snapshots beheert. **Geldt voor zowel de CLI- als de GUI-methode.**

- Het wordt aanbevolen maximaal 10 snapshots te bewaren. Daarboven worden snapshots te oud en minder nuttig. In het ergste geval kan teruggaan naar een oude snapshot compatibiliteitsproblemen met nieuwere softwareversies veroorzaken.
- Snapshots zijn idealiter bedoeld voor herstel. Je kunt ze echter ook gebruiken om wijzigingen aan bestanden ongedaan te maken zonder de hele snapshot te herstellen.
- Voeg bij het maken van snapshots een zinvolle beschrijving toe. Zo kun je later het doel van elke snapshot herkennen.

### Btrfs Assistant (GUI)

Zorg er voordat je verdergaat voor dat je `btrfsmaintenance` hebt geïnstalleerd, zodat je gebruik kunt maken van de functies voor automatisch snapshotbeheer.

Voor wie Btrfs, snapshots en meer liever via een GUI beheert, is [Btrfs Assistant](https://gitlab.com/btrfs-assistant/btrfs-assistant) een geweldig project voor beginners.

#### Automatisch opruimen van snapshots instellen

We gaan het automatisch opruimen van snapshots instellen met Btrfs Assistant. Zo beheer je je snapshots effectief zonder handmatige tussenkomst.

Volg deze stappen:

<Steps>

    1. Start Btrfs Assistant door een terminal te openen en het volgende uit te voeren:
        ```bash
        btrfs-assistant-launcher
        ```

        Of:

        ```bash
        sudo -E btrfs-assistant
        ```

  2. Ga naar het tabblad Snapper Settings:

      <ImageComponent imgsrc={import('~/assets/images/btrfs-maintenance-snapperSettingsTab.png')} />
      Pas de instellingen voor **Snapshot Retention** als volgt aan:
      - Zorg dat de configuratie `root` is geselecteerd
      - Vul de waarde `0` in voor Hourly, Daily, Weekly, Monthly en Yearly.
      - Vink `Enable timeline snapshots` uit.
      - Vul de waarde `10` in bij `Number`.
      - Zet een ✅ bij `Snapper cleanup enabled`.
      - Klik rechtsboven op de knop `Save` en rechtsonder op `Apply systemd changes`.
      **snapper-cleanup.timer wordt nu ingeschakeld om oude snapshots automatisch op te ruimen op basis van je configuratie.**
      :::caution
      Controleer of de aanpassingen die je zojuist hebt gemaakt correct zijn toegepast door de Snapper-configuratie te bekijken:
      ```bash
      sudo nano /etc/snapper/configs/root
      ```
      Verwacht fragment van de uitvoer:
      ```text
      # limit for number cleanup
      NUMBER_MIN_AGE="3600"
      NUMBER_LIMIT="10"
      NUMBER_LIMIT_IMPORTANT="10"
      ```
      Als `NUMBER_LIMIT` en `NUMBER_LIMIT_IMPORTANT` niet de waarde `10` bevatten, pas ze dan aan.
      Sla het bestand op en sluit af door op `CTRL + O`, `Enter` en `CTRL + X` te drukken.
      :::
</Steps>

#### Snapshots verwijderen met Btrfs Assistant

<Steps>
    1. Open Btrfs Assistant:
        ```bash
        btrfs-assistant-launcher
        ```

        Of:

        ```bash
        sudo -E btrfs-assistant
        ```
    2. Ga naar het tabblad Snapper Settings:
        <ImageComponent imgsrc={import('~/assets/images/btrfs-maintenance-snapperTab.png')} />
    3. Selecteer in de lijst de snapshot(s) die je wilt verwijderen.
        :::tip
        - Houd `CTRL` ingedrukt om meerdere snapshots te selecteren.
        - Houd `SHIFT` ingedrukt om een reeks snapshots te selecteren.
        :::
    4. Klik op de knop `Delete` bovenaan het venster.
    5. Genereer de items van je bootloader opnieuw zodat de wijzigingen zichtbaar worden:
        <details>
            <summary>systemd-boot</summary>
            ```bash
            sudo sdboot-manage gen
            ```
        </details>
        <details>
            <summary>GRUB</summary>
            ```bash
            sudo grub-mkconfig -o /boot/grub/grub.cfg
            ```
        </details>
        <details>
            <summary>Limine</summary>
            ```bash
            sudo limine-mkinitcpio
            ```
        </details>
</Steps>

Bekijk hun [officiële wiki](https://gitlab.com/btrfs-assistant/wiki) voor een meer diepgaand overzicht van wat er allemaal mogelijk is.

### Snapper (CLI)

Nu we hebben besproken wat een Btrfs-snapshot is en waarvoor je het kunt gebruiken, gaan we bekijken hoe je snapshots beheert met een hulpmiddel genaamd [Snapper](http://snapper.io/), gemaakt door [Arvin Schnell](https://github.com/aschnell) van [openSUSE](https://www.opensuse.org/).

<details>
<summary>CachyOS gebruikt standaard de volgende Snapper-configuratie:</summary>

```text
# subvolume to snapshot
SUBVOLUME="/"

# filesystem type
FSTYPE="btrfs"

# btrfs qgroup for space aware cleanup algorithms
QGROUP=""

# fraction or absolute size of the filesystems space the snapshots may use
SPACE_LIMIT="0.5"

# fraction or absolute size of the filesystems space that should be free
FREE_LIMIT="0.2"

# users and groups allowed to work with config
ALLOW_USERS=""
ALLOW_GROUPS=""

# sync users and groups from ALLOW_USERS and ALLOW_GROUPS to .snapshots
# directory
SYNC_ACL="no"

# start comparing pre- and post-snapshot in background after creating
# post-snapshot
BACKGROUND_COMPARISON="yes"

# run daily number cleanup
NUMBER_CLEANUP="yes"

# limit for number cleanup
NUMBER_MIN_AGE="1800"
NUMBER_LIMIT="50"
NUMBER_LIMIT_IMPORTANT="15"

# create hourly snapshots
TIMELINE_CREATE="no"

# cleanup hourly snapshots after some time
TIMELINE_CLEANUP="yes"

# limits for timeline cleanup
TIMELINE_MIN_AGE="1800"
TIMELINE_LIMIT_HOURLY="5"
TIMELINE_LIMIT_DAILY="7"
TIMELINE_LIMIT_WEEKLY="0"
TIMELINE_LIMIT_MONTHLY="0"
TIMELINE_LIMIT_YEARLY="0"

# cleanup empty pre-post-pairs
EMPTY_PRE_POST_CLEANUP="yes"

# limits for empty pre-post-pair cleanup
EMPTY_PRE_POST_MIN_AGE="1800"
```

</details>

:::caution
De standaard Snapper-configuratie van CachyOS dekt alleen het root-subvolume (`/`). Als je andere subvolumes met Snapper wilt beheren, moet je voor elk daarvan een aparte configuratie aanmaken.

Deze configuratie moet worden herzien om effectiever te worden.
:::

      - Hier is een samenvatting van de kolommen:
        - `#`: Geeft het nummer van de snapshot aan, dat in andere commando's wordt gebruikt.
        - `Type`: Geeft aan of de snapshot een losse snapshot is of deel uitmaakt van een pre/post-paar.
            - `single`: Deze snapshots hebben geen bijzondere relatie met andere snapshots.
            - `pre`: Deze snapshots worden gemaakt vóór een systeemwijziging (zoals het bewerken van een bestand of het installeren van een pakket).
            - `post`: Zoals de naam al zegt, zijn dit snapshots die zijn gemaakt nadat een systeemwijziging heeft plaatsgevonden. Ze zijn gekoppeld aan de bijbehorende `pre`-snapshot.
        - `Pre #`: Bij `post`-snapshots geeft deze kolom het nummer van de bijbehorende `pre`-snapshot aan.
        - `Date`: De datum en tijd waarop de snapshot is gemaakt.
        - `User`: De gebruiker die de snapshot heeft gemaakt.

            - timeline: Snapshots worden opgeruimd op basis van hun leeftijd en frequentie.
            - empty-pre-post: Verwijdert pre/post-snapshotparen zonder verschillen.
        - `Description`: Een korte beschrijving van de snapshot, die vaak de reden voor het maken ervan aangeeft.
        - `Userdata`: Extra, door de gebruiker gedefinieerde gegevens die bij de snapshot horen.
        Voor meer details over de kolommen in de uitvoer
    </details>
</details>

### Aanbevelingen & tips voor Limine

#### Weergave-instellingen voor snapshots in de Limine-bootloader aanpassen

- Beperk het aantal snapshots dat in het menu van de Limine-bootloader wordt getoond, om het overzichtelijk te houden:

<Steps>
    1. Maak een back-up van het configuratiebestand van limine-snapper-sync:
        ```bash
        sudo cp /etc/limine-snapper-sync.conf /etc/limine-snapper-sync.conf.orig
        ```
    2. Bewerk het configuratiebestand van limine-snapper-sync:
        ```bash
        sudo nano /etc/limine-snapper-sync.conf
        ```
        Verwacht fragment van de uitvoer:
        ```bash
        ### Max Snapshot Entries
        ### Sets the limit for how many snapshot entries show up in the boot menu.
        ### This depends on the size of your FAT32 boot partition and how many different kernel and module versions you want to keep.
        ### A larger FAT32 boot partition allows more snapshot entries.
        MAX_SNAPSHOT_ENTRIES=10
        ```
        Pas eventueel de opmaak van de snapshotnamen aan:
        ```bash
        ### Snapshot Name Format
        ### Choose a format for how snapshot entries look in the Limine bootloader:
        ### 0. ID=111 2023-12-20 10:59:59 (default)
        ### 1. 111│2023-12-20 10:59:59
        ### 2. 111 │ 2023-12-20 10:59:59
        ### 3. 2023-12-20 10:59:59│111
        ### 4. 2023-12-20 10:59:59 │ 111
        ### 5. 2023-12-20 10:59:59
        ### 6. 111
        ### 7. 111│snapshot description
        ### 8. 2023-12-20 10:59:59│snapshot description
        ### 9. │snapshot description
        SNAPSHOT_FORMAT_CHOICE=8
        ```
        `8` is een goede keuze, omdat het de datum en tijd samen met de beschrijving van de snapshot toont.
    3. Sla het bestand op en sluit af door op `CTRL+O` `Enter` `CTRL+X` te drukken
</Steps>
